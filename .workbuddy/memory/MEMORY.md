## 1 本机 / 沙箱坑（**仓库别处没有**，勿再排查）

- **环境** Bash only · **python 两条路全废**（受管 3.13.12 加载系统 3.11 的 `sitecustomize` ⇒ `SRE`）⇒ 脚本用 **Node**（`spawnSync` → EBUSY）· 长驻服务各起一个后台任务 · **e2e 不与前端构建并发**（⇒ 假掉登录）· 本机有 MySQL/nginx（`D:\tools\installer\`）· **无 docker**
- **⚠️ 凭据**（两条 github 凭据详述见 `CONTRIBUTING.md` §八）：取错那条一律回 **401**，别读成"私有库/CI 看不了"；git 必带 `-c credential.helper= -c credential.helper=store`
- **push 只有代理一条路**：`-c http.proxy=` 不是直连（要 `env -u HTTP_PROXY …`）· 代理**按 host 分化**（`github.com`/`gist` 502；`api.github.com` 200、`codeload`/`raw` 301、`objects` 404 都通）⇒ **`github.com` 不通仍能调 REST API 查 CI** · `github.com` **非封死而是低概率窗口**（10 探通 2≈20%，502 与 `schannel: server closed abruptly` 交替）⇒ **持续重试有效**（一轮 15 次里中的）· **提交可能多带文件** ⇒ `git commit -F - -- <paths>` + `git show --name-only`；新文件先 `git add` · 推送成功后可能紧跟 `fatal: unable to write credential store: Permission denied`（**已成功**）与沙箱「Do NOT retry」提示（含凭据字样误报）⇒ 判据只看 `old..new  main -> main`
- **数用例前先清 `target/surefire-reports`**（陈旧 XML 把数算多）；判"类还在不在"先 `replace(/\\/g,'/')`（否则 Windows 永不命中）
- **干净 MySQL 做实验**（不碰舰长那 11 库实例）：`mysqld --basedir=D:/tools/installer/mysql --datadir=D:/tools/tmp/mysql-ci/data --port=3306 --console`（**必须 `run_in_background`**；端口必须 3306 —— `application-mysql.yml` 写死）⇒ root 无口令、`DROP/CREATE DATABASE bluewhale`；用完 `taskkill //PID` · **⚠️ mysql profile 全量用例需 `application-h2.yml` 那对种子口令（逐字相同），该文件被沙箱挡** ⇒ 自选口令时某个"故意登录失败"用例把种子账号**锁 5 分钟**（`attempts=5, level=1`）⇒ 之后全场 `40102`"账号已被锁定"（**别读成口令错**）
