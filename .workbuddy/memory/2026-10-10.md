# 2026-10-10：数据源双轨（H2 / 本机 MySQL）+ Flyway 迁移机制

## 一、起因
舰长问"后端用的哪个数据库？是我本地的吗？你能启动并连接、建表建库吗"。
答：当时用的是 **H2 内存库**（`jdbc:h2:mem:bluewhale`），跑在 JVM 进程内存里，
跟本机装没装数据库无关；进程一停数据全没。本机装着 MySQL 8.0.26（服务 Stopped），

## 三、两个真坑（这次踩得很值，都写进文档 + 测试了）

### 坑 1：MySQL 保留字 `release` —— 而且修一次不够
`release`（发布版本号）是自然的领域命名，但 **`RELEASE` 是 MySQL 8 保留字**，
而 **H2 不认它**。同一个列名：H2 全绿、MySQL `ERROR 1064`。
> 这是最难查的一类差异：只在其中一个库上暴露。

修复踩了第二层：把列名改 `app_release`、Java 属性仍叫 `release` 并加 `@TableField("app_release")`
→ 编译过、H2 过、MySQL 依然 1064。原因是 **MyBatis-Plus 发现"列名 ≠ 属性名"会自动补别名**
`app_release AS release`，别名把保留字原样带回。
**最终做法**：属性名与列名同构 —— `appRelease` ← 由 `map-underscore-to-camel-case` 推导出
`app_release`（与 `traceId → trace_id` 一致），**刻意不加 `@TableField`**。对外字段仍是 `release`。

反编译 MP 的 `TableFieldInfo` 构造函数确认了别名生成条件（`sqlSelect = column`，
当列名与属性名不一致时追加 `" AS " + property`）。

### 坑 2：Flyway 10+ 的数据库支持是模块化的
`flyway-core` 只内置 H2 / SQLite（jar 里能列出 `internal/database/h2/`，没有 mysql 包）。
缺 `flyway-mysql` 的症状：H2 profile 一切正常，切 mysql 启动报 `Unsupported Database: MySQL 8.0`。
与 MyBatis-Plus 拆 `mybatis-plus-jsqlparser` 同一类陷阱。

### 附带发现
`insertBatch` 里的 `#{it.release}` 是 **OGNL 字符串，编译器管不到** —— 属性改名后
只在运行时报错，靠接口测试（`ClientLogApiTest`）才抓到。这是本次唯一被测试当场拦下的问题。

## 四、新增的回归断言（重要）
`ClientLogEntityMappingTest`（日志模块）直接用 `TableInfoHelper` 构造 `TableInfo`，
断言生成的 SQL：① 含 `app_release` ② 不含 `AS release`。
**为什么必须这样测**：默认 profile 是 H2，它不认这些保留字，跑用例永远是绿的 ——
这类问题只能对"生成物"做断言。

## 五、验证
- 后端 10/10 模块、**24 个测试全绿**（日志 12 + 应用层 12）
- mysql profile：Flyway 识别 `MySQL 8.0` → 执行 V1 → 5 个接口（上报/分页/详情/链路/聚合）全通，
  中文与 emoji 落库无损
- **重启验证**：重启后 Flyway 报 `Schema is up to date. No migration necessary.`，

- 走 vite 代理（前端实际路径）读写全通

# 追加：国产库达梦 DM8 支持（同日 · ADR-0010）

## 一、需求与选型
舰长：「现阶段最起码需要支持一种国产库，支持一种主流库。」主流已有（MySQL），本轮补国产库。

按「方言距离 × 本机可验证性」筛候选，选 **达梦 DM8**：信创代表 + 方言最远（最能压测架构）+ 有 Windows 版。
舰长同时拍板：**先不验证，先交付改动，明确标注未验证**。

本机环境限制（本轮查清）：**没有 Docker**；`wsl.exe` 与 `sc.exe` 在**程序黑名单**里不能调用；
本机无任何国产库。→ openGauss / OceanBase / TiDB（仅 Linux 版）在本机根本起不了实例。

## 二、最大的意外收获：MyBatis-Plus 原生内置达梦方言
`mybatis-plus-annotation` 3.5.17 的 `DbType` 枚举里**有 `DM`**（值 `"dm"`），
`mybatis-plus-extension` 的 `JdbcUtils` 用正则 `:dm\d*:` 匹配 URL → `DbType.DM`。
**结论：`DbAutoConfiguration` 里那个刻意不指定 DbType 的分页拦截器，只要 URL 写对就自动用达梦方言
—— 分页 / 防全表更新 / 乐观锁零代码改动。**

枚举里还有一长串国产库：`KINGBASE_ES`、`OPENGAUSS`、`GAUSS`、`GAUSS_DB`、`OCEAN_BASE`、
`XU_GU`、`SINODB`、`OSCAR`、`UXDB`、`VASTBASE`、`GOLDENDB`、`YASDB`、`GBASE` 系列。
**将来再换库，先查这张枚举表。**

## 三、Flyway 对达梦零支持 —— 本轮核心取舍
中央仓 42 个 `flyway-*` 构件里没有任何达梦坐标（国产库只有 `flyway-database-oceanbase` /
`flyway-database-tidb`，而它们本质是 MySQL 协议）。两条路都否决：
1. 引社区 `db-migration` 扩展 → 为一个库引入个人维护的外部依赖
2. 自研 `DatabaseType` → 接口在 `org.flywaydb.core.internal.*`，`BaseDatabaseType` 尚有 8 个抽象方法，
   `createDatabase`/`createParser` 还需配套 Database/Schema/Parser 子类，约 300–400 行，
   **全部绑定 Flyway 内部 API，升级即可能破**；在没有实例可验证时是纯负债

**决定：达梦 profile `flyway.enabled=false`，DDL 走交付脚本**（信创常规做法：DDL 交付、DBA 执行）。
脚本仍放 `db/migration/dameng/`、编号仍 `V1__` —— 不是为了 Flyway，是为了三套脚本能按同一时间线对照；
将来若恢复自动迁移，文件无需挪位改名。

## 四、达梦方言要点
| 项目 | MySQL 8 | 达梦 DM8 |
|------|---------|----------|
| 自增主键 | `AUTO_INCREMENT` | `BIGINT IDENTITY(1,1) NOT NULL` |
| 变长字符串 | `VARCHAR(64)` 按字符 | `VARCHAR(64 CHAR)` —— **默认按字节**，中文必须显式 CHAR |
| 列注释 | inline `COMMENT '...'` | `COMMENT ON COLUMN t.c IS '...'` 独立语句 |
| 表选项 | ENGINE / CHARSET / COLLATE | 不支持，写了报错 |
| 标识符 | 受 `lower_case_table_names` 影响 | 不加引号一律**转大写**（同 Oracle） |

`CHAR` 那条是真问题：Java 侧 truncate 按**字符**、达梦 VARCHAR(n) 按**字节**，
UTF-8 汉字 3 字节 → 255 字符的中文是 765 字节，塞不下且报错只说"数据超长"。

## 五、保留字核对（本表零冲突，结论带版本限定）
达梦查法：`SELECT KEYWORD FROM V$RESERVED_WORDS WHERE RESERVED='Y'`。
逐项核对：表名 / 4 个索引名 / 约束名 / 14 个列名 **全部无冲突**。
- `LEVEL` 在达梦关键字表里但**非保留**（可作列名）
- **`RELEASE` 达梦完全不认** —— 与 ADR-0009 恰好相反
→ **保留字风险按库各算，两库结论不可互推。**（达梦升级会加关键字：8.1.3→8.1.4 增 78 个）
