## 一、服务定位

面向租户内部的员工社区，承载公告、讨论、问答、建议、活动、党建学习六类内容，与 OA、工会、LMS、Agent 打通，形成「人发帖 → 内容沉淀 → 知识复用」的闭环。

**不做的事（划清边界）：**

- 不做外部公开社区（仅租户内部可见，需登录）；
- 不做即时聊天（即时通讯归 `whale-im`，当前状态「规划」，未落地）；
- 不做长文博客专栏（网盘在 `whale-oa` 的 drive 模块；文档协作归 `whale-doc`）；
- 不做电商交易（归 `whale-mall` 鲸宝行）；
- 不做积分账本（可兑换积分归 `whale-mall`，本服务只记论坛经验与流水引用）。

## 六、数据一致性硬规则（v1.3 新增，实现前必须落库）

### 6.1 楼层号

1. `fm_thread.next_floor` 初始 1（1 楼 = 主帖正文），发帖时 `UPDATE fm_thread SET next_floor = next_floor + 1 WHERE id = ?` 取回分配；
2. `uk_fm_post_floor(tenant_id, thread_id, floor)` 兜底，冲突重试 ≤ 3 次后返回 30010；
3. **软删楼层不回收楼层号**（回收必致「N 楼」与引用错位）；
4. **二级回复（楼中楼）不占楼层号**，只记 `parent_post_id`，且最多两级；
5. 单帖楼层上限 `max-posts-per-thread`（默认 5000），达到后自动 `closed` 并提示开新帖（30011）。

### 6.2 软删与唯一键

- 业务内容表（版块/帖子/楼层/标签）挂 `deleted` 逻辑删除；
- 唯一编码（`board.code`、`thread.thread_no`、`tag.name`）软删时改写为 `原编码#D{id}` **释放唯一键**；
- 关联/互动表（`fm_reaction`、收藏、投票记录）**物理删除**，不挂逻辑删除（否则「取消后再点」撞唯一键）；
- 帖子详情：作者与管理员返回 200 + 「已删除」占位，其他用户 404。

### 6.3 计数

- `reply_count / like_count / view_count` 以 DB 条件更新为准（`SET like_count = like_count + 1`）；
- 浏览计数按「同人同帖 24h 只 +1」去重（**落库**：`fm_thread_view` 唯一键 `(tenant_id, thread_id, user_id)` + 滚动 24h 条件更新；不用 Redis，详情是读主路径，不该因缓存不可用报错）；
- 取消投花条件更新 `like_count = like_count - 1 WHERE like_count > 0`，不得为负；
- 每日 `whale-job` 对账：明细 `COUNT` 与展示计数比对，差异写审计并按明细纠正。

### 6.4 匿名

1. **库内恒存 `user_id`**，只做展示层匿名（审计、禁言、申诉都依赖它）；
2. 展示编号 = `HMAC-SHA256(tenant_id|board_id|user_id)` 取 4 位十进制，**同人同版恒定、跨版不同**；
3. 匿名帖**不计论坛经验、不进金榜、不可被打赏**（否则刷分零成本）；
4. 「匿名发帖」是**版块属性 + 用户动作**，不是角色，不得进入权限矩阵。

### 6.5 内容安全

- 富文本**服务端白名单消毒**（标签 + 属性），`script/iframe/on*` 一律剥离；消毒失败 30030；
- 图片附件做魔数校验，类型与大小按版块配置；
- 敏感词命中三档动作，命中必落 `fm_sensitive_hit`（词、位置、动作、处置人）；
- 限流：发帖/回复/投花固定窗口，超限 429；`/forum/hot` 单独更宽窗口。

### 6.6 举报与审核的交集

- 举报**不自动改变帖子状态**，处置是独立动作（人工或规则命中）；
- 举报 `rejected`（不成立）**绝不通知被举报人**（否则等于泄露「有人在举报你」）；
- 同一目标被举报 ≥ N 次（默认 5）自动转 `PENDING` 复检，但不自动删除；
- 所有处置与审核动作 append-only，不设 `update_time/deleted`。

## 七、核心状态机

### 7.1 帖子

```text
draft（草稿）
  ↓ 提交（审核版块 / 新用户前 3 帖 / 敏感词转待审）
pending（待审）
  ├─ 通过 → published（已发布）
  └─ 驳回 → rejected（已驳回，可申诉；申诉通过回到 pending）

scheduled（定时发布，到点由 whale-job 抢占）
  ↓ publish_time 到 → 走「提交」同一路径（审核版块则进 pending）

published
  ├─ 悬榜（置顶，可多帖，按权重排序）
  ├─ 题金榜（精华，唯一标记）
  ├─ 采纳最佳答案 → solved（仍可回复，可撤销）
  ├─ 关闭 → closed（禁新回复，可重开）
  ├─ 编辑（审核版块）→ pending（留原文快照 + EDIT 审计）
  └─ 处置/作者删除 → deleted（软删，保留审计）

优先级（同帖多状态时按此判定）：deleted > closed > solved > pending > scheduled > published > draft
```

### 7.2 举报

```text
pending（待受理，SLA 24h）
  → handling（处理中，SLA 48h，超时 whale-job 升级）
  → resolved（已处置：删帖/禁言/警告，被举报人收到处置通知）
  → rejected（举报不成立：不通知被举报人，举报人收到结果）
```
