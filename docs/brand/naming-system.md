# 蓝鲸命名体系（BlueWhale Naming System）

> 一句话规则：**主品牌叫「蓝鲸」，每个部分是「蓝鲸·鲸X」——「鲸」固定，「X」取该部分唯一职能的一个字。**
> 用途：只用于**对外呈现**（官网、文章、UI 标题、宣传物料、演讲）。代码目录/包名/路由/数据库**一律不动**，理由见 §六。

---

## 一、命名逻辑

蓝鲸有三个天然可用的隐喻，正好对上软件系统的三层：

| 蓝鲸特征 | 对应系统层 | 命名用法 |
|---|---|---|
| 体型巨大、结构复杂但协调 | **平台整体** | 蓝鲸（BlueWhale） |
| 器官各司其职，缺一不可 | **技术底座 / 平台服务** | 鲸 + 身体器官字（喉、瞳、息、脉、囊…） |
| 群游、迁徙、觅食、育幼（有生态） | **业务应用** | 鲸 + 业务动作字（客、造、营、研、契…） |

**格式统一**：`蓝鲸·鲸律`（口语只说「鲸律」）。英文侧保留 `BlueWhale` + 原有模块码（如 `whale-auth`），不造英文新词。

## 二、平台层

| 名称 | 说明 |
|---|---|
| **蓝鲸** BlueWhale | 平台总名，已定 |
| **蓝鲸·洋** | 公有云 / SaaS 交付形态（可选，暂不强推） |
| **蓝鲸·礁** | 私有化部署形态（一个自成一体的礁盘，独立呼吸） |

> 建议：交付形态先用「蓝鲸 Cloud / 蓝鲸 私有化」这种白话，不急着造名。名字一多会稀释主品牌。

## 五、命名规则与禁用词

**五条规则**
1. **两字为主**：`鲸` + 一个职能字。三字只在必须时用（如「鲸脉·设计器」）。
2. **说人话**：企业客户听到「鲸造」要能猜到是制造，「鲸契」要能猜到是合同。猜不到就换字。
3. **不撞常见词**：避开「鲸吞」「鲸落」「鲸爆」等已有强烈联想或负面的词。
4. **一字不两用**：全文只有一个「鲸X」对应一个模块，出现冲突优先改业务层。
5. **英文不硬造**：英文一律 `BlueWhale <Module>`，不编 `WhaleThroat` 这种。

**禁用/慎用**
| 词 | 原因 |
|---|---|
| 鲸落 | 指鲸死亡后沉入海底，虽是美好生态隐喻，但做产品名晦气；可留作内部黑话（"某模块已鲸落"=已下线） |
| 鲸吞 | 有"侵吞、吞并"负面义 |
| 鲸爆 | 尸体腐败爆炸，绝对不用 |
| 蓝鲸 + 数字编号（蓝鲸 1 号/2 号） | 无记忆点，且暗示版本碎片 |

## 六、落地范围：改哪里、不改哪里（重要）

**只改"呈现层"**
- 官网 / 宣传页 / 文章中的产品名
- UI 里的应用标题、菜单分组名、关于页
- README 顶部介绍段、对外 PPT、演示视频字幕
- 新模块从立项起就用中文名

**绝对不改"工程层"**（改了就是事故）
| 不改 | 原因 |
|---|---|
| 目录名、artifactId、包名 | 23 服务 + 26 应用全量重构，构建、部署、CI 49 个 job 全要跟着动 |
| 网关路由前缀 `/auth/**` `/crm/**` | 网关不剥前缀，前端路径必须等于后端类前缀；一改全站 404 |
| 数据库库名 `/ 表前缀` | 迁移脚本、租户隔离、备份策略全部牵连 |
| Nacos 服务名、Redis key 前缀 | 注册发现与缓存键直接失效 |

**做法**：建一张 `模块码 → 中文名` 的**映射表**（就是本文档），前端只改 `title`、`document.title`、菜单配置里的展示字段；一处配置，全局生效。

## 七、配套：Slogan 与视觉

**Slogan 候选**（选一个，全平台统一）
1. **「低频，但传得远。」** — 蓝鲸声波能传数百公里；小团队做出长尾影响
2. **「深海之下，自成生态。」** — 强调平台完整性
3. **「一头鲸，能撑起一片海。」** — 强调单体承载企业全域

推荐第 1 条：短、有反差、不像企业软件广告，适合做公众号简介和文章结尾签名。

**视觉基线**
| 项 | 值 | 用法 |
|---|---|---|
| 深海蓝 | `#0B2A45` | 主背景 / 标题 |
| 鲸腹白 | `#F5F7FA` | 正文背景 |
| 声波青 | `#2CE8D0` | 强调 / 图表高亮 / 链接 |
| 图形母题 | 低频声波同心弧 | 封面、加载动画、架构图分组框 |
