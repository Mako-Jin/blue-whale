## 二、变更点

### 2.1 模型层 + 状态机内核 + BPMN 双向（`support/`，纯 Java，11 + 8 + 4 个新文件）

- **模式判定（`ProcessModelParser`）**：`type=="stateMachine"` → 规范化；`type` 缺失且无 `flows` → **legacy**，原样委托既有 `ProcessNodeParser`（文案「流程定义缺少有效审批节点」**逐字节保留**）后补齐顺序流转（`f1..fn`）；`type` 缺失但有 `flows` → 规范化（宽容）；其它非空 `type` → `UNKNOWN_DEFINITION_TYPE`。上限 `MAX_NODES=200` / `MAX_FLOWS=400`。
- **节点类型收敛为 4 种**（`ProcessNodeType`）：`START_EVENT` / `END_EVENT` / `USER_TASK` / `EXCLUSIVE_GATEWAY`；`from(String)` 大小写不敏感、`-` 归一为 `_`。
- **校验器（`ProcessModelValidator`）**：分层校验（模式判定 → 结构 → 图级），**内容非法不抛异常**，产出 `ValidationReport`（`errors[]/warnings[]`）；错误码 22 个 + 警告码 `CONDITION_IGNORED`。图级校验仅结构无错时执行，legacy 模式跳过（其顺序语义天然合法）。
- **状态机内核（`StateMachine`）**：`pickFlow` 统一选路（`Guard` SPI：`AlwaysGuard` / `DefaultFlowGuard`；条件本轮不参与选路）→ 网关透传 → 终态判定；`MAX_GATEWAY_HOPS=16`，超限抛 `BizException(400,"网关流转超出上限")`；网关多分支无默认抛 `ProcessModelException(GATEWAY_MULTI_BRANCH_NO_DEFAULT)`。
- **BPMN 解析（`BpmnXmlParser`）**：映射 `startEvent/endEvent/userTask/exclusiveGateway` + `sequenceFlow`；`assignee` 读**任意前缀**同名属性（兼容 `flowable:`/`camunda:`）；网关 `default="flowId"` 属性 → 流转 `isDefault`；忽略 `BPMNDiagram/BPMNPlane/BPMNShape/BPMNEdge/documentation/extensionElements`；不支持元素（`serviceTask`/`parallelGateway`/`subProcess`…）抛 `BPMN_UNSUPPORTED_ELEMENT` **并点名元素**。
- **BPMN 加固（`BpmnXmlSupport`）**：JDK DOM + `disallow-doctype-decl` + 禁外部实体/XInclude/外部 DTD·schema + `FEATURE_SECURE_PROCESSING` + 空 `EntityResolver` + 体积卡口 `MAX_BPMN_XML_LENGTH=262144`（**不引入第三方 XML 库**）。
- **BPMN 写出（`BpmnXmlWriter`）**：对称输出 `assignee` / 网关 `default`，属性转义 `& < "`；与解析器**往返节点与流转一致**。

### 2.2 服务接线（S5）

- **`ProcessModelService` + `ProcessModelServiceImpl`**：`validate`（JSON 或 BPMN，非法回 `valid=false` 而**不抛异常**；合法回 `normalizedJson` + `nodeCount/flowCount`）、`importBpmn`（解析 → 校验 → 委托既有 `ProcessDefinitionService.create` 存**规范化 JSON**）、`exportBpmn`（读定义 → 解析模型 → 写 XML 字节）。
- **`ProcessModelController`**（3 端点）：`POST /workflow/definition/validate`（权限 `sys:workflow:definition:validate` = 种子 58）、`POST /workflow/definition/bpmn`（`…:bpmnImport` = 59）、`GET /workflow/definition/{id}/bpmn`（复用 `sys:workflow:list`，先例同 whale-form 5.30 导出复用 `sys:form:data:list`）。
- **请求体承载 XML 为 JSON 字符串字段**（`BpmnImportRequest.bpmnXml`，`DefinitionValidateRequest`）：避免请求体走 XML 反序列化，规避 XXE 入口。
- **`ProcessInstanceServiceImpl#start` / `ProcessTaskServiceImpl#approve` 改由内核驱动**：新增 `current_node_key` 定位（`resolveCurrentKey` **优先** `currentNodeKey`，为空回落 `currentIndex`）；legacy 定义语义**零回归**（相等）。
- **DTO/VO**：新增 `BpmnImportRequest` / `DefinitionValidateRequest` / `ProcessDefinitionValidateVO` / `ValidationIssueVO`。

### 2.3 库表/实体/种子（S4）

- **`whale-workflow/db/init.sql`**：`process_instance` 增加 `current_node_key VARCHAR(64) NULL AFTER current_index`；**`db/migration-5.31.sql`** 为非破坏性 `ALTER`（幂等条件化）。
- **实体/VO**：`entity/ProcessInstance.java` + `vo/ProcessInstanceVO.java` 增 `currentNodeKey`（VO 字段名为冻结契约）。
- **权限种子**：`whale-auth/db/init.sql` 追加 **58** `sys:workflow:definition:validate`、**59** `sys:workflow:definition:bpmnImport`（`super_admin` 自动拥有全部权限）。
- **D5 实机执行**：`bluewhale_workflow` 的 `current_node_key varchar(64) NULL` 已存在；`bluewhale_auth` 的种子 58/59 已就位。

### 2.4 测试（S6）

- 新增 6 个测试类：`ProcessModelParserTest`(14)、`ProcessModelValidatorTest`(21)、`StateMachineTest`(11)、`BpmnXmlSupportTest`(5)、`BpmnXmlParserTest`(10)、`BpmnXmlWriterTest`(5)、`ProcessModelServiceImplTest`(9)。

## 四、风险与遗留

| 项 | 说明 |
|---|---|
| 条件表达式不求值 | 本轮 `condition` / `conditionExpression` 仅解析、不参与选路，产出 `CONDITION_IGNORED` 警告；选路仅依赖 `isDefault` 默认流。后续如需条件路由需引入表达式求值（自有 SPeL/MVEL 或轻量 DSL），届时升级 `Guard` SPI 实现 |
| 仅排他网关 | 并行网关、会签、子流程、边界事件均不在支持范围（`BPMN_UNSUPPORTED_ELEMENT` 明确点名拒绝） |
| `BpmnXmlWriter` 为最小可用 | 输出不含 BPMN-DI（图形坐标），可被解析器与外部 BPMN 工具读取，但**无图形信息**；前端可视化需另行补齐 DI |
| 无前端 | 本轮仅后端：BPMN 设计器/可视化、流程定义可视化编辑未做 |
| 版本语义 | BPMN 导入走既有 `ProcessDefinitionService.create`，`code` 唯一性沿用既有校验（重复 code 报 400） |

## 五、结论

Wave 5.31 达成「whale-workflow 引擎升级」目标：以规范化 JSON 为唯一事实源的**通用状态机内核**、**BPMN 2.0 双向转换（轻量自研 + XXE 加固）**、**向后兼容 legacy** 三部分均落地。构建门禁（28/28 模块）、模块自检（102 用例 + Checkstyle 0 违规）与运行时冒烟（G2–G5，28/28）全部通过；运行时确认 `current_node_key` 定位与 `currentIndex` 回落双路径均可用，legacy 定义零改动可发起并通过。
