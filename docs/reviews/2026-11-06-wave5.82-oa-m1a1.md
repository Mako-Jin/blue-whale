## 三、关键设计复核

1. **事实源单一**：列表与动作全部走 Workflow，OA 不复制任务/抄送/代理状态，避免双写不一致。
2. **动作鉴权**：URL 携带实例与任务双 ID；先用实例详情定位任务，再校验归属与状态，最后调用 Workflow 完成接口。
3. **幂等**：重复同意/驳回在 OA 侧直接返回；Workflow 侧以任务状态兜底。本地结果只在状态迁移时落库发事件。
4. **抄送口径兼容**：`recipientCandidates` 同时覆盖用户 ID 与账号，解决发起级/节点级两套写法。
5. **数据范围**：详情仅发起人、任务审批人/归属人、抄送人、监控角色可见；越权统一按 404，避免泄露流程存在性。
6. **依赖方向**：业务详情 SPI 位于 approval.application，`hr` 实现，审批上下文不反向依赖业务上下文；ArchUnit 全绿。
