## 2. 关键实现口径

### 2.1 越权与存在性不泄露

- `requireOwned` 判定顺序固定为「先可见性、后归属」：对当前用户不可见（跨租户 / 私密他人 / 已删除 / 未发布）一律 `40401`，可见但非上传者才 `40301`。这样避免「403 泄露资源存在」。
- `Content.visibleTo(viewerId, operator)`：运营全可见；普通用户要求 `PUBLISHED && copyrightState.canPlay() && 版权未过期`，且 `PUBLIC` 或 `viewerId == uploaderId`。
- 用户侧公开分页（`/video/movies/page`、`/video/collections/page`、`/video/series/page`、`/video/videos/page`）强制 `PUBLISHED + PUBLIC`，再在应用层按可见性过滤。
- 图片代理（封面 / 海报 / 背景 / 片单封面 / 头像）与详情一致先判可见性，跨租户与不可见内容统一 `404`（`BizException(ErrorCode.NOT_FOUND)`，HTTP 200 + `code=404`）。
- 票据与流式复核顺序：票据存在 → 租户 / 用户 / 内容匹配（`40302`）→ 可播态（`40303`）→ 读取上游字节。

### 2.2 上传安全

| 步骤 | 判定 | 错误码 |
|---|---|---|
| 文件可用 | 文件服务返回存在且未删除 | 40006 |
| MIME 白名单 | `video/mp4, video/webm` / `image/jpeg, image/png, image/webp` | 40003 / 40004 |
| 大小 | 短视频 300MB / 视频 2GB / 电影 4GB | 40005 |
| magic bytes | MP4 偏移 4 为 `ftyp`；WebM 前 4 字节 `1A 45 DF A3` | 40003 |
| 时长 | 短视频 300s / 视频 7200s / 电影 14400s | 40002 |

- `applyBase` 读取文件头 12 字节（`HEAD_BYTES`）后交由 `VideoUploadPolicy.validate` 统一判定；mime 兼容映射仅允许 `mp4/quicktime ↔ MP4`、`webm/matroska ↔ WEBM`，因此「MP4 头 + 声明 webm」或「WebM 头 + 声明 mp4」均 40003。
- 前端在 `/video/meta` 获取白名单与上限做前置校验，后端仍二次校验（不信任客户端）。

### 2.3 内容安全与版权

- 声明：`GET /video/declaration/current` 返回当前版本与是否已签；`POST /video/declaration/accept` 记录 `version`，未签或版本不一致禁止创建内容。
- 来源：创建内容必须提交 `ORIGINAL / AUTHORIZED / ROYALTY_FREE`（40009 / 40010）；电影另有授权来源 `OWNED / LICENSED / PUBLIC_DOMAIN`、授权编号与到期时间。
- 版权下架：`POST /video/admin/content/{id}/takedown` 原因必填 ≤500（40017），写入 `copyright_status=TAKEDOWN`、`takedown_reason`、`takedown_at`，并删除可播缓存、失效首页 / feed 缓存。
- 审计：运营写操作全部 `@AuditLog`，只记资源 ID / 标题 / 状态，不含正文与票据。
- **举报入口（可选）未实现**：本期以「评论审核 + 下架 / 版权下架」闭环替代；错误码 40018 已预留，后续接入无需改码。

### 2.4 限流与票据

- 网关限流先于 JWT（`Order = HIGHEST_PRECEDENCE + 10`），未登录请求也会被计数；限流键含客户端维度，多实例共享 Redis 固定窗口。
- 六条规则中 `like` 与 `favorite` 共用阈值变量（写操作防刷，计数回写幂等）；`/video/stream/**` 不进熔断名单，避免长视频多 Range 被 3s 超时误熔断。
- 票据 TTL 300s、客户端 240s 主动刷新；一次播放的多次 Range 复用同一票据；下架 / 版权下架 / 授权到期通过 30s 可播缓存 + 每次开流复核即时阻断。

### 2.5 清理任务与索引

- `WatchHistoryCleanupScheduler`：`retentionDays = Math.max(historyRetentionDays, 1)`；每批 500，最多 20 批（单次上限 1 万行），不足一批即结束；异常只 `log.warn`，不中断后续调度。
- `WatchHistoryRepositoryImpl.deleteWatchedBefore`：先 `selectList`（`watched_at < cutoff` + `orderByAsc(watched_at, id)` + `LIMIT`）取 ID，再按 ID 删除；两条 SQL 均受租户插件约束，后台无租户上下文时覆盖全部租户。
- `V4__watch_history_cleanup_index.sql` 补 `(tenant_id, watched_at)` 复合索引：V1 的 `idx_vd_history_user` 前缀是 `(tenant_id, user_id)`，无法命中「跨用户按时间清理」的主查询。

### 2.6 监控与 SLO

- 直方图桶对 `/video/meta`、`/video/home`、`/video/content/{id}`、`/video/stream/{contentId}` 均生效，`histogram_quantile` 可直接查询；`uri` 标签为模板化路径。
- Grafana `bluewhale-video`：行「SLO」（三条 P95 + `up`）、行「流量与时延」（端点 QPS + P95 趋势）、行「资源与依赖」（Hikari 四项 + JVM 堆）；阈值线与 SLO 一致（0.3s / 0.25s / 0.4s、5xx 5%、堆 85%）。
- 日志：生产置 `info`；票据、`fileId`、视频字节、评论正文、声明全文不入日志。

## 4. 设计决策与本次修正

| 项 | 决策 / 处理 |
|---|---|
| 越权判定顺序 | `requireOwned` 固定「先 `visibleTo` → 40401，后归属 → 40301」，避免 403 泄露资源存在；与音乐 / 文档服务口径一致 |
| magic bytes 回落 | 文件头不可识别时按声明 MIME 回落（单测 `shouldFallbackToMimeWhenHeadUnknown` 固化）。取舍：文本伪装成 `video/mp4` 可被文件服务接收，但不可解码、无法播放；真正「头与声明不一致」仍 40003。生产可加 ffprobe 深度校验 |
| 举报入口 | M5-3 中标注为可选，本期不实现；以评论审核 + 下架 / 版权下架闭环替代，40018 预留 |
| 孤儿文件清理 | M5-7 中标注为可选，本期不做；内容删除为逻辑删除，视频字节保留可追溯；以 `whale-file` 配额 + 人工清理兜底 |
| 观看历史清理索引 | 新增 V4 `(tenant_id, watched_at)`，而非复用 V1 的 `(tenant_id, user_id)`；理由：清理是跨用户按时间扫描 |
| 片单封面发布态 | 片单 `coverFileId` 未限制「必须已上架」，保留运营在草稿态预览与公开宣传素材的场景；已在 M4 报告记录，M5 复核维持 |
| `$shortId + 1000` 命中真实内容风险 | 冒烟「换内容票据」用例改用 `999999999`，确保命中 `40302`（内容 ID 不匹配）而非 `40401` |
| `Send-VideoStreamProbe` 读不到 `Accept-Ranges` | .NET 把该响应头放在 `response.Headers` 而非 `Content.Headers` → 新增 `Get-VideoHeaderValue` 双集合回退；否则 `4.rangeAcceptRanges` 会误判为空 |
| `publish` 视图断言 | 原计划断言「运营视图不含 `videoFileId`」不成立（`ContentView` 仅上传者 / 运营可见，按设计含 `fileId`）→ 删除该断言，保留 `publishedState` / `playable` |
| 清理阶段身份混用 | `$createdContents` 由 `List[long]` 改为 `List[object]`（`@{ Id; Headers }`），按各自上传者删除，避免 40301 |
| PowerShell 5.1 双 BOM + `param` | `video-backup-restore.ps1` 首字节为双 BOM，5.1 不识别 `param` 块并报「赋值表达式无效」→ 以 `ReadAllText(...).TrimStart([char]0xFEFF)` + `UTF8Encoding($true)` 重写为单 BOM，`[Parser]::ParseFile` 通过，其余脚本同口径归一 |
| 沙箱下 `node` / `pnpm` | 报 `sandbox read-write path is not absolute`；本轮 M5 未改前端，无需绕行构建 |
