## 2. 改动明细

### S-01 撤销时间毫秒精度

- 新增 `whale-backend/whale-common/whale-security/.../token/TokenTimeSupport.java`：统一签发时间解析与撤销比较。
- `JwtTokenProvider`：access/refresh 均写入 `iatMs`（毫秒）。
- `RedisUserAccessRevocationStore` / `RedisTenantMembershipRevocationStore`：写 `System.currentTimeMillis()`；查询用 `TokenTimeSupport.isRevoked`。
- 网关 `UserAccessRevocationChecker` / `MembershipRevocationChecker`：按 `issuedAt.getTime()` 毫秒比较。
- 网关过滤器、auth `JwtAuthenticationFilter`、`AuthService` 刷新校验：由 claims 解析 `iatMs`，缺失回退 `iat`。
- 兼容策略：撤销值为毫秒（≥1e11）按精确时间比较；历史毫秒以下值视为 Unix 秒，按秒粒度比较，保证滚动升级期间不放松。

### S-02 Redis 降级策略

- 新增 `SecurityDegradationPolicy`（whale-security）与网关/auth 两侧 `SecurityDegradationConfig`。
- 接入：用户撤销、成员撤销、租户状态、令牌黑名单（网关 + auth 存储）。
- 配置：`whale.security.degradation.fail-closed` / `SECURITY_DEGRADATION_FAIL_CLOSED`，默认 `false`。
- 默认取舍：Redis 不可读时放行并输出安全降级告警（保持现网可用性）；生产如选择安全优先，设为 `true`，此时 Redis 故障会直接拒绝相关请求。
- 权限缓存未纳入该开关：其失效路径仍按既有 DB 回源/告警逻辑处理，避免把权限缓存故障放大为全站拒绝。

### S-03 租户到期 UTC

- 新增 `TenantExpiryClock`（domain）固定 `ZoneOffset.UTC`。
- `Tenant.renew`、`TenantAppService`、`TenantMembershipAppService` 的可用性判断改为 UTC。
- `TenantStatusCache` 写 Redis 的到期 Unix 秒改为 `expireTime.toEpochSecond(UTC)`。
- 注意：存量 `expire_time` 若按本地时区录入，切换后语义按 UTC；上线前需按下发口径校准存量租户到期时间。

### S-05 审计历史归属

- P1-14 之前的伪造归属无法从数据层区分真伪，不做数据改写（避免误伤真实记录）。
- 现行契约（T2）已去掉请求体 `userId` 回退，新记录只信网关 `X-User-Id`。
- 本项作为「不可回溯」结案，历史数据查询仅作参考，不作为追责依据。

### S-06 直连业务端口

- 产出部署必检清单与示例：[network-boundary.md](../design/network-boundary.md)。
- 要求仅网关暴露公网、业务端口回环/内网监听、`/internal/**` 来源白名单、网关头净化。

### S-07 熔断半开

- `CircuitBreakerGlobalFilter` 注册状态迁移监听，输出 `CLOSED -> OPEN`、`OPEN -> HALF_OPEN`、`HALF_OPEN -> CLOSED/OPEN` 日志。
- 保留既有状态/失败率指标；运行态取证需真实故障注入，见待办 V-14。

### F-01 归档补锁自动补扫

- `ArchiveProperties.LockReconcile`：`enabled`（默认 false）、`cron`（默认每日 03:30）、`batch-size`、`max-batches`、`tenant-ids`。
- 新增 `ArchiveFileLockReconcileScheduler`：逐租户绑定 `TenantContext`，按 `nextAfterId` 游标循环，达到批次上限留给下次；单租户异常不影响其它租户。
- 配置前缀：`whale.archive.lock-reconcile.*`；租户清单优先本配置，其次 `sync.tenant-ids`，最后租户目录。
- 默认关闭避免上线即对历史数据产生批量写；启用前确认文件服务与租户目录可用。

### F-02 job 调度断连重对齐

- `JobScheduler` 增加 `scheduledSignatures`（cron 签名）与 `reconcileWithDatabase()`：取消数据库已非运行中的本地调度；对 cron 变化或依赖变化的任务取消并重注册。
- 新增 `JobScheduleReconcileJob`，默认首次 60s、之后每 5 分钟执行；`whale.job.schedule-reconcile.*` 可调/可关。
- 单轮异常只记录日志，不阻断调度线程。

### F-03 告警通道

- `alert_record` 增加 `fingerprint` 与 `(tenant_id, fingerprint, trigger_time)` 索引；新增幂等迁移 `migration-5.68-alert-record-fingerprint.sql`。
- 入站按标签 `tenant_id` / `tenant` 解析租户并逐条设置 `TenantContext`，落库与通知归属一致；缺标签回退当前上下文/默认租户。
- 租户行级插件在本服务默认启用（`whale.tenant.sql.enabled` 缺省 `true`，随 `whale-spring-boot-starter` 自动装配），入站 `insert`/去重查询均按当前 `TenantContext` 写入并过滤 `tenant_id`，无需额外配置。
- 规则匹配：先在告警归属租户内查规则；业务租户通常无自有规则，此时回落到平台租户（`TenantContext.DEFAULT_TENANT_ID`）的共享规则，避免带 `tenant_id` 标签的告警静默不通知。
- firing 告警在同一 fingerprint、窗口内（默认 300s）只落库与通知一次；recovered 始终落库。
- 邮件改为 HTML（`MimeMessage` + `MimeMessageHelper`），字段 HTML 转义；Webhook 载荷新增 `tenantId`。
- SMS 仍未接入：需要供应商账号、模板与签名报备，拆为 F-03b。

- F-03：SMS 未接（F-03b）；邮件 HTML 需真实邮件服务器实机验证（V-06）。
