## 1. M1 增量

### 1.1 模板管理

| 能力 | 接口 | 权限 |
|---|---|---|
| 分页 | `GET /message/template/page` | `sys:message:template:list` |
| 详情 | `GET /message/template/{id}` | `sys:message:template:list` |
| 新增 | `POST /message/template` | `sys:message:template:add` |
| 更新 | `PUT /message/template/{id}` | `sys:message:template:edit` |
| 删除 | `DELETE /message/template/{id}` | `sys:message:template:delete` |

规则：

- 模板编码租户内唯一；保存时去空白并转大写；发送侧 `resolveTemplate` 同样大写解析，避免大小写漂移。
- 唯一索引 `uk_tenant_template_code` 不含删除标记，因此**逻辑删除行仍占用编码**；校验走 `countByCodeIncludeDeleted`（含 `deleted=1`），避免“校验通过但插入撞唯一键”。
- 新增默认启用（`status=1`）；删除为逻辑删除，历史消息保留标题/正文快照，不受模板删除影响。
- 写操作带 `@AuditLog(targetType="msg_template")`。

### 1.2 失败投递重试

- `POST /message/record/{id}/retry`，权限 `sys:message:record:retry`，审计 `msg_record`。
- 只重试 `FAILED` 投递；成功/跳过/mock 不重发。
- **mock 模式拒绝重试**（`BizException(PARAM_ERROR)`），避免把“未真实发送”误记为恢复成功。
- 按渠道重建接收人：INAPP/IM 用 `recipient`→userId、EMAIL→email、SMS→phone；无法解析时把该投递记为 `FAILED` 并写错误原因。
- 重试后累加 `attempts`、更新状态/供应商消息ID/错误/投递时间，并重算消息聚合状态。

### 1.3 站内信收件箱

| 能力 | 接口 | 隔离方式 |
|---|---|---|
| 本人分页 | `GET /message/inapp/page` | `X-User-Id` + `channel=INAPP` + `recipient=userId` |
| 未读数 | `GET /message/inapp/unread-count` | 同上 + `read_flag=0` |
| 标记已读 | `POST /message/inapp/{messageId}/read` | 只更新本人 INAPP 投递 |

- 收件箱是登录用户自助能力，**不额外分配权限码**，但强依赖网关注入的 `X-User-Id`；缺失/非法返回 `UNAUTHORIZED`。
- 已读状态记在 `msg_delivery.read_flag`，同一消息发给多人时各自独立。
- 消息正文/标题仍从 `msg_record` 读取，模板删除或消息逻辑删除时做空值容错。
