## 三、本轮发现并已修复的 4 个平台缺陷

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| A | 知识增量扫描清空全部文件/档案知识块 | `KnowledgeIngestService.runIncremental` 用 `indexService.listFileHashes()`（含 `file:` 前缀路径）与仓库扫描比对，`file:*` 全部落入 `removedPaths` 被 `deletePaths` 误删 | removedPaths 循环排除 `file:` 前缀（文件知识由 `FileKnowledgeSyncService` 独立管理生命周期），新增 `KnowledgeConstants.FILE_PATH_PREFIX` 共享常量 |
| B | 单文件知识重建恒 SKIPPED 且误删索引 | `GET /file/internal/{id}` 返回 `FileInfoVO`（无 status/deleted/updateTime），`RemoteFileChange.collectable()` 要求 `status != null && status != 0` 恒不通过 | `FileInternalController` 改返 `FileChangeVO`（新增 `FileInfoService.getChangeDetail` 内网专用方法），不动对外冻结契约 `FileInfoVO` |
| C | 事实索引全量重建后文件知识无自愈 | `runFullRebuild` 的 `indexService.deleteAll()` 清空所有块但不触发文件知识重建 | 重建成功后将 `agent_knowledge_file` 台账 INDEXED → PENDING（新增 `resetIndexedToPending`），等待下一轮同步重建 |
| D | 网关路径下全部受限知识块（含档案）0 命中 | `PermissionHeaderGlobalFilter` 回落 `lb://whale-auth/auth/me` 仅透传 Authorization，**未透传 `X-Tenant-Id`**；whale-auth 租户上下文强制校验返回 HTTP 200 信封 `code=400/data=null`，`parsePermissions` 静默解析为空串 → 注入空权限码头（fail-closed 但无告警） | 回落调用透传网关注入的 `X-Tenant-Id`；修复前伪造头攻击面同步验证：过滤器会剥离外部伪造 `X-Permission-Codes`，无法绕过 |

构建验证：`whale-agent`/`whale-file` 含测试 package SUCCESS（10:00:53）；`whale-gateway` 84 用例全绿（10:33:18）。
