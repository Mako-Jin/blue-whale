## 二、完成项

### 2.1 数据库

- `V7__change_request.sql`：新增 `pdm_chg_request` 1 张表；`uk_chg_request_no(tenant_id, change_no)`，查询索引 `idx_chg_request_status` / `idx_chg_request_initiator`；仅 `CREATE TABLE IF NOT EXISTS`，无 `DROP/TRUNCATE/DELETE`、无物理外键。
- `migration-5.80-pdm-change.sql`（`bluewhale_auth`）：权限 950–955、菜单 190、角色 21105 `pdm_change_manager`（平台模板 + 业务租户复制），授权 `tenant_admin/pdm_manager/pdm_change_manager` 全量、`pdm_member` 仅 950；全部 `NOT EXISTS` 幂等，无删除语句。

### 2.2 后端

- 实体/Mapper：`PdmChgRequest`（继承 `BaseEntity`）；状态常量 `PdmChgRequestStatus`；类型校验 `PdmChgObjectType`。
- 服务：`PdmChgRequestServiceImpl`
  - `create` 新建草稿，编号 `CR-yyyyMMddHHmmss-四位随机`，影响对象 JSON 归一化；
  - `update/delete/submit` 仅草稿；
  - `submit` 影响对象为空抛“影响对象不能为空”；
  - `approve/reject` 仅已提交，驳回意见必填；
  - `close` 仅已通过/已驳回；
  - `page` 单页上限 200，按创建时间倒序。
- 控制器：9 端点，权限码与审计注解齐全；审批/驳回意见可空入参，服务侧对驳回做强校验。
- 租户隔离：`tenant_id` 由租户拦截器写入，按 ID 查询跨租户不可见。

### 2.3 前端（8106）

- `api/change.ts`：类型与 9 个函数。
- `pages/change/index.tsx`：编号/状态筛选、分页、新建/编辑抽屉（动态影响对象）、提交、通过/驳回（驳回必填意见）、关闭、删除。
- `App.tsx`：`/change` 菜单（`sys:pdm:change:list`）与路由。

### 2.4 测试

新增 `PdmChgRequestServiceImplTest` 9 项：

1. 新建落草稿并回显影响对象；
2. 影响对象为空不可提交；
3. 草稿提交成功；
4. 非草稿不可修改/删除；
5. 仅已提交可审批，通过写审批人/时间/意见；
6. 驳回意见必填；
7. 仅已通过/已驳回可关闭；
8. 非法对象类型、缺少 ID/编码拒绝；
9. 分页上限 200 且影响对象回显。

## 四、代码检查项（协议漏洞/代码漏洞/复杂度/魔法值）

| 检查项 | 结论 | 说明 |
|---|---|---|
| 越权与协议 | 通过 | 9 端点均带 `@RequirePermission`；审批与编辑拆分为 `approve` / `edit` 两个权限码；无匿名端点 |
| 参数校验 | 通过 | DTO 使用 `@NotBlank/@Size/@Valid`；影响对象最多 100 条；分页 `size` 截断至 200 |
| 状态机闭环 | 通过 | 修改/删除/提交/审批/关闭均由服务层统一 `require*` 校验，前端按钮仅作辅助 |
| 审计覆盖 | 通过 | 新建/修改/删除/提交/审批/驳回/关闭均 `@AuditLog`；查询不审计 |
| 租户隔离 | 通过 | `BaseEntity` + 租户拦截器；跨租户按 ID 查询不可见 |
| 异常口径 | 通过 | 统一 `BizException(ErrorCode.PARAM_ERROR, ...)`，不散用通用异常；JSON 解析失败降级为空并 `warn` |
| 复杂度 | 通过 | 服务类无超过 3 层嵌套；`toImpactJson/parseImpact` 单一职责 |
| 魔法值 | 通过 | 状态与对象类型常量化；仅编号格式、分页上限等以具名常量/局部常量表达 |
| 并发/唯一性 | 通过（有兜底） | 编号重复由 `uk_chg_request_no` 兜底；后续可切换发号器 |
| SQL 安全 | 通过 | 仅 `IF NOT EXISTS` 建表与幂等种子；参数化查询由 MyBatis-Plus 生成 |
