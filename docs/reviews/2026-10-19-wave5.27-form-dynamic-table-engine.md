# Wave 5.27 检查报告 · whale-form 动态表引擎（主从分离 · 版本化物理表 · 多租户）

> 日期：2026-10-19 ｜ 作者：BlueWhale
> 规格：[wave5.27-form-dynamic-table-engine/spec.md](../plans/wave5.27-form-dynamic-table-engine/spec.md) ｜ 分解：[tasks.md](../plans/wave5.27-form-dynamic-table-engine/tasks.md)
> 触发：用户架构质疑「我想的动态表单，是用户在页面可以自由新建表单，对应后端新建对应的表，字段等。然后客户端可以动态绘制渲染出表单，你现在这样的实现，业务多了，是不是这张表会炸。」
> 经 AskUserQuestion 逐轮冻结口径：**业务用户自助动态表单**（用户定义字段 → 后端建真实列 → 客户端动态渲染）+ **多租户行级 `tenant_id`** + **纯后端引擎**（前端设计器/渲染后续排期）+ **保留 `data_json` 过渡**（双写，不迁移历史）+ **版本化建新表** `form_data_{code}_v{version}` + **`X-Tenant-Id` 头**（缺省回落默认租户 1）。
> 依据：REQ-DOC-002（先落文档）、REQ-QA-002（变更后自检）、REQ-CICD-001（Checkstyle 门禁）、REQ-ARCH-003（服务自持前缀）。

## 一、背景与架构选择

原实现（Wave 5.26）把全部业务字段塞进 `form_data.data_json`（单表 JSON 列），业务量增大后：
- 单一宽表 JSON 无法为动态字段建索引，字段级查询/统计退化为全表扫描 + JSON 解析；
- 无字段级约束（长度/类型/必填仅在服务层校验），无 DB 层类型安全；
- JSON 长度受 `MEDIUMTEXT` 上限与 64KB 业务校验双重限制，列膨胀不可控。

**选定方案：主从分离 + 版本化物理表**（方案 B）
- **主表 `form_data`**：主记录（`tenant_id`/`definition_id`/`definition_code`/`definition_version`/`biz_key`/`data_json`/`submitter`/`status`），保留 `data_json` 作为过渡与兜底读源；
- **物理表 `form_data_{code}_v{version}`**：用户在 schema 中定义的字段 → 发布时生成**真实列**（带类型与长度），支持字段级索引与 DB 层类型安全；
- **`form_table_registry`**：登记「定义（code + version）↔ 物理表」映射 + 发布时 schema 快照（后续字段校验以此快照为准，避免定义被改后物理表错位）；
- **版本化语义**：schema 变更 = 升版本 → 建**新物理表**，旧表原地保留；查询按主记录 `definition_version` 路由到对应物理表，历史数据不迁移（字段集不同，迁移会错位）。

**为什么不会「炸」**：写入分摊到 N 张按业务主题切的窄表，单表行数 = 该表单该版本的数据量；JSON 不再承载查询负载（主表 JSON 仅作过渡/兜底）。

## 三、契约与交付物

### A · 表结构与登记（3 项）

| 项 | 交付 |
|---|---|
| A-a | `entity/FormTableRegistry`（继承 `BaseEntity`）+ `mapper/FormTableRegistryMapper` |
| A-b | `whale-form/db/init.sql`：`form_data` 加 `tenant_id` + `idx_tenant_id`；新增 `form_table_registry` |
| A-c | `WebHeaders` 加 `TENANT_ID="X-Tenant-Id"` 常量 + `tenantId(request)` |

### B · 引擎内核（4 项）

| 项 | 交付 | 关键约束 |
|---|---|---|
| B-a | `support/{FormField,FormSchemaParser}` | `schema_json = {"fields":[{key,label,type,required,maxLength}]}`；key 规则 `^[a-z][a-z0-9_]{0,63}$`、type 白名单 text/textarea/number/date/datetime/select/bool、保留列排除、重复 key 拒绝 |
| B-b | `support/FormTableDdlGenerator` | 表名 `form_data_{code}_v{version}`；类型映射 text→VARCHAR(n≤2000 默认255) / textarea→TEXT / number→DECIMAL(18,4) / date→DATE / datetime→DATETIME / select→VARCHAR(255) / bool→TINYINT；公共列 + 动态列 + `PRIMARY KEY(id)` + `idx_tenant_id`/`idx_biz_key` |
| B-c | `support/FormDataEngine(+impl/JdbcFormDataEngine)` | 表名二次正则白名单 `^form_data_[a-z0-9_]+_v[0-9]+$`；列名取自 schema 解析白名单；值 JDBC `?` 全参数化；标识符反引号包裹；`insert`/`selectFields`/`logicDelete` |
| B-d | `support/TenantResolver` | 读 `X-Tenant-Id`；缺省 `DEFAULT_TENANT_ID=1`；非法值抛 400「租户ID格式非法」 |

### C · 发布接线（3 项）

| 项 | 交付 |
|---|---|
| C-a | `service/FormPublishService(+Impl)`：`publish`（校验 code → 校验未发布 → 解析 schema → 执行 DDL → 登记）+ `listTables`（按版本倒序） |
| C-b | `FormController` +`POST /form/definition/{id}/publish`（`sys:form:publish`）、`GET /form/definition/{id}/tables`（`sys:form:list`）；`vo/FormTableRegistryVO`（不含 schemaJson） |
| C-d | `whale-auth/db/init.sql` 追加 `sys:form:publish`（id 52） |

### D · 数据双写改造

- `FormData` +`tenantId`；`FormDataVO` +`tenantId`、+`fields: Map<String,Object>`；
- `FormDataService(+Impl)` 4 方法均加 `Long tenantId`：`submit`（以 registry 的 schema 快照校验字段 → **主表 + 物理表双写**）/ `getDetail`（按版本路由读物理表，回填 `fields`）/ `delete`（主表与物理表**双逻辑删除**）/ `page`（加 `tenant_id` 过滤）；
- `FormDataController` 4 接口均传 `TenantResolver.resolve(httpRequest)`；
- 跨租户访问 → 404（不泄露存在性）；定义不存在 → 404；未发布版本提交 → 400。

**DB 取证**：
- 物理表 `form_data_fm_smoke_v1` 列 = 公共列（id/tenant_id/definition_id/definition_version/biz_key/submitter/status/create_time/update_time/deleted）+ 动态列（`name varchar(64)` / `age decimal(18,4)` / `birthday date` / `memo text` / `active tinyint`）—— **动态列真实建出**；
- `form_table_registry`：`fm_smoke` / v1 / `form_data_fm_smoke_v1` / field_count=5 / status=1 / schema_json 快照存在；
- 主表 `form_data` 行：tenant_id=1、deleted=1（删除后）；
- 物理表行：tenant_id=1、`张三` / 30.0000 / 2020-01-01 / hello world / 1、deleted=1（**双删成功**）。

结论：动态建表 → 双写 → 版本路由查询 → 双删 → 负向校验 全链路符合冻结契约；注入防护（表名白名单 + 列名白名单 + 值参数化）与租户隔离均生效。

| 类别 | 内容 |
|---|---|
| 缺陷 | 无（Checkstyle 一次通过 0 违规，模块单测 36/0/0 一次通过） |

## 七、非目标与残余

- **非目标（本轮明确不做）**：前端表单设计器与动态渲染页（用户自助拖拽建字段 / 客户端按 schema 渲染表单）、字段级索引自动优化、schema 字段删除/改类型的在线迁移、历史数据跨版本聚合查询、跨租户共享表单、DDL 异步任务化（大表建表进度）。
- 遗留：`form_data.data_json` 仍双写（过渡），待前端设计器/渲染落地并切换读源后再评估收窄。
- 后续候选：① `form_data` 查询按版本 + 动态字段条件检索（把 `selectFields` 扩展为条件查询）；② 前端设计器（schema 可视化编排）与动态渲染组件；③ 网关注入租户上下文（免业务服务自行解析头）；④ `service-catalog.md` 更新 8084/`bluewhale_form` 表清单（含 `form_table_registry`）。
