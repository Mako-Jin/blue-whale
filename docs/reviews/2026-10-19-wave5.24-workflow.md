## 二、契约与交付物

### T1 · 骨架接线

| 项 | 结论 |
|---|---|
| `pom.xml` | 新增 `com.bluewhale:whale-spring-boot-starter:${project.version}`（传递 `Result`/`PageResult`/`BizException`/`BaseEntity`/`PageQuery`/MyBatis 自动填充/权限码头 + whale-auth-sdk `@RequirePermission`） |
| `application.yml` | **端口自引用缺陷修复**：`${server.port:8083}` → `${SERVER_PORT:8083}`（对齐 whale-form/whale-file 约定，否则 Spring Boot 4 抛 `Circular placeholder reference 'server.port'`）；补 datasource(`bluewhale_workflow`)/mybatis-plus(逻辑删除 `deleted`)/`whale.permission.header.enabled=true` |

### T2 · 领域层（8 文件）

| 文件 | 说明 |
|---|---|
| `entity/ProcessDefinition` | 继承 `BaseEntity`，`@TableName("process_definition")` |
| `mapper/ProcessDefinitionMapper` | 仅继承 `BaseMapper`（`com.bluewhale.**.mapper` 扫描） |
| `dto/ProcessDefinitionSaveRequest` | code/name 必填（`@NotBlank`+`@Size`）+ definitionJson/version/status/remark |
| `dto/ProcessQueryRequest` | 继承 `PageQuery`：name 模糊、code 等值、status 等值 |
| `vo/ProcessDefinitionVO` | 契约字段（id/code/name/definitionJson/version/status/remark/createTime/updateTime） |
| `service/ProcessDefinitionService(+Impl)` | create/update/delete/getDetail/page；`assertCodeUnique` 查重抛「流程编码已存在」、`validateDefinitionSize`(>65536 抛 `PARAM_ERROR`)、`MAX_PAGE_SIZE=200` |
| `controller/WorkflowController` | `@RequestMapping("/workflow")`，5 接口 + `@RequirePermission("sys:workflow:add/edit/delete/list")` |

### T3 · DDL 与权限种子

| 项 | 结论 |
|---|---|
| `db/init.sql` | 新建：`process_definition` 表；列 `id/code/name/definition_json/version/status/remark/create_time/update_time/deleted`；`definition_json` MEDIUMTEXT；`code` 普通索引 `idx_code`（无唯一索引，唯一性由服务层前置校验） |
| whale-auth `db/init.sql` | 追加 `sys:workflow:add(40)/edit(41)/delete(42)/list(43)`（承接 form 种子 id 至 39） |

## 三、缺陷修复与偏差

| 类别 | 内容 |
|---|---|
| 缺陷（配置，P0 潜在） | `whale-workflow/src/main/resources/application.yml` 沿用骨架的 `${server.port:8083}` **自引用**写法 → Spring Boot 4 会在启动时抛 `Circular placeholder reference 'server.port'`。**本轮修复为 `${SERVER_PORT:8083}`**（与 whale-form 同类缺陷同源，见 [service-catalog.md](../service-catalog.md) §九 C-06 与 task-breakdown 残余登记） |
| 偏差（依赖） | 骨架 `pom.xml` 原缺 `whale-spring-boot-starter`，无法获得 `Result`/`PageResult`/`BaseEntity`/权限码拦截 → 本轮按 whale-form 模式补入 |
| 偏差（构建） | 全量 `mvn clean install -T 1C` 需先释放运行中 7 个服务的 jar 锁（`另一个程序正在使用此文件`）→ 先 `Stop-Process` 停 gateway/auth/job/form/file/workflow/audit 七进程，构建后以 `Start-Process` 重新拉起并核验健康 |

> 未触碰：`AuthService` 顺序、网关过滤链、其余服务生产代码。

## 五、偏差与残余

- **非目标（本轮明确不做）**：流程实例（`process_instance`）、待办任务（`process_task`）、审批动作（同意/驳回）与状态流转、流程定义发布/版本快照、前端工作流设计器 —— 均留后续波次。
- 固化：`whale-workflow` datasource 指向 `bluewhale_workflow`（已建库，[service-catalog.md](../service-catalog.md) 状态需由「规划」改「已建」）。
- 同类残余：`pay/monitor/alert/config/erp/mes/pdm/oa` 等骨架仍存在 `${server.port:…}` 自引用写法，建议后续逐服务接入时一并修复。
