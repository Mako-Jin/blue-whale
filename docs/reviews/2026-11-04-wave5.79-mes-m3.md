## 2. 变更清单

### 2.1 数据库迁移

`backend/whale-apps/whale-mes/src/main/resources/db/migration/V6__mes_quality.sql`

- 检验计划：`mes_qc_inspection_plan`、`mes_qc_inspection_plan_item`；
- 检验执行：`mes_qc_inspection_task`、`mes_qc_inspection_result`、`mes_qc_inspection_defect`；
- 不合格与处置：`mes_qc_ncr`、`mes_qc_disposition`、`mes_qc_rework_order`；
- SPC：`mes_qc_spc_sample`、`mes_qc_spc_rule`；
- 关键唯一键：计划 `(tenant_id, plan_no)`、计划项 `(plan_id, item_no)`、任务 `(tenant_id, task_no)`、
  NCR `(tenant_id, ncr_no)`、处置 `(ncr_id)`（一 NCR 一处置）、返工 `(tenant_id, rework_no)`、
  SPC 样本 `(tenant_id, rule_id, subgroup_no, sample_seq)`；
- 计划、任务、NCR、处置、返工单、SPC 规则含 `version` 乐观锁字段；全部表含 `tenant_id` / `deleted`。

### 2.2 后端（`com.bluewhale.mes.quality`）

- 实体 / Mapper（10 组）：检验计划、检验项、检验任务、检验结果、检验不良、NCR、处置、返工单、SPC 规则、SPC 样本。
- `MesInspectionService`：`savePlan`、`pagePlans`、`getPlan`、`createTask`、`pageTasks`、`getTask`、
  `submitResults`、`judge`、`firstArticleGate`、`board`；
  - 计划保存校验序号唯一与 `minValue ≤ maxValue`，已有任务时拒绝更新；
  - 结果录入限定任务范围（仅 `PENDING/INSPECTED`），测量项 `OK` 必须落在上下限内，录入后推进 `INSPECTED`；
  - 判定前校验计划项全部录入；`FAILED` 时同事务调用 NCR 自动生成；
  - 首件门禁按工单 + 工序取最近一次首件任务，未通过即 `passed=false`。
- `MesNcrService`：`createFromInspectionTask`、`create`、`page`、`get`、`createDisposition`、
  `executeDisposition`、`close`、`pageDispositions`；
  - 自动生成数量 = 检验不良合计（无明细按 1），数量 ≤ 0 拒绝；
  - 处置数量必须等于 NCR 不良数量，且一个 NCR 仅允许一条处置；
  - 执行处置推进 NCR 状态，`REWORK` 自动创建返工单；关闭需结论，返工未完工不可关闭。
- `MesReworkService`：`page`、`start`、`complete`，严格 `CREATED → IN_PROGRESS → COMPLETED`。
- `MesSpcService`：`saveRule`、`pageRules`、`submitSample`、`pageSamples`、`chart`；
  - 规则绑定的检验项必须存在；样本检验项须与规则绑定项一致；
  - 子组满额回填 `subgroup_xbar` / `subgroup_range`，命中控制限写 `alert_flag/alert_rule`；
  - 图表按子组聚合返回均值序列。
- 端点：`/mes/quality/inspection-plan`（3）、`/mes/quality/inspection`（6）、`/mes/quality/ncr`（4）、
  `/mes/quality/disposition`（3）、`/mes/quality/rework`（3）、`/mes/quality/spc`（5）、
  `/mes/quality/board`（1），共 25 个；均带 `@RequirePermission`，写操作带 `@AuditLog(targetType="mes_quality")`。

## 4. 关键不变量与口径

| 不变量 | 实现方式 |
|---|---|
| 检验项未全部录入不可判定 | 判定前统计计划检验项与实际结果数，缺失即拒绝 |
| 检验 `FAILED` 必生成 NCR | 判定通过后同事务调用 `createFromInspectionTask`，数量取不良合计（空则 1） |
| 首件最近一次未通过阻断批量释放 | `firstArticleGate` 按工单 + 工序取最近一次首件任务，`passed=false` 即阻断 |
| 处置数量 = NCR 不良数量 | 创建处置时强校验，不一致拒绝 |
| 一个 NCR 仅一条处置 | 处置表 `ncr_id` 唯一 + 创建前查重 |
| NCR 状态机 | `OPEN → DISPOSITION → REWORK/REPAIR/SCRAP/CONCESSION → CLOSED`；关闭需结论，返工未完工不可关闭 |
| 返工状态机 | `CREATED → IN_PROGRESS → COMPLETED`，动作端点显式 |
| SPC 样本与规则绑定项一致 | 校验样本 `plan_item_id` 属于有效检验项且等于规则绑定项 |
| 子组判定留痕 | 满额回填均值 / 极差，命中控制限写 `alert_flag = 1` + `alert_rule` |

口径说明：

- 检验任务状态为 `PENDING → INSPECTED → PASSED/FAILED`，旁支 `CANCELLED`；
- 自动 NCR 的来源类型为 `INSPECTION`，手工建单为 `MANUAL`；
- SPC 仅实现 Xbar-R 子组判定，其余判异规则（链长 / 趋势）未启用；
- 质量看板按自然日统计，未按班次拆分。
