## 2. 变更清单

### 2.1 数据库迁移（`whale-backend/whale-apps/whale-erp`）

- 新增 `V3__scm.sql`：6 张表
  - `erp_scm_purchase_order` / `erp_scm_purchase_order_line`（`uk_po_doc_no`、`uk_po_line`）；
  - `erp_scm_sales_order` / `erp_scm_sales_order_line`（`uk_so_doc_no`、`uk_so_line`）；
  - `erp_scm_stock_movement`（流水只追加）/ `erp_scm_stock_balance`（`uk_stock_balance` = 租户 + 物料 + 仓库）；
  - 末尾为 `erp_fin_voucher` / `erp_fin_receivable` / `erp_fin_payable` 补自动记账幂等键
    `uk_voucher_source` / `uk_receivable_source` / `uk_payable_source`（`tenant_id, source_type, source_id`）；
  - 金额 `DECIMAL(18,2)`、数量 `DECIMAL(18,4)`；禁止 `DROP/TRUNCATE/DELETE`。

> 计划原拟 `V4__scm.sql`，因 M0+M1 已把主数据与财务合并为 `V2`，此处顺延为 `V3`。

### 2.2 后端代码（`com.bluewhale.erp.scm`，DDD 四层）

- `domain/model`：`PurchaseOrder` / `PurchaseOrderLine`、`SalesOrder` / `SalesOrderLine`、
  `StockMovement`、`StockBalance`、`ScmStatus`、`ScmQuery`；
- `domain/port`：`ItemCatalog` / `SupplierCatalog`（只读快照端口，避免 SCM 直接访问存量表）；
- `domain/repository`：`PurchaseOrderRepository`、`SalesOrderRepository`、`StockRepository`；
- `application`：3 个应用服务（采购 / 销售 / 库存）+ 5 个命令 + 4 个视图；
- `infrastructure`：6 个实体、6 个 Mapper、3 个仓储实现、2 个目录适配器；
- `interfaces/controller`：`PurchaseOrderController`、`SalesOrderController`、`StockController`
  （`@RequirePermission` + `@AuditLog`）；
- `common`：新增 `Quantities`（数量正数 / 非负校验）、`ErpFinanceAccountProperties`
  （科目映射配置 `erp.finance.account.*`，默认 1405 / 2202 / 1122 / 6001 / 6401）；
- `finance`：新增 `AutoVoucherAppService`、`AutoVoucherCommand`；`VoucherRepository`/`ArAp` 增
  `findBySource`；`ArApAppService` 增 `outstandingReceivable(customerId)` 供信用校验；
- 关键规则：
  - 订单状态机不可跳转；只有 `APPROVED`/`PARTIALLY_*` 可收货/发货；已收货/已发货不可取消；
  - 收货/发货数量逐行累加，超过订单数量直接拒绝（`RECEIVE_EXCEEDED` / `SHIP_EXCEEDED`）；
  - 出库按移动加权平均计价，库存不足拒绝（`NEGATIVE_STOCK`），出清后余额归零；
  - 信用额度在审核与发货两个时点校验：`未结应收 + 本单金额 > 客户额度` 时阻断（额度 0 视为不限）；
  - 单个事务内完成「订单更新 + 库存流水/余额 + 应付或应收 + 凭证」；
  - 自动凭证按 `sourceType + sourceId` 幂等，重复调用返回既有凭证 ID；期间关账则拒绝。

### 2.3 权限脚本（`whale-service-auth-starter`）

- 新增 `migration-5.78-erp-scm.sql`：
  - 权限 420–424（采购 list/add/approve/receive/cancel）、426–430（销售 list/add/approve/ship/cancel）、
    431–432（库存 list/adjust），`INSERT ... WHERE NOT EXISTS` 幂等；425 预留；
  - 角色 25112 `erp_scm`，业务租户按 `MD5(tenant:role)` 复制；
  - 授权：`tenant_admin` / `erp_manager` / `erp_scm` 12 项；`erp_member` 420/426/431 只读；
    `erp_finance` 431（库存只读，便于成本核对）；
  - 菜单 79–81（`/erp/scm/purchase`、`/erp/scm/sales`、`/erp/scm/stock`）。

### 2.4 前端（`whale-frontend/platform-apps/whale-erp`）

- `api/scm.ts`：采购/销售/库存类型与查询、动作函数（`buildQuery` 统一分页串）；

## 4. 残余项与后续

| # | 残余 | 影响 | 建议 |
|---|---|---|---|
| R1 | 无独立收货单 / 发货单表 | 收货、发货以订单行累加 + 流水单据号体现，无法按「到货批次」追溯 | M2 剩余引入 `erp_scm_goods_receipt` / `_shipment` 头行表 |
| R2 | 采购申请、退货、销售报价、退货未实现 | 采购/销售链路只有正向单 | 独立切片，退货接红字凭证与库存回写 |
| R3 | 调拨、盘点、批次、安全库存、呆滞未实现 | 多仓协同与盘点差异凭证缺失 | M2 剩余（`stock-take`/`transfer` + 差异凭证） |
| R4 | 价格管理（价目表 / 供应商价格 / 最低售价）未实现 | 订单单价手工录入 | M2 剩余，与客户/供应商维度价目表 |
| R5 | 信用额度为「审核/发货时点校验」而非预占 | 并发下单可能超额占用 | 引入信用占用表或发货前二次校验 |
| R6 | 科目映射为配置文件默认值（D5 未定稿） | 不同准则需改配置而非改代码 | D5 确认后升级为「科目映射表 + 按业务类型/仓库」 |
| R7 | 实机冒烟未执行 | 网关路由与 auth 脚本未在真实库验证 | 部署环境执行两个迁移脚本后按脚本末尾校验 SQL 核对 |
| R8 | 多币种仅存字段，未做汇率换算 | 外币订单金额按原币入账 | 承接 M0+M1 R2 |

## 5. 结论

M2 第一阶段的「采购 → 收货 → 库存/应付/凭证」「销售 → 发货 → 库存/应收/凭证」两条主链路已经闭环，
库存流水只追加、禁止负库存、自动凭证借贷平衡与幂等均可独立验收；架构边界（SCM 只经 domain 端口访问
主数据、finance/masterdata 不反向依赖 SCM）由 ArchUnit 固化。

M2 剩余（财务扩展 + 退货/调拨/盘点/价格）建议先确认 D5 科目映射与 D6 计价方法是否扩展为 FIFO，
再拆分独立切片推进。
