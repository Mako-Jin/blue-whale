# 前端 / 后端国际化现状审计

- 日期：2026-11-19
- 范围：`whale-frontend` 全部前端应用、`whale-backend` 全部服务
- 结论：**前端完全没有国际化；后端只有 auth / file 两个服务带资源包，且错误响应链路未接入 MessageSource，实际等同未国际化。**

## 一、前端现状

| 项目 | 结论 | 证据 |
| --- | --- | --- |
| i18n 框架 | 未引入 | 全仓（排除 `node_modules`）未匹配到 `i18next` / `react-intl` / `vue-i18n` / `useTranslation` / `IntlProvider` |
| 语言包目录 | 不存在 | `whale-frontend/admin/src` 无 `i18n`、`locale`、`locales` 目录 |
| 文案 | 全部中文硬编码 | 页面、表单校验、提示语均为中文字面量（如 `RoleList.tsx` 的 `请输入角色编码`） |
| antd 语言 | 未设置 | [main.tsx](../../whale-frontend/admin/src/main.tsx) 只有 `AntdApp`，无 `ConfigProvider locale`，日期/分页等内置文案为 antd 默认英文 |
| 其他前端 | 同样未接入 | `platform-apps`（28 个应用）、`elemental/whale-ui`、`games`、`ops` 均无 i18n 依赖 |
| 仅有的“语言”痕迹 | 业务字段 / 本地化数字 | 视频、音乐模块的 `language` 字段；`UsageBoard` 的 `toLocaleString()`；生成的 API 类型含 `/auth/i18n/message`（后台无对应页面） |

**结论**：前端需要整体引入 i18n 方案，不是补几个页面即可。

## 二、后端现状

### 2.1 已有能力

`whale-i18n-sdk` 已具备完整基础设施：

- 三级回退 `MessageSource`：数据库（`sys_i18n_message`）> 属性文件 > 调用方默认值，未命中返回 code 本身；
- Redis 缓存 + 负缓存哨兵，Redis 断连自动降级直查数据库；
- 启动自动建表（`whale.i18n.auto-init`）与模块资源扫描（`classpath:i18n/<module>/messages*`）；
- 本地文案管理接口（`whale.i18n.admin.enabled`，默认关闭）。

### 2.2 已接入服务

| 服务 | 依赖 | 资源包 | 管理接口 |
| --- | --- | --- | --- |
| whale-service-auth | ✅ | `i18n/auth/messages{,_zh_CN,_en_US}.properties` | 开启（`/auth/i18n/message`） |
| whale-service-file | ✅ | `i18n/file/messages{,_zh_CN,_en_US}.properties` | 默认关闭 |

### 2.3 关键缺口

1. **错误链路未走 MessageSource**：[ErrorCode.java](../../whale-backend/whale-common/whale-common-core/src/main/java/com/bluewhale/common/core/exception/ErrorCode.java) 的消息是枚举里的中文常量；[GlobalExceptionHandler.java](../../whale-backend/whale-common/whale-spring-boot-starter/src/main/java/com/bluewhale/common/core/handler/GlobalExceptionHandler.java) 直接 `Result.fail(e.getCode(), e.getMessage())`，从未调用 `MessageSource#getMessage`。因此 auth/file 的资源包目前没有任何 Java 消费方，属于“有 SDK、无落地”。
2. **业务异常全部硬编码中文**：各服务大量 `new BizException(ErrorCode.XXX, "中文提示")`，无 code 化的提示 key。
3. **请求语言未透传**：未见 `LocaleContextHolder` / `Accept-Language` 解析逻辑，网关也未透传语言头。
4. **绝大多数服务未接入 i18n SDK**（无依赖、无资源包）。

### 2.4 未接入服务清单

**用户/管理端可见，建议优先接入**

- `whale-service-message`（发送、接收人组、归档等错误提示）
- `whale-service-workflow`、`whale-service-form`、`whale-service-job`
- `whale-service-gateway`（统一错误响应）
- `whale-im`、`whale-mail`、`whale-pay`、`whale-doc`、`whale-forum`、`whale-music`、`whale-video`
- `whale-map`、`whale-iot`、`whale-scene`、`whale-twin`、`whale-agent`、`whale-assistant`、`whale-archive`

**内部运维为主，可低优先级**

- `whale-ops`：`whale-audit`、`whale-monitor`、`whale-alert`

## 三、差距分级与建议顺序

| 级别 | 事项 | 说明 |
| --- | --- | --- |
| P0 | 打通错误响应 i18n 链路 | `ErrorCode` 增加 `messageKey`；`GlobalExceptionHandler` 注入 `MessageSource` 并按请求 Locale 解析；保留中文兜底 |
| P0 | 语言上下文透传 | 网关解析 `Accept-Language`（或 `X-Lang`）写入请求头，服务端 `LocaleContextHolder` 解析；异步线程显式传递 |
| P1 | 公共错误码资源包 | 在 common 提供 `i18n/common/messages*`，覆盖 401/403/404/参数错误等通用提示 |
| P1 | 管理端前端 i18n 框架 | 选定 `react-i18next`（或自研轻量字典），`ConfigProvider locale` 同步 antd；先做框架 + 登录/导航/通用组件 |
| P2 | 业务服务资源包 | message / workflow / form / job / im / mail / pay 等按服务建 `i18n/<module>/messages*`，业务异常改为 key |
| P2 | 前端页面分批迁移 | 按模块分批替换硬编码文案，保留中文为默认语言 |
| P3 | 运维服务 | audit / monitor / alert 视对外暴露程度再定 |

## 四、验收口径

- 请求头 `Accept-Language: en-US` 时，401/403/404/参数校验/业务异常返回英文；缺省返回中文；
- Redis 不可用、数据库不可用时仍能回退到属性文件并正常返回；
- 前端切换语言后，导航、表单校验、空态、分页等系统级文案即时生效；
- 新增服务接入 i18n 只需加依赖 + 资源包，不再改公共代码。
