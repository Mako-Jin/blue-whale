## 二、契约与交付物

### A-a/A-b · 实体、映射、节点解析与 DTO/VO（11 文件）

| 文件 | 说明 |
|---|---|
| `entity/ProcessInstance` | 继承 `BaseEntity`，`@TableName("process_instance")`；definitionId/definitionCode/definitionVersion/title/businessKey/status/currentIndex/initiator |
| `entity/ProcessTask` | 继承 `BaseEntity`，`@TableName("process_task")`；instanceId/nodeIndex/nodeName/assignee/status/comment |
| `mapper/ProcessInstanceMapper`、`mapper/ProcessTaskMapper` | 仅继承 `BaseMapper`（`com.bluewhale.**.mapper` 扫描） |
| `support/ProcessNodeParser` | 解析 `definition_json.nodes`（有序数组）为节点列表；缺失/非法/`assignee` 为空 → `PARAM_ERROR`「流程定义缺少有效审批节点」 |
| `dto/ProcessInstanceStartRequest` | definitionId/title 必填 + businessKey 可选 |
| `dto/ProcessInstanceQueryRequest` | 继承 `PageQuery`：title 模糊、status 等值、definitionCode 等值 |
| `dto/ProcessTaskQueryRequest` | 继承 `PageQuery`：assignee 等值、status 等值、instanceId 等值 |
| `dto/ApprovalRequest` | comment 可选（≤255），同意/驳回共用 |
| `vo/ProcessInstanceVO` | 契约字段 + `tasks`（仅详情填充） |
| `vo/ProcessTaskVO` | 契约字段 |

### B-a/B-b · 服务与接口（6 文件）

| 文件 | 说明 |
|---|---|
| `service/ProcessInstanceService(+Impl)` | `start`（建实例 status=0 + 首节点待办）/`getDetail`（含 tasks）/`page`（按 `create_time desc`，`MAX_PAGE_SIZE=200`）/`cancel`（仅运行中；待办全置「已取消」） |
| `service/ProcessTaskService(+Impl)` | `page`/`approve`（推进下一节点；末节点 → 实例「已通过」）/`reject`（实例「已驳回」+ 其余 PENDING 置「已取消」） |
| `controller/ProcessInstanceController` | `@RequestMapping("/workflow/instance")`，4 接口：POST 发起 / GET 分页 / GET `{id}` / POST `{id}/cancel`；发起接口经 `WebHeaders.username` 回填 initiator |
| `controller/ProcessTaskController` | `@RequestMapping("/workflow/task")`，2 接口：GET 分页 / POST `{id}/approve`、POST `{id}/reject` |

状态流转严格按 spec §3.4 实现：发起 `current_index=0` 生成首节点待办；同意 `current_index+1 >= nodes.size` → 实例通过，否则下标 +1 并生成该节点待办；驳回/撤销 → 实例终态 + 其余待办取消。

### C-a/C-b · DDL 与权限种子

| 项 | 结论 |
|---|---|
| `whale-workflow/db/init.sql` | 追加 `process_instance`（11 列，`idx_definition_id`/`idx_status`）、`process_task`（10 列，`idx_instance_id`/`idx_assignee`/`idx_status`）两表 |
| whale-auth `db/init.sql` | 追加 `sys:workflow:instance:start(44)/list(45)/cancel(46)`、`sys:workflow:task:list(47)/approve(48)`（承接 id 至 43） |

### C-c · 单测

- `ProcessInstanceServiceImplTest`（**8 用例**）：发起成功（断言实例字段 + 首节点待办 assignee/nodeIndex/status）、定义不存在 `404`、无有效节点 `400`「流程定义缺少有效审批节点」、详情含 tasks、详情不存在 `404`、撤销成功（断言 `status=3` + 待办取消 update 调用）、非运行中撤销 `400`「实例非运行中」、分页条件传递。
- `ProcessTaskServiceImplTest`（**6 用例**）：非末节点同意推进（断言新待办 assignee）、末节点同意实例通过（断言不再插入待办）、重复处理 `400`「任务已处理」、实例非运行 `400`「实例非运行中」、驳回（断言实例 `status=2` + 取消其余 update 调用）、分页条件传递。

## 四、缺陷与偏差

| 类别 | 内容 |
|---|---|
| 缺陷（Checkstyle，已修） | `ProcessNodeParser` 私有构造器缺 Javadoc → `MissingJavadocMethod` 报错；补 `/** 工具类不允许实例化 */` 后 `checkstyle:check` 0 违规 |
| 偏差（移除未用常量） | 实现中未引入多余常量（对齐 spec，无冗余状态机） |
| 偏差（构建） | 全量 `clean install` 需先释放运行中 7 个服务的 `target/*.jar` 锁 → 停 gateway/auth/job/workflow/form/file/audit 七进程，构建后 `Start-Process` 重启并核验健康 |
| 环境（缓存刷新） | 新增权限种子后，网关权限码头走 Redis 缓存键 `whale:cache:auth:user:perm:{userId}`；缓存未命中即回落 `/auth/me`（读 DB listAllCodes，含新种子），本轮以清空该缓存键 + 重新登录取得新权限码 |
