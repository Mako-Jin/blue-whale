## 3. 关键规则

| 规则 | 实现 |
|---|---|
| 仅 EBOM 可派生 | `derive` 检查 `source.view == EBOM` |
| 派生独立 | 派生 BOM 拥有独立 `bomNo/version/status` 与独立行，修改不影响源 EBOM |
| 派生幂等 | `sourceBomId + view` 最新为 `DRAFT` 时直接返回 |
| 派生升版 | 最新派生已发布/失效时，同 `bomNo` 升主版本并复制最新派生结构 |
| 对比范围 | 仅同一产品；按树路径（`1`、`1.1`）对齐 |
| 变更类型 | `ADDED / REMOVED / QTY_CHANGED / LOSS_CHANGED / UOM_CHANGED / PART_CHANGED` |
| 对比上限 | 任一 BOM 行数 > 2000 → 400，避免长事务与超时 |
| 导出 | 深度优先，根路径为空；父子层级由路径体现；不引入第三方依赖 |
| 权限 | 派生用 `bom:add`；对比用 `bom:list`；导出用 940 |

## 5. 风险与遗留

| 风险 | 影响 | 处置 |
|---|---|---|
| 对比仅同步、上限 2000 行 | 超大 BOM 无法在线对比 | M1B-2 异步任务：落任务表 + 轮询/通知，后续实现 |
| 派生不回写 EBOM | 符合边界，但 EBOM 变更后派生不会自动同步 | 后续可用「派生差异合并」或人工重建 |
| 导出未含供应商/价格 | M1B-3 验收中的供应商列依赖 M1B-5 | ERP 契约就绪后追加列 |
| 去重未实现 | 历史重复零件仍存在 | 需产品确认合并口径后实现，不自动合并 |
| 视图筛选依赖旧数据 | 存量 `pdm_bom.view` 若为空，列表按视图筛选会漏 | 迁移后核对存量数据，必要时补默认 `EBOM` |
| 前端导出按钮依赖 940 | 未执行权限迁移时用户看不到导出 | 上线前执行 `migration-5.80-pdm-bom-export.sql` |
