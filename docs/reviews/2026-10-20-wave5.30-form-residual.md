## 二、变更点

### 2.1 后端（whale-form）

- **B1/B2 列描述**：`support/FormDataEngine.java` + `support/impl/JdbcFormDataEngine.java` 新增 `Map<String,String> describeColumns(String table)`（`SELECT COLUMN_NAME, COLUMN_TYPE FROM information_schema.COLUMNS WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = ?`；表名走 `assertTable()` 白名单正则 `^form_data_[a-z0-9_]+_v[0-9]+$`，表不存在返回空 Map）。
- **B3 DDL 生成**：`support/FormTableDdlGenerator.java` 新增 `columnDef / alterAdd / alterModify / alterDrop / normalizeType / reservedColumns`；`generateFromColumns` 复用 `columnDef` 消除重复 DDL 拼接。
- **B4 发布语义**：`service/impl/FormPublishServiceImpl.java` 抽 `ensurePublished(table)`——`describeColumns` 为空 → `CREATE`；已存在 → 与 `information_schema` diff 后产出 `ADD/MODIFY/DROP`；`publishTableDefinition` 与 `publishMetadata` 均改走该方法（同版本重复发布 = 结构同步，不再报错）。
- **B4' DROP 护栏**：新增 `listMetadataCodes`，并将「元数据仍在（**含 `status=0` 停用列**）则不下发 DROP」的护栏并入 `applyAlter`（避免停用列被误判为「已删除」而下发 `DROP COLUMN` 造成物理列数据丢失）；被本表定义下表单视图启用字段引用的列，DROP 前由 `FormTableDefinitionServiceImpl.assertColumnNotReferenced` 前置拦截并返回 `PARAM_ERROR`（带表单名）。
- **B5 列合并**：`service/impl/FormTableDefinitionServiceImpl.java` `update()` 改走 `mergeColumns`——按 `columnCode` 命中 → `updateById`（保留列主键）并回写 `tableVersion`；未命中 → `insert`；载入但未出现在 DTO 中的列 → 逻辑删除。
- **B6/B7 导出支撑（新）**：`support/FormDataExportSupport.java`（纯 JDK `csv(headers, rows)` / `xlsx(sheet, headers, rows)`；XLSX 为最小 OpenXML：`[Content_Types].xml` + `_rels/.rels` + `xl/workbook.xml` + `xl/_rels/workbook.xml.rels` + `xl/worksheets/sheet1.xml`，单元格 `t="inlineStr"`）、`vo/FormDataExportVO.java`（`content / filename / contentType`）。
- **B8/B9 导出服务与接口**：`service/FormDataService.java` + `service/impl/FormDataServiceImpl.java` 新增 `export(request, tenantId, format)`（解析 `definitionCode` → 表单定义 `fields[]` → 主表分页取全 ≤ `EXPORT_MAX_ROWS=5000` → 动态列取 `dataJson`，无 N+1）；`controller/FormDataController.java` 新增 `GET /form/data/export` → `ResponseEntity<byte[]>` + `Content-Disposition`。
- **单测（3 文件）**：`FormTableDdlGeneratorTest`（+ALTER/columnDef/normalizeType/reservedColumns 用例）、`FormPublishServiceImplTest`（+7 个 `publishTableDefinition` 用例与 `shouldNotDropDisabledColumn`）、`FormTableDefinitionServiceImplTest`（+4 个 update 用例：保主键 / 新增列 / 被引用拦截 / 未引用删除）。
- **不做**：`FormMetadataCompiler` / `FormSchemaParser` / `schema_json` 结构 / 物理表公共列 / `init.sql`（本轮无 DDL 变更）。

### 2.2 前端（whale-form-designer）

- **C1 契约层**：`api/http.ts` 新增 `downloadBlob`（原始字节流 + `Content-Disposition` 文件名解析 + 401 续期重放一次）；`api/form.ts` 新增 `ExportFormat` 与 `formDataApi.export`。
- **C2 数据列表**：`pages/data/FormDataList.tsx` 新增「导出」`Dropdown.Button`（CSV / Excel）+ blob 下载 + 失败提示 + 无 `definitionCode` 时禁用并提示。
- **C3 表定义页**：`pages/table/TableDefinitionList.tsx` 列编辑区新增迁移语义 `Alert`（「列增删改只更新元数据，点『发布』后才对物理表执行 ALTER」）；发布成功文案改为「发布成功，物理表结构已同步」。
- **C4 设计器历史栈**：`pages/designer/FormDesigner.tsx` 新增 `past/future` ref + `historyVersion` state（上限 50）、统一 `commit()` 入口（拖入 / 排序 / 删除 / 属性补丁 / 切表清理入栈；加载回填不入栈并清空两栈）、撤销/重做按钮、`Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z`（`INPUT/TEXTAREA/SELECT/[contenteditable]` 内不劫持）。

### 2.3 本轮修复的两个真实缺陷

- **P1（列主键悬空）**：原 `FormTableDefinitionServiceImpl.replaceColumns` = `delete(wrapper)`（`@TableLogic` 逻辑删）+ 全量 `insert` → 列主键全变 → 既有表单视图 `form_field_config.column_meta_id` 全部悬空 → `FormMetadataCompiler.compile` 抛「字段配置关联的列不存在」。修复：改 `mergeColumns` 按 `columnCode` 就地合并保主键。**实机佐证**：编辑表定义后 `amount` 列元数据主键保留（见 §3.2 E1）。
- **停用列误删（`DROP COLUMN`）**：列编辑器暴露「状态」选择（`status=0` 停用），而发布只取 `status=1` 列 → 会把停用列当作「已删除」下发 `DROP COLUMN`（若被引用则丢数据）。修复：`applyAlter` 增 `metadataCodes` 判定，元数据仍在则不下发 DROP；`FormPublishServiceImplTest#shouldNotDropDisabledColumn` 覆盖。

## 四、风险与遗留

| 项 | 说明 |
|---|---|
| E6 拖拽手势自动化不可复现 | `@dnd-kit` `PointerSensor` 对合成/自动化指针事件不触发，真实指针拖入画布**未能自动验证**；本轮未改动 DnD 代码，判定无回归，**需人工复核**（与 Wave 5.29 同一限制） |
| ALTER MODIFY 存量数据不兼容 | 走「先校验后执行」（类型/长度已在 `FormDataType.mysqlType` 预检），MySQL DDL 隐式提交故失败原样透出 MySQL 文案；实机未见异常 |
| 导出上限与内存 | `EXPORT_MAX_ROWS=5000`，单次主表分页查询 + 解析 `dataJson`，超限截断；XLSX 为最小 OpenXML，仅保证 Excel/WPS 可打开 |
| 列重命名不做 | `columnCode` 视作物理列名，改名 == DROP + ADD，本轮不提供，避免误删数据 |
| 停用列语义 | 停用列（`status=0`）不在发布目标集合，但元数据仍在 → 不下发 DROP；其物理列在停用期间保留 |
