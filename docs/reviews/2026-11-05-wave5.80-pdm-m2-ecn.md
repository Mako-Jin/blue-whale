### 2.2 后端

- **ECN 服务**：`create` 校验 ECO 状态与生效日期；`update/delete` 仅 `DRAFT` 且不可更换来源；`notify` `DRAFT → NOTIFIED` 并发消息；`effective` 幂等、拒绝提前生效、按已完成任务作废更低版本序号的 `RELEASED` 文档/BOM 版本；`close` 仅已生效；`cancel` 仅草稿；`retryNotify` 重试最近失败投递；`dueNotices` 扫描 `NOTIFIED` 且到期，单批 100 条。
- **审批回调**：`PdmChgApprovalCallbackServiceImpl` 按 `approvalInstanceId` 依次查 ECO/ECR；状态相同直接返回；`APPROVED/REJECTED/WITHDRAWN` 流转并写追溯；未知实例静默忽略。
- **追溯**：`PdmChgTraceRecorder` 提供 `recordBiz`/`recordImpact`/`recordObject`，只 insert；ECR/ECO 的 create/update/submit/approve/reject/execute/任务完成/complete/cancel/close 与 ECN 全流程均写入。
- **生效任务**：`PdmChgEffectiveJob` 每日 `0 0 2 * * ?`（`pdm.change.effective-cron` 可覆盖），`@ConditionalOnProperty(pdm.change.effective-job-enabled, matchIfMissing=true)`；先抢 `pdm-change-effective` 锁，逐条生效，失败 `log.error` 并发告警消息，`tenantId` 缺失时回退 0。
- **通知**：`PdmChgMessageClient` 走 `/message/internal/send`，幂等键 `ECN:{id}:{event}`；成功与失败均落 `pdm_chg_notify_log`；投递异常不外抛，不影响事务。
- **控制器**：ECN 11 端点、追溯 2 端点、内网回调 1 端点；回调不带权限码，路径已在网关 internal-deny 内。

## 三、检查结论

| 检查项 | 结论 |
|---|---|
| 协议/接口 | 14 端点路径、方法、权限码与规格一致；保存/回调请求均带 `@Valid` |
| 代码漏洞 | 无跨租户直读；ECN 不可换来源；回调幂等；内网端点无权限码但网关拒绝外部访问 |
| 状态机 | 非法流转统一拒绝；生效对已生效幂等；关闭/取消来源状态收敛 |
| 事务边界 | 消息投递异常在服务内吞掉，只落日志；ECN 生效与旧版本作废同事务 |
| 并发 | 定时任务单实例由数据库行锁保证；通知幂等键唯一键兜底 |
| 魔法值 | 状态、事件类型、渠道、权限、编号前缀、扫描上限均为常量 |
| ArchUnit | VO 不依赖 entity；四层依赖规则全绿 |
| 测试 | 后端 **152 tests / 0 failures**；前端 lint/build 通过 |

- 真实库尚未执行 `V9` 与 `migration-5.80-pdm-ecn.sql`；前端未在运行环境联调。
- 旧版本作废依赖 ECO 任务的结果版本号，任务未登记版本号时跳过并告警。
- ECN 编号并发碰撞依赖唯一键兜底，后续可改为序列/发号器。
