## 二、变更点

### 2.1 后端（whale-form，最小必要）

- **B1 DDL**：`form_field_config` 新增 `col_span INT NOT NULL DEFAULT 24`（`sort_no` 之后）；同步 `init.sql` 与增量脚本 `db/migration-5.29.sql`。

### 2.2 前端（新应用 whale-form-designer）

- 骨架：`package.json` / `index.html` / `tsconfig.json` / `vite.config.ts`（8002，代理 `^/(auth|form)(/|$)` → 8080）；`api/{token,http,auth,form}.ts`（storage 前缀 `whale_fd_`）；`router/guards.tsx`；`layouts/AppLayout.tsx`；`pages/Login.tsx`；`main.tsx` / `App.tsx`。
- F4 `pages/table/TableDefinitionList.tsx`：查询/分页 + 列编辑器（复用列 id 整体替换）+ 发布 + 「新建表单视图」跳转。
- F5 `pages/form/FormList.tsx`：设计/发布/填报/数据/删除 + 「新建表单视图」（先建空定义 → 带 `tableDefinitionId` 跳设计器）。
- F6 `pages/designer/{FormDesigner,Palette,Canvas,PropertyPanel,FieldPreview}.tsx`：`DndContext` + `SortableContext` 三栏拖拽、12/24 栅格、布局字段、保存/发布/预览/回填 + 前置校验（≥1 数据字段、`columnCode` 不重复）。
- F7 `render/FormRenderer.tsx` + `render/FormRender.tsx`：受控渲染器（12/24 栅格）+ 填报页 + 序列化（`date→YYYY-MM-DD`、`checkbox→join(',')`、`switch→1|0`，空值不下发、纯布局字段不提交）。
- F8 `pages/data/FormDataList.tsx`：分页 + 详情 Drawer（`字段名: 值`）+ 删除。

### 2.3 关键缺陷修复（本轮实机 E2E 暴露，P0）

- **现象**：填报页 `/render/{id}` 报「表单不存在或加载失败」。
- **根因**：后端 `whale-common` 的 `JacksonConfig` 对 `Long` 统一走 `ToStringSerializer`，雪花 ID 在 JSON 中为**字符串**；前端契约层却把 ID 声明为 `number`，并在路由参数处 `Number(id)`，`2112355156699869186 > 2^53` 精度丢失为 `2112355156699869200` → 详情请求命中不存在的 ID（HTTP 404）。
- **验证**：经网关实测 `GET /form/definition/2112355156699869186 → code=0`，`GET /form/definition/2112355156699869200 → code=404`。
- **修复**：契约层新增 `export type Id = string`，`ColumnMeta.id`、`TableDefinition.id`、`FieldConfig.id/columnMetaId`、`FormDefinition.id/tableDefinitionId`、`FormDataItem.id/definitionId`、`FormDataSubmitParams.definitionId` 及全部 API 方法签名统一改为 `Id`；清除 `FormRender.tsx` / `FormDesigner.tsx` 中全部 `Number(id)` 与 `Number.isFinite` 判断，改为 `id ?? null` 与 `!== null` 判空。

## 四、风险与遗留

| 项 | 说明 |
|---|---|
| 拖拽手势未自动化验证 | `@dnd-kit` 的 `PointerSensor` 对合成 `pointerdown/move/up` 事件不触发（激活约束 distance 需真实指针），实机拖拽入画布**建议人工复核**；拖拽链路的排序/落点逻辑已由代码评审与类型检查覆盖，且「保存」后的持久化字段顺序经 API 级 E2E 验证正确 |
| 「+ 新增列」边界 | 设计器内不直接落库列（后端 `replaceColumns` 会重建列并更换列 ID），改为 Modal 提示后跳转 `/tables`；切换所属表定义会清理已放置数据字段（布局字段保留） |
| 新建表单视图两步式 | 受后端「带表定义且 fields 为空 → 400」约束，新建时先建空定义，再带 `?tableDefinitionId=` 进设计器，保存时 PUT 补齐元数据模型 |
| 共享列风险 | 同一表定义被多张表单视图共享（1:N）；「+ 新增列」仅追加列，不修改既有列 |
| 大 chunk 警告 | `vite build` 提示主 chunk > 500 kB（未做 code-split），不影响功能 |

## 五、结论

Wave 5.29 端到端闭环达成：后端最小补强（`col_span` + VO 回填）与前端独立应用（设计器/渲染填报/数据列表）均已落地并通过构建门禁、API 级 E2E 与浏览器实机 E2E。发现的 P0 缺陷（雪花 ID 精度丢失）已修复并复验通过。遗留项为拖拽手势的自动化验证，建议人工复核。
