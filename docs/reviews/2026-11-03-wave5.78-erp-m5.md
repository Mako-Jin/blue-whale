## 1. 交付结论

| 范围 | 结论 | 说明 |
|---|---|---|
| 检验单 | ✅ **已落地** | `IQC/IPQC/FQC`，来源 `PURCHASE_RECEIPT/PRODUCTION_ORDER/MANUAL`；`DRAFT→INSPECTING→PASSED/FAILED`，旁支 `CANCELLED`；单号 `QC-yyyyMMdd-%04d` |
| 检验项录入 | ✅ **已落地** | 行项按 `lineNo` 匹配，全项录入结论后才允许判定；缺项判定抛 `INSPECTION_ITEM_INCOMPLETE(40019)` |
| 判定与 NCR | ✅ **已落地** | 任一 `FAIL` → 整单 `FAILED`；按 `sourceType=INSPECTION + sourceNo` 幂等生成 NCR 并回写 `ncr_id`；重复判定被状态机拒绝 |
| 不合格品处置 | ✅ **已落地** | `OPEN→DISPOSED→CLOSED`；`REWORK/CONCESSION/SCRAP/RETURN`；单号 `NCR-yyyyMM-%04d` |
| 质量成本 | ✅ **已落地** | 处置有金额才登记；`SCRAP→报废成本`、其余→`返工成本`；单号 `QCOST-yyyyMM-%04d`；仅分页查询 |
| 设备档案 | ✅ **已落地** | 设备编码租户内唯一；`RUNNING/IDLE/DOWN/RETIRED`；新增与按编码编辑 |
| 保养计划/工单 | ✅ **已落地** | 计划周期（天）推算下次日期；工单完成回写计划 `lastDate=完成日`、`nextDate=完成日+周期`；不可重复完成、不可早于计划日 |
| OEE | ✅ **已落地** | `(tenant, equipment_no, record_date)` 唯一键 upsert；时间/性能/合格率封顶 1，OEE 4 位 HALF_UP；退役设备拒绝回传 |
| 量具与校准 | ✅ **已落地** | 量具编号唯一、按周期推算下次校准；`PASS` 才回写量具日期并顺延计划，`FAIL` 不改日期 |
| 过期量具拦截 | ✅ **已落地** | 创建检验单绑定量具时校验「存在 + ACTIVE + `nextCalibrationDate ≥ inspectDate`」，否则 `TOOL_EXPIRED(40930)` |
| 前端 | ✅ **已落地** | 检验与不合格品、设备与保养、量具与校准三页合并页签；基座 `/erp` 菜单增至 21 项 |
| 权限/菜单 | ✅ **已落地** | 权限 475–494、角色 25115 `erp_qc`、菜单 91–93 |
| SPC/FMEA/供应商质量绩效/追溯/备件派工/MES 自动采集 | ⏸ **未开始** | 见 §4 残余项 |

## 2. 变更清单

  - `erp_qc_ncr`（`uk_qc_ncr_no`；`disposition`、`status`、`cost_amount DECIMAL(18,2)`）；

  - `erp_qc_measuring_tool`（`uk_qc_tool_no`；`calibration_cycle_months`、`last/next_calibration_date`）；

  `EquipmentAppServiceImpl`、`MetrologyAppServiceImpl`）；
- `infrastructure`：11 个实体、11 个 Mapper、7 个仓储实现（单号 `QC-yyyyMMdd-%04d`、`NCR-yyyyMM-%04d`、
  `QCOST-yyyyMM-%04d`、`MT-yyyyMM-%04d`、`MTW-yyyyMM-%04d`、`CALP-yyyyMM-%04d`、`CALR-yyyyMM-%04d`，均以 count+1 生成）；

  `QcMetrologyController`（`/erp/qc/metrology`），`@RequirePermission` + `@AuditLog`；
- `common`：`ErpErrorCode` 增 `QC_INVALID(40018)`、`INSPECTION_ITEM_INCOMPLETE(40019)`、`NCR_DISPOSITION_REQUIRED(40020)`、
  `OEE_PARAM_INVALID(40021)`、`INSPECTION_NOT_FOUND(40423)`、`NCR_NOT_FOUND(40424)`、`EQUIPMENT_NOT_FOUND(40425)`、
  `MAINTENANCE_PLAN_NOT_FOUND(40426)`、`MAINTENANCE_ORDER_NOT_FOUND(40427)`、`TOOL_NOT_FOUND(40428)`、
  `CALIBRATION_PLAN_NOT_FOUND(40429)`、`QC_STATE_CONFLICT(40926)`、`INSPECTION_ORDER_NO_CONFLICT(40927)`、
  `EQUIPMENT_CODE_CONFLICT(40928)`、`TOOL_CODE_CONFLICT(40929)`、`TOOL_EXPIRED(40930)`、`NCR_ALREADY_EXISTS(40931)`；
- 关键规则：
  - 建单要求检验类型/来源单据号/物料/数量/检验日期必填，数量非负；物料须存在且启用；
  - 录入按 `lineNo` 覆盖，已判定/取消单拒绝录入；全项有结论才可判定，判定后不可修改；
  - 判定 `FAILED` 时幂等创建 NCR（`QC-yyyyMMdd` 单号 + `sourceType=INSPECTION`），已存在则复用并回写；
  - NCR 仅 `OPEN` 可处置、仅 `DISPOSED` 可关闭；处置方式必填；有金额自动派生质量成本（`SCRAP→SCRAP`、其余→`REWORK`）；
  - 设备编码唯一；保养计划关联设备必须存在；工单完成日期不得早于计划日，已完成不可重复完成；
  - OEE 参数校验：计划分钟与理论产量 > 0、运行 ≤ 计划、合格 ≤ 实际产量（`OEE_PARAM_INVALID`）；三率封顶 1；
  - 量具编号唯一；校准记录须与量具/计划匹配（`QC_INVALID`）；`PASS` 才 `calibrated(date)` 并 `plan.advance(date)`。

## 5. 结论

M5 第一期把「检验建单 → 检验项录入 → 判定 → 不合格品处置 → 质量成本」与「设备档案 → 保养计划 → 保养工单 → OEE」
以及「量具台账 → 校准计划 → 校准记录」串成闭环。验收关注点均有实现落点：检验项未完成不可判定、不合格必生成 NCR、
校准过期量具不可检验、OEE 同设备同日期幂等；质量成本与保养日期分别由处置与工单完成单一入口派生，避免双写不一致。
QC 四层通过 3 个控制器暴露 29 个端点，ArchUnit 新增 4 条边界规则并全绿，前端三页已接入基座菜单与独立权限码。

建议下一步先在真实环境执行 `V7__qc.sql` 与 `migration-5.78-erp-qc.sql` 做冒烟，再按 AQL/SPC 与 MES 采集需求
扩展质量与设备能力，避免检验项与 OEE 表结构返工。
