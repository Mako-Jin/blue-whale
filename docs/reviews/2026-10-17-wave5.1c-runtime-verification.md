# 运行时验证报告 — Wave 5.1c · Redis / MySQL 实机验证

- 关联需求：REQ-SEC-002 / REQ-SEC-004（令牌黑名单，含 refreshToken）｜REQ-DIST-002（分布式锁）｜REQ-SEC-001（审计日志）
- 关联任务：T5.2（分布式锁）｜T5.10 / T5.11 / T5.12（审计注解+切面+脱敏+查询）
- 验证日期：2026-10-17 ｜ 执行人：BlueWhale

## 三、发现的问题与处置

| # | 问题 | 定位 | 级别 | 处置 | 复验 |
|---|---|---|---|---|---|
| 1 | **服务在 Spring Boot 4.0.8 下无法启动**：`redisson-spring-boot-starter-3.34.1` 的 `RedissonAutoConfiguration(V2)` / `PropertiesRedisConnectionDetails` 引用 Boot 3 时代的 `org.springframework.boot.autoconfigure.data.redis.RedisProperties`（Boot 4 已迁移至 `spring-boot-data-redis` 模块的新包），Spring 解析 `@EnableConfigurationProperties` 时抛 `IllegalArgumentException: Could not find class [...]` → `Caused by: java.lang.ClassNotFoundException: org.springframework.boot.autoconfigure.data.redis.RedisProperties` → `Application run failed`。以 `--spring.autoconfigure.exclude=…RedissonAutoConfiguration(V2)` 绕过亦失败（该类因元数据不可解析而未被登记为自动配置，启动报 `IllegalStateException: The following classes could not be excluded because they are not auto-configuration classes`） | `whale-parent/pom.xml` 依赖管理 `redisson-spring-boot-starter:3.34.1`；受影响模块 `whale-auth`、`whale-audit`、`whale-pay`（各自 pom 直接引入） | **P0** | **未修复**（第三方依赖与框架大版本不兼容，需选型决策：升级至支持 Boot 4 的 Redisson 版本 / 改用 `redisson` 裸库 + 自建 `RedissonClient` 装配（与既有 `LiveDistributedLockIT` 直连方式一致）/ 移除 starter 自动配置） | 阻塞，见第四节 |
| 2 | **生产数据源 URL 的 `characterEncoding=utf8mb4` 会被 Connector/J 拒绝**：`java.io.UnsupportedEncodingException: utf8mb4` → `SQLException: Unsupported character encoding 'utf8mb4'`（`utf8mb4` 是 MySQL 字符集名，不是 Java 字符集名，须写 `UTF-8`） | `whale-auth/src/main/resources/application.yml#L11`、`whale-audit/src/main/resources/application.yml`（datasource.url） | **P1** | **未修复**（属生产配置，按任务约束不在本轮改动；测试侧改用 `UTF-8` 后通过） | 未复验（需改配置） |

| 4 | **任务书所述 3306 凭据 `root/root` 不可用**：`SQLException: Access denied for user 'root'@'localhost' (using password: YES)`（已排除空口令及 20+ 常见口令；无 `.env`、无 `MYSQL_*` 环境变量、`D:\mysql8\my.ini` 为空、无 `.mylogin.cnf`） | 本机 3306 实例认证失败（该实例已存在 `yc-sts-db-auth` / `yc-sts-db-flow` 两个他项目库） | **P2（环境）** | **改用自建临时实例**：以同版本 `mysqld --initialize-insecure` 在 `%TEMP%\bwmysql\data` 建独立实例，监听 **127.0.0.1:3307**（`--mysqlx-port=33070`、`--skip-log-bin`），并将 root 口令设为 `root`；**未删除/未改动 3306 实例及其数据**，测试通过 `-Dwhale.live.mysql.port=3307` 覆盖 | 已通过（本报告全部 MySQL 结论基于 3307 实例） |

## 五、与既有「仅静态验证」结论的差异

1. **从「无中间件」到「有中间件」**：Wave 5.0/5.1/5.1b 的三份报告均标注「本机无 Docker → 运行时/端到端未验证」。本轮以**本机 Redis 5.0.14.1 + MySQL 8.0.45（自建 3307 实例）**首次取得真实运行时证据，审计落库、审计分页、令牌黑名单、分布式锁四项从「mock 单测通过」升级为「真实中间件通过」。
2. **「待中间件就绪即可端到端」的假设被证伪**：真正的服务级端到端阻塞点**不是**中间件缺位，而是 **P0 的框架/依赖不兼容**（Redisson Starter 3.34.1 ←→ Boot 4.0.8）。此前 devlog §14 将「运行时未验证」归因于无 Docker，需要修正为「① 依赖不兼容（P0，先决）② 中间件（Nacos 缺位）」。
3. **新增两个此前静态检查未发现的 P1**：生产数据源 URL `characterEncoding=utf8mb4`（Connector/J 直接拒绝）与种子 admin 口令与注释不符 —— 二者都不可能在「编译 + 单测 + Checkstyle」阶段暴露。
4. **新增可复用的门控实时测试资产**：4 个 `live` 包测试类默认不参与 CI，`-Dwhale.live.it=true` 一键拉起即可在任一具备 Redis/MySQL 的机器上复现本报告全部结论（含 3307 覆盖能力）。
5. 未变化项：Wave 5.1b 的 57 项静态检查结论与「网关路由前缀冲突（P1）」仍成立，本轮未新增证据，亦未推翻。
