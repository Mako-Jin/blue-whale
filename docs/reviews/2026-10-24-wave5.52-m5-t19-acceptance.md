## 四、本轮修复（联调中发现）

| # | 问题 | 修复 |
|---|---|---|
| 1 | Redis 5.0.14.1 不支持 `GETDEL`（需 ≥6.2），ticket 消费抛异常导致 WS 握手 401 | `WsTicketService` 改为 Lua 脚本 `GET`+`DEL` 原子消费；`WsTicketServiceTest` 同步改为 `execute(RedisScript, keys)` 桩并新增异常失败关闭用例 |
| 2 | Spring Cloud Gateway 的 WebSocket 路由先与客户端完成 101 再连后端，无 ticket 也能升级 | 新增 `ImWsTicketGuardGlobalFilter`（order −95），升级前校验 `ticket`，缺失/空白返回 401；4 例单测覆盖 |
| 3 | qiankun 拉取入口时 `Accept: */*`，vite 代理把 `/im/` 与静态资源转发到网关 → 401 白屏 | `whale-im` vite 代理改为「仅 `/im/conversations`、`/im/agent-runs`、`/im/ws-ticket`、`/im/ws` 走网关，其余 `/im` GET 一律旁路 vite」 |
| 4 | 基座代理未开 `ws: true`，子应用在 8000 端口下的 `/im/ws` 握手失败 | `whale-platform` vite 代理统一加 `ws: true` |
| 5 | `data_query` 在 SQL 层直接 `LIMIT maxRows`，`truncated` 永远为 false | `DataQueryService` 改为取 `maxRows+1` 判定截断后再裁剪，最终仍 ≤200 行；单测断言同步 |
