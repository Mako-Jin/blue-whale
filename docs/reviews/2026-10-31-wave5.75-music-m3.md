## 2. 完成项

### 2.1 领域层

- `Playlist`（歌单聚合根）：`addSong`（幂等 + 500 首上限 + `PLAYLIST_SONG_LIMIT`）、`removeSong`（幂等 + 重编号）、`reorder`（ID 集合必须与歌单内一致，缺失 / 多余 / 重复均拒绝）、`rename`（标题非空且 ≤ 120 字符）、`assertOwnedBy`（非所有者拒绝）、`visibleTo`（公开或所有者可见）。
- `PlaylistSong`（歌单歌曲值对象）、`PlaylistType`（USER / OFFICIAL）、`PlaylistVisibility`（PUBLIC / PRIVATE）、`PlaylistQuery`（分页查询条件）。
- 3 个端口：`PlaylistRepository`、`HomeCacheRepository`、`PlayCountRepository`。
- `MusicErrorCode` 新增歌单相关错误码：`PLAYLIST_SONG_INVALID`、`PLAYLIST_SONG_LIMIT`、`PLAYLIST_SONG_ORDER_INVALID`、`PLAYLIST_TITLE_INVALID`、`PLAYLIST_NOT_OWNED`（40405）等。

### 2.2 基础设施层

| 组件 | 说明 |
|---|---|
| `PlaylistRepositoryImpl` | 歌单分页支持关键词、类型、可见性、所有者过滤；歌单详情装配歌曲列表（按 `sort_no` 升序）；写操作走 `@Transactional` |
| `PlaylistMapper` / `PlaylistSongMapper` | `mu_playlist` / `mu_playlist_song` 基础 CRUD；`mu_playlist_song` 唯一键 `uk_playlist_song(playlist_id, song_id)` 保证加歌幂等 |
| `RedisHomeCacheRepository` | key `whale:music:cache:home:{tenantId}`，TTL 60s + 0–10s 随机抖动；`find` / `save` / `evict` |
| `RedisPlayCountRepository` | key `whale:music:play:count:{songId}`；`increment` 执行 `INCR`；`drain` 通过 `SCAN` + `GETDEL` 原子取出全部增量，回刷期间新增量不丢失 |

### 2.3 应用层

| 能力 | 说明 |
|---|---|
| `PlaylistAppServiceImpl` | 用户歌单 CRUD + 加歌 / 移除 / 重排（全部 `@Transactional`，DB 行锁保证并发安全）；官方歌单由 `createOfficial` / `updateOfficial` / `deleteOfficial` / `addSongAsOperator` / `removeSongAsOperator` / `reorderAsOperator` 承载，强制 `ownerId=0`、`type=OFFICIAL`、`visibility=PUBLIC` |
| `DiscoverAppServiceImpl` | `home`（租户级缓存，命中反序列化，失败回源）、`hotChart`（`play_count DESC, like_count DESC, id DESC`）、`newChart`（`published_at DESC, id DESC`）、`search`（按类型分发歌曲 / 歌手 / 专辑 / 歌单，空关键词返回稳定空结果） |
| `PlayCountFlushScheduler` | `@Scheduled(cron = "0 */5 * * * ?")`，每 5 分钟 `drain` Redis 增量并 `addPlayCount` 累加回 `mu_song.play_count`，避免高并发 `UPDATE` 行锁热点 |

### 2.4 接口层

| 控制器 | 端点 | 权限 |
|---|---|---|
| `PlaylistController` | `POST/PUT/DELETE /music/playlist`、`GET /music/playlist/page`、`GET /music/playlist/{id}`、`POST/DELETE /music/playlist/{id}/song`、`PUT /music/playlist/{id}/sort` | `sys:music:playlist:own`（用户自建） |
| `OfficialPlaylistController` | `POST/PUT/DELETE /music/playlist/official`、`GET /music/playlist/official/page`、`POST/DELETE /music/playlist/official/{id}/song`、`PUT /music/playlist/official/{id}/sort` | `sys:music:playlist:manage`（运营） |
| `DiscoverController` | `GET /music/home`、`GET /music/chart/hot`、`GET /music/chart/new`、`GET /music/search` | `sys:music:browse` |

- 私有歌单跨用户访问返回 `40405`（不暴露存在性）；官方歌单普通用户写操作返回 `403`（`ErrorCode.FORBIDDEN`）。
- 搜索只返回已发布（`PUBLISHED`）且公开（`PUBLIC`）的歌曲，符合 R7 / R9 可见性规则。

## 3. 已修正问题项

| # | 问题 | 处理 |
|---|---|---|
| 1 | 冒烟脚本 `Invoke-Api`（`lib/common.ps1`）发送 JSON 时未指定 `charset=utf-8`，中文标题（如「M3冒烟歌曲」）被存为 `????`，导致搜索命中失败 | `Invoke-Api` 改为 `ContentType = 'application/json;charset=utf-8'` 且 Body 转 `UTF8.GetBytes(json)`，与 `Invoke-SmokeApi` 对齐 |
| 2 | M3 冒烟脚本 `9.officialForbidden` 断言 HTTP 状态 403，但平台统一返回 HTTP 200 + body `{"code":403}`（`GlobalExceptionHandler` 对 `BizException` 不设 HTTP 状态） | 断言改为 `Status -eq 403 -or BodyText -match '"code":403'`，与 `9.officialReadonly` 口径一致 |
| 3 | M3 冒烟脚本 `10.deleteFile` 用 `Invoke-MusicApi` 调 `/file/{id}`，请求被发到 whale-music（8096）而非 whale-file（8085），返回 500 | 改用 `Invoke-Api -Uri "$fileBase/file/$fileId"` 直连 whale-file |
| 4 | M3 冒烟脚本首行 UTF-8 BOM 导致 PowerShell 5.1 报 `﻿#` 未识别（非致命，脚本继续执行） | 保留 BOM（与 M2 脚本一致，Windows 下需 BOM 正确解码中文），首行注释不影响执行 |
