## 2. 排障记录：/auth/me 400（PermCode 校验）

### 现象

登录 `code=0`，`GET /auth/me` 恒 400「权限码须为冒号分隔的小写段落且至少两段」。

### 定位过程

1. 日志时序：user → user_role → role → permission（142 行）查询返回后立即抛错，菜单查询未执行 → 异常在 `PermissionAppService.listAllCodes()` 的流式映射内。
2. `PermCode.of` 生产读路径唯一调用点为 `PermissionPersistenceAssembler.toDomain`（whale-auth）。
3. 关键坑：MySQL 8 `REGEXP` 在 `utf8mb4_0900_ai_ci` 排序规则下**不区分大小写**，此前全量校验漏掉驼峰码；`NULL NOT REGEXP` 结果为 NULL 也会漏掉 NULL 行。
4. 改用 `... NOT REGEXP '...' COLLATE utf8mb4_bin` 后命中 2 行：`sys:user:resetPwd`（id=23）、`sys:workflow:definition:bpmnImport`（id=59）。

### 修正清单

|---|---|
| `whale-auth/db/init.sql` | id 23 → `sys:user:resetpwd`；id 59 → `sys:workflow:definition:bpmnimport`；id 78 → `sys:workflow:task:addsign`（前一日） |
| `whale-auth/db/migration-5.56.sql` | 新增：id 23/59 幂等 UPDATE |

兼容性：`sys_role_permission` 按 `permission_id` 外键关联，改码不影响存量角色授权；REST 路径不变。

## 3. 遗留与建议

- `PermCode` 值对象与 DB 种子无自动对账机制；建议在 CI 增加「init.sql 权限码 vs PermCode 正则」静态校验（可用区分大小写的 grep 规则），防止驼峰/连字符码再次入库。
- 已知自动化限制不变：@dnd-kit 拖拽手势仍需人工复核（E2E 未覆盖画布拖拽）。
