## 2. 变更清单

### 2.1 `whale-scene` 后端（`backend/whale-services/whale-scene`，72 个文件）

- DDD 四层 + Ports & Adapters：`domain` / `application` / `infrastructure` / `interfaces`，ArchUnit 4 条规则；
- 聚合与规则：`Scene` 状态机、节点树、入口绑定、可见性（DENY 优先 / ALLOW 白名单 / 子树隐藏）、发布快照（JSON + SHA-256）；
- 入口 URL 安全：协议白名单、拒绝 `javascript:` / `data:` / `//` / 内网 / userinfo 开放重定向；
- Flyway `V1__baseline.sql`：5 张业务表 + `audit_log` / `api_log`；幂等种子场景 `bluewhale-city`、节点 5101–5104、入口 OA/ERP/DOC；
- 13 个对外端点（含 `/scene/meta`、`/scene/navigation`、`/scene/page`、发布/下线、节点/绑定/可见性）。

### 2.2 `whale-crm` 门禁骨架（`backend/whale-apps/whale-crm`，10 个文件）

- `WhaleCrmApplication` + `CrmProperties`（`demand-gate-passed=false`）；
- `GET /crm/meta`：返回门禁状态、说明、里程碑与边界，不触碰任何业务表；
- Flyway `V1__baseline.sql`：4 张业务表 DDL + 审计/API 日志，**无业务种子**；
- ArchUnit 3 条（domain/application 门禁前允许空集）。

### 2.3 注册与接入

- `backend/whale-services/pom.xml` + `backend/whale-apps/pom.xml` 模块登记；
- 网关：`whale-scene` / `whale-crm` 路由（不配 `StripPrefix`）+ internal-deny `/scene/internal/**`、`/crm/internal/**`；

## 4. 与规划的差异（已实现为准）

| # | 差异 | 原因 |
|---|---|---|
| 1 | 增加 `GET /scene/page` 与 `PUT /scene/{id}/node/{nodeId}` | 管理列表需要分页；节点编辑需要独立接口 |
| 2 | 下线使用 `sys:scene:offline` | 避免发布权限隐含下线能力（最小权限） |
| 3 | 可见性请求体为 `{ rules: [...] }` | 集合 Bean Validation 需要外层包装 |
| 4 | CRM 权限 337–354 已登记但**菜单 57–62 未注册** | 严格遵守需求门禁，避免“可见即 403”的空入口 |
| 5 | 前端增加登录即可见的「2D 导航」菜单 | 导航不需要 `sys:scene:list`；与后端菜单 53 的“登录可见”口径一致 |
| 6 | 场景统计 `/scene/{id}/stats` 未提供 | 属 M3 可选项，本波不做 |
