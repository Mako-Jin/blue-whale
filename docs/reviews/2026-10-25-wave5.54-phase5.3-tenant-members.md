## 二、检查结果

| 类别 | 检查项 | 结论 | 证据 |
|---|---|---|---|
| 租户隔离 | 成员列表只取当前租户启用关系 | 通过 | `listEnabledUserIds(TenantContext.requireId())`；单测 `listMembers` |
| 租户隔离 | 角色分配只影响本租户 | 通过 | `roleRepository.countByIds`（仓储层租户过滤）+ `replaceRoles` 只重建本租户角色行 |
| 越权防护 | 非成员分配角色 | 通过 | 404「成员不存在或关系已停用」；单测 `assignMemberRolesShouldRejectNonMember` |
| 越权防护 | 跨租户角色 ID | 通过 | 400「存在无效的角色ID」；单测 `assignMemberRolesShouldRejectForeignRole` |
| 平台专属 | 绑定/解绑仅平台租户 | 通过 | `tenantAppService.requirePlatformTenant()`；权限 `sys:user:tenant` 不随租户模板下发 |
| 不变量 | 首页租户关系禁删 | 通过 | `tenantId.equals(user.getTenantId())` → 400；单测 `unbindTenantShouldRejectHomeRelation` |
| 幂等 | 重复绑定 / 已停用关系恢复 | 通过 | `ensureEnabled` 复用（存在则启停切换，不存在则插入） |
| 缓存 | 角色/关系变更后权限缓存失效 | 通过（2026-10-27 修订） | 统一发布带目标租户的 `UserDomainEvent(ROLES_ASSIGNED)`，监听器按 `(tenantId,userId)` 清理；原按当前租户失效的缺口见 [P1 #7](2026-10-27-p1-7-auth-cache-after-commit-membership.md) |
| 事务 | 多写操作 | 通过 | 分配/绑定/解绑均 `@Transactional(rollbackFor = Exception.class)` |
| 协议安全 | 不信任客户端租户身份 | 通过 | 租户 ID 全部取自 `TenantContext`（网关可信头），绑定目标租户由平台侧显式入参并校验可用性 |
| 审计 | 敏感写操作留痕 | 通过 | 三个端点 `@AuditLog`（GRANT / DELETE），不记录敏感参数 |
| 圈复杂度 | 新增方法 | 通过 | 最长 `assignMemberRoles` 分支 4，无需拆分 |
| 规范 | 注释与命名 | 通过 | Checkstyle `validate` 门禁 EXIT=0；Javadoc 完整 |
| 规范 | 前端 `console` / 严格模式 / ESLint | 通过 | `tsc -b` + `vite build` + `eslint --max-warnings 0` 均 EXIT=0 |

## 四、待做项与已知边界

- **5.4 双租户 E2E**：切换前后 `userId` 不变、两租户角色/数据隔离、旧令牌 401、解绑后 refresh 401；需 Redis/Nacos/MySQL 与双租户数据。
- 存量租户的 `tenant_admin` 未自动补授 165/166（遵循迁移不写 `sys_role_permission` 的约定），需平台在角色分配界面补授；新开通租户由 `TenantProvisioningAppService` 自动带上。
- 迁移脚本只为租户 1 插入菜单 17；新开通租户由菜单模板复制获得，存量其他租户需按租户补插（当前环境尚无业务租户）。
- 解绑关系在平台租户上下文执行，权限缓存 Key 为 `(tenantId, userId)`；已由 [P1 #7](2026-10-27-p1-7-auth-cache-after-commit-membership.md) 补齐目标租户显式失效与 AFTER_COMMIT 二次延迟问题（MT-09 已关闭）。解绑不撤销已签发令牌、不删除 `sys_user_role`，见 P1 #7 边界。
