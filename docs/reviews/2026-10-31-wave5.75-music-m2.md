## 2. 完成项

### 2.1 领域层

- `PlayTicket`（票据值对象）：`toValue()` 序列化为 `tenantId|userId|songId`，`parse()` 严格校验三段可解析，`matches()` 三要素比对。
- `PlayHistory`（进度 / 最近播放）、`AudioStream`（状态码 + 长度 + `Content-Range` + 类型 + `ETag` + `InputStream`）。
- 4 个端口：`PlayTicketRepository`、`PlayHistoryRepository`、`SongLikeRepository`、`AudioContentRepository`。
- `MusicErrorCode` 新增 `PLAY_PROGRESS_INVALID = 40009`、`PLAY_TICKET_INVALID = 40302`。

### 2.2 基础设施层

| 组件 | 说明 |
|---|---|
| `RedisPlayTicketRepository` | key `whale:music:play:ticket:{ticket}`，值三要素，TTL 取 `whale.music.play-ticket-ttl-seconds`（默认 120）；有效期内可复用（浏览器一次播放会发多个 Range 请求） |
| `FileAudioContentClient` | JDK `HttpClient` + `BodyHandlers.ofInputStream()` 流式转发，避免整包缓冲；转发 `Range` / `If-Range` / `X-Tenant-Id` / `X-Internal-Token`；416 关闭流并回传 `bytes */size` 的 total；非 200/206/416 映射 404 或系统异常 |
| `PlayHistoryRepositoryImpl` / `SongLikeRepositoryImpl` | 进度「先查后改 / 插入」保证幂等（不依赖唯一键也能正确），分页按 `played_at DESC, id DESC`；收藏以雪花 ID 逆序即收藏时间序 |
| `PlayHistoryEntity` / `SongLikeEntity` | 两表无 `update_time` / `deleted` 列，故不继承 `BaseEntity`，仅 `@TableId(ASSIGN_ID)` |
| `SongMapper#addLikeCount` | `GREATEST(like_count + delta, 0)`，避免负数 |

- `mu_play_history` 增加 `UNIQUE KEY uk_mu_history_user_song (tenant_id, user_id, song_id)`，双保险防重复进度行。

### 2.3 应用层

| 能力 | 说明 |
|---|---|
| `issueTicket` | 先校验歌曲可播，再签发 32 位随机票据，视图只回 `streamUrl = /music/stream/{songId}?ticket=...`（不含 `file_id`），携带歌词文本 |
| `openStream` | 票据缺失 / 不存在 / 三要素不匹配 → `40302`；**每次流式请求复核歌曲 `playable()`**，版权下架可即时阻断（强于「等票据过期」） |
| `reportProgress` / `recentHistory` | 进度上报幂等，最近播放分页装配歌曲视图并标注 `playable` |
| `like` / `unlike` / `myLikes` | 幂等增删并同步 `like_count`；我的收藏按可见性过滤 |
| `PlayHistoryCleanupScheduler` | `@Scheduled(cron = "0 0 3 * * ?")`，按 `whale.music.play-history-retention-days`（默认 90）清理 |

### 2.4 接口层

| 控制器 | 端点 | 权限 |
|---|---|---|
| `PlayController` | `POST /music/play/ticket`、`POST /music/play/progress`、`GET /music/play/history`、`POST|DELETE /music/song/{id}/like`、`GET /music/my/likes` | `sys:music:browse` / `sys:music:like` |
| `MusicStreamController` | `GET /music/stream/{songId}?ticket=...` | 票据 + 网关注入身份头 |

- 流式响应统一 `Accept-Ranges: bytes`、`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`、`Content-Type`、`ETag`；416 回 `Content-Range: bytes */total` + `Content-Length: 0` 且无响应体。
- 缺票据时不再由框架抛缺参异常（见 §3 #1），改由应用层统一返回 `40302`。

## 3. 已修正问题项

| # | 问题 | 处理 |
|---|---|---|
| 1 | 冒烟发现 `GET /music/stream/{songId}` 不带 `ticket` 时由 Spring 抛 `MissingServletRequestParameterException`，被兜底处理器转为 `code:500`，与「票据缺失一律 40302」口径不符 | `@RequestParam(required = false)`，交由 `openStream` 判定并返回 `40302` |
| 2 | `mu_play_history` 无 `(tenant,user,song)` 唯一键，进度天然可能多行 | DDL 增加唯一键；仓储仍用「先查后改 / 插入」，兼容 M1 已建库 |
| 3 | 进度 / 收藏两表无 `update_time` / `deleted`，实体继承 `BaseEntity` 会写不存在的列 | 两个实体不继承 `BaseEntity`，仅声明 `@TableId(ASSIGN_ID)`，`create_time` 交给 DB 默认值 |
| 4 | 冒烟脚本在 Windows PowerShell 5.1 下解析失败：脚本与 `lib/common.ps1` 为 UTF-8 无 BOM，中文被按 GBK 解码后吞掉引号 | 两个脚本文件改为 UTF-8 BOM（内容不变），`lib/common.ps1` 修复后全仓冒烟脚本一并恢复可用 |
| 5 | `"/music/stream/$songId?ticket=..."` 中 PowerShell 把 `$songId?ticket` 解析为一个变量名（`?` 可出现在变量名里），导致 URL 缺歌曲 ID | 统一改为 `${songId}?ticket=...` |
| 6 | `PlayerContext.tsx` 同时导出 `PlayerProvider` 与 `usePlayer` 触发 `react-refresh/only-export-components`，`--max-warnings 0` 下 lint 失败 | 局部 `eslint-disable-next-line`（与全仓既有 hook 同文件导出的做法一致） |
| 7 | `FileAudioContentClient` 初版残留未使用字段与无意义请求头、`MapStatus` 过度设计 | 删除无用依赖，改为私有方法 `toException(status)` |
| 8 | 流式转发若用 Spring `RestClient` 会缓冲整个响应体，失去分段意义 | 改用 JDK `HttpClient` + `ofInputStream()`，接口层以 `InputStreamResource` 写出 |

## 4. 冒烟记录（M2-7）

- 脚本：`scripts/smoke/bw-music-m2-smoke.ps1`（环境变量 `MUSIC_BASE` / `FILE_BASE` / `SMOKE_USER_ID` / `SMOKE_TENANT_ID` 可覆盖）。
- 本机无登录口令，故脚本与服务（8096 / 8085）同网段直连，使用与网关注入一致的 `X-User-Id` / `X-Tenant-Id` / `X-Permission-Codes` 身份头，不经过网关鉴权链路。
- 实测链路与结果：

| 步骤 | 断言 | 结果 |
|---|---|---|
| 0 | `whale-music` / `whale-file` `/actuator/health = UP` | OK |
| 1 | 上传 4096B 测试音频，回传 `fileSize = 4096` | OK |
| 2-3 | 建歌手 → 建歌曲 `DRAFT` / `playable=false` → 上架 `PUBLISHED` / `playable=true` | OK |
| 4 | 票据 32 位、`expiresIn=120`、`streamUrl` 精确匹配且不含 `file_id`、视图带歌词 | OK |
| 4.1-4.3 | 无票据 / 票据换歌 / 票据换用户均 `40302` | OK |
| 5 | `Range: bytes=0-1023` → 206，`Content-Range: bytes 0-1023/4096`，`Accept-Ranges: bytes`，`Cache-Control` 含 `private` + `no-store`，`ETag` 存在 | OK |
| 6 | `Range: bytes=99999-` → 416，`Content-Range: bytes */4096`，空体 | OK |
| 7 | 无 Range → 200 全量 4096B，无 `Content-Range` | OK |
| 8 | 进度上报两次（12s → 18s）→ 最近播放同歌仅 1 条且进度为 18s | OK |
| 9 | 收藏两次 → 我的收藏仅 1 条且不含 `audioFileId`；取消两次 → 消失 | OK |
| 10 | 版权下架 → `OFFLINE + TAKEDOWN`、`playable=false`；**同一票据**请求流立即返回 `40403`；再次申票据同样 `40403` | OK |
| 11 | 删除歌曲 / 歌手 / 文件，删除后详情 `40403` | OK |

- 最终输出 `SMOKE-ALL-PASS`；脚本自清理本次创建的数据，遗留的失败重试数据已手工清理（`mu_song` / `mu_artist` / `mu_play_history` / `file_info` 仅保留 M1 已下架的历史行）。
- **M2-6 限流**：核对 `whale-gateway/src/main/resources/application.yml`，`/music/stream/**` 独立阈值 120 次/60s，超限由 `RateLimitGlobalFilter` 返回 **429 + `Result` 体**，配置已满足验收；因本机无登录口令，网关登录态链路（含 429 实测）留待有账号时补测。
