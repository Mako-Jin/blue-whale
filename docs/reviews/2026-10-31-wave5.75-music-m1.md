## 2. 完成项

### 2.1 领域层

- 5 个仓储端口：`ArtistRepository`、`AlbumRepository`、`TagRepository`、`SongRepository`、`CopyrightAgreementRepository`。
- 聚合与值对象：`Artist`（`enabled()`）、`Album`（`publish()` / `offline()`）、`Tag` / `TagType`、`Song`（发布 / 下架 / 版权下架 / `playable()` / `visibleTo()` / `assertOwnedBy()`）、`SongQuery`、`CopyrightAgreement`。
- `MusicErrorCode`：40001–40008 业务校验、40301 越权、40401–40404 资源不存在、40901 状态冲突，统一由 `BizException` 抛出。

### 2.2 基础设施层

- 5 个实体 + 6 个 Mapper（`SongTagMapper` 以注解 SQL 维护 `mu_song_tag`，不重复写 `tenant_id`，由租户插件填充）。
- 4 个仓储实现：`ArtistRepositoryImpl` / `AlbumRepositoryImpl` / `TagRepositoryImpl` / `CopyrightAgreementRepositoryImpl`（手工 entity↔domain 映射）。
- `SongRepositoryImpl`：关键词（标题 / 副标题）、歌手 / 专辑 / 上传者 / 发布态 / 可见性过滤；标签两段式筛选（先查 `song_id` 集合再 `IN`）；`NEW` / `HOT` 排序；标签关系覆盖式保存与批量查询。

### 2.3 应用层

| 服务 | 能力 |
|---|---|
| `CatalogAppServiceImpl` | 歌手 / 专辑 / 标签 CRUD，租户内唯一校验，专辑上架 / 下架，标签删除同步清理歌曲标签关系 |
| `SongAppServiceImpl` | 运营歌曲 CRUD、发布 / 下架 / 版权下架、运营分页与详情（含标签装配，批量查询避免 N+1） |
| `CopyrightAgreementAppServiceImpl` | 当前协议版本与签署状态、版本校验签署（幂等、IP / UA 留痕截断）、`assertAccepted` 未签署拦截 |
| `UserSongAppServiceImpl` | 用户上传（协议前置校验 + 创建即发布）、编辑 / 删除（归属校验）、我的作品、公开分页与详情（强制 `PUBLISHED + PUBLIC`，不可见按 404） |

### 2.4 接口层

| 控制器 | 端点 |
|---|---|
| `CatalogController` | `/music/artist`（CRUD + page + detail）、`/music/album`（CRUD + publish / offline + page + detail）、`/music/tag`（CRUD + list） |
| `SongController` | `/music/song`（CRUD）、`/music/song/{id}/publish|offline|takedown`、`/music/song/page`、`/music/song/{id}` |
| `CopyrightAgreementController` | `GET /music/copyright/agreement/current`、`POST /music/copyright/agreement/accept` |
| `UserSongController` | `POST|PUT|DELETE /music/user/song`、`GET /music/my/songs`、`GET /music/public/song/page`、`GET /music/public/song/{id}` |

- 权限码：`sys:music:artist:*` / `album:*` / `song:*` / `tag:manage` / `browse` / `upload`（对应 M0 已种子的 280–302）。
- 审计：所有写操作标注 `@AuditLog`；歌曲写操作 `recordParams = false`，不落歌词正文。

## 4. 已修正问题项

| # | 问题 | 处理 |
|---|---|---|
| 1 | 计划把 `/music/song/page`、`/music/song/{id}` 同时列为运营与用户侧接口，路径冲突 | 运营保留 `/music/song/**`；用户侧改为 `/music/public/song/**`，入 M1 偏差记录 |
| 2 | ArchUnit 禁止 interfaces 依赖 domain，控制器无法直接绑定 `PublishState` / `SongVisibility` | 分页命令统一用 `SongQueryCommand`（`@ModelAttribute`，由 Spring 完成 String→枚举）；专辑分页签名改为 `String publishState`，在应用层解析 |
| 3 | 「我的作品」需要按上传者过滤，但 `SongQueryCommand` 无该字段 | 增加 `uploaderId`，由 `UserSongAppService` 强制覆盖为当前用户，前端传参无效 |
| 4 | 用户上传与运营新增会重复实现创建逻辑 | 用户上传复用 `SongAppService.create` + `publish`，`UserSongAppServiceImpl` 只做协议前置、归属校验与视图转换 |
| 5 | `CatalogAppServiceImpl` 引入未使用的 `TakedownCommand` | 删除导入，`UnusedImports` 通过 |
