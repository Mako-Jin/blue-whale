## 7. G1 补充完成记录：`whale-file` HTTP Range（2026-10-31）

| 项 | 结论 |
|---|---|
| 范围 | `GET /file/{id}/download`、`GET /file/{id}/preview`、`GET /file/internal/{id}/content` 统一支持单段 Range |
| 响应语义 | 无 Range → 200 全量；可满足 → 206 + `Content-Range: bytes start-end/size`；语法合法越界 → 416 + `Content-Range: bytes */size` + `Content-Length: 0`；多段 / 非法语法 → 按 RFC 9110 忽略，回落 200 全量 |
| 协商头 | 全部响应声明 `Accept-Ranges: bytes`；以 MD5（缺失时 `id-size`）生成强 `ETag`；`If-Range` 弱校验或不匹配时回落 200 全量，避免区间与旧版本错配 |
| 读取链路 | `FileStorage` / `StoragePlugin` 新增区间读取端口；`StoragePluginRegistry` 委派活动插件；local 插件走 `skipNBytes + LimitedInputStream`，MinIO 插件走 `GetObjectArgs.offset/length` 原生分段 |
| 测试 | file 模块 9 个子模块 `mvn test` **全绿**：domain 14、infrastructure 30、application 36、interfaces 21（含 `FileControllerTest` 13 / `FileInternalControllerTest` 7）、plugins-local 7、plugins-minio 7、architecture-test 4；Checkstyle 0 违规 |

- 新增 `LimitedInputStream`（限制响应体不超声明长度）与 `FileContentResponses`（统一下载 / 预览 / 内网内容接口的响应头与区间解析）。
- 修复既有测试 `FileAssetRepositoryImplTest` 构造参数缺参导致的编译失败（与 Range 无关）。
- 上传侧 `POST /file/**` 不受影响；M2 播放票据签发后可基于 `/file/internal/{id}/content` 做 206 流式转发。
