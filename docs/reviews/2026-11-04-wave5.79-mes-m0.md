## 2. 变更清单

### 2.1 数据库迁移（`backend/whale-apps/whale-mes/src/main/resources/db/migration`）

- `V2__mes_foundation.sql`
  - 升级 `mes_work_order`：`erp_order_no`、`item_code`、`item_name`、`planned_quantity`、`uom`、
    `routing_version`、`priority`、`planned_start`、`planned_end`、`version`；
  - 存量状态迁移：`ENABLED → RECEIVED`、`DISABLED → CANCELLED`；
  - 唯一索引 `uk_mes_work_order_erp_order (tenant_id, erp_order_no)`；
  - 新增 12 张表：`mes_md_workshop`、`mes_md_line`、`mes_md_work_center`、`mes_md_station`、
    `mes_md_team`、`mes_md_shift`、`mes_md_operation`、`mes_md_defect_code`、`mes_md_reason_code`、
    `mes_md_routing_snapshot`、`mes_md_routing_operation`、`mes_common_outbox`；
  - 幂等种子：车间 `101`、产线 `201`、工作中心 `301`、工位 `401`、班组 `501`、白班/夜班 `601/602`、
    工序 `701/702`、缺陷 `801/802`、原因 `901/902`、工艺路线 `1001`、路线工序 `1101/1102`。
- `V3__mes_shift_calendar.sql`
  - 新增 `mes_md_shift_calendar`，唯一键 `(tenant_id, calendar_date, shift_id)`；
  - 单独成版而非并入 V2，避免已执行 V2 的环境触发 Flyway 校验和变更。
- 编号调整：M1–M5 迁移号顺延为 `V4`–`V8`，设计稿与计划已同步。

### 2.2 后端代码（`com.bluewhale.mes`）

- `masterdata`（共享内核）：
  - `entity`：抽象基类 `MesMasterDataEntity` + 9 个实体；
  - `mapper`：9 个 `BaseMapper`；
  - `dto`：共用 `MesMasterDataQueryRequest` / `MesMasterDataSaveRequest`（含类型枚举值校验）；
  - `vo`：共用 `MesMasterDataVO`；
  - `converter`：MapStruct 9 个 `toVo` + 运行时分派；
  - `enums.MasterDataKind`：路径标识 `workshop/line/work-center/station/team/shift/operation/defect-code/reason-code`；
  - `service`：`MesMasterDataService` + 实现，编码唯一、产线挂车间、工作中心挂车间与产线、
    工位挂产线与工作中心、班组挂车间、班次时间必填且不同；车间/产线/工作中心被下级引用时禁止删除；
  - `controller`：`/mes/master-data/{kind}/**`（page / options / detail / create / update / delete），
    权限码 `sys:mes:master:list/add/edit/delete`，写操作 `@AuditLog`（`targetType=mes_master_data`）。
- `common.outbox`：`MesOutboxEvent` + Mapper + `MesOutboxService`（幂等入队、标记成功/失败）。
- 工单升级：
  - `MesWorkOrder` 新增 10 个字段，`version` 标注 `@Version`；
  - `MesWorkOrderServiceImpl` 状态机
    `RECEIVED→DISPATCHED→IN_PROGRESS⇄PAUSED→COMPLETED→CLOSED`，可 `CANCELLED`，终态不可再变；
  - 新增时状态为空默认 `RECEIVED`、优先级默认 `NORMAL`、`version=1`；
  - ERP 单号空白归一为 `null` 并做租户内唯一校验；
  - 计划完工早于计划开工拒绝；
  - 仅 `RECEIVED / CANCELLED` 允许删除；
  - 保留 `/mes/work-order/**` 5 个端点与 `Result` 信封。
- 公共层：`MybatisPlusConfig` 追加 `OptimisticLockerInnerInterceptor`（仅作用于 `@Version` 实体，
  对存量实体无行为变化），支撑工单并发编辑。

### 2.3 权限脚本（`backend/whale-services/whale-service-auth/whale-service-auth-starter/src/main/resources/db`）

- 新增 `migration-5.79-mes-foundation.sql`：
  - 权限 1100–1103（基础主数据 list/add/edit/delete）；
  - 菜单 240（基础主数据）、241（生产工单）；
  - 角色 20703–20707：`mes_planner` / `mes_operator` / `mes_quality` / `mes_equipment` / `mes_team_lead`；
  - 授权：`tenant_admin / mes_manager / mes_planner` 得 1100–1103；`mes_member / mes_operator /
    mes_quality / mes_equipment / mes_team_lead` 得 1100 只读；工单权限沿用 207–210 按岗位下发；
  - 业务租户角色与授权按 `MD5(tenant:role)` / `MD5(role:permission)` 前 15 位复制，全部 `NOT EXISTS` 幂等；
  - 脚本末附校验 SQL 与期望计数。

### 2.4 前端（`frontend/platform-apps/whale-mes`）

- `api/mes.ts`：工单生命周期/优先级类型、新工单字段、查询分页；九类主数据分页/选项/保存/删除；
- `App.tsx`：`BrowserRouter basename="/mes"` + 侧栏菜单（`/work-order`、`/master-data`）；
- `pages/List.tsx`：ERP 单号、物料、计划数量、优先级、状态标签、计划开工/完工列；编码/状态/优先级筛选；
- `pages/Form.tsx`：ERP 单号、物料、数量/单位、路线版本、优先级、计划时间（`DatePicker` + `dayjs`）、生命周期状态；
- `pages/MasterDataPage.tsx`：七个页签（车间/产线/工作中心/工位/班组/班次/工序）配置化 CRUD，
  上级引用下拉、状态标签、时间格式校验；缺陷代码/异常原因后端已支持，页面在 M3 质量落地时并入；
- `package.json`：新增 `dayjs` 依赖。
