## 2. 变更清单

### 2.1 数据库迁移

`whale-backend/whale-apps/whale-mes/src/main/resources/db/migration/V5__mes_trace.sql`

- 批次与条码：`mes_tr_batch`、`mes_tr_barcode_rule`、`mes_tr_barcode`；
- 谱系：`mes_tr_trace_link`（父 / 子批次 + 数量 + `ACTIVE/REVERSED`）；
- 线边仓：`mes_tr_line_side_stock`、`mes_tr_line_side_movement`；
- 防错与补货：`mes_tr_scan_rule`、`mes_tr_replenishment`；
- 关键唯一键：批次 `(tenant_id, batch_no)`、条码值 `(tenant_id, barcode_value)`、规则编码、
  线边库存 `(tenant_id, line_id, warehouse_code, item_code, batch_no)`、流水 / 补货单号；
- 批次、条码规则、线边库存、扫码规则含 `version` 乐观锁字段。

### 2.2 后端（`com.bluewhale.mes.trace`）

- 实体 / Mapper（8 组）：批次、条码规则、条码、谱系链接、线边库存、线边流水、扫码规则、补货请求。
- `MesBarcodeService`：`saveRule`、`pageRules`、`generate`、`page`、`voidBarcode`；
  - 生成值 = `前缀 + yyyyMMdd + 定长流水`，流水基于规则内已生成条码数递增；
  - 校验规则 `ENABLED`、批次存在且非 `CLOSED`；`printPayload` 落 JSON 打印载荷。
- `MesBatchService`：`create`、`close`、`link`、`forward`、`backward`、`page`；
  - 建链前 BFS 成环检测（最多遍历 500 节点），父批次消耗量 + 本次数量不得超投入量，
    校验通过后乐观锁更新 `consumed_quantity` 再追加 `ACTIVE` 链接；
  - 正 / 反向追溯按层级 BFS，默认 3 层、上限 10 层，已访问批次去重。
- `MesScanService`：`validate`、`saveRule`、`pageRules`；
  - 校验顺序：条码不存在 / `VOID` → 阻断；`scanNo` 与上次相同 → `duplicate=true` 且放行；
    规则按工位 / 工序匹配取最高分；期望物料不符时 `BLOCK` 阻断（不计扫码次数）、`WARN` 告警并放行。
- `MesLineSideService`：`pageStock`、`inbound`、`issue`、`pageMovements`、`replenish`、`pageReplenishments`；
  - 库存行按 `(lineId, warehouseCode, itemCode, batchNo)` 定位，`batchNo` 归一化为空串；
  - 入库 / 退料方向 +1，领用方向 −1；`after = before ± quantity` 且余额不得为负；
  - 流水只追加并留 `before/after` 快照；补货按 `requestNo` 查重，重复请求直接返回已有记录。
- 端点：`/mes/trace/**` 条码、批次、谱系、扫码 13 个 + `/mes/trace/line-side/**` 5 个，
  均带 `@RequirePermission`，写操作带 `@AuditLog(targetType="mes_trace")`。

## 4. 关键不变量与口径

| 不变量 | 实现方式 |
|---|---|
| 条码值租户内唯一、一码绑定一批次 | 唯一索引 `(tenant_id, barcode_value)` + 生成时绑定 `batch_id/batch_no` |
| 批次号租户内唯一 | 唯一索引 `(tenant_id, batch_no)` + 建档前置校验 |
| 谱系无环 | 建链前从子批次 BFS 检查能否回到父批次，最多 500 节点 |
| 消耗量 ≤ 投入量 | 父批次 `consumed_quantity + 本次数量 ≤ quantity`，乐观锁更新 |
| 线边库存 ≥ 0 | 领用前校验，余额不足抛“线边库存不足” |
| 流水只追加 | 不提供更新 / 删除接口，每笔留 `before/after` 快照 |
| 扫码幂等 | `scanNo` 与 `last_scan_no` 相同即判重复，不再累加扫码次数 |
| 补货幂等 | `request_no` 已存在直接返回已有请求 |

口径说明：

- 条码 `object_type` 当前固定 `BATCH`，序列号 / 托盘等多对象绑定未开放；
- 扫码 `WARN` 仅返回告警文案并放行，不阻断现场作业；`BLOCK` 不更新条码扫码次数；
- 线边仓与 M1 `material-issue` 各自记账，尚未联动扣减；
- 补货只登记请求并写日志，`/erp/scm/transfer` 调用留待 ERP 端接口就绪后开启。
