# Wave 5.82 OA M1A-4 检查报告

> 日期：2026-11-06
> 范围：审批通知、自动催办、状态对账、请假附件强校验
> 规格：[spec.md](../specs/2026-11-06-wave5.82-oa-m1a4/spec.md)

## 一、结论

M1A-4 按计划落地。通知全部走 `whale-message` 内网端点并复用 M0 预置模板，失败不阻断审批动作；自动催办与对账由可配置 Job 承担；请假附件复用 `oa_file_ref`，未新增表。

## 二、实现要点

- **通知分层**：`ApprovalNotificationAppServiceImpl` 负责组装模板变量、账号解析与幂等键；`ApprovalNotifyGatewayImpl` 只负责 HTTP 投递。投递异常在应用服务内捕获并 warn。
- **事件驱动**：绑定、结果同步、催办三个事件触发通知，避免在控制器或网关中散落通知逻辑。
- **对账**：按 100 个实例分批调用 Workflow 状态接口，仅 1/2/3 映射为 `APPROVED/REJECTED/CANCELLED`，通过既有 `syncResult` 保证幂等与业务结果同步事件。
- **自动催办**：仓储查询“运行中 + 已绑定 + 提交早于阈值”，逐条通知；消息幂等键带日期，天然按天去重。
- **附件**：`fileIds` 新增、`keepAttachmentIds` 保留；总数 ≤5；要求附件的类型不得为零；编辑未传保留列表时默认保留全部，避免误删。

## 四、风险与后续

1. 调度任务在无租户上下文时按平台默认租户发送消息；当前按单租户部署，多租户化时需按实例租户分组执行。
2. 附件引用未校验文件归属（仅登记 `fileId`）；若需防止跨用户引用，应在文件服务补“上传者/租户”校验。
3. 抄送通知依赖 Workflow 抄送记录在绑定后可查询；如抄送在流程中途新增，暂不会补发，后续可扩展抄送创建事件。
4. 通知目前同步发送，消息服务抖动会拉长审批接口耗时；高并发场景建议改为事务提交后异步投递。
