## 二、契约与交付物

### A-a/A-b/B · 实体、映射、DTO/VO、服务与接口（8 文件）

| 文件 | 说明 |
|---|---|
| `entity/FormData` | 继承 `BaseEntity`，`@TableName("form_data")`；definitionId/definitionCode/definitionVersion/bizKey/dataJson/submitter/status |
| `mapper/FormDataMapper` | 仅继承 `BaseMapper`（`com.bluewhale.**.mapper` 扫描） |
| `dto/FormDataSubmitRequest` | definitionId、dataJson 必填 + bizKey 可选（≤64） |
| `dto/FormDataQueryRequest` | 继承 `PageQuery`：definitionCode 等值、bizKey 等值、submitter 等值 |
| `vo/FormDataVO` | 契约字段 |
| `service/FormDataService(+Impl)` | `submit`（校验定义存在 + 数据 JSON ≤64KB，回填定义冗余 code/version，status=1）/`getDetail`/`page`（按 `create_time desc`，`MAX_PAGE_SIZE=200`）/`delete`（逻辑删除） |
| `controller/FormDataController` | `@RequestMapping("/form/data")`，4 接口：POST 提交 / GET 分页 / GET `{id}` / DELETE `{id}`；提交接口经 `WebHeaders.username` 回填 submitter |

### C-a/C-b · DDL 与权限种子

| 项 | 结论 |
|---|---|
| `whale-form/db/init.sql` | 追加 `form_data`（11 列，`idx_definition_id`/`idx_biz_key`）表 |
| whale-auth `db/init.sql` | 追加 `sys:form:data:submit(49)/list(50)/delete(51)`（承接 id 至 48） |

### C-c · 单测

- `FormDataServiceImplTest`（**8 用例**）：提交成功（断言定义冗余字段回填 + submitter + status=1）、定义不存在 `404`、数据超 64KB `400`「表单数据长度不能超过 65536 字符」、详情、详情不存在 `404`、删除、删除不存在 `404`、分页条件传递。

## 三、E2E · 运行时取证（经网关 8080，9 步）

前置：`bluewhale_form` 落 2 表（`form_definition`/`form_data`）；`bluewhale_auth.sys_permission` max(id)=48 → 插入 49–51，回读 3 条一致。

| 步骤 | 操作 | 结果 |
|---|---|---|
| 0 | `POST /auth/login`（admin/123456） | `code=0`，取得 accessToken |
| 1 | `POST /form/definition`（code `fm-e2e-526v2`） | `code=0`，id `2112121294539423746` |
| 2 | `POST /form/data`（definitionId + dataJson + bizKey） | `code=0`，status=1，submitter=admin，definitionCode/version 回填 |
| 3 | `GET /form/data/page?definitionCode=fm-e2e-526v2` | `code=0`，total=1 |
| 4 | `GET /form/data/{id}` | `code=0`，dataJson 与提报一致 |
| 5 | `DELETE /form/data/{id}` | `code=0` |
| 6 | `GET /form/data/{id}`（删除后） | **`code=404`**「资源不存在」 |
| 7 | `GET /form/data/page?definitionCode=fm-e2e-526v2`（删除后） | `code=0`，total=0 |
| 8a | `POST /form/data`（definitionId=999999999） | **`code=404`**「资源不存在」 |

冒烟全绿表明：网关 `/form/**` 路由 + 权限码头 `X-Permission-Codes` 注入 + 服务 `@RequirePermission` 放行（super_admin 全量权限码已含新增 `sys:form:data:*`）+ 数据闭环链路均正常。

## 四、缺陷与偏差

| 类别 | 内容 |
|---|---|
| 缺陷 | 无（Checkstyle 一次通过 0 违规，单测一次通过） |
| 偏差（构建） | 全量 `clean install` 需先释放运行中 7 个服务的 `target/*.jar` 锁 → 停 gateway/auth/job/workflow/form/file/audit 七进程，构建后 `Start-Process` 重启并核验健康 |
| 环境（缓存刷新） | 新增权限种子后，网关权限码头走 Redis 缓存键 `whale:cache:auth:user:perm:{userId}`；缓存未命中即回落 `/auth/me`（读 DB listAllCodes，含新种子），本轮以清空该缓存键 + 重新登录取得新权限码 |

## 六、非目标与残余

- **非目标（本轮明确不做）**：表单数据审批流、数据版本快照、草稿/暂存、字段级校验与唯一性约束；表单与工作流联动（发起流程实例时绑定表单 / 按 `bizKey` 关联实例）；前端表单设计器与数据填报页、导入导出、附件上传。
- 固化：`whale-form` 现有 2 表（`form_definition`/`form_data`）。
- 后续候选：whale-form ↔ whale-workflow 联动（按 `bizKey` 关联 `process_instance.business_key` 与 `form_data.biz_key`）；whale-pay 骨架填充。
