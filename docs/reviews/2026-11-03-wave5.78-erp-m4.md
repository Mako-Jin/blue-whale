## 2. 变更清单

### 2.1 数据库迁移（`backend/whale-apps/whale-erp`）

- 新增 `V6__hr.sql`：9 张表
  - `erp_hr_org_unit`（`uk_hr_org_code`、`idx_hr_org_parent`）；
  - `erp_hr_employee`（`uk_hr_employee_no`，`base_salary/allowance/social_base DECIMAL(18,2)`、`user_id`、`status ACTIVE/LEFT`）；
  - `erp_hr_employment_change`（`uk_hr_change_no`，`change_type HIRE/TRANSFER/PROMOTION/RESIGN/RETURN`，`status DRAFT/EFFECTIVE/CANCELLED`）；
  - `erp_hr_attendance_summary`（`uk_hr_attendance` = 租户 + 员工编号 + 期间）；
  - `erp_hr_payroll_run`（`uk_payroll_period` = 租户 + 期间、`uk_payroll_run_no`；合计字段）；
  - `erp_hr_payslip`（`uk_payslip_employee` = 租户 + 批次 + 员工编号）；
  - `erp_hr_performance_cycle`（`uk_hr_cycle_no`）；
  - `erp_hr_kpi`（`uk_hr_kpi_name` = 租户 + 周期 + 名称）；
  - `erp_hr_appraisal`（`uk_hr_appraisal` = 租户 + 周期 + 员工 + 指标）；
  - 数量 `DECIMAL(18,2)`、权重 `DECIMAL(18,2)`；禁止 `DROP/TRUNCATE/DELETE`；
  - 末尾幂等写入科目 `2241`「其他应付款」（ID 7023，`LIABILITY/CREDIT`）。

> `V5__manufacturing.sql` 已发布，人力按版本顺序顺延为 `V6`（设计稿原写 V7，实际 M3 用 V5，故偏差记录）。

- `application`：9 组命令、7 组视图、5 个应用服务及实现（`OrgAppServiceImpl`、`EmployeeAppServiceImpl`、
  `AttendanceAppServiceImpl`、`PayrollAppServiceImpl`、`PerformanceAppServiceImpl`）；
- `infrastructure`：9 个实体、9 个 Mapper、6 个仓储实现（单号 `HC-yyyyMMdd-%04d`、`PR-yyyyMM-%04d`、`PC-yyyyMM-%04d`）；
- `interfaces/controller`：`HrOrgController`（`/erp/hr/org`）、`HrEmployeeController`（`/erp/hr/employee`）、
  `HrAttendanceController`（`/erp/hr/attendance`）、`HrPayrollController`（`/erp/hr/payroll`）、
  `HrPerformanceController`（`/erp/hr/performance`），`@RequirePermission` + `@AuditLog`；
  薪资审批/发放操作人从 `X-User-Id` 取；
- `finance`：`AutoVoucherCommand` 增 `netAmount/taxAmount/withholdingAmount`；`AutoVoucherAppService` 增
  `postPayrollAccrual`、`postPayrollPayment`；`ErpFinanceAccountProperties` 增 `salaryExpense=6602`、
  `salaryPayable=2211`、`bankDeposit=1002`、`taxPayable=2221`、`otherPayable=2241`；
  `application.yml` 增对应 `erp.finance.account.*` 与 `erp.hr.payroll.*`；
- `common`：`ErpErrorCode` 增 `HR_INVALID(40017)`、`ORG_NOT_FOUND(40416)`、`EMPLOYEE_NOT_FOUND(40417)`、
  `EMPLOYMENT_CHANGE_NOT_FOUND(40418)`、`ATTENDANCE_NOT_FOUND(40419)`、`PAYROLL_NOT_FOUND(40420)`、
  `PERFORMANCE_CYCLE_NOT_FOUND(40421)`、`KPI_NOT_FOUND(40422)`、`HR_STATE_CONFLICT(40922)`、
  `PAYROLL_PERIOD_CONFLICT(40923)`、`EMPLOYEE_CODE_CONFLICT(40924)`、`ORG_CODE_CONFLICT(40925)`；
- 关键规则：
  - 组织编码唯一、上级组织必须存在且启用、上级不能是自身；
  - 员工建档要求编号/姓名/组织/入职日期必填、金额非负；组织停用拒绝建档；离职后不再参与计薪（`listActive`）；
  - 异动仅 `DRAFT` 可生效/取消；调动/晋升必须指定目标组织；离职日期不得早于入职日期；
  - 薪资期间强校验 `YYYY-MM` 且租户内唯一；只有 `DRAFT` 可计算、`CALCULATED` 可审批、`APPROVED` 可发放、
    `PAID` 可结账；`APPROVED` 后无工资条更新路径；
  - 计薪：`hourlyRate = base / (monthlyWorkDays × dailyHours)`（4 位 HALF_UP）；`gross = base + allowance +
    overtime − leaveDeduction − absenceDeduction`（负数取 0）；社保/公积金以社保基数为准（为 0 时回退月薪）；
    `taxable = gross − social − fund − threshold`（负数取 0），7 级累进速算扣除；
  - 绩效周期关闭后禁止新增指标/考核；首次录入自动 `DRAFT→IN_PROGRESS`；等级由分数推导，不单独录入。

## 5. 结论

M4 第一阶段把「组织/员工 → 异动 → 考勤 → 薪资计算 → 工资条 → 计提/发放凭证 → 绩效」串成闭环：
员工档案以 `user_id` 关联平台账号，工资条接口只返回本人数据；薪资期间租户内唯一，审批后明细冻结，
保证凭证与工资条一致；计薪比例与个税规则全部配置化，便于按地区政策调整；绩效等级由分数推导，
避免分数与等级不一致。HR 四层与既有 Finance 端口协作，ArchUnit 新增 4 条边界规则并全绿，
前端四页已接入基座菜单与独立权限码。

建议下一步先确认薪资项自定义与个税累计预扣的政策口径，再扩展招聘/合同/排班与绩效联动，避免
薪资表结构返工。
