# Wave 5.80 PDM M1B-4 零件去重与人工合并 评审

> 评审日期：2026-11-06
> 规格：[spec.md](../specs/2026-11-06-wave5.80-pdm-m1b-dedup/spec.md)
> 关联计划：[Wave 5.80 PDM 全景计划](../plans/2026-11-04-wave5.80-pdm-panorama.md)

## 一、范围

- 后端：去重候选分组、人工合并、源件停用与合并目标追溯。
- 迁移：`V13__part_merge.sql`、`migration-5.80-pdm-part-merge.sql`。
- 前端：`/pdm/part/dedup` 审阅页、合并确认弹窗与菜单。

## 二、决策

| 项 | 决策 |
|---|---|
| 引用改写范围 | 仅 `DRAFT` BOM 行；`RELEASED`/`OBSOLETE` 保持不可变，只统计跳过数 |
| 源件处置 | `status=DISABLED` + `merged_to=targetId`，不物理删除，历史快照可追溯 |
| 匹配口径 | 名称/材质/规格去首尾空白、折叠连续空白、大小写不敏感；不做近似匹配 |
| 冲突处理 | 同父件已存在保留件行时用量累加，源行逻辑删除 |
| 装配保护 | 源件为 BOM 主体或作为父件时拒绝合并 |

## 三、实现要点

- `PdmPartDedupServiceImpl`：候选扫描上限 5000、返回上限 100 组，避免全表加载。
- `PdmPartController` 新增 `GET /pdm/part/dedup/candidates`（`sys:pdm:part:dedup:list`）与 `POST /pdm/part/merge`（`sys:pdm:part:merge`，写审计）。
- `pdm_product.merged_to` 通过 information_schema 幂等追加，并建 `idx_product_merged_to`。
- 权限 941 对 `pdm_member` 只读开放，942 仅管理/工程师角色。

## 五、遗留

- 自动合并、相似度匹配：明确不做，保持人工确认。
- 已发布 BOM 引用：按决策不改写，通过 `merged_to` 追溯。
- ERP 只读物料/库存：仍由 M1B-5 承接，依赖 ERP 内网契约。
