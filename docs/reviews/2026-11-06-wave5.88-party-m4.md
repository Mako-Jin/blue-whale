## 四、关键设计复核

1. **比率不落库**：`pty_metric_snapshot` 只存 `numerator` / `denominator`。存比率会带来两个硬伤：四舍五入后的比率不能加也不能平均；换分母口径（如从党员数改为在册员工数）时历史比率无法重算。展示时用 `MetricSnapshot.rate()`，分母 0 返回 `0.00`。
2. **覆盖写而不是追加**：`saveAll` 按唯一键先查后 insert/update，不用「删后插」。删后插会让并发刷新出现空窗，也会让自增 ID 漂移；唯一键 upsert 让补跑幂等，趋势图不会一天多点。
3. **实时兜底与归档分离**：`partyOverview` 无快照时现算但**不写库**，返回 `live=true` 由前端显式提示；写库只由 `refresh` 触发。避免「看一眼就把实时值当审计值落库」。
4. **覆盖率分母必须来自 ERP**：`pty_employee_snapshot` 按 `employee_no` 唯一（ERP 里有尚未开通平台账号的员工，按 `user_id` 会漏人）。空目录拒绝覆盖（`EMPLOYEE_SYNC_EMPTY`），ERP 不可达保留旧快照（`EMPLOYEE_SYNC_FAILED` 上抛但不删旧数据）——覆盖率和趋势宁可停更，也不能用错误分母算出漂亮数字。
5. **书记数据范围强制收敛**：`resolvePartyScope` 对非 `canManageAll()` 一律取 `branchIdOf(userId)`，无支部档案抛 `BRANCH_NOT_FOUND`；换届提醒同样按书记本支部过滤。范围校验在服务层而不是前端菜单。
6. **通知幂等双层**：本地留痕先查后插 + 唯一键兜底，消息服务再按幂等键去重。单场景失败 `markFailed` 不抛，保证「党费催缴失败不阻断换届提醒」；只有 `send` 全失败才抛 `NOTICE_SEND_FAILED`。
7. **导出上限 366 天**：单次导出跨年会给数据库与浏览器都制造长事务/大文件；上限可配（`exportMaxDays`），超限直接 `METRIC_EXPORT_LIMIT`，而不是静默截断。
8. **依赖方向**：`analytics` 只依赖各上下文的 `metrics()` 视图，不直接读其他上下文的表；`integration` 通过端口调 ERP / message，ArchUnit 八上下文门禁通过。

## 五、同批修正

- **`Set<Long>` → `List<Long>`**：转正候选接收人用 `Set` 去重后直接传给 `tryDispatch`，参数类型不符；调用处 `List.copyOf(recipients)`，保留去重。
- **`record DispatchResult` 递增编译失败**：record 字段 final，`sent++ / failed++` 非法；改为可变 `static final class`。
- **指标桶方法返回类型**：`ageMetric/partyAgeMetric/educationMetric` 由 `String` 统一为 `MetricType`，避免 `snapshot(...)` 参数类型不匹配。
- **`record Scope` 字段访问**：record 无字段访问语法，改私有 `static final class Scope`。
- **Checkstyle**：补齐 4 处构造器 javadoc、清理 3 个未使用 import、`PartyMember.validateIdentity` 圈复杂度 17→15 以内（抽 `normalizeEducation()`）。
- **测试桩顺序**：试点全链先桩固定 ID 再 `create`，避免 create 内部读库拿到空；党费档位桩合并进 `@BeforeEach`（JUnit 不保证多个 `@BeforeEach` 顺序）。
