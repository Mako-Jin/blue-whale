## 2. 能力与边界

- **模板**：`${key}` 占位符渲染；未知占位符保留，便于发现模板/变量不匹配；当前租户无模板时回落平台租户共享模板。
- **渠道**：`INAPP`（落库即送达）、`EMAIL`（JavaMailSender 可选）、`SMS`（部署侧 HTTP 网关 + Bearer）、`IM`（`whale-im /im/internal/notify`）。
- **幂等**：`(tenant_id, idempotency_key)` 唯一索引；重复请求返回既有消息，不重复投递；并发冲突捕获 `DuplicateKeyException` 后回查。
- **失败隔离**：单渠道异常/失败只写该条 `FAILED`，不阻断其它渠道；消息状态聚合为 `SENT/PARTIAL/FAILED/MOCKED/SKIPPED`。
- **mock 默认**：`WHALE_MESSAGE_MOCK=true`，外部通道不发起网络请求，只记 `MOCKED/SKIPPED`；生产接入时显式关闭。
- **边界**：IM 会话/已读/在线仍归 `whale-im`；告警规则/去重/静默仍归 `whale-alert`；Portal 待办/公告仍是业务功能，消息中心只负责送达。

## 4. 风险与后续

| 风险 | 说明 | 缓解 |
|---|---|---|
| mock 默认值误用于生产 | 生产未显式关闭 mock 时外部通道不会真实发送 | 启动日志/部署清单要求 `WHALE_MESSAGE_MOCK=false`；后续加生产配置校验 |
| 无模板管理界面 | M0 只能 SQL 维护模板 | M1 增加模板管理 API/页面 |
| 无重试/死信 | 渠道失败只记录一次 | M1 增加重试表/调度与退避 |
| 无用户偏好/免打扰 | 不能按用户静默 | M1 增加 `msg_preference` |
| 无 SDK | 业务方需手写 HTTP 契约 | 出现 2 个以上 Java 消费方后再加 `whale-message-sdk` |
