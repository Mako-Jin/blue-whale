# 《鲸议台 v1.2（2D 版）功能列表》评审意见

> 评审对象：蓝鲸城｜论坛服务 2D 功能列表 v1.2（whale-forum，78 人日 / P0 38 人日）
> 评审基准：[forum-service.md](../design/forum-service.md)（本平台论坛设计稿）、[service-catalog.md](../service-catalog.md)、[naming-conventions.md](../naming-conventions.md)、[network-boundary.md](../design/network-boundary.md)、[security-baseline.md](../design/security-baseline.md)
> 评审日期：2026-11-12
> 结论：**功能视野完整、边界划得清，但作为「需求评审 + 开发排期 + 验收对照」三合一的文档，目前不能直接开工**。有 11 处硬伤（其中 6 处会导致静默失效或验收不可通过），4 处引用了平台不存在的服务或中间件，另有 5 个章节缺失。建议出 v1.3 再排期。

---

## 一、总评

| 维度 | 评价 | 说明 |
|---|---|---|
| 业务边界 | **好** | 「不做 IM / 长文 / 电商 / 外网公开社区」四刀切得准，是本稿最强项 |
| 功能覆盖 | 好（偏多） | 六类内容 + 治理 + 成长体系齐全，但 P0 里混入了 3 个本质属 P1 的重功能 |
| 命名与品牌 | 展示层好，工程层缺 | 「鲸议台 / 投花 / 鸣鼓」体验统一；但表前缀、权限码、端口、库名、菜单号**全缺**，无法落码 |
| 技术选型 | **不符平台现状** | ES、ClickHouse、向量检索、Redis 计数回写——平台一个都没有（详见 §四） |
| 数据一致性与并发 | **不足** | 楼层号分配、软删撞唯一键、计数口径、举报与审核两条链路均未定义（详见 §二） |
| 排期可信度 | 偏低 | 人日只算功能不算基建；且 2D 78 人日 > 3D 67 人日的解释站不住（详见 §六） |
| 验收清单 | 意识好，判据需修 | 10 条里有 4 条与功能清单自相矛盾（限流 vs 并发、403 vs 不泄露存在性等） |

一句话：**这是一份好的产品需求稿，还不是一份可开发、可验收的系统设计稿。**

## 二、必须改（P0 阻塞，不修不能开工）

### 2.1 楼层号分配机制未定义 —— 验收点 3 必挂

- **问题**：F-04 全节没有写楼层号怎么产生，但验收点 3 要求「并发 50 条回帖，楼层号无重复、无跳号」。
- **后果**：实现者只能用 `SELECT MAX(floor)+1` —— 并发下必然重复或跳号，且事务里查-改-写会锁帖。
- **改法（写进设计）**：
  1. `fm_thread.next_floor` 字段，`UPDATE ... SET next_floor = next_floor + 1 WHERE id = ?` 取回值分配；
  2. `fm_post` 建 `uk_fm_post_floor(tenant_id, thread_id, floor)` 兜底，唯一键冲突即重试（≤3 次）；
  3. **软删楼层的 floor 不回收**（回收必然造成「N 楼」与引用错位）；
  4. 楼中楼（F-04-03）**不占楼层号**，只做二级 `parent_post_id`，且**最多两级**——三级以上折叠成「回复 @某人」，否则楼层/分页/只看楼主三处逻辑全要重写。

### 2.2 软删与唯一键冲突 —— 平台已踩过的坑

- **问题**：`thread_no`、标签名、版块 `path/code` 都是唯一键，文档全篇未提删除语义。
- **后果**：删帖后同编号无法重建、删标签后同名无法新建，报唯一键冲突但界面无提示（**典型静默失效**）。商城已用「软删时把编码改写为 `原编码#D{id}`」解决。
- **改法**：明确「业务内容表挂逻辑删除（`deleted`），唯一编码软删改写 `#D{id}` 释放；关联表（互动、收藏）物理删除」。

### 2.3 计数口径自相矛盾（F-05-05 vs 验收点 4）

- **问题**：F-05-05 写「Redis 累加，定时回写库」，验收点 4 要求投花幂等、取消后计数 −1。
- **后果**：Redis 未开 AOF 时重启即丢计数；双写期间展示值与明细不一致；且幂等靠的是唯一键不是 Redis。
- **改法**：
  1. 幂等由 `uk_fm_reaction(tenant_id, user_id, target_type, target_id)` 保证；
  2. 计数以 **DB 条件更新** 为准（`like_count = like_count + 1`），Redis 只承担「浏览去重（同人同帖 24h +1）」与限流；
  3. 每日对账 Job 用明细 `COUNT` 校正展示计数，差异写审计（平台既有口径）。

### 2.4 匿名发帖与治理/审计直接冲突（F-03-12 + F-09-07 + F-07-07）

- **问题**：「匿名鲸友 + 编号」没有定义编号生成规则，但同一份文档要求禁言展示、处置可追溯、审计留痕。
- **后果**：若库内不存 `user_id` → 无法禁言、无法申诉、审计断链；若编号随机 → 同一人换号码即可绕过封禁（**治理形同虚设**）。
- **改法**：
  1. **库内恒存 `user_id`，只做展示层匿名**（写进红线）；
  2. 匿名编号按 `(tenant_id, board_id, user_id)` 稳定映射（HMAC 取 4 位，同人同版恒定、跨版不同）；
  3. 匿名帖**不允许**参与鲸阶积分与金榜（否则刷分无成本）；
  4. 权限矩阵里把「匿名发帖」从角色表移除——它是**属性**不是角色，混进角色矩阵会污染 RBAC。

### 2.5 「已解决 / 已关闭 / 审核中」状态机与功能清单不一致

- **问题**：F-02-08 列了 5 个状态标记，6.1 状态机只有 `draft/pending/published/rejected/deleted` + 三个附属动作，缺 `solved`、`closed`。
- **后果**：问答帖采纳最佳答案后状态怎么变、能否再回复、`solved` 与 `closed` 优先级，三处各有各的实现。
- **改法**：状态机补两条支线并定优先级：
  ```
  published ──采纳最佳答案──> solved（仍可回复，可撤销采纳退回 published）
  published ──关闭──> closed（禁回复，可重开）
  优先级：deleted > closed > solved > pending > published
  ```

### 2.6 发布态编辑是否退回审核 —— 缺一条就白审

- **问题**：F-03-16 只说「30 分钟内可编辑」，6.1 没说编辑后状态。
- **后果**：审核通过后把正文改成违规内容即绕过审核（党政内容模块已按「发布态编辑自动退回 PENDING + 写 EDIT 审计」处理）。
- **改法**：审核模式版块内，`published` 态编辑（标题或正文）**自动退回 `PENDING`** 并留原文快照；非审核版块仅留编辑历史。

### 2.7 举报与审核是两条链路，未定义交集

- **问题**：6.2 举报状态机 `pending→handling→resolved/rejected`，但没写：举报被受理后帖子状态怎么变、`rejected`（举报不成立）是否通知被举报人、超时升级靠谁触发。
- **后果**：① 「举报不成立」通知被举报人 = 告诉对方「有人在举报你」，激化矛盾且泄露举报人存在；② 超时升级无定时任务归属 = 永不升级。
- **改法**：举报受理**不自动改帖状态**（处置是独立动作，必须人工/规则命中）；`rejected` **绝不通知被举报人**；超时升级由 `whale-job` 定时扫描 `handling` 超 SLA 工单。

### 2.8 权限判定顺序与错误码——验收点 1 与安全基线冲突

- **问题**：验收点 1 写「无权限用户访问版块 URL 返回 **403**」，平台安全基线是「跨租户/不可见一律 **404** 不泄露存在性」。
- **改法**：分两档并写清：**版块不可见 → 404**（等同不存在）；**版块可见但缺动作权限（如普通员工调审核接口）→ 403**。验收点 1 改为「返回 404，且列表页不出现该版块」。

### 2.9 「部门管理员」不是平台角色 —— 授权段会整段空转

- **问题**：权限矩阵出现「部门管理员」，F-01-05 写「部门可见」，但平台 RBAC 是「角色 + 数据范围（data-scope）」，没有该角色基线。
- **后果**：代码引用 `dept_admin` 而迁移未播种 → 授权 JOIN 为空、权限判定静默失效（项目最高频事故，`check-role-coverage.py` 专治此病）。
- **改法**：版块可见性用**数据范围**表达（`ALL / ROLE:xxx / DEPT:当前用户部门 / PRIVATE`），不新造角色；若确需「部门管理员」，必须同时提交迁移播种 + 角色覆盖门禁通过。

### 2.10 定时任务全部无归属（0 处提到 whale-job）

- **问题**：草稿清理、定时发布、热榜刷新、计数对账、举报超时升级、关注日摘要、签到结算——7 类定时行为，全篇未提调度载体。
- **后果**：实现者用 `@Scheduled` → 多副本部署后**重复发帖 / 重复结算积分**（静默且不可逆）。
- **改法**：统一走 `whale-job`，每个任务登记「任务名 / cron / 幂等键 / 单次上限 / 失败重试」；定时发布用 `status=SCHEDULED` + 扫描抢占（`WHERE status='SCHEDULED' AND publish_time<=NOW()` 条件更新）。

### 2.11 站内信/分享依赖了不存在或未落地的服务

| 文档写法 | 平台实际 | 影响 |
|---|---|---|
| `whale-msg`（F-11-04） | **`whale-message`**（8094） | 名字错 → 有人会去建新服务 |
| `whale-union`（F-03-05） | **`whale-party`**（9009，工会域） | 同上 |
| `whale-drive`（定位段「长文归 whale-drive」） | **不存在**；网盘在 `whale-oa` M3（`oa_drive_*`），文档协作在 `whale-doc`（8095） | 边界指向空 |
| `whale-rag`（F-11-08） | **不存在**；检索是 `whale-agent`（Lucene）+ `whale-ai`（Python，骨架态） | 排期必延期 |
| `whale-im`（F-11-05 分享卡片） | 存在但**状态「规划」未落地**（8091） | P1 项被未落地服务阻塞 |

## 三、建议改（不阻塞开工，但会反工）

1. **F-01-05「私密（需申请）」**：申请 → 审批 → 开通是完整审批流，工作量 ≥ L，当前标 M。建议 P0 只做 `公开 / 角色 / 部门` 三档，私密申请挪 P1 并明确复用 `whale-workflow`（业务键 `FORUM_BOARD_APPLY:{boardId}`）。
2. **F-03-13 草稿多端续写**：本地 + 服务端双写的冲突策略未定义，必然丢稿。建议只做服务端草稿（单稿、`update_time` 乐观锁、冲突提示「另一处有更新」），P0 降为单端。
3. **F-05-04 赠鲸珠 / F-11-10 积分互通**：打赏与积分是**账本**，账本在商城域（`whale-mall` POINTS 形态）。论坛自建第二本账 = 对不上账。改法：论坛只记「打赏流水引用」，扣减/入账全部走 mall 内网接口；且 80/20 分成需先定义平台抽成科目。
4. **F-01-08「在线人数」无数据源**：平台 presence 只在 `whale-im`（未落地）。建议改为「近 5 分钟活跃人数」（`forum_event_log` 近似）或直接砍。
5. **F-11-06 公告同步方向**：OA 发文自动建帖 = 正文双写（OA 改一次、论坛改一次，必不同步）。建议改为**单向引用**：论坛公告帖只存标题 + OA 文号 + 链接，正文不复制。
6. **F-02-10 相关推荐 / F-06-02/03 语义检索与 RRF**：依赖 embedding 服务与向量库，平台均无。P2 保留可以，但**不得写进 P0 验收**，且需先立「向量能力」独立前置项。
7. **重复功能合并**：F-02-02 热榜 / F-06-05 鲸金榜 / F-06-06 精华榜是三套榜单口径。建议只保留「热榜（24h / 7d）+ 精华聚合页」，**砍 30d**（论坛体量下 30d 榜≈全站榜，无信息量）；权重公式必须写死（回复×1 + 投花×2 + 精华×50，处置 −100，时间衰减）。
8. **F-07-03 鲸阶六级**：等级阈值、升降级是否回退、与积分的关系均未定。建议等级只升不降（降级会引发申诉），阈值写表。
9. **F-09-10 内容脱敏**：打码口径要复用平台统一掩码组件，别自写正则（手机号/工号/薪资三类格式已有实现）。
10. **F-11-12 ClickHouse 埋点**：平台无 ClickHouse。建议落 `forum_event_log`（append-only，按月分区），或直接接 Prometheus 业务指标，砍掉「停留时长」类细粒度埋点。

## 四、与平台现状对照（技术选型必须换）

| 文档要求 | 平台实际能力 | 建议 |
|---|---|---|
| ES 检索（F-06-01） | 无 ES；MySQL **ngram 全文索引**（mail/doc 已用）+ 单字回退 LIKE；`whale-agent` 有 Lucene | 改 ngram；索引重建走 `whale-job` |
| 向量检索 / RRF（F-06-02/03） | 无向量库，embedding 仅 `whale-ai`（骨架，pytest 未跑通） | 挂 P2 前置项，不排期 |
| ClickHouse（F-11-12） | 无；可观测是 Prometheus + Grafana + `audit_log/api_log` | 改 `forum_event_log` |
| Redis 计数回写（F-05-05） | Redis 用于黑名单/限流/去重，非持久账本 | 改 DB 条件更新 + 对账 Job |
| AI 内容审核 + 图片 OCR（F-09-02） | 无 OCR；文本模型可经 `whale-ai` 但未稳定 | P1，先做敏感词 + 人工队列；AI 审核标「试点」 |
| 短链服务（F-02-11 生成短链） | 无短链服务 | 用站内 `/forum/thread/{id}` 直链 + 网关同域，砍短链 |
| 站内信推送（F-08-01「站内信 + 推送」） | `whale-message` 有站内信；**无移动推送通道** | 改「站内信 + 邮件（`whale-mail` 8099）」，砍推送 |

> 这七项里，**ES 与 ClickHouse 两条如果照抄，等于新引入两套中间件**——当前常态栈 22 容器已把 Docker VM 的 8GB 吃到只剩约 600MB，装不下，且违反「新工具链必须落 F 盘 + 可重建」的约束。

## 五、缺失章节（作为验收对照必须有）

1. **落位表**：端口（8081–8100 已满，建议 9011 例外登记）、库 `bluewhale_forum`、表前缀 `fm_`、网关 `lb://whale-forum` + `/forum/**`（不剥前缀）、`/forum/internal/**` internal-deny、前端子应用 8123、服务名 `whale-forum`（五同铁律）。
2. **权限与菜单号段**：建议权限 **2340–2350**（23xx 段已占 2300–2306 / 2313 / 2320–2323，且 2330–2339 属 whale-assistant）、菜单 **510–519**（现最大 505）；授权语句**按 perm_code 不按 ID 区间**。（原稿建议 2330–2359，落码时发现与 `V8__assistant_permission_menu.sql` 的 2330/2331 撞号，已整体后移。）
3. **非功能上限**：标题/正文字数、附件类型与大小、单帖楼层上限、分页 size 上限（建议 100）、`@` 单帖上限（建议 20）、导出上限。
4. **错误码表**：建议 30xxx 段（30001 帖子不存在 / 30010 楼层冲突 / 30020 退回必填意见 / 30030 内容消毒失败 / 30031 敏感词拦截）。
5. **降级策略**：`whale-message` 不可达时通知落本地 outbox 重试（不阻断发帖）；`whale-file` 不可达时禁止带图发帖并提示；检索不可用时自动回退 LIKE。
6. **数据保留**：软删内容保留期（建议 180 天）、审计表 append-only 不设 `update_time/deleted`、合规导出范围。

## 六、排期口径问题

1. **78 人日只算功能，没算基建**：qiankun 子应用骨架、权限映射、路由、antd React 19 补丁、七项门禁接线、单测与 Checkstyle——平台每个子应用实际落地都超出纯功能估算。
2. **2D 比 3D 贵 11 人日的解释站不住**：3D 版 67 人日含 8 人日 3D 元素 → 纯功能 59 人日；2D 却 78 人日。真实原因是**两版功能清单不同源**（2D 拆得更细），不是 2D 更贵。对比表应改为「同口径功能项」而不是总人日。
3. **P0 瘦身后建议**：把 F-01-05 私密申请、F-03-02 问答、F-03-03 投票、F-04-03 楼中楼、F-05-03 结契、F-06-01 搜索 移出 P0（或降级为「只读占位」），P0 可压到 **22–24 人日**，与平台论坛设计稿 M0+M1+M2 对齐：

| 批次 | 对应设计稿 | 内容 |
|---|---|---|
| P0（22–24 人日） | M0 | 版块树 + 权限三档、帖子列表/详情、发帖回帖、投花藏帖、敏感词 + 待审队列、举报受理、通知（回复/@/处置）、后台四页 |
| P1（20 人日） | M1 + M2 | 问答/投票/活动帖、楼中楼、最佳答案、鲸阶积分、热榜、ngram 搜索、申诉、看板 |
| P2（15 人日） | M3 + M4 | 语义检索、相关推荐、勋章签到、赠鲸珠（走商城账本）、重复折叠、RAG 同步、导出 |

## 七、验收清单逐条修订

| # | 原判据 | 问题 | 建议判据 |
|---|---|---|---|
| 1 | 无权限访问版块 URL 返回 **403** | 与「不泄露存在性」冲突 | 返回 **404**；列表页不出现该版块；普通员工调管理接口返回 403 |
