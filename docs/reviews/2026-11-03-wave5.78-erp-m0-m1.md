## 2. 变更清单

### 2.1 数据库迁移（`whale-backend/whale-apps/whale-erp`）

- 新增 `V2__masterdata_finance.sql`：13 张表 + 幂等 `INSERT IGNORE` 种子。
  - 主数据：`erp_account`（科目 7001–7020）、`erp_accounting_period`（2026 年 12 个期间 7101–7112）、
    `erp_customer`（7201–7202）、`erp_warehouse`（7301）、`erp_uom`（7401–7404）、
    `erp_currency`（7501 CNY 本位币 / 7502 USD）、`erp_tax_code`（7601–7604）；
  - 财务：`erp_fin_voucher` / `erp_fin_voucher_line` / `erp_fin_receivable` /
    `erp_fin_receivable_settlement` / `erp_fin_payable` / `erp_fin_payable_settlement`；
  - 约束：`uk_account_code`、`uk_period_code`、`uk_customer_code`、`uk_warehouse_code`、
    `uk_voucher_no(tenant_id, period_code, voucher_no)`、`uk_receivable_doc_no`、`uk_payable_doc_no`；
  - 金额 `DECIMAL(18,2)`、汇率 `DECIMAL(18,8)`；禁止 `DROP/TRUNCATE/DELETE`。

### 2.2 后端代码（新增约 60 个文件）

- `common`：`ErpErrorCode`（400xx/404xx/409xx 三段）、`Amounts`（金额正负与合计）；
- `masterdata` 四层：`Account`/`AccountingPeriod`/`Customer`/`Warehouse`/`Uom`/`Currency`/`TaxCode`、
  7 个仓储端口与实现、`MasterDataAppService`、3 个保存命令与 6 个视图；
- `finance` 四层：`Voucher`/`VoucherLine`/`Receivable`/`Payable`/核销流水、6 个仓储实现、
  `VoucherAppService`、`ArApAppService`、`FinanceReportAppService`、`AgingCalculator`；
- `interfaces`：`MasterDataController`、`VoucherController`、`ArApController`、`FinanceReportController`、
  `ErpUserContext`、`PageParams`；
- 关键规则：
  - 凭证借贷平衡、单边金额、非负、期间必开、科目必须末级且启用；
  - 已记账凭证只能红冲，红冲生成 `TYPE_REVERSAL` 反向凭证并写 `reversal_of_id`；
  - 核销不得超过未结余额；坏账计提不得超过未结余额；结清后禁止继续核销；
  - 期间关账后禁止记账，反结账需独立权限与审计；
  - 资产负债表将未结转收入/费用以「本年利润（未结转）」计入权益，保证报表平衡。

### 2.3 权限脚本

- 新增 `migration-5.78-erp-finance.sql`：
  - 权限 355–367（主数据 13 项）、375–387（财务 13 项），`INSERT ... WHERE NOT EXISTS` 幂等；
  - 角色 `erp_finance`(25110)、`erp_masterdata`(25111)，业务租户按 `MD5(tenant:role)` 复制；
  - 授权：`tenant_admin/erp_manager/erp_finance` 26 项；`erp_masterdata` 13 项；`erp_member` 10 项只读；
  - 菜单 63–66；脚本末附校验 SQL。

### 2.4 前端（`whale-frontend/platform-apps/whale-erp`）

- `api/masterdata.ts`、`api/finance.ts`：分页信封、主数据与财务类型、查询/动作函数；
- `pages/MasterDataPage.tsx`：科目 / 期间 / 客户 / 仓库四页签，关账/反结账动作；
- `pages/VoucherPage.tsx`：凭证列表、录入（多分录）、查看、记账、红冲；
- `pages/ArApPage.tsx`：应收台账、应付台账、账龄分析，核销与坏账 Modal；
- `pages/ReportPage.tsx`：明细账、科目余额表、资产负债表、利润表；
- `App.tsx`：新增菜单与页面切换；`package.json` 增加 `dayjs`；
- 基座 `whale-platform/src/router/menu.ts`：`/erp` 目录展开为物料/供应商/主数据/凭证/应收应付/报表，
  避免仅财务权限的用户看不到 ERP 入口。

## 4. 残余项与后续

| # | 残余 | 影响 | 建议 |
|---|---|---|---|
| R1 | M1-4 自动记账接口未实现 | 供应链单据尚不能自动生成凭证 | 随 M2 采购/销售/库存一起设计科目映射（D5） |
| R2 | 多币种仅存字段，未做汇率换算与汇兑损益 | 外币业务金额按原币入账 | M2 增加 `erp_exchange_rate` 与期末调汇 |
| R3 | 存量 `item`/`supplier` 未迁入 `masterdata` 四层包 | 新旧结构并存 | 单独小步迁移，保持 API 与响应不变 |
| R4 | 期初余额、期末结转、总账汇总表未实现 | 只能从 2026 年启用 | M1 后续迭代补「期初导入 + 结转」 |
| R5 | 账簿/报表分页为全量返回 | 大数据量下性能风险 | M6 增加报表快照或按需分页 |
| R6 | 实机冒烟未执行 | 网关路由与 auth 脚本未在真实库验证 | 部署环境执行 `migration-5.78-erp-finance.sql` 后按 §2.3 校验 SQL 核对 |

---

## 5. 结论

M0 + M1 的主链路（主数据 → 凭证 → 账簿/报表；客户/供应商 → 应收应付 → 账龄）已经闭环，
边界与权限可独立验收。M1-4 自动记账是 M2 的前置条件，建议下一阶段先确认 D5 科目映射规则再启动供应链。
