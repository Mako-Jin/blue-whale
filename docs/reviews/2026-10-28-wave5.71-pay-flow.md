# Wave 5.71 · whale-pay 支付闭环（F-04）检查报告

> 日期：2026-10-28
> 范围：whale-pay 代码、`bluewhale_pay` 建表与迁移、`bluewhale_auth` 权限、本地起服实机验证
> 结论：**F-04 结案（真实渠道仍按既定口径 mock）；17 个单测通过，网关 8 项实机检查全部 PASS**

## 1. 变更前状态

- `whale-pay` 只有支付单分页/详情/创建与 `pay`/`cancel` 状态占位，无渠道调用、无退款、无流水、无对账。
- `pay_order` 历史库缺 `tenant_id`，但多租户拦截器会追加 `tenant_id = ?`，创建前置查重直接 SQL 报错。
- 支付单金额无正数/精度校验，渠道无白名单；并发创建仅靠 `selectCount` 查重，撞唯一索引时抛系统异常。
- `bluewhale_pay` 缺 `audit_log`（`@AuditLog` 写库失败被吞掉）；`tenant_admin` 未被授予 `sys:pay:*`。

## 4. 未覆盖 / 风险

1. **真实渠道未接入**：`whale.pay.mock=true` 时不产生真实资金流；关闭 mock 会明确报错「真实支付渠道尚未接入」。真实支付宝/微信/银联适配、证书与回调验签需按部署侧供应商条件排期。
2. **退款仅支持全额**：多次部分退款、退款单独立编号、退款失败重试未实现。
3. **对账为单笔即时比对**：没有按日/按渠道的批量对账文件拉取与差错池。
4. **渠道失败不落流水**：失败动作依赖 `audit_log`/`api_log`；后续接入真实渠道时应补 `FAILED` 流水（需 `REQUIRES_NEW` 事务避免回滚）。
5. 历史库若缺 `tenant_id`，必须先执行 `migration-5.71-pay-flow.sql`，否则创建支付单会因多租户条件报 SQL 错误。
6. 权限 403 验证使用临时无角色用户，验证后已删除；`tenant_admin` 的支付权限已补齐，但前端支付菜单/按钮尚未接入。

## 5. 结论

F-04 的代码侧缺口已收口：支付单从「占位流转」升级为包含金额/渠道校验、mock 渠道调用、成功流水、全额退款与单笔对账的最小闭环，并修复了历史库 `tenant_id`/唯一键与 `audit_log` 缺失问题。真实渠道、批量对账与部分退款属于外部条件或后续增强，已在待办中明确边界。
