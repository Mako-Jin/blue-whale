## 2. 变更清单

### 2.1 数据库迁移

`whale-backend/whale-apps/whale-mes/src/main/resources/db/migration/V4__mes_dispatch_execution.sql`

- 调度：`mes_dp_work_order_task`、`mes_dp_dispatch_order`、`mes_dp_dispatch_line`、
  `mes_dp_schedule_plan`、`mes_dp_schedule_slot`；
- 执行：`mes_ex_production_report`、`mes_ex_report_defect`、`mes_ex_material_issue`、
  `mes_ex_material_issue_line`、`mes_ex_material_return`、`mes_ex_wip_snapshot`、
  `mes_ex_exception`、`mes_ex_exception_action`；
- 关键唯一键：任务 `(tenant_id, task_no)` 与 `(tenant_id, work_order_id, seq_no)`、
  派工明细 `(tenant_id, dispatch_order_id, task_id)`、在制品 `(tenant_id, task_id)`，
  报工 / 领料 / 退料 / 异常均按单号唯一；
- 任务表含计划 / 已派工 / 报工 / 合格 / 不良 / 完工 / 报废七类数量、状态、优先级与乐观锁 `version`。

### 2.2 后端（`com.bluewhale.mes`）

- `dispatch` 上下文：
  - `MesDispatchService`：`receive`、`split`、`dispatch`、`withdraw`、`pageTasks`、`board`；
  - 拆分不传明细时按已发布工艺路线派生，校验序号唯一且各序合计 = 工单计划量；
  - 派工校验任务同一工单、均处于 `PLANNED`、产线 / 班组启用，生成 `DSP-` 单号并回写任务与工单；
  - 撤回仅限 `DISPATCHED` 派工单且任务无报工，回退任务与工单状态；
  - `MesTaskProgressService` 汇总任务进度并按工单状态机迁移，完工时写发件箱。
- `execution` 上下文：
  - `MesExecutionService`：`start/pause/resume/complete/scrap`、`report`、`pageReports`、`wip`、
    `raiseException`、`handleException`、`issueMaterial`、`returnMaterial`；
  - 报工追加式落库并累加任务数量、刷新在制品与工单；完工取累计合格数；报废需原因且不得超已派工；
  - 异常至少关联工单或任务，动作追加到 `mes_exception_action`；
  - 领料 / 退料校验工单与任务归属，补料原因必填。
- `common`：`MesCodeGenerator`（`前缀-yyyyMMddHHmmss-6位UUID`）、`MesOutboxDispatcher`
  （`@Scheduled`，默认 `whale.mes.outbox.enabled=false`，退避 1/5/15/60 分钟）。
- `masterdata`：新增 `MesRoutingSnapshot` / `MesRoutingOperation` 实体与 Mapper，供自动拆分读取。
- 网关：`/mes/internal/**` 加入 `internal-deny`，外部访问 403。

## 4. 破坏性变更与口径说明

- 工序任务状态由设计稿草案的 `PENDING/READY/CLOSED` 收敛为
  `PLANNED → DISPATCHED → IN_PROGRESS ⇄ PAUSED → COMPLETED / SCRAPPED`，设计稿已同步回填。
- 异常状态由草案的 `PROCESSING/ESCALATED` 收敛为四态最小集，后续增强不改变既有编码。
- 工单状态仍由 `MesWorkOrderServiceImpl` 与 `MesTaskProgressService` 双入口维护，
  开工 / 报工 / 完工路径以任务汇总为准，避免手工跳转。
- 旧 `/mes/work-order/**` 5 个端点保持不变。
