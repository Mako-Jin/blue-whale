## 二、变更点

### 2.1 后端 B 轨：whale-workflow 最小可加性补强

- **节点字段与 JSON 往返**：`support/ProcessModelNode` 新增 `formId`(String)/`formCode`(String)/`x`(Integer)/`y`(Integer)；`ProcessModelParser.readNode` 逐字段读取（`x`/`y` 缺省为 `null`，legacy 分支不带新字段）；`service/impl/ProcessModelServiceImpl.toJson` 用 `putIfPresent`/`putIfPresentInt` 对称写出。
  - 关键点：解析器与序列化器均**逐字段**读写 `JsonNode`，未知字段静默丢弃 → 新字段必须显式加，否则不持久化。
- **校验码**：`support/ValidationCode` 新增 `USER_TASK_FORM_CODE_INVALID`（`formCode` 非空须匹配 `^[A-Za-z0-9_-]{1,64}$`）、`USER_TASK_FORM_INCOMPLETE`（`formId`/`formCode` 必须**成对**出现）；`support/ProcessModelValidator` 新增 `checkUserTaskForm`，**仅对 `USER_TASK` 生效**，仅做边界格式与成对性校验（不校验表单存在性）。
- **BPMN 对称往返**：`support/bpmn/BpmnXmlParser` 读**任意前缀** `formKey`/`formId`（兼容 `flowable:`/`camunda:`）；`BpmnXmlWriter` 在两者非空时写 plain `formKey`/`formId`；**`x`/`y` 坐标不进 XML**（不进 DI）。
- **库表/实体/VO/建任务回填**：`process_task` 加 `node_key`/`form_id`/`form_code`（均 `VARCHAR(64) NULL`）；`entity/ProcessTask` 与 `vo/ProcessTaskVO` 同步 3 字段；`ProcessInstanceServiceImpl` 与 `ProcessTaskServiceImpl` 建任务时从节点模型回填这 3 列（存量行为 `NULL`，回落 `node_index` 语义）。
- **DDL**：新增 `resources/db/migration-5.32.sql`（**幂等**：`information_schema` 存在性守卫 + `PREPARE/EXECUTE/DEALLOCATE`，规避 MySQL 8.0 不支持 `ADD COLUMN IF NOT EXISTS`）；`resources/db/init.sql` 权威同步。
- **测试**：6 个测试类扩展，**新增 18 用例**（新字段往返 / 两个新码 / 三列落库 / BPMN `formKey` 往返）；whale-workflow 由 5.31 基线 **102 → 120 用例全绿**（零回归）。

### 2.2 前端 S 轨：共享表单渲染器

- 新增 `frontend/elemental/whale-ui/src/components/FormRenderer/index.tsx`（从 form-designer 原样迁入，导出 `FormRenderer` / `FormRendererProps` / `WhaleFormFieldConfig`）；`src/index.ts` 按既有**具名 re-export** 约定导出（规避 TS2742）。
- `frontend/platform-apps/whale-form-designer/src/render/FormRenderer.tsx` 改为 `export { FormRenderer as default } from '@bluewhale/whale-ui';`，**调用点零改动**。

- 结构核对：`WhaleFormFieldConfig` 与既有 `FieldConfig` 结构完全一致，无类型断层。

### 2.3 前端 F0/F1–F5：新应用 `whale-workflow-designer`（8003）

- **骨架**：`package.json`/`index.html`/`tsconfig.json`/`vite.config.ts`（8003 + 正则 proxy）；`api/{token,http,auth,workflow,form}.ts`（`Id = string`，**全链路禁 `Number(id)`**，storage 前缀 `whale_wf_`；`workflowApi` 单对象 15 方法）；`router/guards.tsx`；`layouts/AppLayout.tsx`（四菜单）；`pages/Login.tsx`；`main.tsx`/`App.tsx`。

  - `Canvas`：SVG 自绘；整块画布 `useDroppable`；节点 `useDraggable`（`PointerSensor` + `activationConstraint:{distance:4}` 区分「点击选中 / 拖拽移动」）；`handleDragEnd` 对 palette 源按拖影中心换算局部坐标、对 node 源按 `delta` 写回（10px 网格吸附）。

### 2.4 本轮修复 / 收口的两个前端问题

- **whale-ui 产物把 `dayjs` 打包**：`tsup` 未声明 external 且未在 dependencies 声明 → 补 `external: ['dayjs']` + `dependencies.dayjs`，重装重构建通过。

## 四、风险与遗留

| 项 | 说明 |
|---|---|
| C4 拖拽手势未自动化验证 | 拖拽源 DOM 接线已确认正确（dnd-kit 属性齐备），但自动化工具无「按下并拖动」低层原语、合成 PointerEvent 不被 dnd-kit `PointerSensor` 接受 → **需人工复核**。非本轮引入的回归（Wave 5.29/5.30 同一限制） |
| 画布可视区 | 画布为固定大尺寸 SVG 置于 `overflow:auto` 容器内，节点超出可视区需滚动查看（自动化点击被拦截的根因）。属画布常规交互，非缺陷；如需可后续加「缩放/自适应」 |
| 审批表单只读 | 本轮审批抽屉仅**只读回显**绑定表单数据，不支持在审批时修改并回写（spec §六 明确削减） |
| 表单存在性不校验 | `formId`/`formCode` 仅做格式与成对性校验，不校验表单是否真实存在（避免后端耦合 whale-form）；发起时若表单不存在则降级为无表单分支 |
| 条件表达式仍未求值 | 沿用 Wave 5.31：`condition` 不参与选路，设计器可编辑但仅产生 `CONDITION_IGNORED` 警告 |

## 五、结论

Wave 5.32 达成「工作流前端（管理 + 绘制 + 表单绑定）」目标：新独立应用 `whale-workflow-designer`（8003）四域贯通——**流程定义管理**、**自由画布绘制（节点可绑定表单管理器的表单）**、**发起 + 填表单**、**待办审批（表单只读回显）**、**实例监控**；后端以**最小可加性**方式补强节点表单绑定与画布坐标，**向后兼容** Wave 5.31 的 JSON 事实源与 legacy 定义（120 用例零回归）。构建门禁（28/28 模块 + 14/14 前端任务）、DDL 落库、运行时冒烟（15/15）与浏览器实机 E2E（A–G 全链路 PASS）全部通过。唯一遗留为 **C4 拖拽手势**——自动化受限，**需人工复核**（接线已确认无误）。
