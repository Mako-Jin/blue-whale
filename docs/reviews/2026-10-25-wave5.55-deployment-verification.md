### 已修正问题项（冒烟脚本）

1. **PowerShell 5.1 请求体默认编码丢中文**：`-ContentType 'application/json'` 未声明 charset，中文被写成 `?`，导致关键字检索不命中 → 全部改为 `application/json; charset=utf-8`。
2. **工作项 / 报表冒烟直接 `TODO → DONE`**：与默认流转链（`TODO → IN_PROGRESS → DONE`）不符，返回 400「未配置该状态流转」→ 改为两跳流转。
3. **`ExpectReject` 只识别 HTTP 4xx**：统一响应体以 HTTP 200 + `code!=0` 返回业务异常，负向用例被误判为「unexpectedSuccess」→ 兼容业务码判定。
4. **报表冒烟未考虑 5 分钟缓存**：变更后立刻读燃尽仍为旧快照（8 点）→ 按缓存语义接受快照，另用未缓存区间（`cumulative-flow` 新日期区间）验证 DONE 归类即时生效，`velocity` 改用 `limit=6` 走新缓存键。
5. **报表冒烟聚合断言**：`AssertSuccess` 传入聚合对象无 `code` 字段必然失败 → 改为逐个响应断言。
6. **UTF-8 无 BOM 脚本在 PS 5.1 下按 ANSI 解析**：中文与引号错位 → 以「UTF-8 读取 + `scriptblock::Create`」方式执行（本次记录执行方式，脚本本身保持 UTF-8）。

## 四、遗留与建议

### P2-1 并发首建机器人会话偶发失败（whale-im）

- 现象：一轮集成冒烟中评论通知 `delivered=0`，IM 日志 `WARN ImNotifyService 站内通知投递失败 userId=2`，根因链为 `Duplicate entry '1-B:2' for key 'im_conversation.uk_tenant_pair_key'`。
- 分析：`ImBotService#openDefault` 已 `catch (DuplicateKeyException)` 并重查，但方法处于 `@Transactional` 中，MySQL 默认隔离级别为 **REPEATABLE READ**；并发事务的插入在本事务快照中不可见，`findExisting` 仍返回 `null` 后 `throw e`，导致该接收人丢通知。本轮两次并发复现实验（新用户首建）均成功，说明为时序相关。
- 建议修复（需构建环境回归）：`openDefault` 改为 `@Transactional(isolation = Isolation.READ_COMMITTED)`，或将「创建 + 回收重查」拆到 `Propagation.REQUIRES_NEW` 的独立组件；补一条并发回归用例。

### P3 遗留

1. 审批真机联调需 `whale-workflow` 与流程定义 ID；本期仅验证关闭态。
2. 角色补授 172–202 未在真实业务角色上执行（admin 有 `super_admin`）。
3. `api_log` 建表未纳入 `whale-im` 等服务的 `init.sql`，本轮手工补建，建议统一收敛到公共日志 SDK 的初始化脚本。
4. 本机 Maven 本地仓库缺少 Spring Boot 4.0.8 依赖（无网络条件重下），本轮**未能执行 Java 构建/单测**；已提交的 Java 代码与上一轮 `BUILD SUCCESS` 一致，本轮无 Java 变更。
