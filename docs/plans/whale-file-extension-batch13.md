# whale-file 能力扩展（批次 13：版本回滚）

## 一、范围与决策

批次 11、12 已落地版本模型、新版本上传、版本列表以及删除/恢复级联。本批次补齐版本回滚：
把历史版本的内容重新发布为「新版本」，使文件当前内容回到指定版本，同时保留完整历史。

| 事项 | 本轮 | 说明 |
| --- | --- | --- |
| 回滚为复制新版本 | ✅ | 读取目标版本对象，复制为新对象键，登记为版本号最大 + 1 的新版本 |
| 指针切换式回滚 | ❌ | 会破坏历史版本语义，不采用 |
| 目标版本校验 | ✅ | 目标版本必须属于该版本组且未逻辑删除；根版本（version=1）可回滚 |
| 配额 | ✅ | 复制产生新物理对象，按目标版本字节数计入个人/租户/桶配额 |
| 旧版本保留 | ✅ | 回滚不修改、不删除任何既有版本 |
| 回滚事件/审计 | ❌ | 回滚表现为新增版本，沿用上传语义；见待做项 |
| 数据库变更 | ❌ | 复用 `parent_id` / `version` |

**保留策略**：回滚采用「复制为新版本」，新旧版本各自持有独立物理对象。优点是删除、恢复、
到期清理与配额口径完全复用既有逻辑，不需要引入对象引用计数；代价是回滚会额外占用一份存储，
需要容量规划时计入。

## 二、设计

### 2.1 应用层

`FileInfoService` 新增：

```java
FileVersionResult rollback(Long id, int targetVersion, Long requesterId, boolean canManage, UploadLimits limits);
```

流程：

1. 解析版本组根文件（传入版本行时回溯），校验可见性与 `NORMAL` 状态；
2. 在组内未删除版本中查找 `version == targetVersion`，不存在返回 `NOT_FOUND`；
3. 按目标版本字节数做配额预检；
4. 计算下一版本号：组内最大值 + 1（与上传一致，已删除版本序号不复用）；
5. 以目标版本落盘插件读取对象流，写入根文件桶下的新对象键（沿用
   `tenants/{tenantId}/yyyy/MM/dd/<uuid>.<ext>` 规则）；
6. 以目标版本的原始文件名、大小、类型、MD5 登记新版本，上传者为当前请求者；
7. 元数据落库失败时补偿删除新对象；记录 `mode=rollback` 上传指标。

**为什么不复制对象键**：直接让新版本复用目标版本的对象键会让两个元数据行共享同一物理对象，
到期清理任意一行都会删掉另一行仍在引用的对象；复制对象键让每行独立持有对象，语义简单且安全。

### 2.2 接口

`FileVersionApi` 新增：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/file/v1/{id}/versions/{targetVersion}/rollback` | `sys:file:upload` | 回滚到指定版本，返回新版本元数据 |

回滚不新增权限码：其效果等同于「上传一个内容与历史版本一致的新版本」，复用 `sys:file:upload`。

## 四、完成情况

- 应用层：`FileInfoService#rollback` 解析根文件与目标版本，校验状态、目标存在性与配额后，
  按目标版本落盘插件读取对象流，复制到根文件桶的新对象键，登记为组内最大版本号 + 1 的新版本；
  落库失败补偿删除新对象，记录 `mode=rollback` 上传指标。
- 接口：`FileVersionApi`/`FileVersionController` 新增
  `POST /file/v1/{id}/versions/{targetVersion}/rollback`，权限复用 `sys:file:upload`。
- 测试：应用层回滚成功、目标版本不存在、归档锁定拒绝、配额不足、落库失败补偿共 5 项；
  控制器回滚响应与权限注解 1 项。

## 六、已修正问题项

- 回滚若直接复用目标版本对象键，两个元数据行共享物理对象，删除/清理任意一行会破坏另一行 →
  改为复制为新对象键，每行独立持有对象，删除与配额语义保持简单。
- 读取源对象与落库失败需要同一套补偿，但关闭流失败属 `IOException`、落库失败属
  `RuntimeException` → 分开捕获，统一补偿删除新对象并只记录一次 failure 指标。

## 七、待做项
