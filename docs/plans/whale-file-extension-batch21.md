# whale-file 能力扩展（批次 21：秒传同用户去重语义）

## 一、范围与决策

批次 1 遗留了「`rapidUpload` 同用户同文件去重语义」。现状：秒传只按 MD5 + 大小命中任意正常
文件，再新建一条元数据；同一用户反复上传同一个文件会不断产生重复行并重复计入配额。

本批次明确语义：**同一用户、同一原始文件名、同一摘要与大小**的秒传直接返回既有文件，
不再新建元数据、不再重复计配额；文件名不同仍视为不同逻辑文件，保持原有「复用物理对象 +
新建元数据」行为。

| 事项 | 本轮 | 说明 |
| --- | --- | --- |
| 同用户同文件名去重 | ✅ | 命中既有正常根文件时直接返回，不落新行、不计配额 |
| 同名但不同用户 | ✅ | 不跨用户去重，各自保留元数据与配额口径 |
| 文件名不同 | ✅ | 维持原有复用物理对象 + 新建元数据 |
| 版本行参与去重 | ❌ | 仅匹配根文件（`parent_id IS NULL`），避免返回版本行 |
| 锁定/禁用文件 | ❌ | 仅匹配状态正常文件，与既有秒传口径一致 |
| 数据库变更 | ❌ | 无 |

**配额口径**：去重命中不产生新的逻辑文件，因此不校验、不计入配额；物理对象本已存在，
也不产生新的存储占用。

## 二、设计

- 仓储新增 `findReusableByUploaderAndDigest(uploaderId, md5, size, originalName)`：
  按上传者 + 摘要 + 大小 + 原始文件名查询正常、未删除的根文件，主键升序取第一条；
  摘要大小写不敏感，空白摘要/文件名或空上传者直接未命中。
- `rapidUpload` 顺序：
  1. 校验声明大小；
  2. 同用户同文件去重命中 → 直接返回该文件（`hit=true`），不查全局、不落库、不计配额；
  3. 未命中 → 原有全局摘要复用逻辑不变。
- 指标沿用 `rapid/success`，不引入新标签值。

## 三、测试计划

| 范围 | 用例 |
| --- | --- |
| 仓储 | 同用户同文件命中并映射；空上传者/空白摘要/空白文件名直接未命中且不查库 |
| 应用层 | 命中时返回既有文件且不落库、不校验配额、不查全局摘要；未命中时走原有全局复用并新建元数据 |
| 回归 | 既有秒传命中/未命中、配额、指标用例保持通过 |

## 四、完成情况

- 仓储新增 `findReusableByUploaderAndDigest`：上传者 + 摘要 + 大小 + 原始文件名，限正常、
  未删除、`parent_id IS NULL` 的根文件，主键升序取第一条；
- `rapidUpload` 在全局摘要复用之前先做同用户同文件去重，命中直接返回既有文件，
  不落新行、不校验配额、不写存储；未命中保持原有全局复用逻辑；
- 测试：仓储命中与空参数短路、应用层去重命中不落库不计配额共 2 项；既有秒传用例回归通过。
