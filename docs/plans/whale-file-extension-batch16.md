# whale-file 能力扩展（批次 16：存储落盘加密）

## 一、范围与决策

文件内容在对象存储/本地磁盘中以明文保存，介质泄露即可直接读取。本批次在存储注册表层增加
可选的整对象加密：写入时用 AES-GCM 加密，读取时透明解密，业务层与接口层无感知。

| 事项 | 本轮 | 说明 |
| --- | --- | --- |
| 写入加密 | ✅ | AES-256-GCM，随机 12 字节 nonce，密文带认证标签 |
| 读取解密 | ✅ | 按对象头部魔数自动识别，存量明文对象继续可读 |
| 开关与密钥 | ✅ | `whale.file.storage.encryption.enabled/key`，启动期校验密钥 |
| Range 读取 | ✅ | 加密对象从对象头解密后跳过偏移，再按长度截断 |
| 预签名直连 | ❌ | 预签名绕过应用层，加密对象会返回密文；见待做项 |
| 密钥轮换/多版本密钥 | ❌ | 见待做项 |
| 存量明文加密 | ❌ | 可通过批次 14 迁移工具先搬家，再人工重新上传；见待做项 |
| 数据库变更 | ❌ | 无 |

**格式**：`"WHALEENC"`（8 字节魔数）+ 12 字节 nonce + GCM 密文（含 16 字节标签）。
读取时不足 20 字节或魔数不匹配即按明文处理，因此开启加密不影响既有明文对象。

**限制**：Range 读取在认证标签之前截断，完整性校验只在完整读取时由 GCM 标签触发；
预签名下载返回的是密文，启用加密后应引导客户端走网关下载。

## 二、设计

加密落在 `StoragePluginRegistry`（唯一 `FileStorage` 实现）内部：

- `store`：生成 nonce → `AES/GCM/NoPadding` 加密 → 魔数 + nonce 前缀 → 交给活动插件落盘；
- `load(全量)`：读取对象头，命中魔数则用 `CipherInputStream` 解密，否则回吐头部按明文返回；
- `load(offset,length)`：先探测对象头，明文对象继续走插件原生区间读取；加密对象从头解密、
  跳过 offset、按 length 限制；探测失败回落明文路径；
- `delete/move/listObjects` 不感知加密：移动搬运的是密文，删除与对账逻辑不变。

启动期：启用加密但密钥缺失或不是 Base64 的 16/24/32 字节时直接启动失败，避免运行时才发现。

## 四、完成情况

- `FileProperties.Storage` 新增 `encryption.enabled` / `encryption.key`；
- `StoragePluginRegistry` 内部实现 AES-GCM 整对象加密：写入输出「魔数 + 12 字节 nonce + 密文」，
  读取按魔数自动解密；全量读取用 `PushbackInputStream` 回吐明文头部，区间读取先探测对象头，
  密文对象从头解密后跳过偏移并按长度截断，明文对象继续走插件原生区间读取；
- 启用加密但密钥缺失或非法时构造期直接失败；
- 删除、移动、列举、健康检查与预签名路径不变（移动搬运密文）；
- 测试：加密往返、Range 解密、存量明文兼容、非法密钥启动失败共 4 项。

## 六、已修正问题项

- 密文对象的区间读取若直接交给插件原生 Range 会返回密文字节 → 先探测对象头，密文对象
  从头解密后跳过偏移并截断，明文对象保持原生区间读取，兼顾正确性与性能。
- 对象头探测可能因对象过短或插件实现差异失败 → 探测异常时回落明文路径，由后续真实读取
  暴露错误，避免探测把可读文件误判为不可读。

## 七、待做项

- 预签名直连与加密的兼容：改为网关解密、或对加密对象禁用预签名。
- Range 读取的完整性校验：改用分块加密，使每个片段都可独立认证。
- 密钥轮换与多版本密钥（对象头携带密钥版本号）。
- 存量明文对象加密：需要离线重写任务与双写过渡。
