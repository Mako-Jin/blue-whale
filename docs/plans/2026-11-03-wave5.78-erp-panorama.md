## 3. 首个切片建议（M0 + M1）

**为什么不是先做采购/销售**：全景把财务定义为核心骨架，且所有交易最终都要生成凭证。若先做交易单据，凭证科目映射、期间、计价方法未定，后续必然返工。先建「科目 + 期间 + 凭证 + 应收应付」，交易模块上线时只需接事件，不改财务内核。

## 4. 各里程碑要点

### M2 财务扩展 + 供应链

- 财务：固定资产（卡片/折旧/变动/盘点/处置）、成本核算（归集/分摊/差异）、预算（编制/控制/执行）、资金（计划/银行对账/票据/现金流预测）。
- 供应链：采购申请→订单→收货→退货；销售报价→订单→发货→退货；库存出入库/调拨/盘点/批次/安全库存/呆滞；价格管理与信用额度。
- **关键闭环**：收货生成应付与入库成本；发货生成应收与出库成本；盘点差异生成调整凭证。
- 验收：单据状态机不可跳转；禁止负库存；自动凭证平衡；信用超限按 D8 规则阻断；库存流水只追加。
- **2026-11-04 进度**：采购订单 / 销售订单 / 库存 + 自动记账已交付（见 §11）；财务扩展与退货、调拨、盘点、价格管理待排期。

### M3 生产计划

- 预测 → MPS → MRP（BOM 展开，BOM 来自 PDM 快照）→ CRP → 生产订单 → 下发 MES → 完工回传 → 完工入库与成本归集。
- MRP/CRP 异步任务：任务表 + 进度 + 可重跑；同输入结果可重放。
- 验收：MRP 结果可追溯需求来源；计划订单可转采购/生产；MES 重复回调幂等；完工入库数量 ≤ 计划量。

### M4 轻量人力

- 员工/组织/入转调离；考勤汇总（数据可导入，请假加班来自 OA 事件）；薪资批次计算（社保公积金/个税参数化）、工资条、绩效。
- 验收：薪资期间唯一；`APPROVED` 后明细不可改；工资条仅本人可见；薪资成本可归集到成本模块。

### M5 质量与设备

- IQC/IPQC/FQC 检验单与判定；不合格品处置（返工/让步/报废/退货）；质量成本；设备档案/保养计划/维修记录/OEE；量具台账/校准计划/记录。
- 验收：检验项未完成不可判定；`FAILED` 必须创建 NCR；校准过期量具不可用于检验；OEE 数据回传幂等。

### M6 数据分析与报表中心

- 经营驾驶舱（收入/成本/利润/订单）；多维分析（部门/产品/客户/区域）；报表中心（自定义、定时推送、导出）；预警中心（库存/超期应收/超预算/质量异常，并给出计划建议）。
- 验收：指标与账簿/库存抽样对账一致；快照缓存主动失效；预警同规则同对象同周期不重复触发；导出受权限码控制。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 全景范围过大，一次性铺开 | 质量下降、长期不可交付 | 严格 M0→M6，每阶段可独立上线；本波只做 M0+M1 |
| 会计规则未定先编码 | 返工、凭证错误 | D1–D4 先确认；规则外置为配置，不硬编码 |
| 成本与库存计价方法变更 | 历史数据不可比 | 计价方法按「物料+仓库」配置并锁定版本；变更需期初切换流程 |
| 模块化单体的耦合退化 | 变成“大泥球” | ArchUnit 模块规则 + 评审；跨模块只能走应用服务 |
| MRP/结账性能 | 超时、锁表 | 异步任务 + 分批 + 进度查询 + 单实例分布式锁 |
| 跨域集成不稳定（MES/OA） | 工单/凭证不一致 | 幂等键 + 对账任务 + 失败重试表 |
| 权限/菜单号段冲突 | 权限失效 | 355+/63+ 已预留；实施前先查已用最大值 |
| 客户主数据双头 | CRM/ERP 数据不一致 | D9 定归属；上游发布 + 下游只读扩展字段 |
| 薪资合规差异 | 算薪错误 | 参数化模板 + 试算 + 双人复核；不内置未确认税率 |

8. **D11/D12 集成方式**：MES 回调、OA 审批事件的幂等键。
9. **D13 薪资合规模板**范围。

> 未确认前，M1 只实现「凭证平衡、期间控制、核销上限」等不依赖准则的硬规则；科目表模板、税率、折旧年限等一律走配置，不写死默认值。

### 14.2 关键实现决策

- **迁移编号**：`V5__manufacturing.sql` 之后顺延为 `V6__hr.sql`；9 张表全部 `CREATE TABLE IF NOT EXISTS`，不含破坏性语句。
- **组织与员工解耦**：组织树用 `parent_code` 逻辑引用，不建物理外键；员工只存 `org_code` 快照，组织改名不回写历史。
- **我的工资条数据范围**：`erp_hr_employee.user_id` 关联平台账号；`GET /erp/hr/payroll/payslip/my` 只返回当前账号对应员工的工资条，
  与 `payroll:list`（全部批次）分离为独立权限 `payslip:list`。
- **薪资期间唯一**：`erp_hr_payroll_run` 唯一键 `(tenant_id, period)`，应用层再校验 `PAYROLL_PERIOD_CONFLICT`，避免重复计提。
- **审批后明细冻结**：`APPROVED` 之后无工资条更新路径；取消仅允许 `DRAFT/CALCULATED`，保证凭证与工资条一致。
- **凭证科目语义**：计提走「管理费用—应付职工薪酬」，发放冲减应付并拆分「银行存款/应交税费/其他应付款」，
  借贷按「应发合计」平衡；社保与公积金并入其他应付款，避免虚增税费。
- **计薪配置化**：社保比例、公积金比例、个税起征点、加班倍数、月计薪天数、日工时均走 `erp.hr.payroll.*`，
  支持环境变量覆盖（`ERP_HR_*`）。
- **绩效等级由分数推导**：等级不单独录入，避免分数与等级不一致；`cycle×employee×kpi` 唯一，重复录入按 upsert 处理。
- **上下文边界**：HR 应用层只经 `AutoVoucherAppService` 端口访问财务，领域层不依赖财务上下文；
  ArchUnit 新增 4 条规则固化 HR 四层边界与其他上下文不得反向依赖 HR。
