## 1. 结论先行

| 需求域 | 裁决 | 理由 |
|---|---|---|
| 员工学习 / 培训 / 考试 | **新建 `whale-lms` 独立服务**（9008 / `/lms/**` / `bluewhale_lms` / 前端 8115） | 课程、题库、试卷、考试、证书、学分是独立生命周期的领域对象，与 OA 审批/假勤上下文无继承关系；塞进 OA 会撕裂其「行政人事」边界（参照 [CRM/SRM 边界决策](2026-10-28-crm-srm-and-message-service-decisions.md) 的裁决框架） |
| 党政 / 工会 | **并入 `whale-oa` 扩展**（不新建 `whale-party`） | 党建内容发布复用 OA 公告/网盘/文件底座；组织生活、慰问、福利发放走 OA 审批底座（Workflow）；会员/党员台账是「行政人事」的自然延伸；OA M5 文化/投票/建议、M3 公告已预留同类能力。单独立项只会复刻第二个 OA |

## 2. 边界与「不拥有」清单

| 能力 | 归属 | 说明 |
|---|---|---|
| 课件/教材视频字节 | `whale-file` | LMS 只存文件引用 ID 与播放授权校验；不转码、不点播（点播能力已有 `whale-video`，如需课程视频复用其注册/票据模式另立集成任务） |
| 学习/考试提醒、催学通知 | `whale-message` | 模板 `LMS_ENROLL_NOTIFY` / `LMS_EXAM_URGE` / `LMS_CERT_ISSUED`，幂等键同 OA M1A-4 口径 |
| 员工主数据（学员是谁、部门、在职状态） | `whale-erp` / Auth | 只读引用 `erp_hr_employee` 快照（username 精确匹配，同 OA M1A-4 目录口径）；LMS 不建人事表 |
| 培训报名/请假冲突 | `whale-oa` 假勤 | 培训占用工作时间的审批走 OA 请假/出差，LMS 只读结果 |
| 党建内容发布审核 | OA 底座 | 复用 OA 公告 + 文件；敏感内容先审后发（复用 music 域 `comment-pre-audit` 经验） |
| 工会慰问/福利审批 | Workflow（OA 底座） | 新增 `UNION_RELIEF` / `UNION_WELFARE` 审批配置，复用动态审批人/抄送/代理 |
| 组织主数据（部门/支部映射） | ERP `erp_hr_org_unit` + OA | 支部在 OA 建表，但 `orgUnitCode` 必须引用 ERP 组织编码，不平行造组织树 |
| 经营报表聚合 | ERP 分析中心（`erp_bi_*`） | 学习/工会看板只做域内统计；跨域汇总走 BI 快照机制 |

## 4. whale-lms 领域设计（M0–M6）

### 4.1 上下文分区

```
com.bluewhale.lms
├── course      课程/章节/课件/学习进度/报名
├── training    培训班/必修分配/面授签到/讲师课时
├── exam        题库/试卷/考试/判分/成绩
├── cert        证书模板/证书/学分台账
├── analytics   学习与考试统计（域内看板）
└── common      integration（ERP 员工只读、whale-file、whale-message）+ outbox
```

### 4.2 波次

| 波次 | 范围 | 关键表 | 验收 |
|---|---|---|---|
| **M0** 底座 | 骨架（9008 / Nacos / 网关路由 / `bluewhale_lms` 建库）、Flyway 基线（`audit_log`/`api_log`）、Auth 手工迁移（权限 1900–1939 / 菜单 450–460 / 角色）、门禁测试 | 基线 2 张 | 服务可启动；`/lms/meta` 返回门禁状态；ArchUnit 四层/上下文门禁生效 |
| **M1** 课程与学习 ✅ | 课程/章节/课件 CRUD、课程发布状态机（草稿→发布→归档）、课件字节走 `whale-file` 引用、员工报名与自主选学、学习进度（章节完成度/百分比） | `lr_course` / `lr_course_chapter` / `lr_courseware` / `lr_enrollment` / `lr_progress` | ① 未发布课程不可报名；② 进度只增不减（重学可覆盖为更优值）；③ 课件引用删除前必须先下架；④ 报名幂等 |
| **M2** 培训计划 ✅ | 培训班（线上/面授/混合）、必修分配（按部门/角色/全员）、面授签到（时间窗/补签留痕）、讲师与课时台账、完成认定 | `lr_training_class` / `lr_class_session` / `lr_assignment` / `lr_checkin` / `lr_lecturer_hours` | ① 必修分配自动批量报名幂等；② 签到仅限时间窗且留审计；③ 课时合计=各场次之和 |

## 5. 党政工会域设计（并入 whale-oa，M-P1 / M-P2）

### 5.1 上下文分区

```
com.bluewhale.oa
├── party   支部/党员台账/组织生活/党费/党建内容
└── union   会员台账/慰问福利/活动/提案
```

### 5.2 波次

| 波次 | 范围 | 关键表 | 验收 |
|---|---|---|---|
| **M-P1** 党建 | 支部台账（挂 `orgUnitCode`）、党员台账（组织关系/党龄/党费基数）、三会一课与主题党日活动（计划/记录/签到）、党费收缴台账（月度/标准/实缴）、党建内容发布（复用 OA 公告 + 附件，**先审后发**） | `oa_party_branch` / `oa_party_member` / `oa_party_activity` / `oa_party_activity_record` / `oa_party_fee` / 党建内容复用 OA 公告表增 `channel=party` | ① 党员一人一档且与 Auth username 一致；② 活动记录不可删只可归档；③ 党费月度应缴=基数×标准，补缴留痕；④ 未审内容不出现在前台 |
| **M-P2** 工会 | 会员台账（入会/会费）、慰问/困难帮扶申请（走 Workflow `UNION_RELIEF` 审批，金额/频次校验）、节日福利发放台账、工会活动报名、职工代表大会提案（复用 OA 投票/建议底座，增提案状态机：提交→立案→办理→反馈→评价） | `oa_union_member` / `oa_union_relief` / `oa_union_welfare` / `oa_union_activity` / `oa_union_proposal` | ① 慰问金额超标准拒绝且审批幂等；② 福利发放人次与台账一致；③ 提案状态机不可跳转；④ 投票结果不可改 |

### 5.3 与既有 OA 波次的关系

- 权限落在 OA 扩展段 1950–1999 / 菜单 470–489；**不**挤占 OA M6 已预留的 1790–1799 / 菜单 398–409。
- 迁移用 OA `V7` / `V8`（`V6` 已由 OA M1B-2 出差占用，OA M2 考勤等后续波次从 `V9` 起编）；OA M2/M5 若先落地，波次顺序按 roadmap 实际进度编排，表结构互不依赖。
- 前端复用 8103 `whale-oa`：新增「党建园地」「工会之家」两组菜单，不建新前端应用。

## 7. 依赖与排期建议

1. **前置**：OA M0 审批底座已交付 ✅（工会审批直接可用）；ERP `erp_hr_employee` 已交付 ✅（学员快照可用）。无外部阻塞。
2. **建议首切片**：`whale-lms` M0 + M1（课程与自主选学）——独立成域、不依赖 OA 新波次，验证 9008/8115 链路。
3. **党政工会**排在 LMS M1 之后或与 M3 并行（不同服务，互不阻塞）；其审批类功能依赖 Workflow，无新增底座需求。
4. **全局节奏约束**（巡检结论）：新域动工前，优先完成 OA M1A-6 移动端适配与 OA 真实用户试点（12.1）；本计划为「宽」储备，不插队 P0。

## 8. 明确不做（留档）

- 直播授课、视频转码、付费课程商城：视频能力归 `whale-video`，商业行为归 `whale-pay`，均不在 LMS 范围。
- 强反作弊（人脸/摄像头监考）：M3 只做时长/次数/乱序/切屏记次等基础约束；强监考涉及隐私合规，出现真实需求另立 REQ + 安全评审。
- 党建内容独立 CMS：复用 OA 公告/网盘，不建第二套内容体系。
- 学习地图/岗位胜任力模型：留待 M4 后按需登记需求。
- 党费线上支付：涉资金链路归 `whale-pay`，且默认线下收缴台账制，接入支付另立 REQ-SEC 评审。

## 9. 风险登记

| 风险 | 缓解 |
|---|---|
| 与 OA「1600–1799」声明冲突 | 本计划明确扩展段 1950–1999 并在 M0 时修订 OA 全景与命名规范；权限码全局唯一由 Auth 迁移断言测试兜底 |
| 党员等敏感个人信息 | REQ-SEC-035：字段最小化、查询留审计、导出需 `party_admin` 角色且脱敏；不与 BI 共享明细 |
| 考试答案泄露 | 客观题作答明细仅在交卷后可查（独立权限码 `sys:lms:score:detail`）；未交卷试卷答案与抽题种子不回显、不落前端日志 |
| 又一个「宽而浅」域 | 本计划自带试点验收（M6）；CI 侧沿用 DoD：单测 + 起服 + 至少 1 条冒烟脚本方可标「完成」 |
