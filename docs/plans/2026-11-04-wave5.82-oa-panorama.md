## 一、结论

1. **OA 不新建服务、不新建前端、不新建引擎**。继续使用 `whale-oa`（9004、`/oa/**`、`bluewhale_oa`、前端 8103、base `/oa`），按模块化单体 + DDD-lite 四层重构；工作流、表单、组织权限、消息、IM、文件、档案、合同用章、ERP 执行均复用平台既有能力。
2. **OA 的主线是“审批过程 + 行政业务记录”**：OA 管申请、审批、额度、台账与归档；审批通过后通过 Outbox 把结果推给 ERP/PDM/MES 执行，OA 不替代 ERP 做付款/做账，不替代 PDM 管技术文档，不替代 MES 管生产执行。
3. **首个可用切片是 M0 + M1A**：M0 打通审批底座与 Workflow 缺口；M1A 交付“审批中心 + 请假闭环 + 额度台账 + 抄送/代理/催办/流程查询”。这是 OA 的灵魂，也是后续所有行政表单的公共底座。
4. **审批中心不直接暴露 Workflow 给普通员工**：OA 后端封装 Workflow 内网门面，统一做数据范围、业务详情和动作鉴权；员工只需 OA 权限，不需要 `sys:workflow:*` 权限。
5. **表单采取混合策略**：请假/加班/出差/报销/考勤/用章等强业务规则表单由 OA 领域模型承载；低频、非关键、可配置的通用申请使用 `whale-form` 动态表单。这样既有设计器能力，又不在关键金额/额度上依赖动态表单校验。
6. **全员 OA 全量交付周期约 8–11 个月**（2 后端 + 1 前端 + 共享 QA 的假设下）；若 M2 与 M3 并行、再加 1 名后端，可压缩到约 7–9 个月。

| 缺口 | 现状 | M0 需要补 |
|---|---|---|

### 3.2 明确不做（边界）

| 能力 | 归属 | OA 的边界 |
|---|---|---|
| 组织/用户/角色/权限/菜单 | `whale-service-auth` | OA 只读 + 入口；岗位/职级/汇报关系按 D1 决定是否增强 Auth |
| 流程引擎/设计器/任务状态机 | `whale-workflow` | OA 只发起、查询、动作代理；不复制流程表 |
| 动态表单/表单数据 | `whale-form` | 仅低频通用申请使用；关键业务表单归 OA 领域表 |
| 消息投递/站内信/模板 | `whale-message` | OA 只定义业务通知事件与模板编码，不建消息表 |
| 即时通讯 | `whale-im` | OA 只放入口/跳转；不建会话表 |
| 文件字节存储 | `whale-service-file` | OA 存 `fileId` 引用、文件夹与 ACL；不存字节 |
| 档案归档/检索/销毁 | `whale-archive` | OA 只推快照、存 `archiveItemId`；不建档案表 |
| 合同/电子签/印章主数据 | `whale-contract` | OA 发起用章申请、登记使用；印章主数据与签章执行归 Contract |
| 付款/做账/采购订单/薪资 | `whale-erp` | OA 只推审批通过事件；不记账、不付款、不算薪 |
| 项目/工作项/甘特 | `whale-pm` | OA 只做个人待办与会议行动项；项目任务深链 PM |
| 产品技术文档/图纸/BOM | `whale-pdm` | 公文档案归 OA/Archive；技术文档归 PDM |
| 生产执行/工单/报工 | `whale-mes` | OA 只发布审批结果事件；不落 MES 执行表 |

### 3.3 三条硬规则

1. **单一事实源**：员工身份归 Auth，审批状态归 Workflow，文件字节归 File，档案归 Archive，付款归 ERP；OA 只存业务申请与业务台账。
2. **不跨库**：OA 不直连其他服务数据库、不跨服务 JOIN；只走内网 API / Outbox。
3. **外部调用不入本地事务**：本地业务落库 + Outbox 同事务；提交后异步推送/重试；审批副作用按 `approvalInstanceId` 幂等。

### 4.2 OA 上下文（DDD-lite）

| 上下文 | 职责 | 主要表 |
|---|---|---|
| `approval` | 审批配置、审批实例、审批人解析、业务结果处理、抄送/代理/催办入口 | `oa_approval_config`、`oa_approval_instance`、`oa_approval_route_rule`、`oa_approval_route`、`oa_approval_effect` |
| `hr` | 员工扩展档案、请假/加班/出差、人员异动 | `oa_employee_profile`、`oa_leave_*`、`oa_overtime`、`oa_trip`、`oa_employee_change` |
| `attendance` | 考勤规则/班次/地点/设备、打卡、日汇总、异常/补卡 | `oa_att_*`、`oa_work_calendar` |
| `expense` | 报销单/明细/发票/标准、ERP 付款联动 | `oa_expense*`、`oa_invoice` |
| `administrative` | 车辆/司机/预约、用章申请/登记、采购申请 | `oa_vehicle*`、`oa_seal_use`、`oa_purchase*` |
| `collab` | 会议/日程/个人任务/公告/网盘/通讯录/工作台 | `oa_meeting*`、`oa_calendar*`、`oa_task*`、`oa_notice*`、`oa_drive_*` |
| `document` | 公文模板/文号/发文/收文/归档映射 | `oa_doc_*` |
| `culture` | 企业文化、投票、建议箱 | `oa_culture_*`、`oa_poll*`、`oa_suggestion*` |
| `analytics` | OA 报表快照/导出 | `oa_report_snapshot`、`oa_report_export_log` |
| `common` / `integration` | 共享内核、文件引用、序列、Outbox、外部客户端 | `oa_file_ref`、`oa_sequence`、`oa_integration_outbox` |

分层：`interfaces(controller/dto/vo) → application(service/command/query) → domain(model/repository/service) → infrastructure(persistence/client)`。ArchUnit 强制四层与上下文边界；`common` 只放共享值对象/错误码/租户上下文，不放业务。

### 4.3 审批链路（核心）

```
OA 业务表单校验
  → 创建 OA 业务记录（DRAFT/SUBMITTED）
  → 解析审批人（部门经理/HR/财务/总经理/角色）
  → 创建 oa_approval_instance（RUNNING + 审批人快照）
  → 调 Workflow 内网 start（definitionCode + businessKey + variables + assigneeOverrides + ccUserIds）
  → Workflow 生成任务/抄送，Message 通知
  → OA 审批中心查询/动作代理
  → Workflow 终态 → OA 批量对账/详情同步
  → OA 条件更新 RUNNING→APPROVED/REJECTED（幂等）
  → 业务副作用（扣额度/生成台账/Outbox）
  → ERP/Archive/PDM/MES 异步消费，失败重试/对账
```

**业务结果幂等**：`oa_approval_instance.status` 仅在 `RUNNING` 时可迁移；迁移成功后才执行业务副作用；同一实例重复同步不重复扣额度/不重复推送。必要时用 `oa_approval_effect` 唯一键 `(tenant_id, approval_instance_id, effect_type)` 兜底。

### 4.4 表单策略

| 表单类型 | 归属 | 说明 |
|---|---|---|
| 请假、加班、出差、报销、用车、用章、采购、公文、人事异动 | OA 领域表 | 字段固定、服务端强校验（额度、金额、日期、冲突、权限）；Workflow 节点不绑 `formId`，OA 审批详情按 `businessType` 渲染 |
| 低频通用申请、临时调查、非关键行政申请 | `whale-form` | 设计器建表单，提交 `formData`；Workflow 节点绑定 `formId + formCode` |
| 流程设计器 | `whale-workflow` | 设计“谁发起→谁审批→谁抄送”；OA 不复制设计器 |

这样避免把假期额度、报销合计、考勤规则放进动态表单表达式，也保留 form designer 的灵活度。D2 若要求“全部表单可拖拽”，则需在 Form 服务增加业务校验扩展点，工期另计。

### 4.5 审批人解析与动态覆盖

- OA `oa_approval_route_rule`：`businessType + nodeKey → resolverType/resolverValue/fallback`。
- `resolverType`：`USER`、`ROLE`、`DEPT_LEADER`、`PARENT_DEPT_LEADER`、`INITIATOR`、`FIXED_ACCOUNT`。
- 发起时 OA 解析成账号列表，写入 `oa_approval_route` 快照，并作为 Workflow `assigneeOverrides`；中途组织变化不影响在途实例。
- 解析为空/多个但节点非会签 → 拒绝发起（`OA-APPROVAL-NO-APPROVER` / `OA-APPROVAL-MULTI-APPROVER`），提示管理员补规则。
- 代理只在任务创建时生效，任务级转办优先；代理不改变审批人快照，只改当前待办归属。

### 6.4 M1A 验收场景

1. 员工提交 2 天年假 → 直属部门经理 → HR 备案 → 通过；额度冻结→扣减一次；发起人收到结果。
2. 经理驳回 → 额度释放；员工修改后重新提交，生成新审批实例。
3. 请假 3.5 天跨周末 → 按工作日历计算 3 天（或按 D4 规则）；半天起止正确。
4. 同一员工同日期重叠请假 → 拒绝提交；跨年额度按 D4 规则。
5. 审批人 A 设置代理给 B（有效期内）→ 新任务自动到 B；B 审批后记录代理来源；A 不能再次代理给 B 形成环。
6. 员工在“我发起的”看到实例；审批人在“待我审批”处理；处理后在“我已审批”可查；抄送人在“抄送我的”可查且未读/已读正确。
7. 审批超过 SLA → 自动催办一次；手动催办受 1 小时频控；重复点击不重复发消息。
8. 审批完成 → OA 对账 1 分钟内更新；重复对账不重复扣额度；Workflow 不可用时列表降级但详情可读。
9. 普通员工访问 HR 额度配置/他人审批 → 403；跨租户 → 404；附件越权 → 403。
10. 移动端（H5）可提交请假、查看待办、审批；页面 P95 < 500ms。

- 组织增强（D1）：Auth 增加岗位/职级/汇报关系/部门负责人用户 ID，OA 只做入口；若 D1 决定不增强 Auth，则 OA 只维护 `report_to_user_id` 并明确不复制部门树。
- 验收：异动只同步一次；离职后登录失效；匿名建议不泄露身份；投票结果与票数一致。

### 7.6 M6：报表与加固

- 报表：考勤月报、审批效率（P50/P90/节点时长/积压）、部门人均报销、假期余额、用车/用章/会议室利用率、公告阅读率、网盘配额。
- 实现：优先索引 + 只读查询；大数据量用夜间 `oa_report_snapshot`；导出 CSV/XLSX，权限 + 审计。
- 加固：租户/权限/内网/文件 ACL 安全测试；GPS 防作弊边界说明；PII/附件/导出审计；备份恢复；性能压测；试点部门 2 周。
- 验收：报表与源数据抽样一致；导出受权限控制；P95 达标；无 P1 安全问题；试点反馈闭环。

### 8.2 关键不变量

- `oa_approval_instance`：`(tenant_id, business_type, business_id)` 唯一；`workflow_instance_id` 唯一；状态机 `RUNNING → APPROVED/REJECTED/CANCELLED/BROKEN`，不可逆。

- `oa_sequence`：`(tenant_id, biz_type, period)` 行锁递增；业务编号唯一。
- `oa_integration_outbox`：`(tenant_id, event_key)` 唯一；发送与业务事务分离；死信可重放。

## 十一、质量门禁

### 11.1 后端

1. `mvnw.cmd -pl :whale-oa -am test` 全绿；新增代码行覆盖 ≥50%、分支 ≥40%，额度/审批状态机/ACL 关键类 ≥80%。
2. `mvnw.cmd -pl :whale-oa checkstyle:check` 0 违规；Javadoc 规则不破。
3. ArchUnit：四层依赖 + 上下文边界 + 禁止跨上下文 Mapper/表访问；旧 `/oa/leave` 端点不破坏。
4. Flyway 空库启动 + 重复执行幂等；禁止 destructive 迁移；回滚靠备份/前滚修复。
5. Workflow/Auth 变更同步跑各自模块测试与 Checkstyle；内网端点外部 403、跨租户 404。
6. 外部客户端用 WireMock/契约测试：Workflow、Auth、Message、File、Archive、ERP、Contract；超时/重试/降级有断言。

### 11.2 前端

1. `pnpm --dir frontend/platform-apps/whale-oa build`、`lint`、`test` 通过。
2. 路由/菜单/权限一致；无权限菜单不显示，越权按钮不出现。
3. 移动端 375px/768px 布局不破；审批/请假/打卡可完成。
4. 文件上传/下载走 OA 代理，不暴露裸 `fileId`。

### 11.3 安全与数据

1. 租户隔离：所有表 `tenant_id`；跨租户一律 404；列表/详情/导出/附件同一口径。
2. 内网：`/oa/internal/**` 网关 403；服务间必须带内网令牌 + 用户/租户上下文；禁止匿名内网调用。
3. 审计：提交/审批/转审/加签/退回/撤销/代理/催办/额度变更/补卡/报销推送/用章/公告发布/下载/导出全部留审计。
4. 脱敏：日志/审计不含完整手机号、身份证、银行卡、GPS 原始坐标；生日只展示月日。
5. 附件：MIME 白名单、20MB、下载鉴权；网盘 ACL DENY 优先；公开 VO 不含存储路径。
6. 幂等：提交、审批副作用、打卡、会议预约、投票、公告已读、归档、Outbox 全部有幂等键/唯一约束。

### 11.4 冒烟脚本

新增 `scripts/smoke/oa-approval-e2e.ps1`：登录 → 提交请假 → 待办 → 同意 → 额度扣减 → 我发起的/我已审批/抄送 → 重复对账 → 权限 403/跨租户 404。M2 起增加 `oa-attendance-e2e.ps1`、`oa-expense-e2e.ps1`。

## 十三、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 全量 OA 范围过大 | 长期无可用版本 | 先 M0+M1A；P0/P1/P2 分批；每期可独立上线/回滚 |
| Workflow 缺口（动态审批人/CC/代理/催办） | 审批中心无法交付 | M0 作为硬前置；先内网门面与覆盖，不把 Auth 依赖塞进引擎 |
| 无业务回调 | OA 状态滞后 | 批量对账 + 详情按需；副作用幂等；M1 可选回调 |
| 动态表单承载关键业务 | 额度/金额校验不可靠 | 关键表单 OA 领域化；动态表单仅低频通用 |
| ERP/Contract/Auth 内网契约未就绪 | 报销/用章/人员异动阻塞 | 契约先行；不可用时显示“待接入”，不伪造成功；Outbox 重试 |
| Web GPS 防作弊有限 | 代打卡 | 服务端围栏 + 精度阈值 + 设备绑定 + 可选自拍 + IP/Wi-Fi；原生/企微另立 D13 |
| 附件/网盘越权 | 数据泄露 | 下载代理 + ACL DENY 优先 + 审计；不暴露裸 fileId |
| 会议室/车辆并发冲突 | 重复预约 | Redis 锁 + DB 行锁 + 重叠查询 + 唯一约束 |
| 考勤数据量 | 报表慢 | 日汇总 + 月结快照 + 组合索引；避免大表实时聚合 |
| 人员异动误操作 | 账号/权限事故 | 四眼原则 + 审批 + 停用不删除 + 审计 + 可回滚（重新启用） |
| 权限/菜单/需求号段撞号 | 迁移失败/越权 | OA 1600–1799 / 360–409 / 071..079；实施前统一台账复核 |
| 存量请假迁移 | 数据/体验断裂 | legacy 只读 + 新单新流程 + 旧端点保留 + 试点后切换 |
