## 3. 新增服务定义

### 3.1 `whale-scene` 城池场景导航（规划）

| 项 | 值 |
|---|---|
| 分组 / 模块 | `whale-services/whale-scene`（核心服务） |
| Nacos 服务名 | `whale-scene` |
| 端口 | **8097** |
| 对外一级前缀 | `/scene/**` |
| 数据库 | **`bluewhale_scene`**（规划） |
| Java 包 | `com.bluewhale.scene` |
| 前端 | `frontend/platform-apps/whale-scene`，**8112**，base `/scene` |
| 权限点 | 预留 **309–322**（查询/场景 CRUD/发布/节点/绑定/可见性/解析） |
| 菜单 | 预留 **45–48**（城池导航、场景管理、入口绑定、可见性） |
| 网关 | `lb://whale-scene`，不配 `StripPrefix`；`/scene/internal/**` 对外 403 |
| 状态 | **规划，未编码** |

**职责边界**

- 拥有：场景（城池）元数据、区域/建筑/入口节点树、节点到系统/页面/知识库的入口绑定、场景对象可见性、2D/3D 呈现所需布局数据、场景访问统计。
- 不拥有：业务系统数据（OA/ERP/CRM 等）、身份与权限判定结果（auth 为唯一身份源）、文件字节（`whale-file`）、知识检索（`whale-agent`）、3D 引擎实现（前端共享包/渲染层）。
- 3D 定位：**2D 为主生产力界面，3D 为可选可视化入口**；无 WebGL、低配设备、首屏超预算时自动降级 2D。

**数据模型（M0 定稿，M1 落地）**

| 表 | 关键字段 | 说明 |
|---|---|---|
| `sc_scene` | `id` / `tenant_id` / `scene_key` / `name` / `status` / `layout_version` / `published_at` / 审计字段 | 场景聚合根；`scene_key` 租户内唯一 |
| `sc_scene_node` | `id` / `tenant_id` / `scene_id` / `node_key` / `parent_key` / `node_type` / `name` / `icon` / `x` / `y` / `z` / `sort_no` / `status` | 节点树；`node_key` 场景内唯一；禁止环 |
| `sc_node_binding` | `id` / `tenant_id` / `node_id` / `entry_type` / `target_path` / `permission_code` / `enabled` | 入口绑定；`target_path` 协议/前缀白名单 |
| `sc_visibility` | `id` / `tenant_id` / `scene_id` / `node_id` / `subject_type` / `subject_id` / `effect` | `ROLE/DEPT/USER/ALL` + `ALLOW/DENY`；DENY 优先 |
| `sc_layout_version` | `id` / `tenant_id` / `scene_id` / `version` / `layout_json` / `checksum` | 发布快照，支持回滚 |

> 所有业务表带 `tenant_id`，由 starter 租户插件行级隔离；写操作走 `@AuditLog`；不记录敏感数据。

**API 草案（M0 冻结，M1/M2 实现）**

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|

| `GET` | `/scene/{id}` | 场景详情（管理视图） | `sys:scene:list` |
| `POST` | `/scene` | 新建场景 | `sys:scene:add` |
| `PUT` | `/scene/{id}` | 编辑场景 | `sys:scene:edit` |
| `POST` | `/scene/{id}/publish` | 发布（校验节点/入口/可见性） | `sys:scene:publish` |
| `POST` | `/scene/{id}/offline` | 下线 | `sys:scene:publish` |
| `POST` | `/scene/{id}/node` | 新增/更新节点 | `sys:scene:node:manage` |
| `DELETE` | `/scene/node/{id}` | 删除节点（有子节点拒绝） | `sys:scene:node:manage` |
| `PUT` | `/scene/node/{id}/binding` | 设置入口绑定 | `sys:scene:binding:manage` |
| `PUT` | `/scene/{id}/visibility` | 设置场景/节点可见性 | `sys:scene:visibility:manage` |

### 3.2 `whale-crm` 客户关系（规划 + 需求门禁）

| 项 | 值 |
|---|---|
| 分组 / 模块 | `whale-apps/whale-crm`（业务应用） |
| Nacos 服务名 | `whale-crm` |
| 端口 | **9007** |
| 对外一级前缀 | `/crm/**` |
| 数据库 | **`bluewhale_crm`**（规划） |
| Java 包 | `com.bluewhale.crm` |
| 前端 | `frontend/platform-apps/whale-crm`，**8113**，base `/crm` |
| 权限点 | 预留 **323–340**（客户/联系人/商机/跟进/统计） |
| 菜单 | 预留 **49–54** |
| 网关 | `lb://whale-crm`，不配 `StripPrefix`；`/crm/internal/**` 对外 403 |
| 状态 | **规划，未编码；需求门禁未通过前不进入 M4** |

**进入条件（必须同时满足）**

1. 出现真实的客户/联系人/商机/销售漏斗需求，并明确使用者、流程与验收；
2. 明确客户主数据归属：CRM 拥有客户，ERP 只拥有供应商，合同域「相对方」只保存 `crmCustomerId` 快照；
3. 完成 Domain Modeling 复核与 ADR-003 定稿；
4. 产品确认本期不做线索评分、营销自动化、客户服务工单。

**职责边界**

- 拥有：客户、联系人、商机、销售阶段、跟进记录、客户 360 只读视图。
- 不拥有：供应商（ERP 供应商主数据 / 未来 `whale-srm`）、合同正文与签署（`whale-contract`）、审批（`whale-workflow`）、消息投递（`whale-message`）、附件字节（`whale-file`）。
- 与合同：合同相对方快照引用 `crmCustomerId`，不复制客户主数据；合同状态变化回写只读摘要。
- 与 ERP：供应商与客户是两个上下文，禁止合并表或共用编码规则。

**数据模型（M0 定稿，M4/M5 落地）**

| 表 | 关键字段 | 说明 |
|---|---|---|
| `crm_customer` | `id` / `tenant_id` / `customer_code` / `name` / `status` / `owner_id` / `dept_id` / `level` / `source` / `industry` / `address` / `tags` / 审计字段 | 客户聚合根；`customer_code` 租户内唯一 |
| `crm_contact` | `id` / `tenant_id` / `customer_id` / `name` / `phone` / `email` / `title` / `is_primary` / `status` | 联系人；每客户至多一个主联系人 |
| `crm_opportunity` | `id` / `tenant_id` / `customer_id` / `name` / `amount` / `stage` / `expected_close_date` / `owner_id` / `lost_reason` | 商机；阶段状态机 |
| `crm_follow_up` | `id` / `tenant_id` / `customer_id` / `opportunity_id` / `channel` / `content` / `next_action_at` / `created_by` | 跟进记录，append-only |

**阶段状态机（草案）**

```text
LEAD → QUALIFIED → PROPOSAL → NEGOTIATION → WON
  └──────────────┴───────────┴──────────────► LOST（必须填写 lost_reason）
```

- 非法跳转返回业务错误；
- `WON` 必须有金额与客户；
- 客户存在未关闭商机时禁止停用/删除。

## 5. Domain Modeling Result

- **Decision scope**：`landscape + bounded-context`（战略）；`increment`（两个新服务的第一增量）。
- **Depth**：`both`（战略 + 战术）。
- **业务能力**
  - 场景导航：场景/区域/建筑/入口建模、权限可见性、2D/3D 呈现、访问统计。
  - 客户关系：客户主数据、联系人、商机、销售阶段、跟进、客户 360。
- **子域分类**
  - 场景导航：支撑型子域（平台体验与入口编排），不是核心交易域。
  - 客户关系：核心业务型子域（若立项），与合同、ERP 并列，不隶属 OA/ERP。
  - 供应商：支撑型，归 ERP 供应商主数据 / 未来 SRM。
- **限界上下文**

| 上下文 | 归属 | 核心模型 | 不拥有 |
|---|---|---|---|
| 身份与权限 | `whale-service-auth` | 租户/用户/部门/角色/权限/菜单 | 场景布局、客户商机 |
| 场景导航 | `whale-scene`（新） | 场景、节点、入口绑定、可见性 | 业务数据、身份判定、文件字节 |
| 客户关系 | `whale-crm`（新） | 客户、联系人、商机、跟进 | 供应商、合同正文、消息投递 |
| 合同 | `whale-contract` | 合同、相对方快照、签章 | 客户主数据 |
| ERP | `whale-erp` | 物料、供应商主数据 | 客户主数据 |

## 6. Architecture Guidance Result

- **架构风格**：两个新服务均采用 **DDD 四层 + Ports & Adapters**（与 auth/file/doc/music 一致），并用 ArchUnit 固化依赖方向。
- **依赖规则**
  - `interfaces` → `application` → `domain`；`infrastructure` 实现 `domain` 端口；`domain` 不依赖 Spring/MyBatis/Controller DTO。
  - 仓储接口放 `domain`，MyBatis-Plus 实现在 `infrastructure`；控制器只做参数校验与信封转换。
  - 跨服务只走 `/internal/**` + `X-Internal-Token`；禁止跨库 JOIN。
- **CQRS**：**不引入完整 CQRS**；写用例走命令服务，读用例走查询服务与读模型；不为每个用例拆分读写库。
- **事务边界**：事务只包住本地聚合加载 → 领域行为 → 保存；出站调用（消息/合同/归档）在事务外执行，失败不回滚主记录。
- **多租户**：业务表统一 `tenant_id` + 租户行插件；网关剥离外部伪造头；菜单/权限种子为平台表不隔离。
- **安全**：入口 URL 协议白名单（禁止 `javascript:` / `data:` / 内网地址）；场景可见性 DENY 优先；客户手机号/邮箱按脱敏规则落审计；3D 资源来源与许可证必须登记。
- **性能**：2D 导航接口只返回可见节点与入口，不返回布局大字段；3D 资源按需加载，首屏预算与降级阈值写入设计稿。
- **开放问题**：见 §12。

## 9. 验收标准

### 9.1 场景导航（REQ-FUNC-031 / REQ-SEC-020）

1. 跨租户访问场景/节点返回 404，不泄露存在性；
2. 无权限节点的入口不出现在 `/scene/navigation`，直连节点详情返回 403/404；
3. 2D 首屏不依赖 WebGL；导航响应 ≤ 200KB（不含 3D 资源），中端设备首屏 ≤ 1.5s（本地基线，待产品确认）；
4. 入口 URL 只允许 `http/https` 白名单前缀，拒绝 `javascript:`、`data:`、内网地址与开放重定向；
5. 发布前校验：至少 1 个入口节点、无环、深度 ≤ 5、节点数 ≤ 200；下线后导航不可见；
6. 场景/节点/绑定/可见性变更均落审计，且不记录敏感字段；
7. 至少接入 3 个系统入口（建议 OA、ERP、文档/知识库）；
8. 3D 可选：WebGL 不可用或连续 5s FPS < 30 时自动降级 2D；首屏 3D 资源 ≤ 8MB、桌面首帧 ≤ 5s（待产品确认）；
9. 3D 资源来源、许可证、贴图/模型体积登记；不加载未授权素材；
10. 低配/移动端可访问，键盘可操作 2D 导航。

### 9.2 客户关系（REQ-FUNC-032 / REQ-SEC-021，门禁通过后生效）

1. `customer_code` 租户内唯一，重复新增/改码返回业务错误；
2. 只能看到本人/本部门/授权范围客户（数据权限），跨租户 404；
3. 联系人手机号/邮箱在列表与审计中按规则脱敏；
4. 商机阶段只能按状态机流转，非法跳转返回 400；
5. 有未关闭商机的客户禁止停用/删除；合并客户保留引用并可追溯；
6. 合同相对方通过 `crmCustomerId` 引用客户，不复制客户主数据；
7. 客户/商机写操作落审计；导出/列表受权限码控制；
8. 后端单测、Checkstyle、ArchUnit、前端 lint/build、E2E 通过。

### 9.3 文档（借鉴动作）

- 新成员按 `docs/README.md` 30 分钟内了解项目全貌；
- 文档职责边界表可判定内容该写在哪；
- 版本矩阵以 POM/package.json 为唯一源，无硬编码漂移；
- API 规范覆盖错误码/分页/幂等/版本/限流；
- 部署文档可按步骤完成一次测试环境部署与回滚演练；
- 文档一致性脚本对端口/路由/库/命名漂移返回非 0。
