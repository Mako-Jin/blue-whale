> 这份文档回答四个问题：现在有什么、往哪收、按什么顺序做、什么不做。

> 配套文档：[roadmap.md](roadmap.md)（历史波次台账）、[architecture.md](../architecture.md)（服务全景）、[命名体系](../brand/naming-system.md)。

## 一、一句话说清它是什么

**一套能私有化部署的企业业务平台**：统一的身份权限、统一的流程与表单引擎、统一的前端基座，上面长着制造、协同、交易、空间可视化四类业务。

它现在的问题不是功能少，是**故事不完整**——27 个服务都能起来，但没有一条业务链能从输入走到输出、中间不需要人工改库。这份蓝图的第一个目标就是解决这件事。

## 二、现状基线（2026-11-14 实测）

### 2.1 家底

| 维度 | 数字 | 备注 |
|---|---|---|
| 后端服务 | 27（Java 26 + Python 1） | 全部可起，无规划路由 |
| 前端应用 | 26 | qiankun 子应用 + 独立设计器 + admin/ops |
| 权限点 | 966 | `/auth/v1/me` 实测 945（tenant_admin 视角） |
| 文档 | 563 篇 | 需求登记册 + 设计 + 评审 + 日志四类 |
| 数据库迁移 | V29 | Flyway |
| 工程门禁 | 7 道 check 脚本 + 若干冒烟 | 内网边界/权限映射/qiankun 生命周期/角色覆盖/长整型/路径漂移/二次认证 |
| CI | 8 个 workflow | docker-deploy 单次 49 job，约 103 分钟 |

### 2.2 深度不均，这是最大的结构性问题

| 层次 | 状态 | 判断 |
|---|---|---|
| 权限中心（鲸律） | **最完整**：RBAC + 数据范围 + 二次认证 + OAuth 客户端 + 会话/登录历史 + 审计留痕 | 可以作为卖点，敢给别人看 |
| 流程（鲸脉）/ 表单（鲸纹） | **很深**：状态机内核、BPMN 2.0 双向、版本快照与实例迁移、并行会签、加签转办回退、拖拽设计器、动态建表 | 是全平台最扎实的资产，但藏在后台没人知道 |
| 网关（鲸喉）/ 文件（鲸囊）/ 消息（鲸语）/ 任务（鲸息） | 可用，边界清楚 | 不用再投 |
| 商城（鲸市） | 已到售后、定价优惠、物流 | 做得不少，但和主线关系弱 |
| 制造线（鲸造/鲸研/鲸营） | 有全景设计稿（M0–M5），实交付停在 M0–M1 | **缺口最大，也是最能卖钱的** |
| 协同线（鲸办/鲸卷/鲸群/鲸声） | 骨架 + 部分闭环 | 演示友好，替换成本低 |
| 空间线（鲸镜/鲸城/鲸感） | 3D 城 + 联机 IM 能跑 | 唯一"外行看得懂"的东西，但只在 vite preview 上验证过 |
| 移动端 | **没有** | 只有 Web |

### 2.3 已知欠账（别当成已完成）

- 3D 城联机 e2e 是在 `vite preview` 上跑的，**preview 不转发 WebSocket 升级**，所以"e2e 全绿"不等于"真实部署能联机"。必须在 Nginx + 真实网关环境重测。
- `admin/api/generated/auth-schema.d.ts` 还写着旧的 `/auth/refresh`。
- 除 admin 外的子应用没接 `onReauthRequired`，token 过期时不会自动跳登录。
- `whale-games-core`、`whale-common-three` 已冻结（无消费方）。
- 国产化只停留在设计（多数据库演进），**零实测**。

## 三、分层蓝图

```
接入层   Nginx → 网关(鲸喉)：路由/限流/熔断/内网屏蔽/黑名单
────────────────────────────────────────────────────
平台层   鲸律 身份权限 │ 鲸脉 流程 │ 鲸纹 表单 │ 鲸卷 文档
（能力）  鲸囊 文件    │ 鲸语 消息 │ 鲸声 IM │ 鲸群 社区
         鲸息 任务    │ 鲸脑 AI  │ 鲸伴 助手 │ 鲸贝 支付
         鲸镜 孪生    │ 鲸城 3D  │ 鲸感 IoT │ 鲸图/鲸笺/鲸影/鲸歌
────────────────────────────────────────────────────
业务层   制造：鲸造 鲸研 鲸营 鲸程
         协同：鲸办 鲸卷 鲸群 鲸声
         交易：鲸客 鲸市 鲸契
         空间：鲸镜 鲸城 鲸感
────────────────────────────────────────────────────
前端     鲸台 基座 │ 鲸港 门户 │ 26 个子应用（qiankun）
────────────────────────────────────────────────────
交付     Docker Compose 单机私有化 ／ Kubernetes 集群 ／ 离线镜像包
```

三个结构性约束，不能破：

1. **网关不剥前缀**。前端路径必须等于后端「类前缀 + 方法映射」，任何试图在网关做路径改写的方案都会引入新的漂移。
2. **一条兜底路由只挂一个 pattern**。Gateway 不按逗号切分，写了逗号整条路由永不命中，而校验器自己按逗号 split 会放行——校验器也会骗人。
3. **无 `tenant_id` 列的表必须进 `TenantSqlProperties.ignoreTables`**。漏一张，列表接口就 500，而且报的是「Unknown column」这种看着不像权限问题的错。

## 四、往哪收：四条线收成三条

这是本蓝图最重要的判断。现在四条线并行，每条都只到 M1，结果谁也讲不完整。

| 线 | 保留建议 | 理由 |
|---|---|---|
| **A 制造数字化**（鲸造 + 鲸研 + 鲸营 + 鲸程） | **主攻** | 客单价最高、替换成本最高、已有 M0–M5 设计稿；"订单→排产→报工→质检→入库"是天然可演示的完整链条 |
| **B 企业协同**（鲸办 + 鲸脉 + 鲸纹 + 鲸卷 + 鲸声 + 鲸群） | **做深，做标配** | 已经有最扎实的流程/表单引擎；协同是所有行业的公共底座，装了就能用 |
| **C 空间可视**（鲸镜 + 鲸城 + 鲸感） | **做门面，不追功能** | 演示和投标时最抓人；但做到"能看、能点、数据是真的"就够，不追拟真 |
| ~~D 交易**（鲸客 + 鲸市 + 鲸契）**~~ | **降为附属** | 电商是红海，还要支付资质与售后体系；CRM/合同作为 A 线的客户与签约环节保留，商城不主动推 |

一句话：**A 负责赚钱，B 负责通用性，C 负责让人记住。D 先不投。**

## 五、不做什么（比做什么更重要）

| 不做 | 理由 |
|---|---|
| 移动原生 App | 26 个应用做原生等于重写一遍。先做响应式 + 一个只含「审批 / 看板 / 消息」的小程序 |
| 低代码"全场景"平台 | 只守「表单 + 流程」这一窄口。往页面/报表/门户上扩会把最扎实的资产做烂 |
| 自研数据库、中间件、消息队列 | 没有收益，只有维护成本 |
| 引入 Flowable / Camunda / Sentinel | 已定：工作流自研（BPMN 轻量双向）、限流熔断用 resilience4j + Redis |
| 多语言全量铺开 | i18n SDK 在，只保中英双语，不做第三语言 |
| 深度集成第三方 IM（钉钉/企微消息） | 先把自家鲸声做稳；对外只做「企微登录」一个适配器 |
| SaaS 多租户计费 | M4 之前不做。现在做等于过早给自己加结算和合规负担 |
| 追"功能数量" | 加到 30 个模块但没一条链跑通，只会让交付更难 |

## 六、阶段路线与准入门槛

每个阶段都有可验证的判据，达不到就不进下一阶段。这是为了让"完成了"有客观含义。

### M0 骨架（已完成，2026-11 之前）

服务全部可起、权限/网关/流程/表单四件套闭环、CI 与门禁跑通、文档与日志成体系。

### M1 单域闭环（当前 → 约 2 个月）

目标：**制造线一条链跑通，中间不需要人工改库。**

范围：销售订单（鲸客）→ 生产订单（鲸造）→ 排产与报工 → 质检 → 入库（鲸营）→ 3D 看板（鲸城）反映真实数据。

准入门槛：
- [ ] 5 个环节全在系统内完成，全程只点页面，不碰 SQL
- [ ] 一张订单从下达到入库，状态机每步有留痕（谁、何时、改了什么）
- [ ] 3D 看板上看到的数量 == 数据库里查出来的数量（对账脚本可验证）
- [ ] 压测基线：权限判定 P95、订单列表分页 P95、并发报工 3 组数据写进文档
- [ ] 一条链上至少有 3 个自动化冒烟用例，进 CI

### M2 可交付（M1 后 → 约 3–6 个月）

目标：**一台干净机器，2 小时内装完，能交付给一个真实客户。**

范围：私有化交付包 + 初始化向导 + 备份恢复 + 升级脚本 + 离线镜像。

准入门槛：
- [ ] 全新机器（无网络）从零到可登录 ≤ 2 小时，全程按手册操作
- [ ] 备份 → 销毁 → 恢复演练通过，数据零丢失
- [ ] 跨版本升级不丢数据（用 V29 之后的两次迁移做演练）
- [ ] 至少 1 个真实试点环境跑满 2 周，无阻断级缺陷
- [ ] 3D 联机在 Nginx + 真实网关下重测通过（补上 preview 不转发 WS 的坑）

### M3 可复制（→ 6–9 个月）

目标：**第二个客户实施 ≤ 5 人日，差异项走配置不改代码。**

范围：行业模板（字段/流程/报表预置）、实施手册、验收清单、数据导入工具。

准入门槛：
- [ ] 新建租户 → 装模板 → 录入 3 条真实数据 → 出报表，全程 ≤ 4 小时
- [ ] 三家不同客户的差异，能用配置项表达（有清单和开关）
- [ ] Excel 双向导入导出跑通（这是所有企业客户的第一个真需求）
- [ ] 企微登录、金蝶/用友导出两个适配器可用

### M4 可运营（→ 9–12 个月）

目标：**能按租户开通、按用量算钱。**

准入门槛：新租户开通 ≤ 10 分钟；单集群 N 租户压测有数据；计费与对账可核。

> M4 是否要做，取决于 M2–M3 有没有真实付费客户。**没有客户就不要做 M4**——多租户计费和运营后台是纯成本项。

## 七、技术债与风险台账

按"会不会致命"排序。

| # | 风险 | 现状 | 处理 | 期限 |
|---|---|---|---|---|
| R1 | **单点依赖人**：文档与门禁是命门，作者一停就烂 | 靠自律维持 30 天 | 把"当天写日志、当天过门禁"变成脚本强制（pre-commit 钩子 + 每日自动报告），不靠意志 | M1 内 |
| R2 | **性能无数据**：只在单机压过，几十万订单量级没跑过 | 无基线 | M1 结束前出三组压测数字 | M1 |
| R3 | **3D 联机只在 preview 验证** | e2e 绿但真实部署未测 | 真实环境重测 WS 升级链路 | M2 前 |
| R4 | **移动端缺失** | 只有 Web | 做响应式 + 审批小程序；原生 App 明确不做 | M2 前 |
| R5 | **生态薄**：接不进客户既有系统 | 无适配器 | 只做三个：企微登录、Excel 双向、金蝶/用友导出 | M3 |
| R6 | **国产化零实测** | 只有设计 | 至少验证 1 个国产库跑通 auth + 一个业务域 | M2 前 |
| R7 | **合规材料缺**：有审计/脱敏/锁定/step-up，但没有等保材料与渗透报告 | 技术就绪、材料缺失 | 整理材料清单，做一次外部渗透 | M3 前 |
| R8 | CI 太慢：docker-deploy 49 job / 103 分钟 | 全量构建 | 按 git diff 只构建变更服务，或改手动触发 | M1 内 |
| R9 | 前端欠账：旧的 auth-schema、子应用未接 `onReauthRequired` | 已知 | 一次性清掉，别留到 M2 | M1 内 |

## 八、如果只能做五件事（12 个月优先级）

1. **制造线端到端闭环 + 三组压测基线** —— 没有它，一切都只是零件
2. **私有化交付包**（一键装、备份恢复、升级、离线）—— 没有它，卖不了
3. **三个适配器**（企微登录、Excel 双向、金蝶/用友导出）—— 没有它，进不了客户现场
4. **3D 看板接真实数据** —— 唯一能让人"哇"一下的东西，演示和投标全靠它
5. **把工程能力对外化**（文档体系、门禁、案例）—— 内部资产变成可信度，也是内容素材

其余的（商城深化、音乐/视频、党建细化、游戏）一律往后放。

## 九、节奏

- **周**：周一定本周目标（写进 `docs/plans/`），周五复盘写 devlog，四栏（需求/完成/待做/已修正）
- **波次（Wave）**：一个波次一个主题，不混；每个波次必须有验收判据和评审报告
- **每月**：看四个数——端到端流程通过率、私有化安装耗时、缺陷平均修复时长、当月活跃模块数
- **每季**：砍一次。连续两个月没动的模块，标记冻结（参照 `frozen-optional-modules.md`）

## 十、待确认（需要你拍板，我不替你决定）

1. **目标形态**：主要卖给客户（私有化），还是先做内部/孵化验证？——决定 M2 是否提前。
2. **目标行业**：离散制造还是流程制造？——决定鲸造的数据模型往哪边压（工艺路线 vs 配方批次），两条路差别很大。
3. **是否接受 M2 前不做移动端**：我建议接受。
4. **有没有真实试点客户**：没有的话 M2 之后要先去换一个，否则 M3 的"实施人日"无从验证。
5. **商城要不要继续投**：我的建议是停，除非它已经是某个客户的必需项。
