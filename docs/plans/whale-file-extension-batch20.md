# whale-file 能力扩展（批次 20：预签名与落盘加密互斥保护）

## 一、范围与决策

启用批次 16 的落盘加密后，对象在介质中是密文；预签名下载绕过应用层直接访问对象存储，
会把密文原样返回给客户端。本批次增加互斥保护：加密开启时拒绝预签名，引导调用方走网关下载。

| 事项 | 本轮 | 说明 |
| --- | --- | --- |
| 加密开启时拒绝预签名 | ✅ | 返回参数错误并提示使用下载接口 |
| 未加密时行为不变 | ✅ | 预签名、CDN 重写、有效期截断保持原样 |
| 逐对象判断（明文存量可预签名） | ❌ | 当前为全局开关判断，更精细需探测对象头；见待做项 |
| 网关直链签名替代 | ❌ | 见待做项 |
| 数据库变更 | ❌ | 无 |

**错误码**：`PARAM_ERROR`，消息「已启用落盘加密，预签名地址不可用，请使用下载接口」。
先做归属/权限校验再判断加密，避免改变 404/403 语义。

## 二、设计

`FileInfoServiceImpl#presignedUrl` 在 `requireAccessibleFile` 之后、调用存储预签名之前判断：

```
if (whale.file.storage.encryption.enabled) throw PARAM_ERROR("...")
```

这样：
- 未开启加密：完全保持既有行为；
- 开启加密：不再返回密文直链，客户端改走 `/download` 网关接口（应用层透明解密）。

## 三、测试计划

| 范围 | 用例 |
| --- | --- |
| 应用层 | 加密开启时抛出参数错误且不调用存储预签名；未加密时既有预签名、CDN 重写、有效期截断用例保持通过 |

## 四、完成情况

- `FileInfoServiceImpl#presignedUrl` 在归属/权限校验之后、调用存储预签名之前判断落盘加密开关；
- 加密开启时抛出 `PARAM_ERROR`，提示使用下载接口，不再返回密文直链；
- 未开启加密时预签名、CDN 重写与有效期截断行为不变；
- 测试：加密开启时拒绝且不调用存储预签名 1 项；既有预签名 4 项回归通过。
