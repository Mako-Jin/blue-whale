# Wave 5.95 — 商城 M1 首切片：支付闭环与退款（whale-mall ↔ whale-pay）

> 状态：**已实施**（2026-11-07；whale-pay 40 单测 / mall 89 单测全绿，两服务覆盖率门禁通过）
> 前置：Wave 5.94 M0 已交付（`ba88fc86`）：订单状态机四条边、内网回调 `POST /mall/internal/order/paid` 已留好、`mall_order.pay_no`/`pay_time` 已落列
> 日期：2026-11-07

---

## 一、目标与边界

**目标**：打通「下单 → 创建支付单 → 支付 → 回调推进订单状态 → 取消关单联动 → 整单退款」的完整资金主链路，并把 whale-pay 的 MOCK 渠道适配器接口化，真实渠道（微信/支付宝）等有商户资质后只插适配器实现。

**边界（本切片不做）**：部分退款的业务入口与售后单、优惠券/运费/物流轨迹、福利积分账户、B2B 账期、ERP 库存对账、真实支付渠道对接（无商户号资质，只做适配器接口化）。

**现状盘点**：

| 侧 | 已有（M0 及以前） | 缺口 |
|---|---|---|
| whale-pay | pay_order 全生命周期（create/pay/cancel/refund/reconcile）、pay_transaction 流水、条件更新防并发、MOCK 渠道 | 无业务方回调通知；退款为一次性全额（无退款单实体）；无 `/pay/internal/**` 服务间接口；渠道网关是硬编码 MOCK 而非适配器 |
| whale-mall | `POST /mall/internal/order/paid` 回调接口、`mall_order.pay_no`/`pay_time` 列、订单状态机（PAID 不能取消的口径） | 无买家支付发起接口；无退款状态与字段；无退款回调接口；markPaid 金额一致性未校验 |

## 二、关键判断（先定规矩再写码）

1. **支付单由 mall 后端创建，不由前端创建**：金额以订单应付总额为准，前端永远拿不到「改金额」的机会。前端只收 `payNo` 用于展示。
2. **回调必须落任务表，不做内存异步**：新表 `pay_notify_task`，支付/退款成功后投递，失败按指数退避重试 6 次后置 DEAD。进程重启不丢通知——回调丢了业务侧订单会永远停在 PAID 之前，这是资金链路上最贵的一种丢。
3. **幂等各管各的**：whale-pay 创建支付单按 `orderNo` 幂等（同单号已存在直接返回原单，不报错——mall 重试创建是正常路径）；mall 收回调按「状态已推进即幂等成功」处理，重复回调返回 200。
4. **回调金额强校验**：`paidAmount != order.totalAmount` 拒绝并记日志告警，不推进状态。金额不一致宁可卡住人工介入，也不能默默过账。
5. **退款首切片只开整单退款**：`pay_refund` 表模型天然支持部分退款（有 amount 字段），但 mall 侧入口只发全额退款单。SHIPPED/COMPLETED 之后的退款属售后域（要审批流），和部分退款一起放下一切片——没有审批流的部分退款等于谁点谁退。
6. **订单状态机加两条边**：`PAID → REFUNDING → REFUNDED`。REFUNDING 期间禁止发货、禁止再次申请退款（防并发双退）。SHIPPED/COMPLETED 不加退款边。
7. **服务间接口统一 `/pay/internal/**` + 网关 internal-deny**：与 `/mall/internal/**` 同一口径，外部 403。whale-pay 内网接口不走 `@RequirePermission`（服务间无用户态）。
8. **渠道适配器是 SPI 不是 if-else**：`PayChannelAdapter` 接口（pay/refund/close/queryStatus），MOCK 为内置实现；`PayChannelGateway` 退化为按渠道号路由。以后接真实渠道 = 新增实现类 + 配置一行，业务代码零改动。
9. **通知不做签名**：回调走内网直连且网关 internal-deny 兜底，本切片不加签名；若未来回调出内网再加 HMAC。

## 三、数据模型变更

### whale-pay（`V2__pay_m1.sql`）

```sql
-- pay_order 追加两列
ALTER TABLE pay_order ADD COLUMN biz_type   VARCHAR(32)  DEFAULT NULL COMMENT '业务方类型（MALL_ORDER 等）';
ALTER TABLE pay_order ADD COLUMN notify_url VARCHAR(255) DEFAULT NULL COMMENT '支付/退款成功回调地址（内网 lb:// 形式）';

-- 退款单
CREATE TABLE pay_refund (
  id BIGINT PRIMARY KEY,
  refund_no    VARCHAR(64)  NOT NULL COMMENT '退款单号（RF+日期+流水）',
  pay_order_id BIGINT       NOT NULL,
  pay_order_no VARCHAR(64)  NOT NULL,
  amount       DECIMAL(12,2) NOT NULL COMMENT '本笔退款金额',
  reason       VARCHAR(255) DEFAULT NULL,
  status       VARCHAR(16)  NOT NULL COMMENT 'CREATED/SUCCESS/FAILED',
  channel_refund_no VARCHAR(64) DEFAULT NULL,
  refund_time  DATETIME DEFAULT NULL,
  -- BaseEntity 公共列 + uk_refund_no(tenant_id, refund_no) + idx_pay_order(pay_order_id)
);

-- 业务通知任务
CREATE TABLE pay_notify_task (
  id BIGINT PRIMARY KEY,
  biz_type    VARCHAR(32)  NOT NULL,
  biz_order_no VARCHAR(64) NOT NULL COMMENT '业务单号（mall_order_no）',
  event       VARCHAR(16)  NOT NULL COMMENT 'PAID/REFUNDED',
  notify_url  VARCHAR(255) NOT NULL,
  payload     VARCHAR(2000) NOT NULL COMMENT '回调 JSON',
  status      VARCHAR(16)  NOT NULL COMMENT 'PENDING/SUCCESS/DEAD',
  retry_count INT NOT NULL DEFAULT 0,
  next_retry_at DATETIME NOT NULL,
  last_error  VARCHAR(500) DEFAULT NULL,
  -- idx_status_retry(status, next_retry_at)
);
```

### whale-mall（`V3__mall_order_refund.sql`）

```sql

ALTER TABLE mall_order ADD COLUMN refund_time   DATETIME      DEFAULT NULL COMMENT '退款完成时间';
```

## 四、接口清单（新增 10 + 修改 2）

### whale-pay 内网接口（5 个，`/pay/internal/**`，不走用户权限）

| 接口 | 说明 |
|---|---|
| `POST /pay/internal/order` | 创建支付单。body：`bizType`/`orderNo`/`amount`/`currency`/`notifyUrl`/`remark`。按 orderNo 幂等：已存在直接返回原单 |
| `GET /pay/internal/order/{orderNo}` | 按业务单号查支付单（ mall 支付页轮询用） |
| `POST /pay/internal/order/{id}/pay` | 发起支付（MOCK 即时成功），成功后投递 PAID 通知任务 |
| `POST /pay/internal/order/{id}/cancel` | 取消支付单（仅 CREATED 可取消） |
| `POST /pay/internal/refund` | 创建退款单并执行（body：`payOrderNo`/`amount`/`reason`），成功后投递 REFUNDED 通知任务；校验累计退款额 ≤ 支付额 |

### whale-pay 管理侧（沿用现有 `sys:pay:*` 权限）

| 接口 | 说明 |
|---|---|
| `GET /pay/refund/page`、`GET /pay/refund/{id}` | 退款单查询 |
| `GET /pay/notify/page`、`POST /pay/notify/{id}/retry` | 通知任务查询与手工重试（DEAD 任务人工介入入口） |

### whale-mall（3 新 + 2 改）

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /mall/order/{id}/pay` | `sys:mall:order:list`（买家自付） | 对 PENDING_PAYMENT 订单创建支付单（幂等）并发起支付；返回 payNo |
| `POST /mall/order/{id}/refund` | **`sys:mall:order:refund`（新 2214）** | 整单退款：校验状态 ∈ {PAID}，调内网退款，订单 → REFUNDING |
| `POST /mall/internal/order/refunded` | 内网 | 退款回调：REFUNDING → REFUNDED，落 refund_amount/refund_time，幂等 |
| 改 `POST /mall/internal/order/paid` | 内网 | 加金额一致性校验；REFUNDING/REFUNDED 状态收到 paid 回调直接幂等返回 |
| 改 `POST /mall/order/{id}/cancel` | 2213 | 取消时若已建支付单，内网联动取消（支付单不存在或已取消不阻塞订单取消） |

## 五、时序（主链路）

```
买家下单成功(PENDING_PAYMENT)
  → POST /mall/order/{id}/pay
      → mall 内网 POST /pay/internal/order        （金额=订单应付；幂等按 orderNo）
      → mall 内网 POST /pay/internal/order/{id}/pay
            → MockAdapter.pay() 即时成功 → pay_order=PAID + pay_transaction
            → 投递 pay_notify_task(PAID)
  → mall 返回 payNo
  （异步）pay 通知任务重试器 → POST lb://whale-mall /mall/internal/order/paid
      → mall 校验金额 → PENDING_PAYMENT → PAID

管理员整单退款
  → POST /mall/order/{id}/refund
      → 订单 PAID → REFUNDING
      → mall 内网 POST /pay/internal/refund
            → pay_refund(CREATED→SUCCESS) + pay_order.refund_amount 累计 → REFUNDED
            → 投递 pay_notify_task(REFUNDED)
  （异步）→ POST /mall/internal/order/refunded → REFUNDING → REFUNDED
```

通知重试器：`@Scheduled` 每 30s 扫 `status=PENDING AND next_retry_at<=now`，条件更新抢占（`WHERE id=? AND status='PENDING' AND retry_count=?`）防多实例重复投递；退避 30s × 2^n，6 次后 DEAD。
