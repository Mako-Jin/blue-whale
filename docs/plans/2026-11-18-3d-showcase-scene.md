## 5. 风格统一（三源并存的关键）

三道强制工序，不靠"感觉像"：

1. **统一色板**：全场景限定 6 主色（石灰 `#cfc6b4`、木褐 `#6b4a33`、瓦青 `#3f4a4d`、灯笼朱 `#c04a32`、水青 `#3f7c8c`、苔绿 `#5a6b3e`），所有素材入场先过色相/饱和度归一化 shader。
2. **统一材质颗粒度**：所有材质 roughness 落在 0.6-0.95，禁用纯镜面；所有贴图统一 1K（地标 2K），生成模型的塑料感靠"降饱和 + 加粗糙 + 提法线"三件套压下去。
3. **统一后处理**：全场景只有一条 Grade 链（LUT + 暗角 + 颗粒），AI 生成物与素材库物件过同一条链，视觉上会被"焊"在一起。

### 6.1 Blender 管线（已实测，2026-11-18）

| 项 | 结论 |
|---|---|
| 位置 | `D:\blender\blender.exe`，Blender **5.2.2 LTS**（build 2026-09-15，Python 3.x 内置） |
| 冒烟结果 | `--background --factory-startup --python smoke.py` 全链路通过：EEVEE 渲染检查图成功、GLB 导出成功（木箱 3548 B / 24 三角面）。脚本见 `tmp/blender-smoke/smoke.py`，S0 时迁入包内 `tools/blender/` |
| 渲染引擎 | 后台 EEVEE 可用（实际落到 `BLENDER_EEVEE`），不需要 GUI |
| 配置不落 C 盘 | `BLENDER_USER_CONFIG` / `BLENDER_USER_SCRIPTS` 指到 `.toolchains/blender/{config,scripts}` **已实测生效**（默认会写 `%APPDATA%\Blender Foundation`，违反项目硬规则） |
| 为什么脚本优先于 MCP | 18 件道具要批量建模、批量渲三视图、批量导 GLB——脚本一条命令跑完且可入库复现；MCP 适合"边看边调"的探索期，但要 GUI + 插件 + 重启，不作主路径 |
| 插件状态 | **未装 blender-mcp**（`extensions` 下只有默认目录）。不影响任何阶段；若后续需要交互调试再装 |

> 冒烟件已经复现了文章踩的第一个坑：箱盖与箱身之间留了 3 cm 悬空——这正是三视图检查要抓的东西。
> 也就是说，**"导出成功"不等于"能用"**，检查图不是可选项。


**GLB 统一规范（硬性）**：

- 单位 1 unit = 1 m，+Y 向上，朝向 +Z；
- 原点在**底面中心**，导入后仍用 boundingBox 二次贴地（文章踩过"原点贴地、底部悬空"）；
- 单件三角面 ≤ 1.5 万，合计 ≤ 25 万；
- 导出 GLB + Draco 压缩，贴图 WebP/KTX2；
- 命名 `{组}-{件}.glb`，如 `camp-tent.glb`、`facility-bridge.glb`；
- 压缩命令：`npx @gltf-transform/cli optimize in.glb out.glb --compress draco --texture-compress webp`。

**三视图检查（照抄文章的有效动作）**：每件渲正面/侧面/斜后三张，专查悬空、穿模、破面、结构连接、原点。发现问题**只修那一件**，重渲复检。

**资产台账** `docs/design/showcase-assets.md`：件名 / 来源 / 许可证 / 是否商用 / 三角面 / 文件大小 / 检查结论。企业项目，无台账不得入库。

## 11. S1 验收记录（11-18 实施）

**已落地**（`whale-frontend/platform-apps/whale-showcase`，dev 端口 8126）：

| 项 | 实现 | 文件 |
|---|---|---|
| IBL | `PMREMGenerator.fromScene` 把同一套天空 shader 烘成环境贴图，切时段自动重建 | `src/scene/env.ts` |
| 后处理链 | RenderPass → UnrealBloom → OutputPass → GradePass（分离色调/对比/暗角/颗粒）→ SMAA | `src/scene/postfx.ts` |
| 水面 | 值噪声波纹 + 天空同源反射 + 菲涅尔 + 碎金，带距离衰减 | `src/scene/water.ts` |
| 地形 | 反照率按 sRGB 视觉值重取 + 大尺度色斑 + 低频颗粒 | `src/scene/terrain.ts` |
| 石拱桥 | 带三孔拱洞的挤出实体（原来"桥面板+圆环拱+方墩"三者互不相连，出图是悬空薄带） | `src/scene/props.ts` |
| 街/房/墙布局 | 街心 x=17、民居 x≥22.4、城墙 x=31.5；城墙按 4m 分段取地面高度 | `src/scene/props.ts` |

**踩到的四个坑（都是"编译通过、出图才炸"）**：

1. `#include <tonemapping_fragment>` 只在**渲染到画布**时生效（`currentRenderTarget === null`），渲染到 RT 是空操作。所以整条链里只有 OutputPass 做色调映射，不会二次映射——但也不能靠材质的 tonemapping 兜底。
2. `renderer.info` 每次 `render()` 自动重置，接上 composer 后 HUD 只能读到最后一个全屏 quad（2 个三角面、1 次 drawcall）。必须 `info.autoReset = false` + 每帧手动 `reset()`。
3. 水面法线扰动**必须按距离衰减**，否则远水面每像素都在两个噪声格之间跳，白天整条河变成"碎冰/大理石"。
4. `THREE.Color` 按 sRGB 转线性，`0x43512e` 的线性值只有 0.05；配 `NdotL/π` 就是死黑。有 IBL 之后必须按视觉色取值，别再手动压暗。

**当前指标**：163.7k 三角面 / 43 drawcall / 1080×675 下 40–46 fps（含 Bloom+SMAA，未做画质档）。

**对比图**：`docs/art/showcase/s0/`（接 IBL 前）↔ `docs/art/showcase/s1/`（现在），7 个固定机位同名。

**仍然丑的地方（下一步的靶子）**：树是"棒棒糖"、房是方盒子、屋顶是平板、地面无材质、牌坊檐口是平板、夜景灯笼不照地也无水面倒影。这些都是**形体与贴图**问题，靠调光调不出来 → 进入 S3 资产替换。

|---|---|---|---|---|

| 垂柳 | `tree_willow.glb` | 2.6k | 87 KB | 同上 |

**管线约定（写进 `blib.py` 头注释）**：单位米 / 底面严格 z=0 / 硬边过小倒角 /
取色按 hex（`srgb()` 转线性）/ glTF 导出 `Blender(X,Y,Z) → glTF(X,Z,-Y)`。

**踩到的五个坑**：

1. `--factory-startup` 给的是**默认场景**（含立方体、相机、灯）。脚本开头不 `read_factory_settings(use_empty=True)`
   就会把默认立方体一起导出——检查图正中间一个白方块。
2. 树干"根部张开"用了**局部坐标** z（圆柱是 -h/2..+h/2），底面算出 exp(+3.8)≈45 的系数，
   柳树整棵变成撑满画面的圆锥。必须 `zrel = v.co.z + h/2`。
3. 柳条的世界高度漏传，枝条从地面长出来；且曲线转网格后没有 `Col` 属性，套顶点色材质渲染成纯黑。

   只露出三个小方块。必须按 `roof_z(y)` 反推每段顶标高。

**运行时改造**：

- 树 / 民居 / 灯笼全部改 **InstancedMesh**：drawcall 从 108+54+22 降到 6+12+3。
- 民居落点由"随机撒点"改**固定 z 槽位**（间距 9m）：房子正面朝 -X 时面宽是沿 Z 排布的，
  旧判据只按 6.5×7 算，相邻两栋必然互相插进去。

## 14. S5 灯影与渡口夜灯（11-18 实施）

### 14.1 灯影：为什么探针不行，最后还是自己算

先做了 **CubeCamera 环境探针**（512 HDR，河心烘一次，切时段重烘），期望水面反射出岸上的灯笼。
实测**完全无效**，原因值得记下来：

> 灯笼在水面上方 2.7m，它在水下的镜像是 -2.7m。从相机射向镜像点的射线是**向下**的，
> 而水面反射向量 `R` 在掠射角下是**向上**的（几乎水平朝远端）。两者不是同一个方向——
> 探针里灯在 cube 的**下半球**，水面永远采不到。这是**平面反射（Reflector）**才有的效果，
> 而 Reflector 要每帧把 58 万面场景再渲一遍，帧率会掉到 20 以下。

改成按几何直接算（`water.ts` 的 `lampGlow`）：灯的镜像点与相机连线交水面于一点，那里就是
观众看到的倒影位置；在这一点上画一个**沿视线方向拉长的椭圆**，横向 40cm、纵向拖 3m。
再乘一层 `sin(along*3.4 - t*2.1)` 的**横纹调制**——真实水面的灯影是被水波切成一道道横纹的，
少了这层就是"月光洒水面"的雾。

灯位与亮度复用点光源（`water.setLamps`），灯亮水亮，白天 `lamp=0.15` 时自然为 0。

**探针保留**（仍然接在 `uEnv` 上）：它把岸上的建筑与天空带进远水面的反射，只是不再指望它出灯影。

### 14.2 渡口夜灯

原来码头附近**没有灯**：最近的街灯在 20m 外，而点光源衰减距离 14m——夜里整片码头是黑的，
相机抬到 3.6m 也看不清平台在哪。加了：

- **两盏立杆灯**在码头靠岸一侧（z=-16.6 / -11.4，挑向水面），走 `lanternSpots()` 与街灯同一套实例；
- **一盏 17m 衰减的专用点光**在 `(-8.2, 2.7, -14)`。街灯那三盏是"每三个灯位取一个"抽出来的，
  全在街上，码头一盏都分不到。

顺带确认了一条几何事实（写进截图脚本注释）：**只有低机位能看到灯影**。灯高 2.7m、相机高 3.6m 时
倒影点落在 x≈-2.9 / z≈-20.3，在河面内；全景机位相机高 21m，算出的倒影点落在岸上——物理上就没有。
所以新增机位 `04b-dock-night` 作为唯一的灯影验收位。

## 15. S6 牌坊重做与左岸（11-19 实施）

### 15.1 斗拱为什么会变成栅栏

原写法是"一排 0.2×0.24×0.30 的小方块 + 一块 0.30×0.30×0.12 的帽"，块距 0.36、净距 0.16，
背后**直接是天空**。逆光下就是一道等距竖条。问题不在方块本身，在三点：

1. **没有拱眼壁**。真实斗拱背后是垫板，从正面看不到天；
2. **没有横拱**。真斗拱的视觉主体是那条**连续的水平拱**，斗只是它上面的节点，
   不能等宽等高地排一溜；
3. **没有出跳**。斗拱是垂直墙面伸出去的悬挑构件，只在墙面内堆方块，从哪看都是贴片。

现在按"坐斗 → 一跳华拱（出跳 0.94，贯通前后两面）→ 横拱（通长）→ 升 / 二跳 → 挑檐桁"分层做。
另外**攒距收到 0.44、坐斗 0.28**（净距 0.16，只有一个斗口）：0.62 攒距时净距 0.38，
出图仍是一排垛口——这是"像不像斗拱"最敏感的一个数。

### 15.2 牌坊的三个比例问题

- **三间几乎等宽**：旧值 INNER=1.30 / OUTER=3.90，明间 2.60、次间也是 2.60，三等分出一座牌坊。
  改成 3.10 : 2.20（1.4 : 1，四柱三间的常规比例）。
- **柱径太细**：0.34 撑 6.3m 高，正视像竹竿。改 0.40。
- **次间屋顶插进匾额**：屋顶按开间中心 2.65 摆、宽 3.00，内沿到 1.15，正好探进明间，
  从正面把匾额下角切掉一块。中心挪到 2.85、宽 2.75，内沿 1.475，藏在内柱后面。

### 15.3 牌坊西腿其实一直站在桥面上

牌坊跨度 7.5m、柱位 12.75 / 20.25；石拱桥的实体是 x -14…14（桥必须够到东岸：
河心 4.2、河槽半宽 9）。x=12.75 处桥面已抬到 **2.03m**，而广场地面只有 1.15——
**柱脚埋进桥面 0.88m，夹杆石整个看不见**。挪到 GATE_X=17.9 后柱位 14.15 / 21.65，
跨在桥头广场上，东腿落在街沿（街面 13.5…20.5），也就是"骑街而立"的真实摆法。

## 16. S7 临街铺面与镇区平台（11-19 实施）

### 16.1 "一排货架"的三个根因

### 16.4 镇区临水平台（重大修正）

### 16.5 两处"缝里露草"

## 17. S8 屋顶群落与巷口（11-19 实施）

> 目标：把俯视时"一整块屋顶"拆成**有脊、有山墙、有巷口**的城镇（§16.8 第 1 条），
> 并给程序化几何补上"材料颗粒度"，解决整片地表是一块平色的问题。

### 17.1 三处改动（都在 `house.py`）

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 马头墙高出屋面 | 0.52 | **0.78** | 0.52 时俯视只能看到压顶瓦的**顶面**，白墙立面被屋面自己挡住——出图是"浮在瓦上的几块石片"。1.02 又过头：每户山墙长成 6×5.2 的大白板，整条街变成"墙的城市"，屋顶反被挡住 |
| 压顶瓦 | 宽 +0.18、厚 0.1 | 宽 +0.14、厚 0.09 | 出挑太大就成了"搁板"；0.09 才是一条影子线 |
| 正脊 | h0.34 / w0.20 / curl0.16 | **h0.46 / w0.28 / curl0.30** | 俯视时正脊是唯一能"分块"的线，加粗起翘后才读得出来 |

**翘角（鹊尾）试过，删了**：这个尺度上（0.3m）做不出真正的起翘——做成 0.34 深、
0.11 厚的斜板，出图是一排"水泥舌头"，比干净的阶梯轮廓难看。

### 17.2 瓦色：两次翻车与结论

| 尝试 | 结果 |
|---|---|
| 照片取色 `0x2B2F33`（S3 起） | 黄昏/夜晚纯黑，整片屋顶读不出形状 |
| `0x3E474E` + rough 0.46 | 过曝成"压型钢板"：20cm 瓦垄每条一道高光 |
| `0x333B41` + rough 0.62 | 仍然偏亮，且**瓦垄纹理被冲掉**（自遮蔽对比被高反照率淹没） |
| **`0x2E3338` + rough 0.58** | 定稿。比照片色亮一档，剩下的变化交给逐栋色差 |

**教训**：反照率是 sRGB→线性，`0x2B` 与 `0x3E` 在线性空间差 2 倍——"只改了一点颜色"
在小数值区等于换了一档材质。要调暗部材质，必须按线性值算，不能按 hex 的肉眼差。

### 17.3 逐栋瓦面色差（`InstancedMesh.setColorAt`）

整片屋顶同色同亮是"一整块"的第二个成因。用 `setColorAt` 逐实例乘一个色偏，
**不加 drawcall**（`instanceColor` 会让 three 在片元里定义 `USE_COLOR`，
`diffuseColor.rgb *= vColor`）。色表 6 档、均值约 0.83：
`0xffffff / 0xf6f2ea / 0xe2e6e2 / 0xece6da / 0xd2d6d2 / 0xf0ece4`。

> 验证方法是把它临时设成纯红/绿/蓝——**看起来"没效果"不一定是没生效**，
> 也可能是幅度太小。第一版用近白色表，肉眼看不出差别，差点当成 no-op 删掉。

### 17.4 程序化构件的"材料颗粒度"

`Builder` 写顶点色（每个构件一个均匀色 + 一点冷/暖偏移），幅度按材料给：
石头 0.11~0.13、木 0.06、白墙 0.045。**不加 drawcall、不加贴图**，
但街面从此是"一块块石板"而不是"一块水泥地"。

配套 `Builder.darken(k)`：做**假环境光遮蔽**。巷子只有 2.8m 宽，两侧山墙挡掉大半天光，
而 IBL 是一张无遮挡的天空贴图——不压暗，巷内亮得像街上，纵深全没了。

### 17.5 巷口（`buildAlleys`）

两处铺面之间让出 2.8m（`STREET_PLOTS` 加 `kind:'alley'`），巷深 6.2：

- 两侧墙不用另建——铺面的山墙本来就整进深落地、高过屋面；
- 巷门：两垛砖墩 + 门楣 + **前后两坡的瓦顶（厚 0.2、前坡挑 0.55）**。
  0.12 厚的瓦片从街面平视只看得见一条边，出图是"门楣上浮着一块黑板"；
- 巷尾是**一户人家的后门**（石门框 + 双扇板门 + 门罩 + 一口水缸），不是照壁。
  照壁是一堵亮白墙，眼睛没有落点，6m 纵深被压成 1m 的壁龛；一扇暗色的门是巷内
  唯一的高对比物；
- 巷名匾用 `woodDark`：第一版用 `gold`（金属度 0.62），在 1m 内的壁灯下烧成一块橙红色发光板。

**巷灯**：两盏 9 candela / 9m 的独立点光源。不能塞进 `lanternLights`——那个数组同时喂给
`water.setLamps` 算水面倒影，巷子离河 9m，倒影是假的。位置离墙留 0.8m，
贴着墙时"距离的一次方"会把白墙烧成纯白。

### 17.6 街灯避让巷口

2.6m 高的灯杆正好立在 2.8m 宽的口子上，把 6m 深的巷子从巷口机位整个挡住
（第一版出图：一根灯笼怼在镜头前，后面一道黑缝）。`lanternSpots()` 按巷口 ±2.6m 跳过。

### 17.7 其他

- 石板街南北各延 2m（`-46…41`）：北端新加的院落原本铺装之外。
- `stone/stoneDark` 压暗一档（`0xcfc6b4/0x9d9587 → 0xb8ae9a/0x847d71`）：

## 18. S9 地被与街面（11-19 实施）

> 目标：解决 §17.9 的第 1、2 条——**近景植被**与**街面痕迹**。
> 这两项对近景机位（河岸 / 码头 / 街口）的观感提升最直接，而它们共同的问题是
> 同一个：**画面下半部是一整块平色**。

### 18.1 地被三层（`props.ts` 地被段）

| 层 | 数量 | 几何 | drawcall |
|---|---|---|---|
| 草簇 | 1.62 万丛 | 6 片叶 × 3 面 = 18 tri | 1 |
| 灌木 | ~240 丛 | 4 个二十面体（detail=1）= 320 tri | 1 |
| 滩石 | 300 颗 | 二十面体压扁 | 1 |

- **草簇不用 alpha 贴图**：这个项目没有透明材质的排序管线，一张透明 PNG 在
  Bloom 与阴影下会露方边。实体叶片的代价是三角面，但没有排序问题，还能吃逐顶点色。
- **草叶法线往 +Y 掰**（保留 45% 朝向信息）：竖直薄片的几何法线是水平的，
  黄昏低角度光会让一半叶片全黑、一半全亮，出图是一丛丛"刀片"。
- **逐实例着色**：用高度定干湿（近水青、上坡黄）× 位置哈希定抖动。
  `Math.sin(x*12.9898+z*78.233)*43758.5453` 取小数——哈希而不是 `Math.random`，
  重建场景不跳色。
- **不投影**：几万根 0.45m 的细叶投出来的只是阴影贴图上的噪点。

### 18.2 落点规则（`blockedByPaving`）

铺装区必须**按矩形写死**，不能靠地形高度判断：镇区平台被 `townMask` 压到 1.18，
与河滩草地高度几乎一样，靠高度分不出来。排除项：镇区（x 13.2…34 / z -50…45）、
田垄（整块 + 0.8m 边距）、西岸小路（距中心线 2.6m 内）、码头平台、水埠、
西岸四栋房子（`WEST_VILLAGE` 提到模块级，房子与地被共用同一份坐标）。

采样分两遍：全岸带（距河心 9.4…39m，`pow(rand, 0.72)` 让分布偏向近岸）+
码头近景 3200 丛（那一块是画面下半部）。

### 18.3 街面：排水明沟

**做法是让路，不是叠层**：西半幅石板从 13.53 收到 13.99，露出下面的垫层当沟底
（比街面低 11cm），沟内侧一条 0.16 宽、高出街面 2cm 的牙石，沟底每 7m 一道跌水坎。

> 叠上去的"沟底"是一条凸起的暗带，看着像路缘；只有真的让开，才是一条沟。

### 18.4 两次翻车：所有"贴在街面上的薄皮"

先做了**车辙**（两条 18cm 宽的磨亮石带）和**门前踏石**（每家门口一块 1.1m 的亮石板），
都是 6mm 厚的薄板贴在街面上。两次都失败，而且<b>改材质改不动</b>：

| 尝试 | 结果 |
|---|---|
| `0xc2b8a4` + rough 0.52 | 两条纯白"马路标线" |
| `0x928a7b`（与石材同色）+ rough 0.42 | 还是白的（掠射角菲涅耳反射整片天空） |
| `0x8f8779` + rough 0.86（与周围石材完全同参） | 仍然比街面亮一档 |
| `0xff00ff` 纯洋红 | **是这块几何**，材质确实生效 |
| `0x101010` 近黑 | 阴影里变黑、阳光下仍比街面亮 |

结论：**这个场景里不要在既有表面上叠 5~6mm 的薄板**。原因没查到底（薄板的
自阴影偏移 / 掠射角下的深度关系），但现象稳定复现，性价比也不支持继续查。
改用两条零风险的替代：

- 石板**高低差**从 ±0.015 提到 ±0.055（老石板的沉陷是厘米级的，掠射角下就是明暗线）；
- 按 7% 的比例把石板换成浅一档的 `stone`——几十年里陆续换过的板子，街面因此有了"时间"。

### 18.5 新机位：河岸

`bank`：pos [-19, 6.4, -31] → target [-5.5, 0.9, -12.5]，fov 46。

地被只有 0.3~1.2m 高，而所有既有相机位都在 3.5m 以上——草在画面里只是地面上的
一层颗粒，看不出"是一片草"还是"撒了一把碎屑"。**验收地被必须有贴地机位。**

> 第一次把机位放在 [-21.5, 1.95, -23.5]（真的是眼高），结果镜头正对着一丛草：
> 半屏是几片巨大的叶子。地被机位要"低但不要钻进草里"：5~7m 高、10~20m 外。

**1073.7k 三角面 / 144 drawcall**（S8：732.5k/139；+341k 全是草簇与灌木，
drawcall 只 +5）。1080p mid 17~29 fps。
存档 `docs/art/showcase/s9/`（17 张，新增 `04c/04d-bank-*`）。

## 19. S10 树（11-19 实施）

> 目标：§18.7 第 1 条——**树是"棒棒糖"**。这是全图最明显的低模信号，而且它救不了：
> 树在 54 个落点上，任何一点假都被放大 54 倍。

### 19.1 三个病，三个改法

| 病 | 成因 | 改法 |
|---|---|---|
| 树冠是一颗光滑的"蛋/花椰菜" | 22 个大球（半径 0.85~1.3m）融成一块，平滑着色把剩下的细节全插值掉 | 元素减到 **0.34~0.60m**、数量加到 104 个，铺在椭球壳上；shading 改 **flat** |
| 冠是"棒棒糖"的球 | 冠的剪影是一个正球 | 冠压成伞（纵向只有 0.60R）+ 外圈按水平半径压低 + 约四成方位多垂 0.58m（"垂舌"） |
| 树干直接插进冠心，没有结构 | 只有一根锥形圆柱 | 5 根锥形分枝从 45%~64% 高度斜出，末端各挂两团叶 |

**flat shading 是这一版的第二个关键决定**：3000 面铺在约 50m² 的冠面上，每个三角面约
12cm——正好是"一簇叶子"的尺度。平面着色让每簇自己朝一个方向，冠面在光下碎成几十个
明暗不同的小块；平滑着色是把 3000 个面糊回一个连续曲面（前三版就是这个病）。

**叶团分布不能用随机**：随机撒点在球面上必然结块（几处挤在一起、几处空着），出图是
"一串疙瘩"。改用斐波那契球面分布 + 位置哈希做径向抖动。

### 19.2 垂柳：两版都是错的

1. 18 根贝塞尔曲线 + bevel 做垂枝 → 出图是 **18 根铁丝**：3.2cm 粗、等距、从冠底一圈垂下，像水母。
2. 改成"每条 3 团"堆叶幕，团距 0.55m 而团半径 0.5m → **悬空的珠子**，比铁丝更糟。

结论：柳条是**连续**的。28 条 × 5 团、团距 0.28m、半径 0.26R→0.185R，重叠够了才融成
一条垂舌，垂舌之间的缝就是柳树的竖向纹理。

### 19.3 高瘦树：分层就是糖葫芦

第一版按 5 层"轮生枝"撒团，层距 0.86m、团半径只 0.5m——相邻层不接触，出图是一根
串了五串糖葫芦的竿子。**树的冠必须是一个连续体**：要么层间重叠，要么干脆不分层。
改成沿螺旋线一路撒 64 团，半径按纺锤剖面（下 0.35 / 中 1.0 / 上 0.22）收放。

### 19.4 三处配套修改

- **叶色提亮半档**（`0x2E4520/0x6E8C3C` → `0x354C22/0x7C9C44`）：黄昏时树冠是纯黑剪影，
  暗绿在阴影里等于没有反照率。树皮 `0x4A3B2E` → `0x574736`。
- **树根下的灌木改成"六成的树才有"**：第一版每棵树必挂 2~3 丛、半径固定 0.8~2.3m，
  出图每棵树脚下都长着一模一样的一摊深绿——灌木的<b>均匀性</b>比它的稀疏更假。
- **黄昏 hemi 0.95 → 1.5**：西岸整片落在山影里，只有 hemi + IBL 给光，0.95（实际 0.21）
  时那里是一块纯黑，画面左三分之一全废。上限是 2.0——再高，石桥与白墙的暗面发灰，
  灯笼的光池就没对比了。蓝调 0.8 → 1.1。

### 19.5 地表色斑（`terrain.ts`）

60m 外的山坡是一整块平滑的橄榄绿：细颗粒贴图在 mip 链里被平均掉了。加一层 90m 级的
低频色斑（`fbm(x*0.0105, z*0.0105)`），与原来的 28m 级叠加。低频色斑是<b>唯一</b>在远景
还能留下的地表信息。

### 19.6 指标

**1254.2k 三角面 / 142 drawcall**（S9：1073.7k/144；+180k 全是树冠，drawcall 不变）。
1080p mid 13~24 fps。存档 `docs/art/showcase/s10/`（17 张）。

### 19.7 仍未解决

1. **白墙大面积无变化**：没有雨痕、没有勒脚水渍。粉墙的魂就在这道水渍线上，现在是
   一整块奶油色平板。需要 subdivision + 逐顶点噪声（`house.py`），场景层救不了。
2. **城墙远景像一排格子**：分段铺在 9m 高差上，段间高差形成锯齿。
3. **屋顶在掠射角下发白**：rough 0.58 的青瓦在相机贴近屋面的角度反射整片暖天光，
   出图是"水泥屋面"。要给瓦加一点粗糙度扰动（不能统一抬 rough，会变成哑光塑料）。
4. 码头东侧的"上岸平台"仍是一块浅灰平板（三级台阶总落差只有 0.2m，等于一块台面）。
5. 蓝调 / 夜晚的全景仍偏暗（西岸几乎全黑）。

## 20. S11 墙面与瓦面（11-19 实施）

> 目标：§19.7 第 1、3 条。这两条是同一件事——**表面没有任何尺度信息**。
> 白墙是一块奶油色平板，青瓦是一块会反光的深灰板。几何再准，PBR 参数再调，
> 缺了"3cm 的雨痕"和"哑光的烧结面"这两个尺度，远看就是塑料。

### 20.1 白墙为什么必须是贴图，不能是顶点色

要的是 3~6cm 尺度的雨痕。写进顶点色，一栋房就是几万顶点（`subdivide` 到 0.25m 网格
才有这个精度）；更要命的是民居走 `InstancedMesh`，九栋共**一份几何**，顶点色只能
"整栋一样脏"——真墙不会是九块一模一样的斑。

贴图免费、分辨率高、还能给不同尺寸的墙复用。所以走 canvas 程序化生成 512²，
**只做 ±20% 的亮度调制、不承担颜色**（颜色仍由 `baseColorFactor` 0xB6AE9C 给）。
图一旦自己带颜色，就变成"墙纸"了。

### 20.2 最大的坑：Blender 立方体的默认 UV

第一版挂上贴图后**完全看不到效果**，查了三轮才定位：`primitive_cube_add` 的 UV 是
"十字展开图"，每个面只占整张图的 **1/4 × 1/3**。等于把 512 的图放大到 20m 见方的
平面上用——3cm 的雨痕在墙上变成 12cm 宽的色块，再被一层 3% 的调制抹平。

诊断路径值得记下来：贴图挂载有日志（`std.map` 非空、尺寸 512）、材质名匹配（`plaster`）、
GLB 里每个 primitive 都有 `TEXCOORD_0`——**全部正常，但画面毫无变化**。最后去 dump
UV 数值，才发现范围只有 `0.13~0.38`。

这不是"渲染没生效"，是"生效了但看不见"——与 S9 那块 6mm 薄板的教训同类：
**判断"有没有生效"不能靠看画面，要先找到一个数值判据**。

### 20.3 盒式投影 UV：两条路，同一把尺

同一个材质在两个地方被用：GLB 民居（Blender 生成）与程序化院墙/巷门（`props.ts` 的
`Builder`）。两个都必须按米重算 UV，否则同一张图在 7m 正墙与 0.32m 巷壁上是两种尺度
（第一版巷子里就是一片**细条纹布**，比没贴图更假）。

- **Blender 端**：`house.py` 的 `box_uv()`，join 之后按面法线主轴选两个世界轴 ÷ 3.2。
  只对 `plaster` / `plasterBack` 的面生效（其它材质保持原 UV，它们没有 map）。
- **运行时**：`props.ts` 的 `boxUvWorld()`，在 `Builder.add()` 里对 `key === 'plaster'`
  的几何重算——**必须在 `applyMatrix4` 之后**，这样斜置的构件（门楼、照壁）用世界轴
  投影才是正的。

两处共用常量 `PLASTER_METERS = 3.2`。v 轴必须取**世界 Y**，否则雨痕会变成横纹。

### 20.4 纹理设计：三层尺度 + 可平铺

| 层 | 尺度 | 频率（1 UV = 3.2m = 512px） |
|---|---|---|
| 石灰不匀 | 1.5m | `fbm(u*2.2, v*2.2)`，幅度 ±10% |
| 雨痕 | 宽 2~5cm / 长 ~1m | `fbm(u*86, v*8)` + `fbm(u*24, v*3.4)` 两种宽窄 |
| 砂粒 | 6cm | `fbm(u*46, v*46)`，幅度 ±5% |
| 霉斑 | 0.7m 斑块 | 低频 fbm 阈值化，只在约一成面积出现 |

**不能有"墙根水渍"**：贴图是平铺的，一条底部水渍会在墙上重复成一条条水平带。
墙根的脏交给几何（勒脚石带 + 门前踏石）。这条限制是第一版设计（"上浓下淡的雨痕
+ 底部水渍"）没能落地的原因——它是给"整面墙一张图"设计的，而整面墙一张图的分辨率
根本不够（见 20.2）。

平铺用 `MirroredRepeatWrapping`：fbm 不是周期函数，直接 repeat 会在 3.2m 网格上留
一条看得见的接缝；镜像折返没有硬边，代价是对称感，而这个尺度上没人会注意。

### 20.5 第二版像"条纹布"

只用一个 `fbm(u*96, v*2.8)` 做雨痕，结果是**整面墙均匀细密的竖线**——因为每一列
都在出痕，而且上下贯穿。真实墙面上雨痕是**一段一段**的。加一层低频 `cover`
（`smoothstep(0.40,0.70, fbm(u*9, v*1.6))`）做掩码，只在约三成区域出痕，立刻像了。

### 20.6 瓦面发白：不是 albedo，是菲涅尔

§19.7 的判断（"rough 0.58 反射整片天光，要加粗糙度扰动"）方向对，但优先级错了一半：

- 抬高 roughness 有效，但到 0.9 会让瓦变"哑光塑料"，垄形被糊掉；
- **`envMapIntensity` 才是主因那条路**：青瓦是烧结陶土、无釉，它几乎不该反射天空。
  全场景 `tuneSurfaces()` 扫一遍所有 `/tile/i` 的材质统一压到 0.5（牌坊、民居、
  巷门三条装配路都要覆盖）。
- roughness 只从 0.58 抬到 **0.78**：站在街上看檐口时，视线与屋面夹角只有几度，
  0.58 时菲涅尔把太阳与天空整片反射回来，牌坊顶是一条**银白色波浪**；0.78 把高光
  打散成一层雾，瓦垄反而更清楚（高光不再盖住几何自遮蔽）。

**代价与补偿**：0.78 + env 0.5 之后，黄昏的屋顶变成纯黑剪影（S8 的老问题复发）。
瓦色从 `0x2E3338` 提到 `0x363E44` 补回半档；牌坊用 `0x343A40`。黄昏街景的牌坊仍是
剪影——这是对的，低角度夕阳照不到朝东的屋面。

### 20.7 指标

**1254.2k 三角面 / 142 drawcall**（与 S10 持平：贴图不增加几何，`boxUvWorld` 只改
UV 属性）。GLB 体积 +0（民居 634/694/831KB、牌坊 1286KB 未变）。
1080p mid 14~26 fps。存档 `docs/art/showcase/s11/`（17 张）。

### 20.8 仍未解决

1. **窗纸过曝**：`glowMaterials` 的 `emissiveIntensity = 2.2 * lampScale`，黄昏时
   二层三扇窗糊成三块纯白 LED 板。需要压到 1.4 左右并给窗纸一点"纸"的透光渐变。
2. **城墙远景像一排格子**（§19.7 第 2 条未动）：分段铺在 9m 高差上，段间锯齿。
3. **码头东侧上岸平台**仍是浅灰平板（§19.7 第 4 条未动）。
4. **石板街面没有贴图**：S9 给了逐块色差与磨损，但一块 1.2m 的石板内部是纯色。
   石面缺的是"颗粒 + 边角脏"，与白墙同一类问题，只是 UV 在 InstancedMesh 上要另想办法。
5. 蓝调 / 夜晚全景偏暗（§19.7 第 5 条未动）。

## 21. S12 窗纸与石面（11-19 实施）

> 目标：§20.8 第 1、4 条。两条都是"一个材质同时服务两种东西"引起的：
> 窗纸和灯笼共用一个发光参数，石板和三米高的桥墩共用一套贴图尺度。

### 21.1 窗纸不是灯

`PAPER` 材质被三处共用：二层窗纸、铺面里的光板、檐廊吊灯。原来与灯笼本体
（`lanternGlow`）一起按 `2.2 * lampScale` 推，黄昏时二层三扇窗糊成三块纯白 LED 板——
窗棂被 bloom 吃成一片，反而看不出"这是窗"。

拆成两组：**纸 1.25、灯罩 2.2**。颜色不动（Blender 里给的 0xFFB964 暖橙），
强度一降，窗棂立刻长回来，纸色也从白回黄。

判据不是"看着亮不亮"而是**窗棂还能不能数出来**：AE 压完 1.25 倍时窗棂与纸的
亮度差仍在 0.25 以上，2.2 倍时两者都进 ACES 的肩部、被压成同一个白。

### 21.2 石面：先证明 UV 通，再谈幅度

给 `stone` / `stoneDark` 挂贴图后**画面毫无变化**。这次没有急着调幅度，先用一个
`DEBUG_STONE_UV` 开关把贴图换成 8×8 棋盘截图——棋盘一次就说明三件事：
UV 被采样了、投影轴对了、尺度是 40cm/格。**机制没问题，是幅度太弱。**

这个诊断顺序值得固定下来：**贴图"看起来没生效"时，先换一张不可能看错的图**
（棋盘/纯色），比反复调参数快一个数量级。S11 的 UV 坑浪费了两轮截图，就是因为
当时是"调幅度—截图—再调"。

### 21.3 幅度：fbm 的方差会吃掉系数

`fbm()` 输出集中在 0.5（std 约 0.1）。写 `lum = 0.975 + (fbm-0.5) * 0.08`，实际
标准差只有 0.8%、在深灰石面上差 6 个灰阶——**小于人眼在纹理上的分辨阈值**。

改成 `(fbm-0.5) * 2` 先拉满再乘系数（0.22 / 0.12）。而真正让石板"活"过来的不是
颗粒：4cm 的颗粒在 5m 外被 mip 平均掉了，起作用的是 **0.4~0.5m 尺度的苔斑**
（`smoothstep(0.60,0.80, fbm(u*7, v*7))`，暗 28%、偏绿）与 2~5cm 的凿痕。

这条对白墙同样成立（白墙的雨痕之所以一眼可见，是因为它是 `smoothstep` 全幅 × 0.19，
不是 fbm 乘小系数）。

### 21.4 指标

**1254.2k 三角面 / 142 drawcall**（与 S11 持平）。1080p mid 13~24 fps。
存档 `docs/art/showcase/s12/`（17 张）。

### 21.5 仍未解决

1. **城墙远景像一排格子**：8m 标准段沿 Z 缩放铺在 9m 高差上，段间锯齿；
   而且 `wallBrick` 是纯色——加砖纹要按米算 UV，但**实例缩放会把 UV 一起拉**，
   得改成"UV 按未缩放的局部坐标算 + 每段固定 8m"才成立。
2. **码头东侧上岸平台**仍是浅灰坡面（§19.7 第 4 条未动）。
3. 蓝调 / 夜晚全景偏暗（§19.7 第 5 条未动）。
4. 河岸近景的草与滩石仍是程序化色块（S9 的成果在 5m 内够用，2m 内不够）。

## 22. S13 城墙砌石与顺坡马道（11-19 实施）

> 目标：§21.5 第 1、3 条。城墙是远景里最大的一块纯色面，也是唯一一处
> "8m 一断"的规律结构。两条其实是同一个问题的两面：**远景缺的是肌理，不是细节**。

### 22.1 贴图三版：从马赛克到条石

| 版本 | 块尺度 | 块间色差 | 缝 | 出图 |
|---|---|---|---|---|
| v1 | 0.8×0.5m，5 块/层 | 0.86~1.12（26%） | 3px、0.47 | 马赛克瓷砖 |
| v2 | 0.67×0.5m，6 块/层 | 0.94~1.04（10%） | 2px、0.58 | 混凝土砌块墙 |
| v3 | 同上 | 0.965~1.025（6%） | 2px、**0.80** | 条石 |

判据不是"缝够不够清楚"，而是**远处的墙面读成"一片有层理的灰"，还是"一格一格的方块"**。
v1 的致命处不是缝太深，是**每块都自成一个色阶**——眼睛先读到格子，再读到墙。

真正让远处成立的是**层理**（0.5m 层高的层间明度差 + 竖向雨痕）：
0.5m 的层在 40m 外约 4px，仍可读；0.67m 的块在同样距离只剩 3px，读不出来。
所以块只负责近景，远景全靠层。

贴图**完全不用 `fbm`**：它不可平铺，平铺边界会跳一条硬边。改用
`pnoise(u,v,period)`（格点索引对 period 取模，数学上严格无缝）叠 3 倍频，
以及 `pnoise(u,v,6,1)`（u 高频 / v 低频）做竖向雨痕——两个方向都用整数周期。

### 22.2 一次差点走错的诊断

第一版贴图挂上后，墙面砖块看起来"尺度大了一倍、像砌块"。先后怀疑
UV 范围、UV 层、实例缩放，甚至改成运行时重算 UV，全部无效。
最后用**垛墙高度当标尺**量了一下：垛高 1.18m ↔ 棋盘 0.44m 格高，比值 0.37，
与设计的 0.465/1.18 = 0.39 吻合——**尺度一直是对的**，错的是"看起来该多大"。

教训：**判断贴图尺度不要用眼睛估，用场景里已知尺寸的构件做标尺**。
S12 用棋盘验证"UV 通不通"是对的，但"棋盘对不对大小"必须有一个参照物。

顺带修掉一个真问题：`blib.join` 之后网格上有**两份 UV 层**（立方体自带的 +
给无 UV 件自动补的），glTF 导出取 `active_render`。`uv_layers.active` 未必是它，
写错层等于没写。现在 `box_uv` 先清空再建一层，杜绝歧义。

运行时那条 `boxUvLocal()` 保留了：它按几何主轴重算，与 `wall.py` 同一套规则，
是这套贴图的第二道保险（也是 `props.ts` 里唯一不依赖 GLB UV 的地方）。

### 22.3 格子感的第二因：每 8m 跌一级

坡度 9m/41m = 0.22，8m 段必然跌 1.76m。段段都跌，就成了一排等大的盒子。

改法不是"少跌几级"（坡度决定跌多少，量化到 1.44m 也会每段跨一级），而是
**让墙段顺着坡度俯仰**：整个 run 用同一个 `pitch = -atan(Δh/Δz)`，墙顶连成一条斜线。

- 绕 X 轴旋转**不改变墙面的垂直性**（墙面法线是 ±X，与旋转轴平行），
  所以墙身仍是竖直的，只有顶面、马道、垛口随坡倾斜——正是山城顺坡马道的形态。
- 整段区间只用一个角度：逐段取坡度的话，相邻段端面不平行，8m 会把 1° 的
  角度差放大成 14cm 的楔形缝。
- 俯仰让水平投影缩短 `cos θ`（12° 是 8cm/端），`sz` 必须乘 `1/cos θ` 补偿，
  再加 6cm 溢出防共面闪烁。

坐标准确性靠"埋深 3.2m"兜底：段中心取 5 点平均高度，两端最多高出/低于地面
0.9m，仍在埋深之内，不会露墙根。

### 22.4 城墙提亮，夜景提月光

砖色 `0x585549 → 0x6B6659`（贴图乘上去之后原色偏黑，白天也像剪影）。

夜景的问题不是 exposure 不够，是**月光没有方向**：`sunIntensity 0.55` 时
建筑全靠灯笼的局部光勾边，全景里整片是黑的，只剩一排灯笼飘着。
`sunIntensity 0.55 → 0.95`、`hemiIntensity 0.42 → 0.7`、`exposure` 只动 1.42→1.46。
**提月光而不是提曝光**：曝光一抬，天空与灯笼一起变灰，夜色就没了。

蓝调 `hemiIntensity 1.1 → 1.35`、`exposure 1.16 → 1.22`。

### 22.5 指标

**1254.2k 三角面 / 142 drawcall，与 S12 持平**（贴图不加几何，俯仰不加 drawcall）。
1080p mid 13~25 fps。存档 `docs/art/showcase/s13/`（17 张）。

### 22.6 仍未解决

1. **城墙两端是"切断"的**：run 端点（z=-56 / 44）直接截断，俯视时看得到平口。
   真实城墙要么收进山体，要么以敌台/转角收头。
2. **码头东侧上岸平台**仍是浅灰坡面（§19.7 第 4 条）。
3. 河岸近景的草与滩石仍是程序化色块（2m 内不够）。
4. 牌坊匾额在白天是一块黄绿发光板（`gold` 材质吃灯太狠）。
5. 白天预设整体偏暗偏冷（天空是深蓝渐变、地面偏灰），与"白天"不符。

## 23. S14 白天重打光、暗角收敛、敌台收头与匾额（11-19 实施）

> 目标：§22.6 第 1、4、5 条。三条拼在一轮是因为它们互为因果——
> **暗角一直在替错误的打光擦屁股**。

### 23.1 白天偏暗偏冷：主光方向与所有可见立面垂直

`sunAzim -95` 时太阳从正北打过来。全城主街的临河立面（法线 -X）与城墙外墙面
（+X）**同时吃不到直射光**，整座城只有屋顶顶面亮。这才是"白天像阴天"的真正原因——
不是曝光不够，是主光方向错了。

改成西南偏南（130°）：主立面与 +Z 端都有 0.6~0.7 的入射角，阴影朝东北落在
建筑背后，不挡视线还白送街道一层硬影。

配套三刀：

- `sunIntensity 4.2 → 3.2`：暗角去掉之后 4.2 会把桥栏、石阶、白墙烤成纯白
  （暗角过去一直在替它压掉约 40% 亮度）。
- `hemiSky 0x9fc7ff → 0xc4cbd2`：纯蓝天光让所有背光白墙变成"蓝灰水泥板"。
  天空蓝保留在天顶，环境光往灰里拉；`hemiGround` 给暖色（土、石、草都是暖的）。
- `envIntensity 1.8 → 1.25`：满额 IBL 让白墙吃满蓝天天光，出图是"青瓷墙"。
  环境反射只该作补光。

### 23.2 暗角：不该由后期承担的亮度

原 `uVignette` 固定 0.9，白天四角压掉近 40% 亮度。改为每时段参数
`vignette`（day 0.3 / dusk 0.5 / blue 0.55 / night 0.62），后期加 `setVignette()`。
**构图氛围靠打光与雾，不靠把画面四角涂黑。**

### 23.3 白天的黑河

俯视时水面菲涅尔只占 ~15%，剩下 85% 是水体色。白天沿用黄昏的
`0x0d2126` 就是一条黑河（"白天比黄昏还暗"的根源之一）。`waterDeep` 改为
每时段独立：day `0x2c4a52`、dusk `0x0d2126`、blue `0x14282e`、night `0x081820`。

### 23.4 匾额：金地反光板 → 深木匾

原来 `GOLD 0xD9B25E / rough 0.42 / metal 0.15` 一整块金属板扣在牌坊明间，
白天吃直射光就是一块黄绿反光板。拆成 `plaqueBoard 0x2B1F19 / rough 0.68`
的深木匾 + 原石框——白天读作"挂了块匾"，黄昏灯笼一亮再由 gilt 饰线负责金。

### 23.5 敌台：收头体量与"两种灰"

城墙端头不能平口截断。收头选敌台（马面墩台）而不是收进山体，因为它三层都能
兑现：**加宽**（比墙体宽 1.5m，端面被吃进去）、**升高**（马道 5.1 > 墙顶 4.6，
再高就成孤零零的黑塔）、**垛口**（四面包 1.18m 女墙）。基座再比台身宽一圈、
向下埋 0.9m，坡地端头不露墙根。

**最大的坑：材质"参数抄一样"没用。** 敌台是程序化 Builder 出来的，新建的
`MeshStandardMaterial` 与 GLB 城墙的材质就算 color/roughness 全同，贴图对象、
envMapIntensity、顶点色开关、color 的线性化路径只要差一点，接缝两侧就是
"两种灰"——实测敌台比墙暗近一半，像另砌了一座黑塔。中途还怀疑过
`receiveShadow`（墩台吃墙影确实更暗），关掉后只是好一点，不是主因。
**最终解法最简单也最稳：直接把 GLB 的 `wallBrick` 材质实例换给敌台网格**，
连贴图引用一起共享。S11/S12 的贴图是按材质名全局扫的，所以敌台换引用之后
砖纹、UV 尺度自动对齐，一行参数都不用抄。

四座敌台的体量（约 +2k），1080p mid 13~25 fps。存档 `docs/art/showcase/s14/`
（17 张）。HUD 副标题更新为 S14。

## 24. S15 埠头归草与草地去饱和（11-19 实施）

> 目标：§23.7 第 1、2 条。两条都小，但第 1 条背后的教训值一整节——
> **四轮返工（S9-S14 各改一版），最后是"删掉"才对的**。

### 24.1 码头上岸处：地形在说什么就听什么

上岸处先后做过四版：写死三级台阶（S9，比岸高 1.3m 变成爬墙）→ 按地形现算
三级台阶（S9 修正，落差太小读作平板）→ 强制最小级高 0.17 + 两侧侧石
（S15 第一版，读作"抬高的灰色平台 + 发白的水泥边框"）→ 2×2 旗石埠头
（S15 第二版，被地形啃成三角碎片）。

最后查明了根因：**这段岸坡的地面高度本来就与码头面齐平（±0.1m）**。
旗石按"足迹四角最高地形 +0.10"放置时四块全部不满足放置条件——岸坡比
旗石允许的顶面还高。岸与码头齐平的渡口，本来就不需要任何上岸构件；
草地直接包住甲板边缘就是这种渡口的原样。删掉 `buildApron`，衔接反而干净。

两半条经验沉淀在代码注释里：

- **平的构件放进连续的地形面，只要一角低于地面就会被"啃"**——顶面必须
  盖过足迹内最高角，或者干脆不放；
- **"看起来缺一块石头"和"实际需要一块石头"是两回事**——先量地形再动手，
  别用构件去迁就想象中的高差。

### 24.2 草地去饱和

白天 hemi 提到 1.15 之后，两处叠加让草地发"艳"：

- 地形色斑的饱和度抖动 `offsetHSL(..., tone*0.16, ...)` → 0.10。
  干湿差靠明度通道就够，饱和度通道一动就出 0x7f9a3a 一类的荧光绿。
- 草簇基色 `0x7b8a4c → 0x767f4e`。去饱和的关键是**压 G 通道而不是压亮度**
  ——亮度一压草丛就从草地里"沉"下去了。

逐丛干湿差（近水冷绿 / 上坡黄枯）保留，远景 90m 低频色斑保留。
