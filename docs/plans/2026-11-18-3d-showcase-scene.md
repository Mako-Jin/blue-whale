## 5. 风格统一（三源并存的关键）

三道强制工序，不靠"感觉像"：

1. **统一色板**：全场景限定 6 主色（石灰 `#cfc6b4`、木褐 `#6b4a33`、瓦青 `#3f4a4d`、灯笼朱 `#c04a32`、水青 `#3f7c8c`、苔绿 `#5a6b3e`），所有素材入场先过色相/饱和度归一化 shader。
2. **统一材质颗粒度**：所有材质 roughness 落在 0.6-0.95，禁用纯镜面；所有贴图统一 1K（地标 2K），生成模型的塑料感靠"降饱和 + 加粗糙 + 提法线"三件套压下去。
3. **统一后处理**：全场景只有一条 Grade 链（LUT + 暗角 + 颗粒），AI 生成物与素材库物件过同一条链，视觉上会被"焊"在一起。

### 6.1 Blender 管线（已实测，2026-11-18）

| 项 | 结论 |
|---|---|
| 位置 | `D:\blender\blender.exe`，Blender **5.2.2 LTS**（build 2026-09-15，Python 3.x 内置） |
| 冒烟结果 | `--background --factory-startup --python smoke.py` 全链路通过：EEVEE 渲染检查图成功、GLB 导出成功（木箱 3548 B / 24 三角面）。脚本见 `tmp/blender-smoke/smoke.py`，S0 时迁入包内 `tools/blender/` |
| 渲染引擎 | 后台 EEVEE 可用（实际落到 `BLENDER_EEVEE`），不需要 GUI |
| 配置不落 C 盘 | `BLENDER_USER_CONFIG` / `BLENDER_USER_SCRIPTS` 指到 `.toolchains/blender/{config,scripts}` **已实测生效**（默认会写 `%APPDATA%\Blender Foundation`，违反项目硬规则） |
| 为什么脚本优先于 MCP | 18 件道具要批量建模、批量渲三视图、批量导 GLB——脚本一条命令跑完且可入库复现；MCP 适合"边看边调"的探索期，但要 GUI + 插件 + 重启，不作主路径 |
| 插件状态 | **未装 blender-mcp**（`extensions` 下只有默认目录）。不影响任何阶段；若后续需要交互调试再装 |

> 冒烟件已经复现了文章踩的第一个坑：箱盖与箱身之间留了 3 cm 悬空——这正是三视图检查要抓的东西。
> 也就是说，**"导出成功"不等于"能用"**，检查图不是可选项。


**GLB 统一规范（硬性）**：

- 单位 1 unit = 1 m，+Y 向上，朝向 +Z；
- 原点在**底面中心**，导入后仍用 boundingBox 二次贴地（文章踩过"原点贴地、底部悬空"）；
- 单件三角面 ≤ 1.5 万，合计 ≤ 25 万；
- 导出 GLB + Draco 压缩，贴图 WebP/KTX2；
- 命名 `{组}-{件}.glb`，如 `camp-tent.glb`、`facility-bridge.glb`；
- 压缩命令：`npx @gltf-transform/cli optimize in.glb out.glb --compress draco --texture-compress webp`。

**三视图检查（照抄文章的有效动作）**：每件渲正面/侧面/斜后三张，专查悬空、穿模、破面、结构连接、原点。发现问题**只修那一件**，重渲复检。

**资产台账** `docs/design/showcase-assets.md`：件名 / 来源 / 许可证 / 是否商用 / 三角面 / 文件大小 / 检查结论。企业项目，无台账不得入库。

## 11. S1 验收记录（11-18 实施）

**已落地**（`whale-frontend/platform-apps/whale-showcase`，dev 端口 8126）：

| 项 | 实现 | 文件 |
|---|---|---|
| IBL | `PMREMGenerator.fromScene` 把同一套天空 shader 烘成环境贴图，切时段自动重建 | `src/scene/env.ts` |
| 后处理链 | RenderPass → UnrealBloom → OutputPass → GradePass（分离色调/对比/暗角/颗粒）→ SMAA | `src/scene/postfx.ts` |
| 水面 | 值噪声波纹 + 天空同源反射 + 菲涅尔 + 碎金，带距离衰减 | `src/scene/water.ts` |
| 地形 | 反照率按 sRGB 视觉值重取 + 大尺度色斑 + 低频颗粒 | `src/scene/terrain.ts` |
| 石拱桥 | 带三孔拱洞的挤出实体（原来"桥面板+圆环拱+方墩"三者互不相连，出图是悬空薄带） | `src/scene/props.ts` |
| 街/房/墙布局 | 街心 x=17、民居 x≥22.4、城墙 x=31.5；城墙按 4m 分段取地面高度 | `src/scene/props.ts` |

**踩到的四个坑（都是"编译通过、出图才炸"）**：

1. `#include <tonemapping_fragment>` 只在**渲染到画布**时生效（`currentRenderTarget === null`），渲染到 RT 是空操作。所以整条链里只有 OutputPass 做色调映射，不会二次映射——但也不能靠材质的 tonemapping 兜底。
2. `renderer.info` 每次 `render()` 自动重置，接上 composer 后 HUD 只能读到最后一个全屏 quad（2 个三角面、1 次 drawcall）。必须 `info.autoReset = false` + 每帧手动 `reset()`。
3. 水面法线扰动**必须按距离衰减**，否则远水面每像素都在两个噪声格之间跳，白天整条河变成"碎冰/大理石"。
4. `THREE.Color` 按 sRGB 转线性，`0x43512e` 的线性值只有 0.05；配 `NdotL/π` 就是死黑。有 IBL 之后必须按视觉色取值，别再手动压暗。

**当前指标**：163.7k 三角面 / 43 drawcall / 1080×675 下 40–46 fps（含 Bloom+SMAA，未做画质档）。

**对比图**：`docs/art/showcase/s0/`（接 IBL 前）↔ `docs/art/showcase/s1/`（现在），7 个固定机位同名。

**仍然丑的地方（下一步的靶子）**：树是"棒棒糖"、房是方盒子、屋顶是平板、地面无材质、牌坊檐口是平板、夜景灯笼不照地也无水面倒影。这些都是**形体与贴图**问题，靠调光调不出来 → 进入 S3 资产替换。

| 资产 | 文件 | 三角面 | 体积 | 替换对象 |
|---|---|---|---|---|
| 牌坊（四柱三间三楼） | `paifang.glb` | 19.2k | 1.3 MB | 程序化 `buildGate` |
| 民居（马头墙） | `house_small/big.glb` | 9.1k / 10.0k | 0.6 / 0.7 MB | `buildHouses` |
| 街灯（挑杆灯笼） | `lantern.glb` | 0.7k | 54 KB | `buildLanterns` |

| 垂柳 | `tree_willow.glb` | 2.6k | 87 KB | 同上 |

**管线约定（写进 `blib.py` 头注释）**：单位米 / 底面严格 z=0 / 硬边过小倒角 /
取色按 hex（`srgb()` 转线性）/ glTF 导出 `Blender(X,Y,Z) → glTF(X,Z,-Y)`。

**踩到的五个坑**：

1. `--factory-startup` 给的是**默认场景**（含立方体、相机、灯）。脚本开头不 `read_factory_settings(use_empty=True)`
   就会把默认立方体一起导出——检查图正中间一个白方块。
2. 树干"根部张开"用了**局部坐标** z（圆柱是 -h/2..+h/2），底面算出 exp(+3.8)≈45 的系数，
   柳树整棵变成撑满画面的圆锥。必须 `zrel = v.co.z + h/2`。
3. 柳条的世界高度漏传，枝条从地面长出来；且曲线转网格后没有 `Col` 属性，套顶点色材质渲染成纯黑。

5. 马头墙高度写死成"檐口 + 0.55 + i·0.62"，最高一档 5.55m 而正脊 5.75m——整道墙埋在屋面里，
   只露出三个小方块。必须按 `roof_z(y)` 反推每段顶标高。

**运行时改造**：

- 树 / 民居 / 灯笼全部改 **InstancedMesh**：drawcall 从 108+54+22 降到 6+12+3。
- 民居落点由"随机撒点"改**固定 z 槽位**（间距 9m）：房子正面朝 -X 时面宽是沿 Z 排布的，
  旧判据只按 6.5×7 算，相邻两栋必然互相插进去。

- 画质三档 `?q=high|mid|low` 或 HUD 按钮：只动像素比 / SMAA / 阴影分辨率。

## 14. S5 灯影与渡口夜灯（11-18 实施）

### 14.1 灯影：为什么探针不行，最后还是自己算

先做了 **CubeCamera 环境探针**（512 HDR，河心烘一次，切时段重烘），期望水面反射出岸上的灯笼。
实测**完全无效**，原因值得记下来：

> 灯笼在水面上方 2.7m，它在水下的镜像是 -2.7m。从相机射向镜像点的射线是**向下**的，
> 而水面反射向量 `R` 在掠射角下是**向上**的（几乎水平朝远端）。两者不是同一个方向——
> 探针里灯在 cube 的**下半球**，水面永远采不到。这是**平面反射（Reflector）**才有的效果，
> 而 Reflector 要每帧把 58 万面场景再渲一遍，帧率会掉到 20 以下。

改成按几何直接算（`water.ts` 的 `lampGlow`）：灯的镜像点与相机连线交水面于一点，那里就是
观众看到的倒影位置；在这一点上画一个**沿视线方向拉长的椭圆**，横向 40cm、纵向拖 3m。
再乘一层 `sin(along*3.4 - t*2.1)` 的**横纹调制**——真实水面的灯影是被水波切成一道道横纹的，
少了这层就是"月光洒水面"的雾。

灯位与亮度复用点光源（`water.setLamps`），灯亮水亮，白天 `lamp=0.15` 时自然为 0。

**探针保留**（仍然接在 `uEnv` 上）：它把岸上的建筑与天空带进远水面的反射，只是不再指望它出灯影。

### 14.2 渡口夜灯

原来码头附近**没有灯**：最近的街灯在 20m 外，而点光源衰减距离 14m——夜里整片码头是黑的，
相机抬到 3.6m 也看不清平台在哪。加了：

- **两盏立杆灯**在码头靠岸一侧（z=-16.6 / -11.4，挑向水面），走 `lanternSpots()` 与街灯同一套实例；
- **一盏 17m 衰减的专用点光**在 `(-8.2, 2.7, -14)`。街灯那三盏是"每三个灯位取一个"抽出来的，
  全在街上，码头一盏都分不到。

顺带确认了一条几何事实（写进截图脚本注释）：**只有低机位能看到灯影**。灯高 2.7m、相机高 3.6m 时
倒影点落在 x≈-2.9 / z≈-20.3，在河面内；全景机位相机高 21m，算出的倒影点落在岸上——物理上就没有。
所以新增机位 `04b-dock-night` 作为唯一的灯影验收位。

## 15. S6 牌坊重做与左岸（11-19 实施）

### 15.1 斗拱为什么会变成栅栏

原写法是"一排 0.2×0.24×0.30 的小方块 + 一块 0.30×0.30×0.12 的帽"，块距 0.36、净距 0.16，
背后**直接是天空**。逆光下就是一道等距竖条。问题不在方块本身，在三点：

1. **没有拱眼壁**。真实斗拱背后是垫板，从正面看不到天；
2. **没有横拱**。真斗拱的视觉主体是那条**连续的水平拱**，斗只是它上面的节点，
   不能等宽等高地排一溜；
3. **没有出跳**。斗拱是垂直墙面伸出去的悬挑构件，只在墙面内堆方块，从哪看都是贴片。

现在按"坐斗 → 一跳华拱（出跳 0.94，贯通前后两面）→ 横拱（通长）→ 升 / 二跳 → 挑檐桁"分层做。
另外**攒距收到 0.44、坐斗 0.28**（净距 0.16，只有一个斗口）：0.62 攒距时净距 0.38，
出图仍是一排垛口——这是"像不像斗拱"最敏感的一个数。

### 15.2 牌坊的三个比例问题

- **三间几乎等宽**：旧值 INNER=1.30 / OUTER=3.90，明间 2.60、次间也是 2.60，三等分出一座牌坊。
  改成 3.10 : 2.20（1.4 : 1，四柱三间的常规比例）。
- **柱径太细**：0.34 撑 6.3m 高，正视像竹竿。改 0.40。
- **次间屋顶插进匾额**：屋顶按开间中心 2.65 摆、宽 3.00，内沿到 1.15，正好探进明间，
  从正面把匾额下角切掉一块。中心挪到 2.85、宽 2.75，内沿 1.475，藏在内柱后面。

### 15.3 牌坊西腿其实一直站在桥面上

牌坊跨度 7.5m、柱位 12.75 / 20.25；石拱桥的实体是 x -14…14（桥必须够到东岸：
河心 4.2、河槽半宽 9）。x=12.75 处桥面已抬到 **2.03m**，而广场地面只有 1.15——
**柱脚埋进桥面 0.88m，夹杆石整个看不见**。挪到 GATE_X=17.9 后柱位 14.15 / 21.65，
跨在桥头广场上，东腿落在街沿（街面 13.5…20.5），也就是"骑街而立"的真实摆法。

## 16. S7 临街铺面与镇区平台（11-19 实施）

### 16.1 "一排货架"的三个根因

1. **九栋同型**：只有 small / big 两款，都是"贴街的单层白盒子"，面宽 6.2 / 7.4、进深 4.4 / 5.2。

### 16.2 新铺面（`house.py -- shop`）

|---|---|

### 16.4 镇区临水平台（重大修正）

原来河道中心线随 Z 摆动到 7.1，东岸水线到 16.1，而街面从 13.5 起——**z>18 的街道泡在河里**

### 16.5 两处"缝里露草"

## 17. S8 屋顶群落与巷口（11-19 实施）

> 目标：把俯视时"一整块屋顶"拆成**有脊、有山墙、有巷口**的城镇（§16.8 第 1 条），
> 并给程序化几何补上"材料颗粒度"，解决整片地表是一块平色的问题。

### 17.1 三处改动（都在 `house.py`）

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 马头墙高出屋面 | 0.52 | **0.78** | 0.52 时俯视只能看到压顶瓦的**顶面**，白墙立面被屋面自己挡住——出图是"浮在瓦上的几块石片"。1.02 又过头：每户山墙长成 6×5.2 的大白板，整条街变成"墙的城市"，屋顶反被挡住 |
| 压顶瓦 | 宽 +0.18、厚 0.1 | 宽 +0.14、厚 0.09 | 出挑太大就成了"搁板"；0.09 才是一条影子线 |
| 正脊 | h0.34 / w0.20 / curl0.16 | **h0.46 / w0.28 / curl0.30** | 俯视时正脊是唯一能"分块"的线，加粗起翘后才读得出来 |

**翘角（鹊尾）试过，删了**：这个尺度上（0.3m）做不出真正的起翘——做成 0.34 深、
0.11 厚的斜板，出图是一排"水泥舌头"，比干净的阶梯轮廓难看。

### 17.2 瓦色：两次翻车与结论

| 尝试 | 结果 |
|---|---|
| 照片取色 `0x2B2F33`（S3 起） | 黄昏/夜晚纯黑，整片屋顶读不出形状 |
| `0x3E474E` + rough 0.46 | 过曝成"压型钢板"：20cm 瓦垄每条一道高光 |
| `0x333B41` + rough 0.62 | 仍然偏亮，且**瓦垄纹理被冲掉**（自遮蔽对比被高反照率淹没） |
| **`0x2E3338` + rough 0.58** | 定稿。比照片色亮一档，剩下的变化交给逐栋色差 |

**教训**：反照率是 sRGB→线性，`0x2B` 与 `0x3E` 在线性空间差 2 倍——"只改了一点颜色"
在小数值区等于换了一档材质。要调暗部材质，必须按线性值算，不能按 hex 的肉眼差。

### 17.3 逐栋瓦面色差（`InstancedMesh.setColorAt`）

整片屋顶同色同亮是"一整块"的第二个成因。用 `setColorAt` 逐实例乘一个色偏，
**不加 drawcall**（`instanceColor` 会让 three 在片元里定义 `USE_COLOR`，
`diffuseColor.rgb *= vColor`）。色表 6 档、均值约 0.83：
`0xffffff / 0xf6f2ea / 0xe2e6e2 / 0xece6da / 0xd2d6d2 / 0xf0ece4`。

> 验证方法是把它临时设成纯红/绿/蓝——**看起来"没效果"不一定是没生效**，
> 也可能是幅度太小。第一版用近白色表，肉眼看不出差别，差点当成 no-op 删掉。

### 17.4 程序化构件的"材料颗粒度"

`Builder` 写顶点色（每个构件一个均匀色 + 一点冷/暖偏移），幅度按材料给：
石头 0.11~0.13、木 0.06、白墙 0.045。**不加 drawcall、不加贴图**，
但街面从此是"一块块石板"而不是"一块水泥地"。

配套 `Builder.darken(k)`：做**假环境光遮蔽**。巷子只有 2.8m 宽，两侧山墙挡掉大半天光，
而 IBL 是一张无遮挡的天空贴图——不压暗，巷内亮得像街上，纵深全没了。

### 17.5 巷口（`buildAlleys`）

两处铺面之间让出 2.8m（`STREET_PLOTS` 加 `kind:'alley'`），巷深 6.2：

- 两侧墙不用另建——铺面的山墙本来就整进深落地、高过屋面；
- 巷门：两垛砖墩 + 门楣 + **前后两坡的瓦顶（厚 0.2、前坡挑 0.55）**。
  0.12 厚的瓦片从街面平视只看得见一条边，出图是"门楣上浮着一块黑板"；
- 巷尾是**一户人家的后门**（石门框 + 双扇板门 + 门罩 + 一口水缸），不是照壁。
  照壁是一堵亮白墙，眼睛没有落点，6m 纵深被压成 1m 的壁龛；一扇暗色的门是巷内
  唯一的高对比物；
- 巷名匾用 `woodDark`：第一版用 `gold`（金属度 0.62），在 1m 内的壁灯下烧成一块橙红色发光板。

**巷灯**：两盏 9 candela / 9m 的独立点光源。不能塞进 `lanternLights`——那个数组同时喂给
`water.setLamps` 算水面倒影，巷子离河 9m，倒影是假的。位置离墙留 0.8m，
贴着墙时"距离的一次方"会把白墙烧成纯白。

### 17.6 街灯避让巷口

2.6m 高的灯杆正好立在 2.8m 宽的口子上，把 6m 深的巷子从巷口机位整个挡住
（第一版出图：一根灯笼怼在镜头前，后面一道黑缝）。`lanternSpots()` 按巷口 ±2.6m 跳过。

### 17.7 其他

- 石板街南北各延 2m（`-46…41`）：北端新加的院落原本铺装之外。
- `stone/stoneDark` 压暗一档（`0xcfc6b4/0x9d9587 → 0xb8ae9a/0x847d71`）：
  正午直射 + ACES 会把浅石色烧成纯白，整条街像水泥地。
- 后巷围墙（`buildBackWalls`，x=28.6，逐段取地形高度）：俯视时屋顶之后到城墙根之间
  原本是一大片空地，城镇"只有一层皮"。
- 新机位 **`俯视`（roofs）**：屋顶是画面里面积最大的东西，全景机位（高 21m / 距 60m）
  看过去屋顶只有几条斜边，改的全在盲区里。
- 新机位 **`巷口`（alley）**：正对着拍是"门洞证件照"，退到 z=19.2 斜看，巷门是斜的，
  巷内光斑与尽头门形成两级纵深。

### 17.8 指标

**732.5k 三角面 / 139 drawcall**（S7：737k/141，面数略降是因为翘角被删）；
1080p mid 21~32 fps。存档 `docs/art/showcase/s8/`（15 张）。

### 17.9 仍未解决

## 18. S9 地被与街面（11-19 实施）

> 目标：解决 §17.9 的第 1、2 条——**近景植被**与**街面痕迹**。
> 这两项对近景机位（河岸 / 码头 / 街口）的观感提升最直接，而它们共同的问题是
> 同一个：**画面下半部是一整块平色**。

### 18.1 地被三层（`props.ts` 地被段）

| 层 | 数量 | 几何 | drawcall |
|---|---|---|---|
| 草簇 | 1.62 万丛 | 6 片叶 × 3 面 = 18 tri | 1 |
| 灌木 | ~240 丛 | 4 个二十面体（detail=1）= 320 tri | 1 |
| 滩石 | 300 颗 | 二十面体压扁 | 1 |

- **草簇不用 alpha 贴图**：这个项目没有透明材质的排序管线，一张透明 PNG 在
  Bloom 与阴影下会露方边。实体叶片的代价是三角面，但没有排序问题，还能吃逐顶点色。
- **草叶法线往 +Y 掰**（保留 45% 朝向信息）：竖直薄片的几何法线是水平的，
  黄昏低角度光会让一半叶片全黑、一半全亮，出图是一丛丛"刀片"。
- **逐实例着色**：用高度定干湿（近水青、上坡黄）× 位置哈希定抖动。
  `Math.sin(x*12.9898+z*78.233)*43758.5453` 取小数——哈希而不是 `Math.random`，
  重建场景不跳色。
- **不投影**：几万根 0.45m 的细叶投出来的只是阴影贴图上的噪点。

### 18.2 落点规则（`blockedByPaving`）

铺装区必须**按矩形写死**，不能靠地形高度判断：镇区平台被 `townMask` 压到 1.18，
与河滩草地高度几乎一样，靠高度分不出来。排除项：镇区（x 13.2…34 / z -50…45）、
田垄（整块 + 0.8m 边距）、西岸小路（距中心线 2.6m 内）、码头平台、水埠、
西岸四栋房子（`WEST_VILLAGE` 提到模块级，房子与地被共用同一份坐标）。

采样分两遍：全岸带（距河心 9.4…39m，`pow(rand, 0.72)` 让分布偏向近岸）+
码头近景 3200 丛（那一块是画面下半部）。

### 18.3 街面：排水明沟

**做法是让路，不是叠层**：西半幅石板从 13.53 收到 13.99，露出下面的垫层当沟底
（比街面低 11cm），沟内侧一条 0.16 宽、高出街面 2cm 的牙石，沟底每 7m 一道跌水坎。

> 叠上去的"沟底"是一条凸起的暗带，看着像路缘；只有真的让开，才是一条沟。

### 18.4 两次翻车：所有"贴在街面上的薄皮"

先做了**车辙**（两条 18cm 宽的磨亮石带）和**门前踏石**（每家门口一块 1.1m 的亮石板），
都是 6mm 厚的薄板贴在街面上。两次都失败，而且<b>改材质改不动</b>：

| 尝试 | 结果 |
|---|---|
| `0xc2b8a4` + rough 0.52 | 两条纯白"马路标线" |
| `0x928a7b`（与石材同色）+ rough 0.42 | 还是白的（掠射角菲涅耳反射整片天空） |
| `0x8f8779` + rough 0.86（与周围石材完全同参） | 仍然比街面亮一档 |
| `0xff00ff` 纯洋红 | **是这块几何**，材质确实生效 |
| `0x101010` 近黑 | 阴影里变黑、阳光下仍比街面亮 |

结论：**这个场景里不要在既有表面上叠 5~6mm 的薄板**。原因没查到底（薄板的
自阴影偏移 / 掠射角下的深度关系），但现象稳定复现，性价比也不支持继续查。
改用两条零风险的替代：

- 石板**高低差**从 ±0.015 提到 ±0.055（老石板的沉陷是厘米级的，掠射角下就是明暗线）；
- 按 7% 的比例把石板换成浅一档的 `stone`——几十年里陆续换过的板子，街面因此有了"时间"。

### 18.5 新机位：河岸

`bank`：pos [-19, 6.4, -31] → target [-5.5, 0.9, -12.5]，fov 46。

地被只有 0.3~1.2m 高，而所有既有相机位都在 3.5m 以上——草在画面里只是地面上的
一层颗粒，看不出"是一片草"还是"撒了一把碎屑"。**验收地被必须有贴地机位。**

> 第一次把机位放在 [-21.5, 1.95, -23.5]（真的是眼高），结果镜头正对着一丛草：
> 半屏是几片巨大的叶子。地被机位要"低但不要钻进草里"：5~7m 高、10~20m 外。
