## 一、为什么要有这一层

后端 M0/M1-2 已经把「地址 ↔ 坐标、点位、围栏判定」收进 `whale-map`，Key 也不再下发到前端。
但每个要显示地图的页面仍然会各写一遍：

1. `axios.get('/map/poi/search')` 之类的裸调用与类型；
2. 底图脚本的 `<script>` 注入（每个应用一份，重复下载 SDK）；
3. `new TMap.LatLng(lat, lng)` 这种**纬度在前**的调用；
4. 浏览器的 GPS 坐标直接往底图上放（这是最贵的一条，见下）。

结果就是「四个页面四种写法、四种坐标系、三种 Key」。共享包把这几件事收成一份。

### 最容易出错的一条：GPS 是 WGS84

`navigator.geolocation.getCurrentPosition()` 返回 **WGS84**，而腾讯/高德底图是 **GCJ-02**。
直接把 GPS 结果画到底图上，位置偏 300–500 米，且**数据本身完全合法**——
坐标系没写错、接口没报错、日志里什么都看不出来，只有「员工说打卡点飘到马路对面」。
所以前端必须能做 WGS84 ↔ GCJ-02，而且算法参数要和后端逐字一致。

│   │   ├── tencent.ts        腾讯 GL 适配器 + SDK 加载器

| 层 | 依赖 | 没有底图 Key 时 |
|---|---|---|
| `coord` / `client` / `fenceDraft` | 无（纯函数 + 一个 `request` 函数） | 完全可用 |

## 三、关键决策与理由

### 3.1 共享包不选底图，只定义 `MapEngine`

腾讯、高德、天地图的 JS API 在初始化、图元命名、事件对象上都不一样，而「用哪家」取决于
各应用自己申请的 Key（带 Referer 白名单）。把腾讯 SDK 焊死在共享包里，等于替所有应用做了这个决定。

`MapEngine` 只暴露 7 个方法：`setCenter` / `setZoom` / `fitBounds` / `setMarkers` /
`setPolygons` / `onClick` / `destroy`。够画围栏、够放点位，不够做「炫酷驾驶舱」——
后者本来就该自己写。

**进出一律 GCJ-02**：引擎内部不许再做坐标系转换，否则就会出现「转两次」的经典事故。

### 3.2 只用 SDK 的五个能力，不用 `fitBounds`

适配器只碰 `Map` / `LatLng` / `MultiMarker` / `MultiPolygon` / `PolygonStyle`。
刻意不用 SDK 的 `fitBounds`——各家对「bounds 对象怎么造」差异很大（有的要
`LatLngBounds`，有的要 `[southWest, northEast]`），赌错就是运行时 `undefined` 崩。
改成按经纬跨度自己算 zoom（`zoomForSpan`，`log2(360 / span)`），逻辑可测、不随 SDK 小版本漂移。

### 3.3 `engineKey` 决定重建，而不是工厂函数引用

工厂通常是内联的：`factory={createTencentMapEngine(key)}`，每次渲染都是新引用。
拿它当 `useEffect` 依赖，就会**每渲染一次重建一次地图**（表现是地图疯狂闪烁、点位闪回原位）。
组件把依赖固定在 `engineKey` 字符串上：真要重建（换 Key、换供应商）改这个字符串。

### 3.4 围栏不做「双击闭合」

底图 SDK 自带双击缩放，两件事抢同一个手势，实际结果是「想闭合，结果放大了两倍」。
改成工具栏按钮显式结束绘制，手机上也不会出现「双击被浏览器吞掉」。

### 3.5 圆离散成 64 边形

多数 SDK 的多边形图元是稳定 API，圆图元各家不同名（`Circle` / `MultiCircle` / `Marker`+`radius`）。
统一按 64 段离散成多边形：在几公里尺度上视觉偏差远小于半个像素，而代码只依赖一个图元。
**面积仍按 πr² 算**，不按离散多边形算——离散多边形面积系统性偏小 0.16%。

### 3.6 搜索加请求序号

`searchPoi` 是网络请求，用户连打两个字会有两次并发。「后发先至」会让列表停在旧关键词的结果上，
看起来像「搜索结果不对」。每次请求带序号，回来的不是最新一次就直接丢弃。

### 3.7 组件不依赖 antd

`whale-auth` 的弹窗也是纯 React。共享包一旦依赖 antd，就会把 antd 版本绑死到所有宿主上
（现有应用 antd 5.21，未来可能 6.x）。样式走内联，够用即可。

## 四、接入方式

### 4.1 带底图

```tsx
import { createTencentMapEngine, FencePicker, toFenceSaveParams } from '@bluewhale/whale-map';

const factory = createTencentMapEngine(import.meta.env.VITE_TENCENT_MAP_KEY);

<FencePicker
  factory={factory}
  engineKey="tencent-default"
  height={480}
  onChange={(draft, stats) => setStats(stats)}
/>
// 保存时：
const params = toFenceSaveParams(draft, { name, bizType: 'OA_ATTEND', bizId: String(groupId), enabled: 1 });
await client.saveFence(params);           // coordType 已固定 GCJ02
```

### 4.2 无底图（地址录入、CI、离线演示）

```tsx
import { createMapClient, createFakeEngine, PoiPicker } from '@bluewhale/whale-map';
import { createHttpClient } from '@bluewhale/http';

const http = createHttpClient({ getToken: () => token, getTenantId: () => tenantId });
const mapClient = createMapClient(http);   // 结构兼容，无需适配层

<PoiPicker client={mapClient} city="北京" onSelect={(p) => saveLocation(p)} />
```

### 4.3 GPS 打点（必须转换）

```ts
const pos = await new Promise<GeolocationPosition>((ok, fail) =>
  navigator.geolocation.getCurrentPosition(ok, fail),
);
// 浏览器给的是 WGS84，底图/接口要 GCJ-02
const gcj = wgs84ToGcj02({ lng: pos.coords.longitude, lat: pos.coords.latitude });
await mapClient.saveLocation('OA_ATTEND', recordId, {
  lng: gcj.lng, lat: gcj.lat, coordType: 'GCJ02',
});
```

## 五、验证

| 项 | 结果 |
|---|---|
| 单测 `vitest run` | **70 项全过**（coord 17 / client 9 / fenceDraft 27 / engine 17） |
| 类型 `tsc -p tsconfig.json` | 0 错误 |
| 构建 `tsup` | ESM 37 KB / CJS 41 KB / d.ts 22 KB |
| Lint `eslint --max-warnings 0` | 0 问题 |
| 实机底图 | **未验证**——需前端底图 Key（带 Referer 白名单），M1-1b 做 |

单测覆盖的是「算错不会报错」的部分：加偏量、往返误差、面积、自交判定、
`LatLng(lat, lng)` 顺序、`destroy` 幂等。像素级渲染不在单测范围。

> 若在本机沙箱里并行跑测试报 `EPERM ... \Temp\...\ssr\`，
> 是临时目录写入被拦，用 `vitest run --no-file-parallelism` 可绕开。
