# 审计日志服务完善方案（多通道）

## Context（为什么做）

现有审计能力（`docs/design/audit-log.md`，REQ-SEC-001，Wave 5.1b/5.1e 落地）只覆盖 **业务事件审计**：`@AuditLog` + AOP + 异步线程池 + 本地直写 `audit_log`，由 `whale-audit` 提供查询接口。它**回答不了**以下四类观测需求：

1. **后端接口日志**：每个 HTTP 请求的入参/出参/耗时/结果码/TraceId —— 现无任何请求日志过滤器（仅 `AuditLogAspect` 按注解零星打点，且 `recordResult` 默认关闭）。
2. **后端请求第三方日志**：出站 HTTP 调用无统一封装，也无出站日志（backend 下无统一 `RestTemplate`/`WebClient` 拦截器）。
3. **前端开发者 console 日志**：前端停留在浏览器 console（如 `platform-apps/whale-portal/src/main.tsx`），无采集上报。
4. **前端用户行为埋点**：无任何行为埋点 SDK / 上报接口。

目标：在**不污染审计表语义**的前提下，补齐上述 4 类通道，统一走「异步 sink → 本地库 → 统一查询接口」，并预留 MQ 汇聚开关（阶段二）。

已确认决策：**4 张独立表**、**本地异步直写 + `whale.audit.sink=local|mq` 预留开关**、**前端新建独立包 `whale-log-sdk`**、**分两批交付（先后端 Wave A，再前端 Wave B）**。

---

## 总体设计

```
[后端接口]  ApiLogFilter ─┐
[出站调用]  OutboundLogInterceptor ─┤
                                   ├─→ LogPersistSupport(脱敏+异步) ─→ api_log / outbound_log / frontend_log / behavior_log
[前端 console] ┐                   │
[前端行为埋点] ┴→ POST /audit/log/{frontend|behavior}/batch → whale-audit ─┘
```

- **复用而非新造**：抽用既有 `SensitiveDataMasker`（递归脱敏/截断）与 `AuditLogAspect` 的 `afterCommit + 线程池 + 失败仅 warn` 三段，提为共享 `LogPersistSupport`；`@AuditLog` 切面继续只写 `audit_log`。
- **TraceId/用户链路复用现有**：网关 `TraceIdGlobalFilter`(order=-200) 注入 `X-Trace-Id`、`JwtAuthGlobalFilter`(order=-100) 注入 `X-User-Id`/`X-Username`，全部通道从请求头取，不新增 MDC。
- **网关不落日志**：`whale-gateway` 无数据源，落库需新增依赖，收益低；网关仅做**上报接口白名单 + 限流**（复用 `RateLimitGlobalFilter`）。

## Wave A（后端，本批先做）

### A1 文档先行
- `docs/requirements/register.md` 新增 **REQ-SEC-006**（多通道日志采集），关联 REQ-SEC-001/002/003。
- `docs/specs/2026-10-18-wave5.10-multichannel-log/{spec,tasks,checklist}.md`（接口契约冻结：4 表 DDL + 上报/查询接口路径 + 配置项）。
- `docs/naming-conventions.md` §八 登记 4 张表名与 `@bluewhale/whale-log-sdk` 包名。

### A2 表结构与实体
- DDL 追加到 `whale-backend/whale-ops/whale-audit/src/main/resources/db/init.sql` 与各写入服务（`whale-auth/db/init.sql`），append-only 风格对齐 `audit_log`（`id BIGINT` 雪花、无 `update_time`/`deleted`、`create_time DEFAULT CURRENT_TIMESTAMP`）：
  - `api_log`：trace_id / user_id / username / module / request_uri / http_method / query_string / request_params / response_body / response_code / biz_status / error_msg / ip / user_agent / cost_ms + `idx_trace_id,idx_create_time,idx_user_id,idx_biz_status`
  - `outbound_log`：+ `target_host VARCHAR(255)` / `target_uri VARCHAR(512)` / `response_body TEXT` + `idx_target_host`
  - `frontend_log`：client_id / page_url / log_level / message TEXT / stack TEXT / browser
  - `behavior_log`：client_id / event_type / event_name / page_url / target / payload TEXT
- starter 新增 `com.bluewhale.common.log.entity.{ApiLogRecord,OutboundLogRecord,FrontendLogRecord,BehaviorLogRecord}`（`@TableName` + `@TableId(IdType.ASSIGN_ID)`，**不继承 `BaseEntity`**）与 4 个 `mapper/*Mapper extends BaseMapper`（由既有 `@MapperScan("com.bluewhale.**.mapper")` 扫描）。

### A3 落库支撑与 sink
- `com.bluewhale.common.log.sink.LogPersistSupport`：`submit(Supplier, channel)` —— 事务活跃则 `afterCommit` 注册，否则直接投递 `whaleLogExecutor`；组装/落库异常仅 `log.warn`。
- `whaleLogExecutor`：**新建**独立线程池（core=2/max=4/queue=2048/`CallerRunsPolicy`/前缀 `whale-log-`），**不复用** `auditLogExecutor`（core=1，会被高频接口日志打满并阻塞审计）。不采用静默丢弃策略（避免无声数据丢失），风险见下。
- `LogSink` 抽象 + `LocalLogSink`（阶段一）；`LogSinkProperties`(`whale.audit.sink=local|mq`) 预留，`mq` 分支未实现时 **fail-fast 提示 + 回落 local**。

### A4 Part 1：后端接口日志（Filter）
- `ApiLogFilter extends OncePerRequestFilter`（选 Filter 而非拦截器：只有 Filter 能在 DispatcherServlet 读 body 前包 wrapper；且能覆盖 filter 链异常与静态资源状态码）。
- 自研 `LimitedCachingRequestWrapper` / `LimitedCachingResponseWrapper`（**不用** Spring `ContentCaching*`：其无上限整体缓存，文件下载会 OOM）：超 `max-body-length` 停缓存；按 Content-Type 白名单只缓存 JSON/表单；finally **必须** `copyBodyToResponse()`（否则客户端收空响应）；`shouldNotFilterAsyncDispatch()=true`（异步派发跳过，登记为已知丢采集）。
- 配置：`whale.log.api.enabled` / `sample-rate` / `max-body-length` / `exclude-paths`（默认含 `/actuator/**,/health,/favicon.ico,/error` **以及上报接口 `/audit/log/frontend/**,/audit/log/behavior/**` 防回环**）。

### A5 Part 2：出站调用日志（Interceptor）
- `OutboundLogInterceptor implements ClientHttpRequestInterceptor` + `OutboundLogRestTemplateCustomizer implements RestTemplateCustomizer`：经 `RestTemplateBuilder` 构建的 `RestTemplate` 自动挂载，业务调用点零改动。
- 采集 method/uri/host/cost_ms/status/biz_status/error_msg/request+response 摘要；**traceId 透传**（取当前 `X-Trace-Id` 写出站请求头，缺失生成 32 位 UUID）；超时/连接异常记 `biz_status=0` 并原样抛出。
- 复用 `SensitiveDataMasker`，为此**新增** `String maskJson(String)`（解析 Map/List 后递归 mask，解析失败仅截断），出站与前端接收端共用。

### A6 接收与查询接口（whale-audit）
- `LogIngestController @RequestMapping("/audit/log")`：`POST /whale-frontend/batch`、`POST /behavior/batch`，体 `LogBatchRequest{ traceId, userId, clientId, pageUrl, List<LogItem> items }`，`items` 上限 50（超限 `BizException(PARAM_INVALID)`），`sink.submit` 后立即 `Result.ok()`。
- **鉴权**：两个上报接口 `permitAll`（未登录期报错也需上报），但 token 存在时以网关 `X-User-Id` 回填 `user_id`；防刷 = 网关限流规则 + 批量上限。
- 查询：`GET /whale-frontend/page`、`GET /behavior/page`（`*QueryRequest extends PageQuery`，`size` 收敛 `[1,200]`、`orderByDesc(create_time)`，风格同 `AuditLogServiceImpl`），权限 `@RequirePermission("sys:audit:log:list")`。
- 路由：服务自持一级前缀 `/audit/log`，网关按 REQ-ARCH-003 不剥离（与既有 `audit_log` 路由一致）。

### A7 自动配置
- `com.bluewhale.common.log.config.WhaleLogAutoConfiguration`：`@AutoConfiguration(after = {MybatisPlusConfig.class, AuditLogAutoConfiguration.class})` + `@ConditionalOnWebApplication(SERVLET)` + `@ConditionalOnClass`，Bean 内用 `ObjectProvider<XxxMapper>` **实例化期延迟解析**（**禁止 `@ConditionalOnBean(Mapper)`** —— Wave 5.1e 已证实时序缺陷致切面永不装配）。
- 注册到 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`。

## Wave B（前端，A 批接口冻结后做）

- 新建 `whale-frontend/shared-packages/whale-log-sdk`（`@bluewhale/whale-log-sdk`，tsup 构建，tsconfig `strict`、ESLint 禁 `any`）。
- 导出：`initLogSdk(config)` / `track(event, payload)` / `trackPageView(path?)` / `flush()` / `setUser({userId,username})` / `destroy()`。
- console 劫持：包裹 `log/info/warn/error/debug`，保留原始引用 `.apply(this,args)`（不影响 DevTools 与来源行号）；`isFlushing` 递归锁防回环；参数 `JSON.stringify`（循环引用降级、超 2KB 截断）。
- 缓冲与 flush：队列满 20 / 定时 5s / `visibilitychange(hidden)` 触发；`pagehide` 用 `navigator.sendBeacon`，其余 `fetch(...,{keepalive:true})`（**独立上报，不复用仍为占位的 `whale-common-tools/src/request.ts`**，另留 adapter）。
- 采样/去重/重试：console 与 behavior 各自 `sampleRate`；同 `(type+event+payloadHash)` 5s 去重；失败 1s/2s/4s 退避，3 次丢弃。
- 隐私：`<input>` 只采 name/type 不采 value、`type=password` 跳过；URL query 白名单外一律 `<masked>`；message 命中 password/token 键名掩码；`whale.log.behavior.enabled` 开关。
- qiankun：**基座 `whale-platform` 统一 `initLogSdk` 一次**（`window.__WHALE_LOG_INITED` 幂等），子应用经 qiankun props 透传通道，不各自初始化。
- 接入示例：基座启动 + 一个页面 `trackPageView` + 一个按钮 `track`。

## 风险与残余

1. **写放大**：接口日志行数远大于审计 → 采样 + 排除路径 + body 截断；建议 `api_log` 保留期 30 天（`whale.audit.retention.days` 待扩多表）。
2. **响应包装**：漏 `copyBodyToResponse()` 会致客户端空响应；文件/大 body 走 Content-Type 白名单跳过。
3. **可观测性线程池积压**：`CallerRunsPolicy` 在高负载下会由业务线程兜底写库（不静默丢数据 vs 可能级联）；缓解：队列 2048 + 采样 + 可关闭通道。
4. **前端上报被刷量**：`permitAll` 公开写库 → 网关限流 + 批量上限 + `client_id` 维度限速，恶意刷量仍可能膨胀表。
5. **隐私合规**：行为埋点涉及个人信息 → 掩码规则 + 开关 + 保留期，需登记合规说明。
6. **跨库可见性**：阶段一查询服务须与写入服务同库/同实例（同 `audit_log` 既有约束），否则查不到；阶段二 MQ 汇聚消除。
7. **无 MQ 可靠性边界**：进程崩溃丢内存队列记录；`sink=mq` 仅为预留，未就绪时回落 local。
8. **console 劫持副作用**：可能影响三方库日志格式；仅生产按需开启。
9. **异步 Servlet 跳过采集**：`shouldNotFilterAsyncDispatch=true` → 异步请求不记接口日志（已知取舍）。

## 残余（不做，登记）
- 保留归档定时任务（T-AUD-8，配合多表保留策略另立）。
- 阶段二 RabbitMQ 汇聚（T-AUD-9，本机无 Docker）。
- 网关侧访问日志（无数据源）。
- `POST /audit/log/export` 与元审计（沿用既有待做项）。

## 分批执行顺序

**Wave A**：A1 文档 → A2 表/实体/Mapper → A3 sink+线程池 → A4 ApiLogFilter → A5 OutboundLogInterceptor → A6 接收/查询接口 → A7 自动配置 → 单测+实时 IT → 自检报告 → `mvn verify`+checkstyle → commit+push。
**Wave B**：SDK spec → 包骨架 → console 采集 → 行为埋点 → 基座接入 → lint/typecheck/build → 报告 → commit+push。
依赖：Wave B 的上报接入必须在 Wave A 接口契约冻结后；A3/A4/A5 可与前端包骨架并行。
