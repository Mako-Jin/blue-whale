## 正文

写在最开始：蓝图已经铺开，工地仍在叮叮当当施工。

这个号的第一篇，写一个我还在施工中的开源项目——蓝鲸系统（BlueWhale Platform）。

很多人眼里，办公系统 = 枯燥的表单、没完没了的审批、冰冷的工单；游戏 = 消遣、闯关、剧情、反馈感。二者仿佛是两条永不相交的平行线。上班是消耗，游戏是逃离。

而我想做一件反过来的事：把现实上班里的完整生活场景，装进一套游戏化的工作系统里。

不是简单给 OA 加个徽章、积分的表皮玩法，而是底层去容纳一个打工人完整的工作世界：从早上登入系统开始，工作台待办流转、请假出差报销，车间生产工单处理，查阅产品图纸，跟进客户商机，参与培训考试，处理合同签章，搭建自定义表单与审批流程。

一个普通人职场会遇到的绝大多数场景：填表单、发起审批、处理待办、跟进项目、学习考试、客户对接、归档合同文档，这套平台都为之准备了对应的能力底座。

它是一套实打实的企业业务中台，基于 Spring Boot 微服务与 React 微前端构建。权限、网关、表单引擎、BPMN 工作流、多业务域模块逐步落地，沉淀数百张业务数据表。每一轮迭代都配套单测与检查报告，所有变更都会归档到 docs/reviews 下形成评审文档，并非纸上构想。

### 我的最终目标，不止于「好用的企业管理平台」

现实上班，我们会接任务、处理工单、完成审批、参加培训考试、跟进客户项目、处理异常问题；会有请假调休、绩效考核、技能成长；会对接同事协作，处理客户线索，归档合同文档。这些本来就是现实世界的「任务、副本、技能、声望、事件」。

我希望未来在这套底座之上，叠加上游戏化的外壳：

现实的工作业务作为真实内核，游戏作为表现层。

不再割裂「上班」和「玩游戏」。

工作台是你的角色主城，待办任务是每日任务、主线支线副本；

完成审批、处理工单、交付项目，获得成长反馈；

培训考试是技能试炼，岗位对应角色天赋树；

项目协作是多人组队，跨部门配合就是团队副本；

客户跟进、合同签署对应世界事件；

请假、考勤、绩效，映射角色状态与履历。

业务系统负责解决真实工作问题，游戏化负责给平淡的工作赋予叙事和反馈。

### 需要说明的是，游戏化还没写一行代码

现在这套系统只是业务底座大规模落地：RBAC + ABAC 权限、动态版本化物理表单、BPMN 2.0 双向解析、分布式令牌黑名单、CI 质量门禁这些基础设施已经跑通，可支撑完整业务流转；但上面所说的游戏化叙事、角色、任务体系，还停留在构想蓝图，尚未编码实现。

我不想等项目 100% 做完再来发布一个完美的成品，这也是我开这个公众号的初衷。我想记录建造的全过程。

### 在这里我会记录

✅ 项目阶段性进展：新模块完成了什么，解决了什么棘手架构问题；

✅ 技术思考：微服务、表单引擎、工作流、权限体系踩过的坑；

✅ 脑洞与蓝图：怎么把上班的各类现实场景转化为游戏设计；

✅ 踩坑、取舍、失败的尝试，而不仅仅只展示光鲜的成果；

✅ 未来游戏化层的设计推演，从想法到落地的每一步。

它不是一个已经完工的作品，而是一份正在展开的工程日志。可能会有推翻重构，可能会有设想无法落地，会有无数待办清单，有大量还未实现的标记。

现实的工作本身就足够宏大，我们每天都在「上班这个大型多人现实模拟游戏」里，只是缺少一层有趣的包装。

我想试着亲手把这层外壳造出来。

工程仍在继续，欢迎一起见证建造。

PS：这是开源项目的持续记录。下一篇我会拆解权限中心，聊聊它如何成为未来角色成长体系的雏形。
