# 蓝鲸系统 · 内容推广规划（2026-11 起）

> 目标：把「一个人在造企业级平台」这件事，持续变成可分发的内容资产。
> 节奏：日更（每篇 600–3000 字，按周轮转题材），90 天为一个周期复盘。
> 三类读者同时覆盖：企业决策者 / 开发者 / 个人 IP 关注者。

---

## 一、定位：一句话说清我们在卖什么

**主叙事**
> 「一个人 + 一个 AI，用 30 天造出一个有 20+ 微服务、26 个前端应用、带 3D 数字孪生大屏的企业级平台。」

**三个不可替代的差异点**（这三条是别人抄不走的，全文都要反复落在上面）

| 差异点 | 事实支撑（可公开的） | 对谁有用 |
|---|---|---|
| **真做出来了**，不是 PPT 架构 | 23 个后端服务、26 个 qiankun 前端应用、CRM/ERP/MES/PDM/OA/商城/合同/论坛/IM 全部可跑 | 决策者（信可信度）、开发者（信深度） |
| **真的踩过坑**，且都留了痕 | 30 天 devlog、560+ 篇文档、9 道 CI 门禁、几十份 review 报告 | 开发者（收藏转发的主力） |
| **AI 是协作者不是玩具** | 文档先行 + REQ 编号 + 门禁负向验证 + 每日 devlog 的真实工作流 | 个人 IP（方法论溢价） |

**人设关键词**：造物者 / 门禁控 / 不吹牛（只写跑通的东西）

**统一 CTA**（每篇结尾固定一句，不硬广）：
> 「系统叫蓝鲸（BlueWhale），技术栈 Spring Boot 4 + React 19 + qiankun。想聊私有化部署或想看我踩过的坑，评论区/私信。」

## 二、内容支柱：五条线，按周轮转

素材全部来自真实工作，**不凭空选题**——每天写完代码/踩完坑，从 devlog 里"搬"一篇出来。

> **首周例外**：第 1 周只发公众号、不套用下面这套多平台轮转，按 §五 的 W1 表执行；本表从第 2 周起生效。
> 产品名一律用 [命名体系](../brand/naming-system.md)（鲸律 / 鲸造 / 鲸客…），文章里第一次出现时带一句「（鲸造，即制造执行系统）」。

| # | 支柱 | 内容内核 | 主要平台 | 占比 |
|---|---|---|---|---|
| P1 | **技术深水区** | 微服务、qiankun、权限体系、多租户、网关、并发与一致性 | 掘金 / CSDN / 知乎 / 公众号 | 35% |
| P2 | **造物方法论** | 文档先行、REQ 门禁、devlog、AI 协作边界、一个人怎么管 23 个服务 | 公众号 / 知乎 / 即刻 | 25% |
| P3 | **产品与方案** | MES/CRM/ERP 模块全景、私有化交付、国产化迁移、权限中心设计 | 公众号 / 头条 / 百家号 / 36氪投稿 | 20% |
| P4 | **视觉与现场** | 3D 数字孪生城、界面截图、构建日志、深夜进度 | 小红书 / B站 / 视频号 | 10% |
| P5 | **清单与观点** | 「5 个静默失效」「7 个必看文件」这类易传播体 | 全平台 + 知乎回答 | 10% |

## 三、日更怎么落地：七日轮转表

日更的真实成本不是"写"，是**选题 + 配图 + 排版**。所以用两条机制兜底：

1. **工作搬运法**：当天干了什么就写什么，素材零成本（devlog + commit + 报错日志就是大纲）。
2. **周末囤稿**：周六固定产出 3 篇缓冲稿，保证生病/加班也不断更。

| 周几 | 题材 | 字数 | 主发平台 | 说明 |
|---|---|---|---|---|
| 周一 | 支柱长文（P1↔P2 交替） | 1500–3000 | 公众号 + 知乎专栏 | 本周主菜，其余内容从它拆 |
| 周二 | 技术实战拆解（P1） | 800–1200 | 掘金 + CSDN | 一个具体 bug / 一个具体设计 |
| 周三 | 产品场景（P3） | 600–900 | 头条 + 百家号 | 用业务语言，不写代码 |
| 周四 | 踩坑复盘（P1/P2） | 800–1200 | 知乎回答 + 公众号 | 优先蹭已有高赞问题 |
| 周五 | 清单 / 观点（P5） | 400–600 | 全平台 | 最易传播，做引流款 |
| 周六 | 图文 / 视频脚本（P4） | 300 + 图 | 小红书 + B站 + 视频号 | 3–6 张图讲一件事 |
| 周日 | 本周造物周记 | 600 | 公众号 + 即刻 | 汇总裁剪，也是下周选题池 |

**一鱼多吃流水线**（同一份素材，五种产物）

```
当天真实工作
   └─→ ① 长文（公众号/知乎专栏）
        ├─→ ② 知乎回答（切其中一段，回答问题而非发文章）
        ├─→ ③ 掘金/CSDN 技术版（保留代码，删掉感慨）
        ├─→ ④ 小红书图文（3 张图：问题截图 / 关键代码 / 结论）
        └─→ ⑤ 60 秒视频脚本（只讲"最反直觉的那一句"）
```

## 四、平台矩阵（按投入产出排序）

### 阶段策略：先单平台验证，再横向扩

| 阶段 | 时间 | 平台范围 | 目的 |
|---|---|---|---|
| **阶段一** | 第 1 周（7 天） | **只有微信公众号** | 验证「能不能持续产出 + 有没有人看」，不看涨粉只看完成率与反馈质量 |
| **阶段二** | 第 2 周起 | 公众号 + **知乎** | 达标即启动知乎（判据见 §五），公众号仍是阵地 |
| **阶段三** | 第 4 周起 | 加 掘金 / 头条 / 小红书 | 前三周跑稳后再横向铺，避免一开始就被多平台拖死 |

> 单平台先行是刻意为之：日更真正的失败原因不是写得差，是**同时开五个号，每个都更新不动**。一周只发公众号，把"每天能交一篇"这件事验证掉。

| 优先级 | 平台 | 承担角色 | 形态 | 频率 | 备注 |
|---|---|---|---|---|---|
| P0 | **微信公众号** | 唯一阵地，沉淀 + 转化 | 长文 | 每周 4 篇 | 所有内容最终回流到这里 |
| P0 | **知乎** | 搜索长尾，最高质量线索 | 回答 + 专栏 | 每周 3–4 次 | 先答问题再引文，别直接发文章 |
| P1 | **掘金** | 技术圈口碑、被转载 | 技术文 | 每周 2 篇 | 代码要能跑，掘金读者会挑刺 |
| P1 | **今日头条（头条号）** | 算法分发，起量最快 | 长文 | 每周 3 篇 | 标题党适度，正文要实 |
| P1 | **小红书** | 过程感、视觉、非技术受众 | 图文 | 每周 3 篇 | 3D 城截图是天然爆款素材 |
| P2 | **百家号** | 百度 SEO 收录 | 长文 | 每周 2 篇 | 与头条同稿，改标题 |
| P2 | **B站** | 视频 + 专栏，人格化 | 视频/专栏 | 每周 1 条 | 用录屏 + 旁白即可，不必真人出镜 |
| P2 | **CSDN** | 长尾搜索 | 技术文 | 每周 2 篇 | 与掘金同步 |
| P3 | **36氪 / 人人都是产品经理** | 权威背书（投稿制） | 深度稿 | 每月 1 篇 | 用 P3 支柱最好的那篇去投 |
| P3 | **即刻 / 微博** | 碎片、日常、涨粉 | 短动态 | 每天 | 一句话 + 一张图，成本极低 |
| P3 | **雪球**（若讲商业化） | 投资视角受众 | 分析文 | 按需 | 只在写商业模式时用 |

**分发工具**：多平台重复发布用第三方一键分发（蚁小二 / 简媒），我只负责产出各平台适配版文案。

### 升级判据：什么算"可以的话就推知乎"

首周结束后按下表打分，**满足 3 项即启动知乎**（不必全中）：

| # | 指标 | 门槛 | 说明 |
|---|---|---|---|
| 1 | 完成率 | 7 篇全发 | 硬指标，缺 2 篇以上说明节奏不可持续，先降频不断更 |
| 2 | 7 篇累计阅读 | ≥ 600 | 冷启动现实值，别拿爆款当基线 |
| 3 | 单篇最高阅读 | ≥ 200 | 说明至少有一篇被算法/转发推了一把 |
| 4 | 新增关注 | ≥ 20 | 有人愿意持续看 |
| 5 | 有效反馈 | ≥ 3 条实质留言或 ≥ 5 次转发 | **权重最高**，这是唯一能证明"内容有用"的信号 |

**反向判据（比达标更重要）**
- 某支柱连续 2 篇阅读 < 50 → 该支柱降权，换切入角度，别硬撑
- 出现"这篇我写得很难受"→ 大概率读者也读得难受，标记为淘汰题材
- 若 7 天里有 2 天靠"凑"，说明选题池空 → 回到 `docs/devlog/` 捞素材，而不是硬写

## 七、写作规范（保证风格统一）

- **开头 50 字给结论**：不要铺垫，第一段就说出"这篇能让你少踩什么坑"。
- **标题公式**：数字 + 反差 + 具体物。例：「5 个」+「静默失效」+「企业级项目」。避免「浅谈」「漫谈」。
- **代码/截图只放关键 10 行**，其余折叠或说明"完整版在仓库"。
- **每篇一个"可带走的东西"**：一段配置、一个检查清单、一个判断标准。
- **结尾固定 3 行**：一句总结 + 一句 CTA + 一句下篇预告。
- **不吹牛红线**：只写跑通的；没验证的不写"已支持"。

## 八、脱敏与合规红线（写之前必读）

1. **不出现真实口令/密钥/内网 IP/域名**——`.env`、Nacos 配置、数据库账号一律打码。
2. **不出现客户与员工真实信息**——截图前先造测试号（如 `qa_admin` 这类演示账号）。
3. **后台截图去敏**：租户名、手机号、真实订单金额一律遮挡或替换为假数据。
4. **开源边界先定**：当前仓库 Apache-2.0。若含商业模块，发代码前先确认哪些是可公开的，避免"发了才发现不能发"。
5. **平台规则**：知乎先答问题再引文；公众号标原创；不要在技术文里放硬广二维码（会被限流）。

## 九、执行与自动化

| 环节 | 谁做 | 工具 |
|---|---|---|
| 选题（每日） | 我 | 扫 `docs/devlog/` 当日条目 + `git log` + 当日报错 |
| 出稿 | 我 | 按支柱模板直接产出初稿（1200–2500 字） |
| 多平台改版 | 我 | 一篇出 4 版：公众号 / 知乎 / 掘金 / 小红书 |
| 配图 | 我 | 截图去敏建议 + 封面文案；也可生成配图 |
| 推送草稿箱 | 连接器 | 公众号可绑定「言序」等连接器一键推草稿，手机确认群发 |
| 分发其他平台 | 手动 | 蚁小二/简媒 + 复制粘贴（多数平台无开放发布 API） |
| 定时提醒/出稿 | 自动化 | 可设「每天 9:00 生成当日选题与初稿」的定时任务 |

**推荐先跑起来的最小闭环**：我在每天早上一句「今天写第 N 篇」，你确认选题 → 我出公众号版 + 知乎版 → 你复制发布。稳定两周后再接自动化与连接器。
