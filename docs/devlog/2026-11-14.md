## whale-form 动态表单设计评审处置（P0/P1 首批整改）

- **评审核对结论**：外部评审方向正确但事实准确度不足，共 3 处硬错误（`spring-boot-starter-flyway` 不存在、
  缺 `mapstruct-processor`、缺 `spring-boot-starter-aop`）、5 项「已实现被当成缺失」（DDL 标识符白名单、
  类型枚举白名单、租户头缺失拒绝、双写本地事务、分页上限）。上述 8 条不纳入整改，理由与代码位置见本日评审记录。
- **需求项**：① DDL 注释转义可被反斜杠绕过；② 定义/表定义链路缺租户上下文时 MyBatis-Plus 租户插件不加条件，
  存在跨租户读写；③ 发布登记/版本快照唯一性仅靠「先查后插」，并发可重复登记。
- **完成项**：
  - `FormTableDdlGenerator.escapeComment` 先转义反斜杠再双写单引号：MySQL 默认 `sql_mode` 下 `\'` 为转义序列，
    以 `\` 结尾的字段中文名会吞掉闭合引号导致 DDL 语法错误，构造输入还可越出注释边界。补 2 条单测。
  - 新增 `FormTenantConfig`（`WebMvcConfigurer` + `TenantGuardInterceptor`）：对 `/form/**` 统一要求
    `TenantContext` 非空，缺失或非法直接 400；不再依赖各控制器自行调用 `TenantResolver`。补 2 条单测。
  - 新增 `V3__unique_constraints.sql`（幂等：`information_schema` 判定 + `PREPARE/EXECUTE`）：
    `form_table_registry(tenant_id, table_code, table_version)`、`form_table_registry(tenant_id, definition_code,
    definition_version)`、`form_definition_version(definition_id, version)` 三条唯一约束。
  - `FormPublishServiceImpl` 两处 registry 插入捕获 `DuplicateKeyException`，转为「已发布或正在发布」参数错误，
    避免并发发布从静默重复登记变为 500。
- **已修正问题项**：控制器/归档接口 javadoc 中过期的「租户缺省 1」文案（行为早已是缺失即拒绝）。
- **有意不做**：`form_definition`、`form_table_definition` 不加唯一索引——两表含逻辑删除，唯一索引会与
  「软删后按同编码重建」冲突（与回款期次唯一键的既有教训一致），继续保留服务层前置校验。
- **待做项**：无（首批与第二批 P1 均已落地）。

## whale-form 动态表单设计评审处置（P1 第二批：发布可靠性 / 并发 / 导出 / 内网 / 审计）

- **需求项**：① 导出跨版本丢列、CSV 公式注入、非法 `format` 静默回落；② MySQL DDL 隐式提交导致孤儿表/半迁移；
  ③ 定义 `publish/rollback/update` 并发覆盖；④ `/form/internal/**` 仅靠网关 deny；⑤ 动态 DDL 无审计留痕。
- **完成项**：
  - 导出：`format` 仅接受 `csv/xlsx`，其余返回 `PARAM_ERROR`；`escapeCsv` 对 `= @ \t \r` 及非数值的 `+ -`
    前置单引号，纯数值不处理；表头改为「当前 schema 字段 + 数据行中出现的历史字段并集」，历史版本独有字段
    不再静默丢失（按字段编码兜底作表头）。补 1 条单测。
  - 发布：`publish/publishTableDefinition` 移除声明式事务并注释原因（DDL 隐式提交使事务无法兜底）；
    每条 DDL 经 `FormDdlAuditor` 以 `REQUIRES_NEW` 独立事务写入 `form_ddl_audit`（成功/失败均留痕，
    审计失败仅 warn 不影响发布）；元数据模型发布失败时由 `FormRegistryStatusMarker` 以独立事务把登记置为
    `status=3` 并写 `last_error`，重新发布成功后恢复 `status=1` 并清空原因；`assertNotPublished` 忽略失败登记，
    允许失败后重试；登记状态非「生效」的物理表不参与数据读写。
  - 并发：`update/rollback` 改为以「读取时版本号」为条件的 CAS 更新（`LambdaUpdateWrapper` + `version` 条件），
    影响 0 行抛「表单已被并发修改，请刷新后重试」，不再整行覆盖。
  - 内网：`application.yml` 显式声明 `bluewhale.internal-token.path-patterns: /form/internal/**`，
    档案侧 `RemoteHttpSupport` 经 `InternalTokenSupport` 已自动附加 `X-Internal-Token`，形成网关 deny + 服务端令牌双重防护。
  - `V4__ddl_audit.sql`（幂等）：`form_table_registry.last_error` 列 + `form_ddl_audit` 只追加审计表。
- **已修正问题项**：`FormInternalController` javadoc 未说明内网令牌，补齐鉴权链路说明。
- **验证**：`mvn -o -pl whale-services/whale-form test` → 124 项测试全部通过，checkstyle 随构建通过。
- **待做项**：`publish` 失败后的自动补偿/对账 Job（当前为审计追溯 + 失败状态可见，人工或后续任务补偿）；
  导出独立权限码 `sys:form:data:export`（需同步权限中心数据）；submit 幂等键。
