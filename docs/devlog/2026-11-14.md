## whale-form 动态表单设计评审处置（P1 第二批：发布可靠性 / 并发 / 导出 / 内网 / 审计）

- **需求项**：① 导出跨版本丢列、CSV 公式注入、非法 `format` 静默回落；② MySQL DDL 隐式提交导致孤儿表/半迁移；
  ③ 定义 `publish/rollback/update` 并发覆盖；④ `/form/internal/**` 仅靠网关 deny；⑤ 动态 DDL 无审计留痕。
- **完成项**：
  - 导出：`format` 仅接受 `csv/xlsx`，其余返回 `PARAM_ERROR`；`escapeCsv` 对 `= @ \t \r` 及非数值的 `+ -`
    前置单引号，纯数值不处理；表头改为「当前 schema 字段 + 数据行中出现的历史字段并集」，历史版本独有字段
    不再静默丢失（按字段编码兜底作表头）。补 1 条单测。
  - 发布：`publish/publishTableDefinition` 移除声明式事务并注释原因（DDL 隐式提交使事务无法兜底）；
    每条 DDL 经 `FormDdlAuditor` 以 `REQUIRES_NEW` 独立事务写入 `form_ddl_audit`（成功/失败均留痕，
    审计失败仅 warn 不影响发布）；元数据模型发布失败时由 `FormRegistryStatusMarker` 以独立事务把登记置为
    `status=3` 并写 `last_error`，重新发布成功后恢复 `status=1` 并清空原因；`assertNotPublished` 忽略失败登记，
    允许失败后重试；登记状态非「生效」的物理表不参与数据读写。
  - 并发：`update/rollback` 改为以「读取时版本号」为条件的 CAS 更新（`LambdaUpdateWrapper` + `version` 条件），
    影响 0 行抛「表单已被并发修改，请刷新后重试」，不再整行覆盖。
  - 内网：`application.yml` 显式声明 `bluewhale.internal-token.path-patterns: /form/internal/**`，
    档案侧 `RemoteHttpSupport` 经 `InternalTokenSupport` 已自动附加 `X-Internal-Token`，形成网关 deny + 服务端令牌双重防护。
  - `V4__ddl_audit.sql`（幂等）：`form_table_registry.last_error` 列 + `form_ddl_audit` 只追加审计表。
- **已修正问题项**：`FormInternalController` javadoc 未说明内网令牌，补齐鉴权链路说明。
- **验证**：`mvn -o -pl whale-services/whale-form test` → 124 项测试全部通过，checkstyle 随构建通过。
- **待做项**：`publish` 失败后的自动补偿/对账 Job（当前为审计追溯 + 失败状态可见，人工或后续任务补偿）。

## whale-form Service 层评审处置（P0/P1 第四批）

- **需求项**：① 版本快照先删后插导致同版本编辑历史被覆盖；② 旧数据读取使用当前表单 schema 而非记录版本 schema；
  ③ 顶层基础字段无类型校验；④ 表定义删除未校验被表单引用；⑤ 并发发布 DDL 缺少收敛；
  ⑥ 导出截断无提示；⑦ 表定义详情全表查列。
- **关键设计决策（schema 路由）**：采用「**发布时写 registry 快照**」。
  - 表级 schema 由列元数据在**表定义发布时**编译（首次发布与再次发布均刷新），写入
    `form_table_registry.schema_json`；同 `tableVersion` 的就地 ALTER 属于结构演进，快照随发布刷新，
    需要冻结历史时先升版本再发布。
  - **重编译时机**：仅在表定义发布时；表单视图保存/回滚只重编译视图自身 `schema_json`，不触碰物理表快照。
  - 读取旧数据的兜底：仅当存量登记没有 `schema_json` 时，按该记录 `tableVersion` 的列元数据即时重编译，
    并只保留物理表实际存在的列（不写回，避免读路径写库）。
- **完成项**：
  - 新增 `FormMetadataCompiler.compileTable`（表级 schema）；`ensurePublished` 建表/改表后均写入 registry 快照。
  - `getDetail/update/getArchiveDetail` 与过滤 `fieldsOf` 改为按记录 `tableVersion` 取快照，修复旧数据按新 schema
    校验失败、以及历史版本物理表被静默跳过的问题。
  - 版本快照改为 append-only：`V6__definition_snapshot_seq.sql` 新增 `snapshot_seq` 并回填、建立
    `(definition_id, snapshot_seq)` 唯一键、移除 V3 的 `(definition_id, version)` 唯一键；
    `writeVersionSnapshot` 不再删除同版本快照；`listVersions` 按 `snapshot_seq` 倒序并返回序号。
  - 版本号只增：`update` 拒绝版本回退；`rollback` 新版本号取「当前版本与历史快照最大版本」较大者 +1，永不复用。
  - 顶层类型校验：基础字段统一走 `matchesType`；`date/datetime` 追加格式与真实日历值校验（`2026-13-01` 拒绝）。
  - 表定义删除前校验 `form_definition.table_definition_id` 引用，命中的直接拒绝。
  - 并发发布收敛：增量 DDL 遇到 `Duplicate column name` / `Duplicate key name` / `check that column/key exists`
    视为另一实例已完成，记 warn 后继续；其他 DDL 错误仍抛出。
  - `V7__definition_code_uniqueness.sql`：生成列 `active_code` / `active_table_code`（软删为 NULL）+
    `(tenant_id, active_code)` 唯一键，解决并发创建同编码，且不与逻辑删除冲突。
  - 导出新增 `X-Export-Truncated: true` 响应头；`enrichColumnInfo` 改为按引用列 ID `IN` 查询。
- **已修正问题项**：`FormDataExportSupport` 的 CSV 注入防护、`@TableLogic` 均已在此前提交落地，本轮复核确认无需再改。
- **有意不做**：`selectByFilters` 跨版本内存合并分页保持现状（设计取舍，已明确 5000 上限）；
  过滤字段仍按当前版本校验，文档明确「仅支持当前版本字段过滤」；发布未引入分布式锁，改为 DDL 幂等收敛。
- **验证**：`mvn -o -pl whale-services/whale-form test` → 131 项测试全部通过，checkstyle 通过。
- **待做项**：存量 `form_table_registry` 需重新发布一次生成 `schema_json` 快照（在此之前读取走即时重编译兜底）；
  V7 若存量存在同租户重复编码会迁移失败，需先清理脏数据。

## whale-form 支撑层评审处置（S1–S4：快照解析 / 更新语义 / 兜底一致性 / 日期校验）

- **评审结论核验**：安全底座判断成立（表名二次正则、CSV 公式中和、DDL 注释转义、审计独立事务）；
  但「审计器/状态标记器未接线」「findRegistry 不恢复 status」「ALTER 无幂等」三条与代码不符，
  对应实现与单测均已存在，本轮不再处理。
- **S1 修复（P0）**：表级快照由列元数据生成，不含子表 `children`，原 `FormSchemaParser.parse` 强制非空
  导致含 subtable 列的表定义在 `getDetail/update/getArchiveDetail/过滤` 直接 400。
  新增 `FormSchemaParser.parseStorage` 宽松模式（subtable 允许无 children，解析为空列表），
  读路径与物理列集合改用该模式；表单级校验仍走严格 `parse`。
- **S2 修复（P0）**：`update` 原用表级快照做必填校验与全列写入，造成「视图未引用的必填列导致更新永远失败」
  与「视图外物理列每次更新被置 NULL」。现拆分为：
  - 未知字段白名单 = 表级物理列集合（兼容历史数据 key）；
  - 必填/类型校验 = 当前视图 `schema_json`；
  - 物理写入 = 视图字段与表级列的交集（视图新增字段尚未落到该表版本时自动跳过）。
- **S3 修复（P1）**：存量无快照兜底编译补 `form_column_meta.status = 1`，字段集合与发布快照一致。
- **S4 修复（P2）**：过滤条件日期值追加真实日历校验（`2024-02-31` 返 400，不再下推 MySQL 变 500）。
- **有意不采纳**：`definition_id/definition_version` 拆列（影响面大，先按「物理表归属表定义、旧模型记录表单定义 ID」
  文档约定）；审计 tenantId 为 null 改 0/-1（列允许 NULL，保持诚实）；保留列常量合并、操作符命名统一、
  XLSX 列宽（排期）。
- **验证**：`mvn -o -pl whale-services/whale-form test` → 135 项通过，checkstyle 0 violations，BUILD SUCCESS。
