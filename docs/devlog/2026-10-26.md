### 平台级 Bug 修正：PermCode 非法权限码导致 /auth/me 400

- **现象**：登录 code=0，但 `GET /auth/me` 恒返回 `code=400 权限码须为冒号分隔的小写段落且至少两段`。
- **定位**：日志显示权限查询（142 行）返回后立即抛错、菜单查询未执行 → 异常发生在 `PermissionPersistenceAssembler.toDomain` 的 `PermCode.of(...)`。此前 MySQL `REGEXP` 校验因 `utf8mb4_0900_ai_ci` 排序规则**不区分大小写**漏判；改用 `COLLATE utf8mb4_bin` 后定位到 2 个驼峰权限码：
  - id=23 `sys:user:resetPwd`（Wave 5.3 种子）
  - id=59 `sys:workflow:definition:bpmnImport`（Wave 5.31 种子）
- **修正**（沿用 `add-sign→addsign` 同口径，改全小写）：
  - `init.sql`：id 23 → `sys:user:resetpwd`；id 59 → `sys:workflow:definition:bpmnimport`
  - `UserController#changePassword`、`ProcessModelController#importBpmn` 注解同步
  - admin 前端 `UserList.tsx` 重置密码按钮 `perm` 同步
  - `UserControllerTest` 权限契约断言同步
  - 新增 `migration-5.56.sql`（幂等 UPDATE，修正存量库；`sys_role_permission` 按 permission_id 外键关联，授权不受影响）
  - 前一日已修正 id=78 `sys:workflow:task:add-sign` → `addsign`（注解 + init.sql + migration-5.36.sql 追加幂等 UPDATE）
- **验证**：运行库 UPDATE 后全表 0 行非法（区分大小写校验）；重建 auth/workflow jar 并重启后 `/auth/me` 恢复 `code=0`（menus=4，perms=142）。
