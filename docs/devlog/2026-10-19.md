### 二、变更点

**1. whale-admin 前端（8 处）**

- 新增 `src/api/auth.ts`：真实认证客户端（login/fetchMe/logout），统一响应体 `{code,message,data}` 解析、Bearer 注入、401 自动清态抛错、refreshToken 本地保存（登出时随请求体提交使之一并失效）。

**2. whale-spring-boot-starter（缺陷修复，P1）**

- `CacheAutoConfiguration` 补 `@AutoConfigureAfter(name = "org.springframework.boot.data.redis.autoconfigure.DataRedisAutoConfiguration")`。
- 根因：自动配置按「Order → Before/After 拓扑 → 类名字母序」排序，`com.bluewhale.*` 字母序先于 Boot 的 Redis 自动配置；`@ConditionalOnBean(StringRedisTemplate.class)` 在 Redis 模板注册前提前判定为 false，Wave 5.8（AUTH-20）将 `PermissionCache` 接入 `CacheConsistencyTemplate` 后，该时序缺陷在服务首次真实启动时暴露（Bean 缺失 → 启动失败）。以 name 形式声明（Boot 4 自动配置类已迁移至模块化包名），避免对 optional 依赖的编译期耦合。

**3. 环境中间件（本机，不入仓）**

- MySQL 8.0.26（3306）：`mysqld --console` 启动；新建 `bluewhale_auth` 库并导入 `whale-auth` 的 `db/init.sql`（13 表 + admin/super_admin 种子数据）。
- Redis 5.0.14（6379）：`redis-server.exe redis.windows.conf` 启动；确认开启 requirepass，服务侧经 `SPRING_DATA_REDIS_PASSWORD` 注入。
- Nacos 2.4.0（8848，`D:\tools\installer\nacos`，与 Wave 5.1f 所用 3.2.4 实例不同）：外置 MySQL 存储 JDBC URL 补 `allowPublicKeyRetrieval=true` 修复启动失败；认证开启状态下新增专用账号 `bluewhale` 并授 `ROLE_ADMIN`，服务侧经 `SPRING_CLOUD_NACOS_USERNAME/PASSWORD` 注入。

### 一、范围

把 whale-job 从「可跑骨架」补齐为「可交付服务」，共四条轨道：R1 调度健壮性、R2 可观测与异步化、R3 日志归档清理、R4 单测基线。
**非目标**：`job_log` 归档**导出至对象存储**（依赖 whale-file）继续阻塞，本轮只落地本地保留策略（逻辑删除）。

### 二、变更点

**R1 调度健壮性**

- 新增 `config/JobProperties`（`@ConfigurationProperties("whale.job")`，`logRetentionDays` 默认 30）；`WhaleJobApplication` 增 `@ConfigurationPropertiesScan`。
- 新增 `scheduler/JobExecutionGuard`：`ConcurrentHashMap.newKeySet()` 维护 `running`（实例内互斥）与 `pendingOnce`（待补跑一次），方法 `tryEnter`/`exit`/`markPendingOnce`/`consumePendingOnce`/`isRunning`。
- 新增 `scheduler/JobHandlerRegistry`：`resolve(String)`（空名/缺 Bean/类型不符抛 `PARAM_ERROR`）与 `exists(String)`；`JobScheduler` 原私有 `resolveHandler` 下沉至此，服务层复用 `exists` 做创建/更新校验。
- 重构 `scheduler/JobScheduler`：
  - `execute(JobInfo)`（包可见）先 `guard.tryEnter`；失败 → `handleOverlap` 按 `misfire_policy` 处理；成功 → `runWithDistributedLock` + `finally exit` → `drainPendingOnce`。
  - 分布式锁：`ObjectProvider<RedissonClient>` 注入，键 `lock:job:execute:{jobId}`，`tryLock(0, TimeUnit.SECONDS)`（waitTime=0 立即返回，lease 走看门狗）；未获锁（他实例执行中）**跳过且不补偿**；`InterruptedException` 恢复中断位跳过；Redis 异常**降级放行**为仅实例内互斥；`unlock` 仅当 `isHeldByCurrentThread()`。
  - **`misfire_policy` 由死字段转为生效**：`DO_NOTHING` 跳过；`FIRE_ONCE`/`SMART` 登记一次性补跑；`drainPendingOnce` 循环 `consumePendingOnce`（补跑前重新 `tryEnter`，失败则放回标记），补跑不再补偿、栈深有界。
  - 原执行体改名包可见 `doExecute`（落 `job_log` → 调 handler → 回写 `end_time`/`status`/`result`/`error_msg`，异常只记录不外抛）。
  - `runOnce(Long)` 保留同步存在性校验（`NOT_FOUND`）后改 `taskScheduler.execute(...)` **异步**触发，请求线程不再阻塞。
  - 补 `@PreDestroy destroy()`：真正关闭线程池（此前 `setWaitForTasksToCompleteOnShutdown` 因线程池非 Spring 托管 Bean 而从未生效）。

**R2 可观测与校验**

### 四、缺陷修复与偏差

- **缺陷（已修 · P1）**：`precision` MySQL 保留字两处 —— ① 迁移/init 脚本列定义写为 `` `precision` ``（否则 `ERROR 1064`）；② 冒烟时 MyBatis-Plus 生成 `INSERT ... precision, scale ...` 报 SQL 语法错误（HTTP 500）→ 实体加 `@TableField("`precision`")`，重建后通过（`precision=10/scale=2` 正确回读）。
- **缺陷（已修 · 测试）**：`FormMetadataMigrationServiceImplTest` 报 `MybatisPlusException: can not find lambda cache for this entity [FormDefinition]`（`LambdaUpdateWrapper.set` 立即解析列名）→ 加 `@BeforeAll initTableInfoCache()`（复用项目既有模式，`TableInfoHelper.initTableInfo`）后 44 tests 全绿。
- **设计决策**：动态列一律 `DEFAULT NULL`，**不建 DB NOT NULL** —— 因 1:N 视图可见性不同，强制 NOT NULL 会使隐藏列的表单无法提交；空值/必填约束统一由服务层按视图字段校验（spec §3.2）。
- **偏差（构建）**：全量 `clean install` 需先停占用 `target/*.jar` 的业务 Java 进程（保留 Nacos）再重建（属**环境占用**）。
- **说明（权限缓存）**：super_admin 走 authorities 直放（`PermissionInterceptor`），权限种子 53–57 主要为权限清单完整性。
- **环境噪声**：whale-form 日志报 `Table 'bluewhale_form.api_log' doesn't exist`（common starter 的 ApiLogMapper 写入本库而该表缺失），经证据确认不影响响应，登记为环境残余。
