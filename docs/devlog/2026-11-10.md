## 第四批（孪生阈值告警体系：Wave 6.06–6.09，`6d7875ee` `8068dd06` `50b7088e` `d91ddc88` `780a453e` `d4bf42ee` `22229039` `6da600b2` `433cfd60` `feb570bb`）

这是本日最长的一条线，逐层把「阈值越界」做成可用能力：

| Wave | 里程碑 | 内容 |
|---|---|---|
| 6.06 | M0 | 后端评估器 + SSE `alert` 帧，**级别变化才推**（不刷屏） |
| 6.06 | M1 | 阈值告警持久化：`twin_alert` 表 + 落库收口 + 历史/未恢复查询 |
| 6.06 | M2 | 前端告警中心：SSE 实时角标 + 未恢复/历史抽屉 |
| 6.07 | M0 | 规则引擎：持续确认（n 次越界才报）+ 回差防抖（回落到死区外才恢复）+ 级别跟踪器 |
| 6.07 | M1 | 告警确认（`twin_alert` ack 字段 + 确认接口 + `acked` 过滤） |
| 6.07 | M2 | 前端规则编辑（确认时长/回差写回 `propertyMap`）+ 确认操作 |
| 6.08 | M0 | **无头告警消费**：无订阅场景也周期评估落库，独立节流 + 保留集清理（告警不再依赖有人开着页面） |
| 6.08 | M1 | 跨场景告警总览（未恢复列表 + 级别/确认统计 + 全局索引） |
| 6.08 | M2 | 场景列表全局告警角标 + 跨场景总览抽屉（就地确认/跳转查看器） |
| 6.09 | — | 场景行级告警角标：分页一次聚合 + 列表列角标 + 抽屉按场景聚焦 |

设计要点：

- **级别跟踪器是整条链的核心口径**：评估结果只在「级别发生变化」时才产生告警事件与推送，否则每分钟一次评估会把 SSE 与站内信打爆。
- **6.08 的动机**：6.06/6.07 的评估挂在 SSE 订阅上，没人看页面就不评估 → 告警数据出现空洞。6.08 改为服务端周期消费，SSE 只做「订阅时的即时视图」。
- **角标聚合**：列表页不为每行发一次查询，改为分页结果集一次聚合（`IN (sceneIds)` + group by），避免 N+1。
