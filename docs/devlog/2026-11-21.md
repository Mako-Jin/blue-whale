## 三维王城 S4 接口层（第一批：契约 + starter + ERP 标杆 + 厅配置）

- **需求项**：把"每殿各吃一个异构接口、前端靠 dig 猜字段"改成"每服务一个 `/<前缀>/overview`"，
  先通一个标杆（户部 / ERP）再复制到其余 20 处。总纲 T4.1–T4.4、T4.6。
- **契约（T4.1）**：`docs/specs/overview-contract/README.md` + `overview.schema.json`。
  三个决定值得记：
  - **百分比只传比率**。S3 的 `formatPercent` 用"小于 1.5 就当比率"兜底，遇到真实的 0.8% 会显示成 80%；
    契约层定死 `0.82`，渲染层只乘一次 100，兜底逻辑不再有存在理由。
  - **三态 `live/stale/degraded`**。概览最坏的情况不是接口挂了（会白屏、会被发现），
    而是"牌上有数字、但数字是三天前的"。`stale` 强制带 `notes` 与上次时刻，前端必须标"陈旧"。
  - **降级也走同一形状**。404/500 由前端折成 `unreachable`，服务端降级也是一个 `OverviewSnapshot`，
    前端不必为失败写第二套解析。
- **后端 starter（T4.2）**：新增 `whale-sdk/whale-overview-sdk`（自动装配，注册进 `whale-sdk/pom.xml`）。
  - 接入成本＝实现 `OverviewProvider` + 配 `whale.overview.base-path`（示例 `/erp/overview`）。
    路径放配置而不是写死注解：服务一级前缀本来就不在 Java 里（REQ-ARCH-003 网关不剥前缀）。
  - **缓存键含租户** `service|nodeKey|tenantId`。少一段就是"A 租户的数发给 B 租户"，
    这类越权不报错、只表现为"数据看起来怪"。
  - **provider 在独立 daemon 线程池执行 + `Future.get(timeout)` + `cancel(true)`**：直接在请求线程跑
    provider，一旦里面有个没设超时的下游，会把 Tomcat 工作线程一起拖住；概览没有这个权力。
  - **失败不写缓存**：有上次成功快照 → 返回它并置 `stale`；没有 → `degraded` 空态。
    不缓存失败是为了让下一轮轮询自动重试，下游恢复最多晚一个周期。
  - **权限在控制器判定**（`UserContext.hasPermission`，与 `RequirePermissionInterceptor` 同口径，
    `super_admin` 放行），provider 拿不到请求头（它在别的线程）；块级裁剪用 `OverviewContext#hasPermission`。
  - **`overview.load{service,outcome}` 计数**：降级是静默失效高发区，必须有可告警的时序。
    Micrometer 挂在 `@ConditionalOnClass + @ConditionalOnBean` 的嵌套配置里，没有 actuator 的服务不受影响。
- **ERP 标杆（T4.4）**：`ErpOverviewProvider` 三个 KPI（营收/订单/预警）直接复用
  `AnalyticsAppService#getCockpit` —— 与 2D 经营驾驶舱同一个方法，**没有另造口径**；
  权限码复用 `sys:erp:bi:cockpit:list`，**没有新增权限点、没有新迁移**；告警条由未关闭预警数派生。
- **前端（T4.3/T4.6）**：

## 三维王城 S4 第二批：户部屏风页（列表 + 详情，T4.5）

- **需求项**：S4 的最后一块 —— 屏风里要能跑一张**真业务页**（筛选、翻页、看详情），
  并把上一批已下发但没人用的 `charts` / `links` 接上。总纲 T4.5。
- **为什么做成通用渲染器**：S5 有 9 殿 × 3 件套，每殿手写一张页，三周后就是 21 套各不相同的
  表格与分页逻辑。所以拆成两半：
  - `src/world/screenpage.ts`：取数 / 筛选 / 分页 / 详情 / 降级，一次做完；
  - `src/world/screenpages.ts`：按殿登记的配置（列口径、状态字典、详情字段、分录列）。
  接入第二张列表 = 加一条配置，渲染器不动。
- **数据不另造**：列表与详情直接复用 2D 后台的分页/详情接口
  （`/erp/scm/purchase-order/page`、`/erp/scm/purchase-order/{id}`），权限码复用
  `sys:erp:purchase:list`。**无新接口、无新权限点、无新迁移**。契约 §2.5 同步写明
  `links[].path` 就是这条列表接口（不搞"屏风专用第二套口径"）。
- **概览侧补齐**：`ErpOverviewProvider` 新增
  - `charts[0]`：营收/成本/利润柱状图 —— 三列都来自同一份 cockpit 快照，`null` 一律补 0
    （图表里的 `null` 会画成 NaN 柱，整张卡静默变白）；
  - `links[]`：采购订单入口，按 `ctx.hasPermission` 裁剪。没采购权限的人连"能点进去"都不该知道。
- **两条踩出来的硬约束**：
  1. **屏风没进入时，内部行/按钮一律不响应**。玩家"点一下屏风想进去"时，事件目标会落在表体行上，
     于是先弹详情、再被过场盖住——现场表现为"进殿后停在详情页"。现在由 `body.closest('.bws-screen').dataset.focus`
     判定，未进入只把点击让给外层 `screen.ts`。
  2. **屏风位置要按台基反算**。户部台基深 `(7+9)×0.95 = 15.2m`、顶面高 2.47m；按殿心偏移摆屏风会插进台基里，
     而 CSS3D 不做深度测试，看上去就是"浮在半空"。改成沿殿正面法线退到台基外的地面，并用
     `__bwwScreenOf` 校验：屏风底边投影 563px vs 地面 556px。
- **排版**：大屏 620px 高，KPI 单行 + 横向条形图（3 个值摊在 1100px 宽里用竖柱只剩发丝）+ 每页 6 行，
  刚好排满不用滚；详情态收起 KPI/图表/标签/工具栏，把整块屏让给详情与分录（分录区自己滚，整页不滚）。
- **验证**：`e2e/tools/world-screenpage-smoke.mjs` 35 项全绿：进屏风前后态、关键字筛选（20→1→20）、
  状态筛选（只剩已收货且回第 1 页）、4 页翻页与末页禁用、行点击详情（8 字段 + 12 行分录）、
  分录区滚动且整页不动、返回、Esc 退出、零控制台错误。
  回归 `world-screen-smoke/engage/ime/resize/hint`、`world-datahall-smoke`、`world-glyphs` 全通过；
  `world-city-smoke` 仍是 S1 扩容后的 3 项旧断言失败（传送门 9→13 等），与本阶段无关。
- **未做**：数枢殿那块写死数据的演示屏仍在（S5 统一按布局生成时替换）；真接口 HTTP 未验（本机 Nacos 未起）。
