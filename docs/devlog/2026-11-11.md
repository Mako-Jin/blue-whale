## 17:00-17:20 Wave 6.21 定位修复 whale-agent 控制台 SyntaxError（承 6.18/6.20 遗留）

### 根因（harness 实机复现实证）

- `@vitejs/plugin-react` 在 dev 下向 **head** 注入内联 `<script type="module">` 形式的
  react-refresh 预导脚本（`import { injectIntoGlobalHook } from "/agent/@react-refresh"`）。
  `vite-plugin-qiankun` 的 ESM→经典脚本改写选择器是
  `body script[type=module], head script[crossorigin=""]`——head 内、无 crossorigin 的内联
  预导**恰好漏掉**。
- 基座 qiankun 的 import-html-entry 不支持 ESM，把该片段按**经典脚本** eval →
  `SyntaxError: Cannot use import statement outside a module`。仅 HMR 预导失效，
  渲染不受影响，故 6.18 白屏修复后应用能正常跑、控制台恒报错。
- 复现方式（免登录）：基座 dev server 加临时 harness 页 `loadMicroApp({entry:'//localhost:8004/agent/'})`，
  Playwright 抓控制台——修复前 `[import-html-entry]: error occurs while executing normal script ...`
  + `pageerror: SyntaxError` 双证据。

### 修复（`whale-agent/vite.config.ts`）

- 新增 dev-only 插件 `qiankunReactPreambleFix()`（`apply:'serve'` + `transformIndexHtml order:'post'`）：
  把该内联脚本改写为**经典脚本 + 动态 import**，与 vite-plugin-qiankun 对 src 脚本的处理
  完全一致（沙箱内 `window.proxy.__INJECTED_PUBLIC_PATH_BY_QIANKUN__ + '..'` 前缀、独立运行回落文档地址）；
  import 解析支持 named/default/namespace/bare 四形态，非单条静态 import 的形态保持原样。
- 独立运行不受影响：改写后的 classic 动态 import 在纯浏览器同样成立。
