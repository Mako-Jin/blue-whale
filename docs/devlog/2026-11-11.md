## 20:15-20:55 Wave 6.26 mall 分类页崩溃的真实根因（http 返回契约 + React19 提示全丢）

- 起点是 mall `pages/category/index.tsx` 的 `setTree(data)` 不防 `undefined`：接口异常时整页落 ErrorBoundary。
  但根因不在页面：`@bluewhale/http` 的 `send()` 结尾 `payload ? payload.data : undefined`，把
  「反代/静态兜底把页面 HTML 以 200 返回」静默折叠成 `undefined` 当业务数据交给调用方，`setState(undefined)`
  要到**渲染期**才炸，现场无线索。
- 现在：2xx 空 body（204/void）→ `undefined`；2xx 非 JSON → 抛 `ApiError`（文案带 `Content-Type`）；
  JSON 缺 `code` → 抛「响应缺少统一信封」。页面侧另加 `Array.isArray(data) ? data : []` 与
  `flattenOptions(nodes ?? [])` 双保险（后端 200 + `{code:0}` 无 data 时不炸）。
- 顺带挖出两个更早的**静默失败**：① 静默续期写死 `POST /auth/refresh`，而网关白名单与服务端点全是
  `/auth/v1/refresh` → 续期恒 404，用户每次 access 过期都被踢回登录页（单测断言的却是正确路径，实现漂移）；
  ② antd v5 静态 `message`/`notification`/`Modal.confirm` 在 React 19 下**调用不报错但不渲染任何 DOM**
  （实测 `.ant-message-notice` count=0），全平台约 2000 处提示集体消失。缺 `@ant-design/v5-patch-for-react-19`，
  统一在 `elemental/whale-ui` 入口注入（25 个应用全依赖它，一处生效）。
- 验收：http 单测 14/14（新增空 body / HTML 200 / 缺信封 3 条）、whale-ui 17/17；mall tsc + eslint +
  vite build 通过（补丁已进产物）；Playwright 四场景（200+HTML、404+JSON、200+无 data、正常树）4/4 不落
  ErrorBoundary 且提示可见。
