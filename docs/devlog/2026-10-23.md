## 二、GitHub 远端同步策略（归档旧线 + 强制镜像）

- 背景：本地 `main`（`d089818`，目录布局 `backend/ frontend/ deploy/ infrastructure/`）与 `github/main`（`589d49a`，旧布局 `web/ server/ infra/ scripts/`，含租户隔离 0074-0079 系列）**无共同祖先**，`git merge-base main github/main` 输出为空；`git rev-list --left-right --count main...github/main` = `108  205`。两侧不是同一套代码的分叉，无法常规 merge/rebase 收敛。
- 决策（用户确认）：**归档旧线 + 强制镜像**——GitHub 现有主线先存档到 `legacy/main-20261023`，再用本地 `main` 覆盖 GitHub `main`；GitHub 从此作为本地仓库的只读镜像，不再作为开发主线。
- 本地已执行（不需要网络）：
  - `git branch github-legacy-20261023 589d49a`：本地保留 GitHub 旧主线全部 205 提交。
  - `git tag -a legacy-github-main-20261023 589d49a -m "GitHub 旧主线存档"`：打标签便于长期追溯（标签对象 `23a0323`）。
- 待网络恢复后执行（当前 `github.com:443` 不可达：`git ls-remote github` 超时、`git fetch github` 报 `OpenSSL SSL_read: Connection was reset, errno 10054`，本机无系统代理且 7890/10809/1080 等常见代理端口均未监听）：
  1. `git fetch github` —— 先刷新 remote-tracking 引用，确认远端自 `589d49a` 之后无新提交。
  2. `git push github github-legacy-20261023:refs/heads/legacy/main-20261023` —— 归档分支落到远端。
  3. `git push github main --force-with-lease` —— 镜像本地主线（不推送本地临时分支、不删远端其他分支）。
  4. `git push github legacy-github-main-20261023` —— 标签同步（可选，便于远端按标签追溯）。
- 风险与约束：
  - `--force-with-lease` 以本地 remote-tracking 引用为基线；若远端在此期间被他人更新，会安全拒绝。此时应重新 `fetch` 并复核差异，**不得改用裸 `--force` 跳过校验**。
  - 强制镜像只针对 `main` 与 `legacy/*`，不动 GitHub 上的 `ci`/`blue-whale-platform` 仓库。
  - 镜像后 GitHub 侧不再接受直接开发提交；所有变更仍以 Gitee `origin` 为主推送目标，GitHub 只做同步。
- 当前状态：本地存档已完成，远端推送**因网络阻塞待重试**（与既往 GitHub 直连超时问题同源）。
