# 开发日志 2026-10-23

## 一、监控闭环（Prometheus 告警 + Grafana 仪表盘）

- 目标：把上一轮「Prometheus/Grafana 已能启动」推进到可用的监控闭环 —— 版本化告警规则、可视化仪表盘、实机指标验证。
- 新增版本化产物（入仓）：
  - `deploy/monitoring/prometheus-rules.yml`：5 条告警规则，分 `bluewhale-availability`（ServiceDown 1m、TargetFlapping 5m）、`bluewhale-http`（5xx 占比 >5%、登录 P95 >1.5s）、`bluewhale-jvm`（堆使用率 >85%）。
  - `deploy/monitoring/grafana/dashboards/bluewhale-overview.json`：11 个面板 + 5 个分组行，含存活目标、SLO-1 登录 P95、5xx 错误率、审计上报 QPS、QPS/错误率/时延/JVM/GC 与抓取明细。
- 本地工具配置（`/tools/` 不入仓）：
  - `tools/monitoring/prometheus.local.yml` 增加 `rule_files` 指向仓库规则文件；启动参数加 `--web.enable-lifecycle` 支持热加载。
  - 数据源 provisioning 增加 `uid: prometheus`，供仪表盘 JSON 固定引用。
  - 新增 `tools/monitoring/grafana-provisioning/dashboards/bluewhale.yml`，指向仓库仪表盘目录，30s 轮询、文件夹 `BlueWhale`。
- 实机验证（MySQL/Redis/Nacos + gateway 8080 + auth 8081 + audit 9101 + Prometheus 9090 + Grafana 3000）：
  - `promtool check rules` → SUCCESS 5 rules；`/api/v1/rules` → 3 组 5 条。
  - 抓取：`whale-gateway`、`whale-auth`、`whale-ops(9101)` 三目标 `up=1`；其余 15 个未启动目标 `down`，触发 15 条 `ServiceDown` FIRING（本地按需启动，属预期）。
  - 生成 12 轮登录 + 审计上报流量后实测：登录 P95 ≈ 0.153s、平台总 QPS ≈ 0.42、审计上报 QPS ≈ 0.086、whale-auth 堆使用率 ≈ 18%。
  - Grafana `/api/dashboards/uid/bluewhale-overview` → 16 panels、文件夹 BlueWhale；`/api/ds/query` 返回 0.389（数据源链路通）。
- 故障与处理：Grafana 首次启动报 `Datasource provisioning error: data source not found`（旧 `grafana.db` 内数据源 uid 与新加 `uid: prometheus` 冲突），备份为 `grafana.db.bak-20261023` 后重建数据库，provisioning 恢复正常。
- 文档：`docs/ops/slo.md` 追加「告警规则」「Grafana 仪表盘」「本地监控闭环验证」三节。
- 说明：本地未接 Alertmanager，告警以 FIRING 状态展示于 `http://127.0.0.1:9090/alerts`；生产接入 Alertmanager 后可直接复用同一规则文件。
