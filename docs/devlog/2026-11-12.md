## Wave 6.37 auth 服务代码结构改造：契约上移 + 实现下沉 + URL 版本化

- **结构对齐 AuthApi**：`whale-service-auth-interfaces` 只留纯契约（12 个 `*Api` 接口，
  `@RequestMapping(path = "/xxx/v{version}", version = "1")` + mapping/校验注解，零业务依赖）；
  实现下沉到 `whale-service-auth-starter/controller/*Controller`（`@RestController implements XxxApi`，
  承载 `@RequirePermission` / `@AuditLog` / `@Idempotent` / `@RequireReauth`）。旧的
  `interfaces/controller` 12 个类已删除。
- **契约返回值只认 `interfaces.dto.response`**：新增 15 个 Response DTO（含
  `ResetPasswordResponse`、`UserDirectoryResponse`、`TenantPasswordPolicyResponse` 等），
  application 的 VO 不再泄漏进契约；由 7 个 MapStruct 装配器
  （`starter/assemble/*Assembler`，`Mappers.getMapper` 可测）完成 VO → Response 转换。
- **URL 全量版本化**：`/user|/role|/menu|/permission|/dept|/tenant` 及内网端点统一 `/xxx/v1/**`；
  内网版本段必须在 `internal` 之前（`/user/v1/internal/exists`）。
- **异常处理器迁出 controller 包**（用户 TODO）：`LoginLockedExceptionHandler`、
  `ReauthExceptionHandler` → `interfaces/web/advice/`（与 `AuthCookieManager` 同层归口，
  interfaces 已依赖 spring-boot-starter-web 与 application）。
- **门禁联动**：
  - `scripts/check-api-path-drift.py` 支持 `v{version}` 归一；
  - `scripts/check-internal-boundary.py` 新增 `normalize_version()`，网关/默认模式改
    `/*/*/internal/**`（ant 匹配只认整段 `*`，`v*` 不生效），控制器扫描兼容「实现契约接口」形态；
  - 网关 `whale.internal-deny.patterns` 与 auth `SecurityConfig` permitAll 白名单同步为版本化路径。
- **调用方/前端/文档联动**：whale-im、archive、agent、twin、scene、message、oa 共 15 处内网
  URL 加 `/v1`；admin 6 个 api 模块 + `auth-schema.d.ts`、whale-platform `system.ts`、
  smoke 脚本、e2e 清理路径同步；`docs/api.md`、`docs/design/{network-boundary,ddd-whale-auth,security-baseline}.md`、
  `docs/service-catalog.md`、auth README 口径更新。
- **测试**：8 个 ControllerTest 迁到 `starter/controller`，`LoginLockedExceptionHandlerTest` 迁到
  `starter/web/advice`。standalone MockMvc 需显式装 `DefaultApiVersionStrategy(PathApiVersionResolver(1))`，
  否则接口级 `version` 映射在 standalone 下直接构建失败（`RequestMappingInfo.DefaultBuilder`）。
