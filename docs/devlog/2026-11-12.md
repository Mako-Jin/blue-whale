## Wave 6.42 infra 规则收紧：触发型组件上移 starter，`infrastructure ↛ application.service`

6.41 遗留项收口。核实 6.41 清单里的 5 处 infra→service 引用，发现其中 2 处是**死 import**
（PermissionCache 的 `RoleAppService`、MailProvisionListener 的 `UserAppService`——
均只有 import 无使用，直接删除）；真实编排引用只剩 3 处：

- **MVC 基建上移 `starter.web`**：`ReauthInterceptor` + `WebMvcConfig`（连同 javadoc
  全限定修正）；`PermissionInterceptor` 留守 infra（不引 service，权限语义的 infra 实现）。
  `ReauthInterceptorTest` 随迁（starter web 包，7 例）。
- **定时任务上移 `starter.trigger`**：`PasswordExpiryNoticeJob`（编排
  TenantPasswordPolicyService 发到期提醒），测试随迁（6 例）。
- **MailProvisionListener 留守 infra**：它是领域事件 `AFTER_COMMIT` 副作用适配器
  （只读聚合 + 调 infra 邮箱客户端，不调任何应用服务），javadoc 自述「基础设施侧的可选
  副作用」——首版误迁 starter 暴露 `starter↛domain` 违规后回退，删死 import 即达标。
- **ArchUnit 收紧**：`infrastructure_must_not_depend_on_service_impl` →
  `infrastructure_must_not_depend_on_application_service`（禁接口+impl 全量）；
  复核发现初版迁移曾触发既有 `starter↛domain` 规则（监听器消费领域事件/仓储属 infra
  职责），反向印证「副作用适配器留 infra、编排组件上移 starter」的分界正确。
- 验证：auth 全链 BUILD SUCCESS——starter **550/550**、architecture-test **9/9**
  （含收紧后新规则与既有 starter↛domain 双绿）。
