## whale-form 扩展评审处置（批次 1：数据变更历史 / 发布预检 / 对账 / 单测补强）

- **评审事实核对**：外部第二轮 24 项扩展建议中，第 16、17 项与代码现状不符（ArchUnit 规则已存在 3 条；
  关键路径单测大多已覆盖），snapshotSeq / truncated 也早已接线完成。核对结论与差异清单见
  [whale-form-expansion-roadmap.md](../plans/whale-form-expansion-roadmap.md) 第二节。
- **决策**：表单数据审批能力由外部工作流（whale-workflow）承载，本模块后续只加
  `bizStatus` + `processInstanceId` + 审批中只读判定，不建本地状态机（排入批次 2）。
- **需求项**：① 数据变更无历史，update 直接覆盖 dataJson；② 动态 DDL 无发布预检，列类型收窄会静默截断；
  ③ 主表与物理表双写缺对账与修复手段；④ 少数组装路径缺安全边界单测。
- **完成项**：
  - 变更历史：新增 `V8__form_data_history.sql`（只追加表）+ `FormDataHistoryPo/Mapper/VO` +
    `FormDataHistoryRecorder`；`submit/update/delete` 在同一事务内留痕（历史写入失败即回滚业务变更），
    `update` 额外记录前后快照与 `changed_keys` 差异字段；新增
    `GET /form/v1/data/{id}/history`（`sys:form:data:list`，倒序最多 200 条，按租户限定，
    记录删除后仍可追溯）。
  - 发布预检：新增 `FormColumnNarrowingDetector`，识别 `VARCHAR` 缩短、`TEXT → VARCHAR`、
    `DECIMAL` 精度/小数位收窄、`DATETIME → DATE`；`ensurePublished` 在执行任何 DDL **之前**整体预检，
    未确认时一次性列出全部收窄列并抛 400。`publish` / `publishTableDefinition` 增加 `force` 重载，
    控制器新增 `force` 参数（默认 false，行为与升级前一致）。
  - 主从对账：新增 `V9__form_reconcile_diff.sql`（唯一键 `uk_batch_table_data` + 状态索引）、
    `FormDataEngine#listIds`、`FormDataMapper#selectActiveTenantIds`、`FormReconcileService`
    （对账 / 分页 / 修复）、`FormReconcileJob`（`form.data.reconcile`，默认每日 03:40，
    `whale.form.reconcile-enabled` 可关闭）与 `FormReconcileController`
    （`POST /run`、`GET /diffs`、`POST /diffs/{id}/repair`，权限 `sys:form:data:reconcile`）。
    auth 侧新增 `V32__form_data_reconcile_permission.sql`（权限编号 2421，不自动授权）。
  - 单测：`escapeComment` 补注入载荷包裹、反斜杠结尾、200 字符截断、换行归一 4 类参数化用例；
    `in` / `between` 补参数顺序、值数量边界；新增变更历史 5 项、对账与修复 8 项、收窄识别 3 组参数化。
- **已修正问题项**：对账首版在物理表扫描被截断（>20000 条）时仍登记「主表有物理表无」差异，
  会把未扫描到的记录误判为缺失；改为截断时跳过该方向并 warn（「物理表有主表无」仍完整比对）。
- **验证**：`mvn -o -pl whale-services/whale-service-form test` → 179 项测试通过、0 失败，
  `checkstyle:check` 通过；auth 迁移脚本命名/破坏性语句/白名单 3 项校验通过
  （`rbacBaselineShouldMatchPlatformOnlyCodes` 单模块运行缺 auth-application 类，为既有环境问题，与本次改动无关）。
- **待做项**：批次 2（审批接线、批量导入、业务指标、发布失败告警、模板分类）、
  批次 3（缓存、事件解耦、多租户物理表策略评估、冷热分离、drift 检测）、
  批次 4（字段级权限、导出脱敏、检索限流、JSON 深度限制、DDL 权限收敛等），详见路线图。
- **上线注意**：必须执行 form 库 `V8`、`V9` 与 auth 库 `V32`；对账 Job 默认开启，首次建议先手动
  触发 `/run` 观察差异量与耗时；对账单表扫描上限 20000 条、单批次差异上限 5000 条。
