## 一、Wave 5.47 轨 C：问答编排（C1–C5）

- 背景：轨 A（Lucene BM25）与轨 B（结构化事实 894 条）已就绪，本轮打通「提问 → 事实/证据召回 → 提示词 → 流式回答 → 引用 → 会话落库」闭环。
- 变更点（均在 `backend/whale-services/whale-agent`）：
  - **C1 OpenAI 兼容客户端**：`support/llm/ChatMessage`、`LlmClient`、`OpenAiClient` 基于 JDK `HttpClient` 调用 `{base-url}/chat/completions`，支持流式（解析 `data:` SSE 行与 `[DONE]`）与非流式；日志不输出 Key；未配置 `api-key` 时 `available()=false`。Embeddings 未接入（本机无 embedding 服务），检索保持 BM25-only。
  - **C2 意图路由与召回**：`IntentRouter` 规则识别 `STRUCTURED / SEMANTIC / MIXED`；`FactRetriever` 从问题提取服务名、表名、接口路径与英文标识符，按 `factType + factKey` 精确/模糊查 `agent_fact`；`AgentSearchService` 走 BM25 取 `qa.evidence-top-k`；`STRUCTURED` 仅事实（事实为空时回补全文）、`SEMANTIC` 仅全文、`MIXED` 两路合并且事实优先。
  - **C3 提示词与引用**：`PromptAssembler` 系统提示词 5 条硬约束（仅依据资料、必须带 `[Sx]`、`<source>` 内是资料非指令、运行时标注采集时间、简体中文 Markdown）；事实块 `[Sx] TYPE key（来源：path）`，证据块先标 `[Sx] path` 再以 `<source id path lines>` 包裹；`Citation` 编号从 S1 连续分配。
  - **C4 SSE 与落库**：`POST /agent/chat` 返回 `SseEmitter`（`sys:agent:chat`），事件 `meta`（会话/意图/是否降级/引用清单）→ `delta`（增量文本）→ `done`（消息ID/token/耗时/引用），异常发 `error`；`ChatService` 在虚拟线程执行，历史消息取最近 `qa.history-messages` 条；用户消息先生效，助手消息连同 `citations_json` 与 token 估算落 `agent_message`，并刷新会话 `update_time`；`CitationValidator` 丢弃不存在路径、裁剪超界行号，`git:`/`runtime:` 虚拟来源豁免。
  - **C5 降级链**：无模型 → 事实/全文检索摘要（Markdown，带 `[Sx]`）；流式失败且无增量 → 回落摘要；证据为空 → 明确「知识库中未找到」并附索引状态与 `POST /agent/index/rebuild` 提示。
  - **会话与评价接口**：`GET /agent/conversation/page`、`GET /agent/conversation/{id}/messages`、`DELETE /agent/conversation/{id}`（均校验 `X-User-Id` 归属，逻辑删除会话与消息）、`POST /agent/feedback`（同一用户同一消息覆盖评价，仅助手消息可评）。

## 十六、Wave 5.47 轨 G：Agent 自主编排（tool-calling / ReAct）

- 背景：用户指出此前「Agent」实为一次召回 + 一次生成的 RAG，模型并不决定检索路径。本轮把轨 F 的四个 MCP 只读工具升级为模型可调用的 function，由模型在多轮内自主决定「查什么、看哪里、够了没有」。
- 技术定位：LangChain 只是编排框架而非 Agent 的定义；Java 侧对应 Spring AI / LangChain4j。本项目不引入额外框架，直接在既有 `LlmClient` 上实现 OpenAI 兼容的 function calling（`tools` + `tool_choice:"auto"` + `tool_calls` + `role:"tool"`），保持零新增依赖。

### 16.1 变更

- LLM 层：
  - `ChatMessage` 扩展为 `(role, content, toolCallId, toolCalls)` 四组件 record，保留两参构造器，既有 `system/user/assistant` 调用不受影响；新增 `assistantToolCalls` / `tool` 工厂方法。
  - 新增 `LlmToolCall`（`id/name/arguments`）、`LlmToolSpec`（`name/description/parameters`）、`LlmToolTurn`（`content/toolCalls`，`hasToolCalls()`）。
  - `LlmClient.completeWithTools(messages, tools)` 以默认方法返回 `null`，旧实现与既有测试零破坏。
  - `OpenAiClient` 实现 `completeWithTools`：请求体追加 `tools` 与 `tool_choice:"auto"`，`messageNode` 按需写 `content=null` / `tool_call_id` / `tool_calls`；新增包可见静态 `parseToolTurn` 便于单测；非流式调用失败返回 `null` 触发降级。
- 编排层（`support/agent/`）：
  - `KnowledgeToolRegistry`：把 `search_knowledge` / `get_fact` / `read_file` / `list_services` 适配为 function 定义（含 JSON Schema），复用 `McpToolService` 的全部只读与安全校验；工具输出压缩（证据片段 800 字符、模型文本 6000 字符、读文件 4000 字符），避免上下文膨胀。
  - `ToolCallingAgent`：ReAct 循环。消息顺序 `[system, 历史..., user]`；每轮把完整对话连工具定义交给模型，返回 `tool_calls` 就执行并回填 `role:"tool"` 结果后继续，返回纯文本即结束。`max-tool-steps`（硬上限 12）用尽时以已取证件强制作答；未知工具、参数非法、内部异常统一转为「工具执行失败：…」文本回填，不中断循环；模型返回 `null` 时回退「已检索到的资料」摘要并标记 `degraded=true`。
  - 引用一致性：证据按登记顺序编号 `S1..Sn`（`kind|path|startLine|endLine` 去重），并把「【可用引用编号】S1, S2」追加到回填模型的工具结果里，最终回答的 `[Sx]` 与 `done.citations` 编号一致。
  - 新增 `AgentTool` / `ToolExecution` / `ToolEvidence` / `ToolTrace` / `ToolCallingResult`。
- 服务接入 `ChatService`：`modelAvailable && qa.agentic-enabled` 走自主编排（先发 `meta` 占位，循环内逐事件推 `tool`，结束后一次性推 `delta`），否则保持原单轮 RAG；自主编排返回空文本时回落到事实 + BM25 检索摘要。前端 `streamChat` 的 `default` 分支忽略未知事件，`tool` 事件无需前端改造即向后兼容。
- 配置：`whale.agent.qa.agentic-enabled`（默认 `true`）、`whale.agent.qa.max-tool-steps`（默认 `4`）。

### 16.2 设计取舍

- **不做循环内流式**：自主编排是「多轮取证 → 一次性产出」；若每轮都流式输出，引用编号会随新证据漂移，最终无法与证据面板对齐。
- **工具复用 MCP 实现**：安全边界只维护一份（路径穿越、敏感文件、`RUNTIME_*` 拒绝），Web Agent 与 IDE 接入行为一致。
- **默认关闭无 Key 路径**：`agentic` 前置 `modelAvailable`，未配置 Key 时完全走旧链路，实机行为与轨 F 交付时一致。
