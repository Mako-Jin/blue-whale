### 修复的真实 Bug（后端，2 个）

1. **`LoginResponse` 缺 `userId` 字段**（T-02 批C 遗留实机联调缺口）：首登强制改密弹窗 `MustChangePasswordDialog` 需要 `userId` 提交 `PUT /user/{id}/password`，字段缺失导致弹窗永远无法提交、E2E 全挂。已在 [LoginResponse.java](../backend/whale-services/whale-service-auth/whale-service-auth-application/src/main/java/com/bluewhale/auth/vo/LoginResponse.java) 补字段，`SessionAppService#buildAuthTokenIssue` 回填。
2. **CSRF Cookie `Path=/auth` 缺陷**（V-03）：`whale_csrf` 本应整站可读（前端任意业务页面读取后回传 `X-CSRF-Token`），却复用了 refresh Cookie 的 `Path=/auth`——业务页面 `document.cookie` 读不到 → `bootstrapAuth` 静默续期请求缺 CSRF 头 → 403「CSRF 校验失败」→ 整页刷新被踢回登录页。[AuthCookieManager.java](../backend/whale-services/whale-service-auth/whale-service-auth-interfaces/src/main/java/com/bluewhale/auth/web/AuthCookieManager.java) 新增 `CSRF_COOKIE_PATH="/"`：下发（`writeAuthCookies`）与清除（`clearAuthCookies`/`expiredCookie`）路径同步修正，refresh Cookie 保持 `Path=/auth`；单测断言同步更新。实测登录 `Set-Cookie` 中 `whale_csrf ...; Path=/` 生效。

### 现象

GitHub Actions docker-deploy 在 `fact-assets 5/5` 步骤失败：`cp: can't create directory '/repo/backend': No such file or directory`（`NEED_FACT_ASSETS=true` 的模块，如 whale-agent）。

### 根因

[deploy/backend/sample/Dockerfile](../../deploy/backend/sample/Dockerfile) 的 `mkdir -p /repo` 只写在 `NEED_FACT_ASSETS != "true"` 的提前退出分支里；`true` 分支直接 `cp -a /src/backend /repo/backend`，目标父目录不存在。

### 修复

把 `mkdir -p /repo` 提到分支判断之前，两条路径下都保证 `/repo` 存在（`false` 时仍为空目录，运行时 `COPY --from=fact-assets /repo /opt/whale-repo` 行为不变）。

## whale-message 系统公告（全员广播）能力（2026-11-02 晚）

### 背景

统一消息服务此前只有定向站内信（INAPP 需显式枚举接收人）。本轮补齐「系统公告/全员广播」：单条发布、不枚举接收人，公告面向当前租户全体用户。

### 方案（惰性展开）

- 新增 `msg_announcement` 表（record_id 关联 `msg_record`，标题/正文/业务类型在 record 上；status=PUBLISHED/REVOKED；publisher_id、publish_time）。
- **发布** = 落一条 `msg_record`（channels=INAPP、status=SENT、bizType 缺省 SYSTEM_ANNOUNCE）+ 一条公告行，不做任何 fan-out。
- **读取时展开**：[AnnouncementExpander](../backend/whale-services/whale-message/src/main/java/com/bluewhale/message/support/AnnouncementExpander.java) 在收件箱三个接口（page / unread-count / markRead）读取前，将「已发布公告 − 本人已有 INAPP 投递」的差集补写为个人 `msg_delivery` 行（read_flag=0、sent_at=公告发布时间）。幂等护栏 = `msg_delivery` 新增唯一索引 `uk_message_channel_recipient (message_id, channel, recipient)`，并发展开撞 `DuplicateKeyException` 静默跳过；展开整体 try/catch 降级，失败不阻断收件箱读取。
- **撤回**：公告置 REVOKED——未展开用户不再看到；已展开的个人消息保留（已投递语义）。
- **已读**：复用投递记录 `read_flag` 与既有 markRead 链路，收件箱查询代码零改动。

### 变更点

- DDL：[migration-5.76-message-announcement.sql](../backend/whale-services/whale-message/src/main/resources/db/migration-5.76-message-announcement.sql)（建表 + 历史重复投递去重 + 幂等加唯一索引）；init.sql 同步（全新安装口径）。
- 后端：`MessageAnnouncement` 实体 / `AnnouncementStatus` 枚举 / `MessageAnnouncementMapper` / `AnnouncementPublishRequest` / `AnnouncementQueryRequest` / `AnnouncementVO` / `MessageAnnouncementService(+Impl)`（publish/page/revoke/delete）/ [MessageAnnouncementController](../backend/whale-services/whale-message/src/main/java/com/bluewhale/message/controller/MessageAnnouncementController.java)（`/message/announce/**`，`sys:message:announce:*` 权限 + @AuditLog）。
