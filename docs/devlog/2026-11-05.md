### 落地内容

- **迁移**：`V10__scm_requisition_quotation.sql` 4 张表（采购申请头/行、销售报价头/行），唯一键 `uk_pa_doc_no`/`uk_pa_line`/`uk_sq_doc_no`/`uk_sq_line`；仅 `CREATE TABLE IF NOT EXISTS`，无物理外键。

## Wave 5.83 M2 收尾：销售预测 + 销售目标

### 起因

CRM M2 已完成线索/商机/漏斗/报价，剩余预测与目标两项。用户指令「继续，完成之后提交代码」，本片补齐 M2 最后增量并仅提交 CRM 范围。

### 落地内容

- **迁移**：`V6__forecast_target.sql` 四表——`crm_forecast_snapshot`、`crm_forecast_adjustment`、`crm_sales_target`、`crm_sales_target_adjustment`；唯一键 `uk_crm_forecast_period_scope` / `uk_crm_sales_target_period_scope`；仅 `CREATE TABLE IF NOT EXISTS`，无业务种子。M3–M6 迁移顺延为 `V7–V10`。
- **预测口径**：管道 = 未关闭商机金额（CONTACT/PROPOSAL/NEGOTIATION）；最佳 = NEGOTIATION；承诺 = WON + 概率 ≥ 90 的未关闭商机；加权 = Σ 金额 × 概率 / 100（WON 按全额）；`opportunityCount` 为未关闭商机数。周期支持月 `yyyy-MM` 与季 `yyyy-Qn`，季周期起止自动展开为季度首末日。
- **目标口径**：范围 USER（`owner_id`，`dept_id=0`）/ DEPT（`dept_id`，`owner_id=0`）；完成率 = 同期赢单商机金额 ÷ 目标金额 × 100（2 位 HALF_UP）；金额调整必须填原因并写调整记录。
- **应用服务**：`ForecastAppService`（分页/详情/生成/调整/调整记录）、`SalesTargetAppService`（分页/详情/新建/修改/删除/完成率/调整记录）；预测生成按周期 + 范围 upsert 并置 `manualAdjusted=false`，调整后置 `true`；部门范围需全量数据范围，非全量角色只见本人；乐观锁冲突提示刷新重试。
- **接口**：`/crm/forecast`（page/detail/adjustments/generate/adjust）、`/crm/sales-target`（page/detail/completion/adjustments/create/update/delete），均带 `@RequirePermission` 与 `@AuditLog`。
- **权限**：`migration-5.86-crm-forecast-target.sql` 1855–1859（预测查询/维护、目标查询/维护/删除）；`crm_admin`/`tenant_admin`/`crm_sales_manager` 全授权，`crm_sales`/`crm_analyst` 仅查询。
- **错误码**：41037 `FORECAST_NOT_FOUND`、41038 `FORECAST_PERIOD_INVALID`、41039 `FORECAST_ADJUST_INVALID`、41040 `TARGET_NOT_FOUND`、41041 `TARGET_DUPLICATE`、41042 `TARGET_AMOUNT_INVALID`。
- **测试**：`ForecastAppServiceImplTest` 9 项、`SalesTargetAppServiceImplTest` 8 项；`CrmFlywayMigrationScriptTest` 补 V6 四表、两个唯一键与无种子断言。

## Wave 5.78 M2 剩余 B 第四期：ERP 安全库存、缺料预警与呆滞分析

### 起因

价格表（第三期）已提交，M2 剩余 B 尚缺库存侧的「安全库存 / 缺料 / 呆滞」能力，采购与计划无法判断补货优先级。本片按计划 §12.8 补齐，批次追溯因需 `ALTER` 既有库存表，与迁移门禁冲突，明确推迟。

### 落地内容

- **迁移**：`V12__scm_safety_stock.sql` 单表 `erp_scm_safety_stock`（仓库 + 物料、编码/名称快照、安全量、最高量、备注），唯一键 `uk_safety_stock(tenant_id, warehouse_id, item_id)`、索引 `idx_safety_stock_item`；仅 `CREATE TABLE IF NOT EXISTS`，无物理外键。
- **领域**：`SafetyStock.validate()` 校验安全量 ≥ 0、最高量为空或 ≥ 安全量；`SafetyStockQuery` 复用 `ScmQuery` 的仓库/物料/关键字过滤。
- **仓储**：`SafetyStockRepository` 三件套；`StockRepository` 增 `listBalances`（呆滞计算）与 `lastOutboundAt(itemId, warehouseId)`（最近 `OUT` 流水）。
- **应用**：`SafetyStockAppService` page/detail/create/update/delete/shortage/idle；新增时校验仓库与物料启用并查重（`40941`）。
- **预警口径**：缺料 = 安全量 − 余额，仅返回 > 0，余额缺失按 0；呆滞 = 余额 > 0 且最近出库早于阈值（默认 90 天，`< 1` 抛 `40024`），从未出库恒计入且库龄为空；两者内存计算后按 `current/size` 切片。
- **接口**：`/erp/scm/safety-stock` 6 端点（page/detail/create/update/delete/shortage/idle），写操作 `@AuditLog`；`/idle` 与 `/shortage` 共用 `analysis` 权限。
- **错误码**：40024 `SAFETY_STOCK_INVALID`、40439 `SAFETY_STOCK_NOT_FOUND`、40941 `SAFETY_STOCK_CONFLICT`。
- **权限/菜单**：`migration-5.78-erp-safety-stock.sql` 权限 533–538、菜单 103；`tenant_admin`/`erp_manager`/`erp_scm` 全量，`erp_member` 仅 533/534/538。
- **前端**：`api/scm.ts` 类型与 7 个函数；`SafetyStockPage.tsx` 三页签（配置/缺料预警/呆滞分析），仓库与物料下拉复用主数据接口；`App.tsx` 路由与基座菜单补「安全库存」。
