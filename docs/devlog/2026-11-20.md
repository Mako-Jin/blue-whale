## 国际化整改（P2 第五批：DTO 校验文案试点 forum）

  `messages` / `messages_zh_CN` 与原文逐字一致，`messages_en_US` 为自然英文，三份键集均为 118 键。
- **验证**：新增 `ValidationMessageI18nTest` 2 例（zh-CN 中文原文 / en-US 英文翻译，
  覆盖 Boot 自动配置 + SDK 资源扫描链路）；forum `mvn test` + `checkstyle:check` 通过，
  代码引用键零缺失。
- **注意**：未接入 i18n SDK 且无 `spring.messages` 资源的模块需先补资源包，

## 三员分立收尾（审计防篡改 / 超管互斥 / 验收断言）

- **审计追加写保护**（等保 8.1.4.3 c）：`audit_log` 是合规证据，只允许 INSERT/SELECT。
  - 代码层：`scripts/security/check-audit-append-only.py`，禁 UPDATE/DELETE/REPLACE/TRUNCATE，
    已挂进 `.github/workflows/code-quality.yml`（`audit-append-only` 作业）；
    既有 `V25__drop_local_log_tables.sql` 属一次性历史迁移，走白名单豁免并打印理由。
  - 数据库层：`scripts/security/AuditAppendOnlyGuard.java` 给所有含 `audit_log` 的库建
    BEFORE UPDATE/DELETE 触发器（28 库全 PASS），内置「首列赋给自己」的无害 UPDATE 做行为验证；
    新环境由 `whale-audit` 的 `V2__audit_log_append_only_guard.sql` + `db/init.sql` 自动带守卫。
  - **踩到的坑**：第一版把 `api_log`/`outbound_log`/`frontend_log`/`behavior_log` 一起加了 DELETE 守卫，
    而 `LogRetentionCleaner` 正是按 cron 删这四张表的过期行——保留期会静默失效、表无限膨胀。
    已回滚为「只守 `audit_log`」，工具加 `--tables=` 供临时指定。
- **超管并入三员互斥**：`V37__super_admin_three_admin_mutex.sql` 把 `super_admin` 的角色 id 追加进
  `three_admin_mutex` 的 `role_ids`（`JSON_CONTAINS` 判存，幂等；二次执行 `affected=0`），
  实测约束变 `[26004, 26005, 26006, 1]`——「超管 + 任一三员」与「三员相互兼任」统一被同一个 MUTEX 拦住。
- **验收断言集**：`scripts/verify/three-admin-assertions.sql` 11 条只读断言（三员齐备 / 审计员恰 2 码 /
