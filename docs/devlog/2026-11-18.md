## whale-job 代码评审整改（P0/P1 与健壮性收尾）

- **需求项**：外部评审提出 17 项问题，复核后确认 11 项成立。优先修复会直接影响线上数据正确性与多实例语义的项：
  编辑任务静默停止任务、告警冷却单实例失效、内网执行器接口租户丢失、调度广播早于事务提交；
  并完成线程池/超时配置化、Flyway 表名转义、编码截断等健壮性收尾。
- **决策**：
  - 不采纳「在应用层手写租户过滤」：租户隔离已由全局 `TenantLineInnerInterceptor` 承担，
    重复实现会形成两套事实源；仅在创建任务时补防御性 `tenantId` 回填。
  - 告警冷却选 Redis `SETNX + TTL`（项目已有 Redisson），保留实例内降级，避免中间件故障中断告警。
  - 调度变更整体延后到 `afterCommit` 执行，提交后失败仅告警，由 5 分钟对账任务自愈。
  - P3-15（DTO 抽父类）与 P3-17（run 审计类型）不采纳，理由见整改记录。
- **完成项**：
  - `JobInfoServiceImpl`：update 保留原 status/分组/失火策略；调度注册/取消改事务提交后执行；创建时防御性回填租户；
  - `JobInfoCreateRequest` / `JobInfoUpdateRequest`：status 补 `@Min(0)` / `@Max(1)`；
  - `WebhookJobAlertNotifier`：冷却态迁 Redis（键含租户+任务），Redis 异常降级本地并清理过期项，
    失败消息对空任务名兜底，关闭改为 `shutdown` + 等待在途推送；
  - `JobExecutorRegistrar`（starter）：注册/心跳/注销补 `X-Tenant-Id`；
  - `JobExecutorInternalController`：`@Validated` + `appName @Size(max=64)`；
  - `JobProperties` / `JobScheduler` / `application.yml`：线程池默认 8 且可配置，HTTP 默认超时 15s；
  - `FlywayLegacyRepairConfig`：表名按元数据引用符转义、支持 schema 前缀、清理未命中时只查一次；
  - `JobExecutorServiceImpl#joinCodes`：按完整 code 边界截断；
  - `JobController#saveDependencies`：补 `@Valid`。
- **已修正问题项**：
  - 当前 Redisson 版本无 `setIfAbsent(V, long, TimeUnit)`，改用 `Duration` 重载；
  - `JobArchitectureTest` 仍扫描已改名的 `job.entity` 包（评审前既有失败），规则同步改为 `job.po`；
  - Flyway 清理改造初稿会漏删「仅有失败版本残行」的场景，预查询条件已与 DELETE 对齐。
- **验证**：`mvn -o test`（`whale-service-job`）→ **108 项单测零失败、BUILD SUCCESS**、checkstyle 0 violation；
  `whale-spring-boot-starter` 编译与新增用例通过、checkstyle 0 violation。本轮新增 7 项单测（状态保留、分组保留、
  提交后调度、Redis 冷却命中/降级、编码边界截断、注册器租户透传），另新增 1 项默认跳过的实机 IT。
- **实机验证**（本地 Redis 5.0.14.1）：`LiveWebhookCooldownIT` 证明两个通知器实例共享冷却窗口，
  冷却期内仅首个实例外发、告警仍逐次落库，冷却键带 TTL 且失效后可再次外发；`JobExecutorRegistrarTest`
  证明注册/心跳/注销均携带 `X-Tenant-Id`。
- **待做项**：无。真实双 JVM 并行部署未单独执行，冷却共享机制已由实机 IT 覆盖。
- **上线注意**：各业务服务需将 `whale.job.executor.tenant-id` 配置为自身租户；
  长耗时 HTTP 任务需在 `handlerParam.timeoutMillis` 显式覆盖默认 15s。

## whale-job 韧性增强：超时中断 / 自动暂停 / 优雅停机（扩展路线图第 2、3、4 项）

- **需求项**：封住三类生产事故来源——慢任务长期占调度线程、坏任务按 cron 无限失败刷屏、
  进程停机遇派发中的任务被杀导致执行流水永远停在「执行中」。设计见 `docs/job-resilience-timeout-autopause.md`。
- **决策**：
  - 任务超时使用独立执行线程池（`Future.get` 等待 + `cancel(true)` 中断），不与调度线程池共用，
    避免「等自己」死锁；超时不重试，告警按「超时」独立口径。
  - 熔断计数按「一次执行」而非「一次分片」，自增/暂停/清零全部用条件更新，多实例并发只有一个生效；
    自动暂停写 `audit_log`（`username=SYSTEM`）与人工启停区分。
  - 业务侧停机顺序为「注销 → 等在途任务清零（有界）→ 关心跳」，调度侧启动时对账孤儿执行日志。
  - 超时、熔断、停机等待默认值均保持「零行为变化」：超时默认 0（不限制）、熔断阈值默认 0（关闭）。
- **完成项**：
  - 新增 `V16__job_resilience.sql`：`job_info` 增加 `timeout_seconds` / `fail_threshold` / `fail_count`（判存后 ADD，幂等）；
  - `JobInfoPo` / 创建与更新 DTO / `JobInfoVO` 补齐三个字段，`JobInfoServiceImpl` 创建补默认值、
    更新保留原值、启用时清零 `fail_count`；
  - 新增 `JobTimeoutException`；`JobScheduler` 增加任务执行线程池、超时等待与中断、超时不重试；
  - `JobScheduler` 增加连续失败累计与熔断暂停（取消调度 + 广播 + SYSTEM 审计 + WARN 告警）；
  - `JobScheduler` 启动对账孤儿执行日志（`whale.job.orphan-log-timeout-minutes`，默认 120 分钟）；
  - `JobAlertNotifier` 新增 `notifyTimeout` / `notifyAutoPaused` 默认方法，
    `WebhookJobAlertNotifier` 区分「任务执行超时」「连续失败已自动暂停」摘要与级别；
  - starter `RemoteJobRegistry` 增加在途执行计数与 `awaitIdle`，`JobExecutorRegistrar` 停机先注销再等待，
    等待时长 `whale.schedule.executor.shutdown-await-seconds`（默认 30 秒）；
  - `application.yml` 增加 `task-pool-size` / `task-timeout-seconds` / `orphan-log-timeout-minutes`。
- **已修正问题项**：
  - 单测中 Lambda 更新条件需要实体元信息，`JobSchedulerTest` 补 `TableInfoHelper` 初始化；
  - 超时测试的任务线程中断存在竞态，改为有界轮询等待中断标记后再断言。
- **验证**：`whale-service-job` 全量 `mvn -o test` → **116 项零失败**、BUILD SUCCESS；
  `whale-spring-boot-starter` → **174 项零失败**；新增 4 项调度韧性用例、1 项告警口径用例、2 项在途计数用例。
- **待做项**：真实停机演练（容器收到 SIGTERM 后观察在途任务与 `job_log` 终态）；
  业务服务建议同时开启 `server.shutdown=graceful`；熔断阈值建议先在测试环境观察失败率后再配置。

## whale-job 运维效率：DAG 拓扑图与执行统计（扩展路线图第 5、6 项）

- **需求项**：让管理端能看见依赖拓扑与执行质量——全量图渲染、整图环校验、按天成功率/耗时 P95、
  失败与耗时 TopN。设计见 `docs/job-dag-graph-and-stats.md`。
- **决策**：
  - 图接口返回精简节点（`JobGraphNodeVO`）而不是 `JobInfoVO`，避免图渲染携带 `handlerParam`
    与逐条解析 cron；边方向固定为上游 → 下游，分组过滤时只保留两端都在节点集合内的边。
  - 环检测用三色 DFS 找第一条回边并返回闭环路径，作为保存前校验与数据体检入口；
    `saveDependencies` 的增量环检测保持不变。
  - 统计只计入已结束执行（成功/失败），按 `start_time` 本地日期分桶，P95 用离散口径；
    明细一次扫描在应用内完成计数/均值/P95/TopN，超过 10 万行置 `sampled=true` 提示截断。
  - 默认窗口 7 天、最大 90 天；指定 `jobId` 时 TopN 返回空。
- **完成项**：
  - 新增 `GET /job/graph?jobGroup=`、`GET /job/graph/validate`、`GET /job/log/stats`；
  - 新增 `JobGraphService`/`JobGraphServiceImpl`、`JobLogStatsQueryRequest` 与 5 个统计/图视图对象；
  - `JobLogService` 增加 `stats`，控制器与权限（`sys:job:list` / `sys:job:log:list`）对齐现有口径。
- **验证**：
  - 单测：`mvn -o test` → **124 项零失败**、BUILD SUCCESS（新增 8 项：图/环检测 3 项、统计 5 项）。
  - 起服实测：图接口返回 33 节点 0 边；`validate` 返回 `acyclic=true`；
    统计返回 6 天、6053 条样本、失败/耗时 Top10；
    临时建两个任务配置 A→B 依赖后图接口返回方向正确的边，反向配置被 400「任务依赖关系存在环」拦截，测试任务已清理。
- **待做项**：前端 DAG 渲染（AntV G6 / ECharts graph）与 dashboard 图表接入；
  数据量增长后把统计切到 Prometheus 或按天汇总表。
