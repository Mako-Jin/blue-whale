## 第八批（CRM 分析 cron 迁移 whale-job 调度中心 + 实机验证）

### 查证结论

- CRM `snapshot-cron` / `action-plan-cron` 原为**进程内 Spring `@Scheduled`**（`AnalyticsSnapshotJob`），未接 whale-job；whale-job 此前仅有 3 个本地 handler（Demo / 日志清理 / 日志归档），**无远程派发能力**，业务服务也没有可被调度的触发端点 → 按用户指令先迁移再验证。

- **whale-job 新增 `HttpInvokeJobHandler`**（Bean 名 `httpInvokeJobHandler`）：`handler_param` 为 JSON `{service, method(GET/POST, 缺省 POST), path, body(可选)}`；Nacos `DiscoveryClient` 取首个实例解析基地址，`InternalTokenSupport` 自动附加内网令牌头；响应按 `Result` 解析，业务码非 0 抛 `BizException` 落 `job_log` 失败终态。JSON 解析用自有 `ObjectMapper` 字段，不依赖容器 Bean（规避 Spring Boot 4 装配差异）。
