**3. P0 缺陷修复：雪花 ID 精度丢失（实机 E2E 暴露）**

- 现象：填报页 `/render/{id}` 报「表单不存在或加载失败」。
- 根因：后端 `JacksonConfig` 对 `Long` 走 `ToStringSerializer`（ID 为字符串），前端契约层把 ID 声明为 `number` 并在路由处 `Number(id)`，`2112355156699869186 > 2^53` 被截断为 `2112355156699869200` → 详情请求 404。
- 实测佐证：`GET /form/definition/2112355156699869186 → code=0`；`GET /.../2112355156699869200 → code=404`。
- 修复：契约层新增 `type Id = string`，全部 Long 类 ID 字段与 API 方法签名改为 `Id`；清除 `FormRender.tsx`/`FormDesigner.tsx` 中全部 `Number(id)`、`Number.isFinite`，改为 `id ?? null` / `!== null`。

### 二、变更点

**1. 后端 whale-form（8 改 + 2 新 main + 3 测试）**

- `support/FormDataEngine.java` + `support/impl/JdbcFormDataEngine.java`：新增 `Map<String,String> describeColumns(table)`（`information_schema.COLUMNS`，表名走白名单正则）。
- `support/FormTableDdlGenerator.java`：新增 `columnDef / alterAdd / alterModify / alterDrop / normalizeType / reservedColumns`，`generateFromColumns` 复用 `columnDef`。
- `service/impl/FormPublishServiceImpl.java`：抽 `ensurePublished`（无物理表 → CREATE；已存在 → 与 `information_schema` diff 后 ADD/MODIFY/DROP）；新增 `listMetadataCodes`，并把「元数据仍在（含 `status=0` 停用列）则不下发 DROP」的护栏并入 `applyAlter`；`publishTableDefinition` 与 `publishMetadata` 均走该方法。
- `service/impl/FormTableDefinitionServiceImpl.java`：`update()` 改走 `mergeColumns`（按 `columnCode` 就地更新保留列主键；缺失列先 `assertColumnNotReferenced` 再逻辑删除）。
- `service/FormDataService.java` + `service/impl/FormDataServiceImpl.java`：新增 `export(request, tenantId, format)`（`EXPORT_MAX_ROWS=5000`，解析 `dataJson` 生成导出）。
- `controller/FormDataController.java`：新增 `GET /form/data/export`（`format=csv|xlsx`，`ResponseEntity<byte[]>` + `Content-Disposition`）。
- 新增 `support/FormDataExportSupport.java`（纯 JDK UTF-8 BOM CSV 与最小 OpenXML XLSX）、`vo/FormDataExportVO.java`（`content/filename/contentType`）。
- 测试：`FormTableDdlGeneratorTest`（+ALTER/columnDef/normalizeType/reservedColumns）、`FormPublishServiceImplTest`（+7 个 `publishTableDefinition` 用例与 `shouldNotDropDisabledColumn`）、`FormTableDefinitionServiceImplTest`（+4 个 update 用例：保主键/新增列/被引用拦截/未引用删除）。

**2. 前端 `whale-form-designer`（5 改）**

- `api/http.ts`：新增 `downloadBlob`（原始字节流 + `Content-Disposition` 文件名解析 + 401 续期重放一次）；`api/form.ts`：新增 `ExportFormat` 与 `formDataApi.export`。
- `pages/data/FormDataList.tsx`：新增「导出」`Dropdown.Button`（CSV / Excel）。
- `pages/table/TableDefinitionList.tsx`：列编辑区新增迁移语义 `Alert`；发布成功文案改为「发布成功，物理表结构已同步」。
- `pages/designer/FormDesigner.tsx`：新增历史栈（`past/future` ref + `historyVersion` + 统一 `commit()`）、撤销/重做按钮、`Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z`（输入控件内不劫持）。

**3. 本轮修复的两个真实缺陷**

- **P1（列主键悬空）**：`replaceColumns` 原为「整体逻辑删除 + 重建全部列」→ 列主键全变 → 既有表单视图 `form_field_config.column_meta_id` 悬空（`FormMetadataCompiler.compile` 抛「字段配置关联的列不存在」）。修复：改 `mergeColumns` 按 `columnCode` 就地合并保主键。
- **停用列误删**：列编辑器暴露「状态」选择（`status=0` 停用），发布只取 `status=1` 列 → 会把停用列当作「已删除」下发 `DROP COLUMN`（若被引用则丢数据）。修复：`applyAlter` 增 `metadataCodes` 判定，元数据仍在则不下发 DROP。
