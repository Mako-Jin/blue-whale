- 修复：契约层新增 `type Id = string`，全部 Long 类 ID 字段与 API 方法签名改为 `Id`；清除 `FormRender.tsx`/`FormDesigner.tsx` 中全部 `Number(id)`、`Number.isFinite`，改为 `id ?? null` / `!== null`。

### 二、变更点

**1. 模型层 + 状态机内核 + BPMN 双向（`support/` 新增 23 个 main 文件，纯 Java / 纯 JDK）**

- `ProcessModelParser`：`type=="stateMachine"` → 规范化；`type` 缺失且无 `flows` → **legacy**（原样委托既有 `ProcessNodeParser`，文案「流程定义缺少有效审批节点」逐字节保留）后补齐顺序流转；`type` 缺失但有 `flows` → 规范化（宽容）；其它非空 `type` → `UNKNOWN_DEFINITION_TYPE`。
- `ProcessNodeType`：仅 4 种（`START_EVENT`/`END_EVENT`/`USER_TASK`/`EXCLUSIVE_GATEWAY`），`from(String)` 大小写不敏感、`-`→`_`。
- `ProcessModelValidator`：分层校验（模式判定 → 结构 → 图级），**内容非法不抛异常**；图级校验仅结构无错时执行，legacy 跳过。
- `StateMachine`：`Guard` SPI（`AlwaysGuard`/`DefaultFlowGuard`，条件本轮不参与选路）；超 `MAX_GATEWAY_HOPS=16` 抛 `BizException(400,"网关流转超出上限")`；网关多分支无默认抛 `ProcessModelException(GATEWAY_MULTI_BRANCH_NO_DEFAULT)`。
- `BpmnXmlParser`：映射 `startEvent/endEvent/userTask/exclusiveGateway` + `sequenceFlow`；`assignee` 读**任意前缀**同名属性；网关 `default` → `isDefault`；忽略 DI/documentation/extensionElements；不支持元素抛 `BPMN_UNSUPPORTED_ELEMENT` 并点名元素。

- `BpmnXmlWriter`：对称输出 `assignee` / 网关 `default`，属性转义；往返节点与流转一致。
