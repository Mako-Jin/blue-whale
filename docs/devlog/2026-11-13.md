## 00:19 Wave 6.69 网关路由来源治理硬化（GW-10 Phase 0/1）

- **评审结论落纸**：新增 ADR [gateway-route-source.md](../design/gateway-route-source.md)，纠正三个前提——
  ① 现在 Nacos 不是权威源（38 条基础路由原在 `application.yml`，本轮已迁至独立兜底文件）；
  ② DB 不应接在网关（无 JDBC/Flyway，沿用「控制平面在 auth、网关拉快照」范式）；
  ③ 单路由 `weight` 不能直接生效、`match_tags` 无消费方，Phase 2 只做 `enabled + 生效窗口`。
- **order 解析**：`NacosRouteDefinitionRepository.toRouteDefinition` 读取 `order`（支持负数，缺省 0）；
  非整数视为条目级错误，WARN 后跳过该条，避免静默按 0 排序导致重叠路径命中不可预期。
- **重复 id 整体拒绝**：新增 `RouteDefinitionValidator.validateAll()`（逐条校验 + id 唯一），
  仓库改用批量校验；重复 id 使整份 Nacos 配置不生效并保留上一版，`rejectedCount` +1。
- **兜底路由落盘**：38 条基础路由从 `application.yml` 的 `spring.cloud.gateway.server.webflux.routes`
  迁至 `classpath:gateway-routes-fallback.yaml`，结构与 Nacos 侧 `whale.gateway.dynamic-routes` 完全一致，
  由仓库复用 `convert()` 解析并 `validateAll()` 校验，进程内缓存一次。
  未采用 Spring `routes` 结构的原因：Binder 会把 `- Path=/x/**` 绑定成 `_genkey_0`，
  而校验器只认 `patterns`，整份兜底会被判非法。
- **按 id 合并**：兜底在前、Nacos 动态新增在后，同 id 由 Nacos 覆盖；合并结果再校验一次，
  Nacos 不可用/为空/校验失败时保持已有快照，首次加载使用兜底 —— 基础路由不再依赖双源协调发布。
- **签名纳入 order**：`sameAsCurrent` 内容签名追加 `order`，仅调整优先级也会触发快照替换
  （此前会误判为无变化）。
- **治理端点**：路由摘要新增 `order`，顶层新增 `currentCount` / `previousCount`，保留 `rejectedCount`。
- **测试**：网关全量 **163/163** 通过（`NacosRouteDefinitionRepositoryTest` 23 例：order 解析/非法 order 跳过/
  重复 id 拒绝/仅 order 变化刷新/兜底加载/Nacos 同 id 覆盖兜底/生产兜底文件解析校验）；`RouteDefinitionValidatorTest` 12/12。
- **未做**：38 条路由分批发布到 Nacos（已可分批，同 id 由 Nacos 覆盖，步骤见 ADR §4）；
  DB 覆盖层 Phase 2（等运营开关/时间窗需求触发）。
- **台账**：网关 GW-10 与新版权记录 v1.8 已同步。
