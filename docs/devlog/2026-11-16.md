## whale-file 能力扩展（批次 28：清理 / 回滚 / 找回审计）

- **需求项**：回收站物理清理、版本回滚/删除/找回、文件删除/找回等操作会改变文件可用性与物理
  对象，但此前只留业务日志，没有可追溯的审计记录（谁、何时、对哪个文件、做了什么、结果如何）。
- **决策**：复用 `whale-common` starter 的 `@AuditLog` 切面，不新建审计表与写入通道；
  file 库 `audit_log` 已由 `V2__audit_log.sql` 创建，本次无迁移。
- **完成项**：
  - Web 入口：`FileController#delete/#restore`、`FileBatchController#batchDelete`、
    `FileVersionController#rollback/#delete/#restore` 标注 `@AuditLog`，
    `target_type=file_info`，targetId 取 `#id`（批量删除取 `#request.ids`）；
  - 清理任务：`RecyclePurgeTask#purgeExpired` 标注 `@AuditLog(recordParams=false,
    recordResult=true)`，每次执行留一条运行审计，摘要（`purged=n` / `skipped: ...`）写入 `result_body`；
  - 测试：`FileAuditLogAnnotationTest`（3 项）与 `RecyclePurgeTaskTest` 注解用例（1 项）。
- **已修正问题项**：设计初稿拟为清理任务逐文件写审计；因 file 库 `audit_log` 无本地清理策略、
  逐条写入会随删除量同阶增长，改为「运行级摘要 + 单文件明细留业务日志」。
- **验证**：`mvn -o test`（`whale-service-file`）→ 13 个模块 BUILD SUCCESS，381 项单测零失败
  （本轮新增 4 项），checkstyle 0 violation。
- **待做项**：版本超限清理与孤儿对账的运行审计、审计落库联调（转发开关与 `audit_log` 观察）。
- **上线注意**：file 库无需迁移；未开启 `whale.audit.forward` 时审计落各服务本地 `audit_log`。

## whale-file 能力扩展（批次 29：版本组版本号并发唯一约束）

- **需求项**：`uploadVersion` / `rollback` 以「组内最大版本号 + 1」计算新版本号，并发时可能写入
  同组重复版本，后续按版本号定位（列表、回滚、删除）只能命中其中一条。
- **决策**：用数据库唯一索引兜底，应用层捕获唯一键冲突后重算版本号重试；不做存量版本号
  重排（会破坏历史回滚/下载/审计中的版本引用）。
- **完成项**：
  - 迁移：`V8__file_version_unique.sql` 幂等创建 `uk_parent_version(parent_id, version)`，
    同一条 `ALTER` 移除被覆盖的普通索引 `idx_parent_version`，脚本注释附存量查重 SQL；
  - `db/init.sql` 同步为 `UNIQUE KEY uk_parent_version`；
  - 应用层：`FileInfoServiceImpl#registerVersionWithRetry` 在 `uploadVersion` / `rollback` 共用，
    `DuplicateKeyException` 最多尝试 3 次，耗尽后抛原异常并由既有补偿删除已写对象；
  - 测试：冲突后重试成功、连续冲突补偿删除各 1 项。
- **已修正问题项**：普通索引与唯一索引并存只会增加写入开销（唯一索引以 `parent_id` 为前缀，
  完全覆盖查询），迁移中一并移除；迁移不自动改号，避免历史版本引用失真。
- **验证**：`mvn -o test`（`whale-service-file`）→ 13 个模块 BUILD SUCCESS，383 项单测零失败
  （本轮新增 2 项），checkstyle 0 violation。
- **待做项**：上线前执行查重 SQL；版本超限清理与孤儿对账的运行审计；outbox、分块加密、异步打包下载。
- **上线注意**：目标环境若已有重复版本号，V8 迁移会失败并暴露问题，需先人工处理。
