## whale-job 运维效率：任务批量操作与导入导出（扩展路线图第 7 项）

- **需求项**：批量启停/批量删除、跨环境搬运任务定义与依赖。设计见 `docs/job-batch-import-export.md`。
- **决策**：
  - 批量操作逐条复用单条服务方法（`changeStatus` / `delete`），单条失败只记明细、不整批回滚；
    整体加事务会让一条坏数据把整批回滚，与「批量治理」的使用预期相反。
  - 导出只含可移植字段，排除 `id` / `tenantId` / `failCount`：环境相关标识与运行态失败历史不可搬运。
  - 依赖边以 `{executorApp, jobCode, jobName}` 表达，跨环境 ID 必然不同，用 ID 导出等于不可用。
  - 导入匹配键：`jobCode` 非空用 `executorApp + jobCode`，否则用 `jobName`；冲突策略默认 SKIP，
    非法取值直接 400，避免拼写错误被静默当成 SKIP。
  - 导入的条目校验在服务层逐条执行 Jakarta Bean Validation，不在请求体上加 `@Valid`，
    否则一条坏数据会让整份文件被 400 拒绝。
  - 依赖在任务全部落库后按下游聚合，一次全量替换；新增任务因此可作为同文件内的依赖端点。
- **完成项**：
  - 新增 `POST /job/info/batch-status`、`POST /job/info/batch-delete`、
    `GET /job/info/export?jobGroup=`、`POST /job/info/import`；
  - 新增 `JobBatchService` / `JobBatchServiceImpl` 与 8 个 DTO/VO；
  - 权限与单条接口对齐（`sys:job:edit|delete|list|add`），写操作全部标 `@AuditLog`。
- **验证**：
  - 单测：`mvn -o test` → **137 项零失败**、BUILD SUCCESS、checkstyle 0 violation（新增 13 项）。
  - 起服实测（8082）：导出 TMP 分组 2 个任务 0 条边且不含 `id` / `failCount`；
    SKIP 导入 `skipped=2, dependencyCount=1`，`GET /job/info/{B}/dependencies` 回显上游 A；
    OVERWRITE 导入 `updated=2` 且 `remark` 已覆盖；非法策略返回 400；
    批量启停 `[A,B,999999]` → `successCount=2`、失败明细含 999999；
    批量删除两次 → 首次 `successCount=2`，再次全部「资源不存在」；测试任务已清理。
- **待做项**：管理端批量选择与导入文件上传交互。

## M1 部署加固：内网令牌统一注入

- **需求项**：M1 链上关键调用全部走 `/internal/**`（CRM→ERP、ERP→MES、scene→ERP），令牌不一致时链路会 403 或静默降级。
- **问题**：`docker-compose.services.yml` 只有 auth 与 scene 注入 `WHALE_INTERNAL_TOKEN`。一旦运维在 `.env` 配置令牌，
  ERP/MES/CRM 等服务端的令牌仍为空——dev 下 `InternalTokenFilter` fail-open，所有 `/internal/**` 实际无防护；
  非 dev 下 `InternalTokenGuard` 直接拒绝启动。
- **完成项**：为 compose 中全部 34 个服务（含 profiles）的 `environment` 注入
  `WHALE_INTERNAL_TOKEN: "${WHALE_INTERNAL_TOKEN:-}"`，auth/scene 原有显式项保持不变。
- **决策**：没有把变量放进 `x-common` 的 `environment`——YAML `<<` 是浅合并，服务自带的 `environment` 会整体覆盖锚点，
  实测只有 auth 生效；因此逐服务注入，并用 `docker compose --profile '*' config` 校验全集。
- **验证**：`docker compose --profile '*' config --format json` 解析通过，34/34 服务均注入测试令牌；未配置时为空串，
  与原有 dev fail-open 行为一致。
- **待做项**：生产部署需在 `.env` 显式设置随机 `WHALE_INTERNAL_TOKEN`。
- **已修正问题项**：内网令牌注入覆盖不全。
