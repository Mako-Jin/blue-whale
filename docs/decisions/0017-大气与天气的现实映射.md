# 0017. 大气与天气的现实映射（三维环境 · 第二阶段）

- **状态**：已采纳
- **日期**：2026-10-11
- **决策者**：舰长

## 背景

三维环境应用已经立住了三层地基：多场景切换（ADR-0014）、可操控主人公（ADR-0015）、
WebGL 渲染生命周期（ADR-0013）。但**画面里的"天"一直是假的**：

- 每个场景的太阳是一盏写死的方向光（古建筑 `addSun({ position: [14, 13, 9] })`）；
- 雾色与背景色是同一个写死的 `#342f3d`；
- 没有天空 —— 相机抬头只有一片纯色背景。

这一阶段要补的是：**日出日落、天空盒、云、风雪雨霜**，而且要求是
**现实世界的映射**，不是"把灯挪到一个好看的角度"。

这条要求把所有实现方式逼到同一个分岔口：**"好看"可以调，"对"不能调。**

如果按"手调"做，会得到一堆互相矛盾的数字：黄昏的强度是 1.8 还是 2.4？
夜里的环境光该有多蓝？没有人能回答，因为没有一个量可以作为依据。
所以必须先决定：**谁是自变量，谁是因变量。**

## 决策

### 1. 环境参数是**数据**，大气是**场景的能力** —— 两者必须分开

- `EnvironmentState`（时刻、日期、经纬度、时区、时间流逝倍速）与 `SceneOptions` 同级，
  但**刻意不放进 `SceneOptions`**。
- 天穹、日月主光、云是几何体与材质，做成 `SceneBuild.createAtmosphere?(): SceneAtmosphere | null`
  —— 与 `createControls?()` 同级。

理由有两个方向，缺一不可：

- **朝上**：`SceneOptions` 会被 `sceneOptions(meta)` **随场景重置**（网格开关对丛林没意义）。
  时刻不能这样 —— 切一圈场景回来，天还是那个天。把环境塞进去的话，
  每次切场景都会把时刻悄悄拨回默认值，而那种 bug 没人会当成 bug 报出来。
- **朝下**：天穹属于"这个场景长什么样"。做成舞台的全局设施，每个场景都得写
  `if (不是太空)` 来躲开它 —— 而那种判断迟早会漏一处。

于是**不实现 `createAtmosphere` 的场景天然退出**（室内、太空），零特判。

### 2. 纯内核四层：**物理量可断言，画面是推导出来的**

```
scene/env/solar.ts     年积日 + 经纬度 + 时刻  →  高度角 / 方位角
scene/env/palette.ts   高度角                 →  光、雾、天穹、曝光（一条关键帧曲线）
scene/env/sample.ts    状态                  →  SolarPosition + EnvironmentLook（+ 时间推进、归一化）
scene/atmosphere/rig.ts  画面参数             →  天穹 mesh、灯光、雾（唯一碰 three 的地方）
```

前三层**不碰 three、不碰 DOM**，与 `player/motor.ts` 同一套纪律：可以在无 GPU 环境里逐值断言。
Rig 只做翻译，**不做任何自己的判断** —— 判断一旦分叉到两处，就再也说不清哪个是对的。

太阳位置用 Spencer 1971 的傅里叶近似（赤纬 + 均时差）+ 时角解算。对拍结果：

| 北京（39.90°N, 116.41°E, UTC+8） | 实测（公开天文数据） | 本实现 |
| --- | --- | --- |
| 夏至正午高度角 | 73.5° | 73.2° |
| 冬至正午高度角 | 26.6° | 26.6° |
| 夏至日出 / 日落 | 04:46 / 19:46 | 04:45 / 19:45 |
| 冬至日出 / 日落 | 07:32 / 16:53 | 07:32 / 16:52 |

这些锚点全部写进了 `tests/env.test.ts`。**超出 1° / 5 分钟就是错，而不是"精度不够"** ——
公式或符号一定有一处反了。

### 3. **高度角是唯一的自变量**

`palette.ts` 只吃一个数：太阳高度角（度）。它一个量同时编码了"几点、什么季节、什么纬度"，
所以换到漠河或赤道，同一套曲线照样成立 —— 而"按小时查表"的写法换一个纬度就全废。

关键帧之间**线性插值**，不用指数或样条：曲线要能被打印出来看懂，才能被讨论和修改。
拟合得漂亮但没人敢动的曲线没有价值。

三条锚点是真实的，不是调出来的：

- `-0.833°` 是天文上的日出日落定义（太阳圆面 + 大气折射）；
- `-6°` / `-18°` 是民用暮光与天文暮光的边界；
- 白昼主光强度 3.1、环境光 0.55，与场景此前手调的常数量级一致 ——
  接上环境之后画面不会突然变成另一个样子。

**日落泛红是算出来的**：低角度时直射光穿过的大气路径是正午的几十倍，短波被散射殆尽，
只剩长波。所以 `horizonColor` 在 `3°` 处给 `0xc9703f`（橙红），在 `45°` 处给淡蓝白。

### 4. 雾距给**系数**，背景色**混向**天光

- `look.fogNearScale / fogFarScale` 是乘子，不是绝对距离。各场景的雾距基调差着数量级
  （丛林 `9~46`、写字楼 `46~130`），环境只该说"今天能见度是几成"，
  不该把丛林拉成写字楼那样通透。
- 背景 = `lerp(场景基色, 地平线色, weight)`，权重由 palette 给。
  取"混合"而不是"直接用天光色"：场景基色是每个场景的气质（古建筑紫灰、丛林墨绿），
  天光色是现实。混合之后场景基色在任何时刻都还认得出来。
- **雾色与背景色必须是同一个 `Color` 实例的颜色** —— 两者不一致，
  "远处融进背景"这句话就不成立。

### 5. 夜间主光指向**反日点**（月亮在太阳对面），并且不许贴地

夜间太阳位于地平线以下，若照原方向打光，光会**从地底往上照** —— 比没有光还假。
所以 `night`（`altitude < -4°`，民用暮光之后）时主光方向取反：方位角仍跟着天走
（月亮也东升西落），影子方向在夜里自然翻到另一边。

另有 `MIN_KEY_ELEVATION = 0.09`（约 5°）的硬下限：光贴着地平线时，
阴影正交相机的视锥会退化成一条线 —— 表现是**阴影整片消失且不报错**，
这是"阴影开关坏了"这类误判最常见的来源。

### 6. 动态 IBL：场景提供"纯天穹"，舞台**节流**重烤

黄昏时建筑被染成金色，靠的不是灯，是**环境贴图**。所以 IBL 必须跟着天穹走。

```
场景：createAtmosphere().captureSource() → 一个**只有天穹**的可渲染对象
舞台：pmrem.fromScene(只含天穹的临时场景) → 换到 scene.environment → dispose 旧的
```

三个要点：

- **必须是纯天穹**。把整棵场景图烘进去，建筑会把自己的颜色当环境光反射回来 ——
  于是"环境光照亮建筑"变成"建筑照亮自己"，画面莫名其妙地发亮。
- **且不含太阳直射**：烘焙前把**捕获份**天穹的 `showSunDisc` 关成 0
  （three 官方就是为"生成环境贴图时隐藏太阳圆盘"准备的这个开关）。
  圆盘是 HDR 超亮斑，烘进去会污染环境贴图 —— 但实测它的贡献比预想小：
  PMREM 的宽卷积核把小立体角的圆盘稀释了，把镜面反射拉爆的大头是**天空散射本身
  的 HDR 亮度**（正午天空远亮于兜底的 RoomEnvironment）。所以关圆盘只解决
  "直射污染"；镜面材质的过曝要靠场景对真实 IBL **重标** `environmentIntensity`
  （写字楼 0.85 → 0.45，那个 0.85 是按室内兜底环境标定的）。症状随镜面比例递增
  （古建筑轻、丛林居中、写字楼最重），第一眼很像"材质调错了"，其实是
  "IBL 的亮度基准换了"。另外别用"把 `sunPosition` 压到地平线下"来藏太阳 ——
  那会把散射分布一起改成暮色，两个旋钮各管各的（圆盘归 `showSunDisc`，
  散射归 `sunPosition`）。
- **节流两层**：高度角变化 ≥ 0.021 rad（约 1.2°）**且**距上次 ≥ 320ms。
  单靠阈值挡不住拖滑块（一次拖动能触发几十次卷积，手感发涩）；
  单靠时间又会漏掉"最后一次变化"。
- **每帧补一次检查**（`maybeBakeEnvironment(false)`，代价只是一次比较）。
  不然节流窗口会把最后一次变化挡在门外，而那次之后再没有新事件 ——
  天光就永久停在旧值上。这是"节流 + 事件驱动"组合最经典的漏洞。

渲染器与 PMREM 仍然归舞台（ADR-0013 的约束不变）：`pmrem` 不再"用完即弃"，
它的释放搬到了 `dispose()`。

### 7. 时间流逝由**舞台**推进，界面**读回**

"时间流逝"本质是播放，播放属于帧循环。让 React 以 60Hz `setState` 去驱动它，
等于拿重渲染当节拍器，而且会把"当前时刻"变成两个真相源。

```
App 持有 environment 基准 → stage.setEnvironment()（拨滑块时的"设定"）
舞台每帧 advanceEnvironment(delta) → stage.environment()（流逝时的"当前"）
界面每帧读回，且只在"分钟变化"时才落进 state
```

与小地图读 `interaction()` 是同一个套路：**传读取入口，不传快照**。

**默认暂停（`flow = 0`）**。演示要可复现 —— 画面自己一直走，回头就找不到刚才那一帧了。
这与场景散布用 `createPrng(seed)` 拒绝 `Math.random()` 是同一条思路。

### 8. `SceneMeta` 增加必填的 `climate`

`'outdoor' | 'indoor' | 'space'`。它回答一个单纯但绕不开的问题：
**室外的天气该不该影响这个场景。** 必填的理由和 `camera` 一样：
漏填一个场景就等于让这个问题没有答案，而无论默认取哪个都会在某个场景上变成错的。

`climate: 'outdoor'` 与"实现了大气"是**一一对应**的：三个室外场景（古建筑、丛林、写字楼）
都挂了 `createAtmosphere`，室内与太空则一定不挂。这条对应关系在 `scenes.test.ts` 里双向钉住 ——
新增一个室外场景却忘了挂天穹，会立刻红。

（第一版曾把它写成"只有古建筑有大气"。那是一句**进度**而非契约：别人按本节给其余场景补齐时，
它会认认真真地变红，逼着后人删掉它。契约要能容纳进度往前走。）

### 9. 云：直接用 three 自带 `Sky` 的内置云层

three r186 的 `Sky` 着色器已经内置了 fbm 云（`cloudCoverage / cloudDensity /
cloudScale / cloudSpeed / time`）与太阳圆盘，**以及一套基于大气自身的云光照**
（Beer-powder 自阴影 + Henyey-Greenstein 前向散射的银边）。

于是"云"这件事一期就能落地，而且顺带解决了"风"的第一半：
`time` uniform 随 elapsed 前进，云就被推着走 ——
这一帧的云位置仍只由 `elapsed` 决定，是纯函数。

放弃自写云层的理由是**成本不对称**：自写要一整套噪声、光照、地平线淡出，
而现成的这一套已经与散射模型自洽（云的受光来自天穹本身的辐射）。

### 10. 配套调整：默认取景的俯角必须小于垂直半视角

加了天空却看不见，等于没做。古建筑原来的默认机位俯角约 35°，
而垂直半视角只有 25° —— **地平线落在画面之外**，天空、日出、云全都看不见。

所以把默认机位从 `[0, 9, 24]` 调整为 `[0, 5, 24]`（俯角约 18°）：
画面顶部留出一条天，殿宇仍完整入画，而且从低于屋檐的高度仰视，中式殿宇的体量反而更足。

**这条不是审美偏好，是"加了天穹"的必要配套。**

## 后果

**正面**

- `EnvironmentState` 一变，画面全链路跟着变：天穹颜色、日月方向与色温、环境光、
  雾色雾距、背景色、曝光、环境贴图。**没有一个数字需要手调。**
- 时间滑块从 00:00 拖到 24:00 能看到完整的日出日落；日期滑块能拨出四季差异。
- 纯内核四层全部可单测，含"日出日落对拍天文数据"这类硬锚点（新增 34 条断言）。
- 太空与室内场景零特判地退出了大气系统。
- 动态 IBL 让黄昏的建筑真的被染成金色，而不是"换了一盏灯的颜色"。

**负面 / 代价**

- **每帧多了一次比较 + 潜在的一次卷积**。静止时只多一次比较；拨时刻时最多每 320ms
  一次 PMREM 卷积（比渲染一帧贵得多），这是最实质的开销。
- 多出约 5 个绘制调用（天穹 1、云含在天穹里、日月共用主光、捕获天穹不参与渲染）。
- 天穹有**两份**实例（主天穹 + 捕获天穹），常驻一个 `BoxGeometry` 的显存。
  之所以不"烘的时候移出去、烘完移回来"，是为了避免"天穹暂时不在场景里"的脆弱窗口。
- 云的漂移速度是常量（`WIND_TIME_SCALE = 45`），不是"风速"算出来的 ——
  它还没有接入真正的风向量，属于过渡状态。
- 环境贴图的节流意味着**拖动时刻滑块时，环境反射会滞后最多 320ms** 才跟上。

**后续约束**

- 新增室外场景若要天光，必须实现 `createAtmosphere` 并标 `climate: 'outdoor'`。
- **任何新场景的默认取景都要检查俯角 < 垂直半视角**，否则天穹等于不存在。
- 改 `palette.ts` 的关键帧必须同步 `tests/env.test.ts` 里"亮度单调""日落偏暖"这类
  关系型断言 —— 它们约束的是**物理关系**，不是具体数值。
- 天气（雨、雪、霜）落地时**不要改主光与雾的现有语义**，而是新增一层
  "天气 → 云量 / 降水 / 能见度"的调制，叠在 `EnvironmentLook` 之上。

**未做（二期及以后）**

- 天气状态机与预设（晴 / 多云 / 雨 / 雪 / 雾）与转移概率
- 雨雪的 GPU 粒子（相机周围循环盒）与地面湿反射
- 霜：不是粒子，是地面材质向白偏 —— 需要地面材质支持按温度混色
- 风向量：云速、雨雪倾角、树摆幅度目前都不接风速
- 气温与相态判据（`<0℃` 落雪）
- 夜空星点与月亮圆盘（目前月亮只是"反向的主光 + 更暗的天穹"）
- 丛林的树摆动、写字楼的窗光随昼夜变化
- 场景**固有色光**随昼夜淡出：每个室外场景都留了一盏特征补光（古建筑的地面反射、
  丛林落叶层的绿反弹、写字楼广场的余晖），它们是常量，入夜不会暗下去
- 移动端适配、性能预算
