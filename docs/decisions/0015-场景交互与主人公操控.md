# 0015. 场景交互与主人公操控（古建筑 · 第一阶段）

- **状态**：已采纳
- **日期**：2026-10-10
- **决策者**：舰长

## 背景

古建筑场景进入第一阶段：殿前广场、左上角小地图（含人物视角与指北方向）、
可操控的主人公（上下左右移动、放大缩小视角）、鼠标右键设置行动终点。

这件事牵出三个必须先定的问题：

1. **交互控制放在哪一层** —— 是舞台的全局能力，还是某个场景自己的能力？
2. 相机一直由舞台持有并终身复用（ADR-0013），**镜头怎么跟着人走**而不破坏这条约束？
3. 小地图是 UI，**它的数据从哪来**、走不走 React 状态？

## 决策

### 1. 交互是**场景的能力**，不是舞台的全局能力

`SceneBuild` 增加可选的 `createControls?(context): SceneControls | null`。
只有需要"人在场景里走动"的场景才实现它；其余场景不受影响。

理由：丛林、写字楼、太空不一定要有主人公，"可操控"是**场景的属性**。
做成全局能力的话，所有场景都得面对"我这个场景要不要人物"这种别人的问题。

生命周期全部由舞台管：装载场景时 `createControls()` 造出来、每帧 `update()`、
切场景或销毁时 `dispose()`。**场景自己不碰帧循环** —— 否则每个可操控场景
都要各自维护一套 rAF，迟早漏掉一次取消。

### 2. 相机仍归舞台；控制器只上报焦点，舞台"整体平移"跟过去

`SceneControls.focus()` 返回相机应当对准的世界坐标点。舞台每帧在
`controls.update()` **之前**做这件事：

```
delta = focus - orbit.target
orbit.target += delta
camera.position += delta     ← 关键：相机跟着挪同样的位移
```

**"整体平移"是这条的全部要点。** 只改 `target` 不动相机的话，相机停在原地
转头看新目标 —— 人一走远，镜头里就只剩一个俯视小点。相机与目标一起挪同样的
位移，环绕姿态与距离原样保留，看起来才是"镜头跟着人走"。

这样 ADR-0013 的"相机由舞台持有并终身复用"**没有被破坏**：
控制器从头到尾没有摸过相机的旋转与缩放。

### 3. 左键旋转与滚轮缩放交给 OrbitControls，控制器只借走键盘和右键

"放大缩小视角"就是轨道控制器的滚轮缩放，**不另写一套**。
有控制器的场景 `orbit.enablePan = false`：右键让给"设置行动终点"，
左键旋转与滚轮缩放保留。

这一步基于 OrbitControls 源码确认过：它的 `contextmenu` 处理只做
`preventDefault`，右键平移在 `enablePan === false` 时直接返回 ——
所以右键腾得出来，而且**键盘监听只有显式调 `listenToKeyEvents()` 才会装**，
不会和本控制器的 WASD/方向键打架。

### 4. 移动算法独立成纯内核，不碰 three、不碰 DOM

`scene/player/motor.ts` 是一个纯状态机：输入"意图 + 相机方位 + 帧间隔"，
输出对位置/朝向的推进。包含相机相对位移、目标点行走、最短转向、
边界夹取与"沿穿透最浅的一边"的障碍推出。

理由很实际：转身抖动、到点不判、贴墙原地走 —— 这些 bug 在浏览器里
只能肉眼盯，在纯函数里可以逐帧断言。本 ADR 配套的测试有 20 余条，
全部不需要 WebGL。

### 5. 右键用射线打到**地面平面**，不打到网格

`Raycaster` + `Plane(y=0)`。打到 `GridHelper` 的话，功能会跟着
"地面网格"开关一起失效 —— 开关一关右键就哑了，那是把两个不相干的东西
耦合在了一起。

另外加了一道护栏：画布还没布局（尺寸为 0）时直接返回 `null`，
否则会除出 `NaN` 一路传进内核。

### 6. 小地图自绘 canvas，**不走 React 状态**

小地图每秒要重画 60 次。用 state 驱动等于让整棵组件树跟着重渲染 ——
拿最贵的手段做最便宜的事。这里用 `requestAnimationFrame` 直接画，
React 只负责挂载与卸载。

数据通道同样绕开 React：舞台暴露 `interaction()`（当前场景无交互时返回
`null`），`SceneView` 在舞台就绪/销毁时通过 `onReady` 回调把它交给 App，
小地图每帧自己去读。**没有任何订阅、没有任何 setState**。

### 7. 小地图正北朝上，指北针是静态标记

地图**不随镜头旋转**，因此"哪边是北"有一个永远不变的答案 —— 正上方。
指北针做成静态的 `N` 徽标，而不是跟着镜头跑的指针。

人物朝向与相机朝向**画成两个独立的东西**：朝向是箭头、
相机视野是扇形（半透明，半径随滚轮缩放变化）。混用一个指示器的话，
"人朝哪走"和"镜头看哪"就说不清了。

坐标约定（`player/motor.ts` 与 `scene/minimap.ts` 共用）：
世界 +X 向右（东）、+Z 向下（南）、**-Z 向上（北）**，角度 0 表示朝 +Z、
方向向量 `(sin a, cos a)`。因为方向向量在两个坐标系里形式相同，
世界 → 地图**不需要任何角度补偿** —— 少一处补偿就少一处画反的机会。

### 8. 小地图地物与碰撞矩形**同源**

可行走范围、不可通行矩形由场景声明一次，同时喂给移动内核与小地图。
挡人的东西必须也是地图上画出来的东西 —— 两份数据早晚不同步，
而"地图上没有、却撞上去了"是最让人困惑的一类 bug。

### 9. 只挡殿宇与台阶，不引物理引擎

这一阶段的诉求是"能走、不会穿墙"，不是碰撞仿真。
障碍就是两块轴对齐矩形（台基、台阶），推出策略是沿穿透最浅的一边弹出去。
物理引擎（及其调参成本）等有真实需求再引。

## 后果

**正面**

- 新增可操控场景 = 实现 `createControls` + 声明可行走范围与障碍，舞台零改动
- 移动算法有逐帧断言；"按上往后走"这类方向符号错误被测试与端到端脚本同时钉住
- 小地图与 WebGL 完全解耦（纯 2D canvas），投影与几何全部可单测
- 无交互场景（丛林/写字楼/太空/基线）行为零变化，小地图自动隐藏

**负面 / 代价**

- `SceneBuild` 契约变大了（多一个可选方法 + 三个快照类型）
- 交互快照每帧新建对象：小地图 60 次/秒的读取频率下 GC 压力可接受，
  但**不要**把这个快照再喂给 React 状态
- 相机跟随是"硬跟随"（无延迟、无弹簧），手感偏机械 —— 要更顺滑需要加阻尼，
  而阻尼会破坏"逐帧确定性"，暂时不做

## 明确未做

- **寻路**：终点直线过不去时直接放弃（清掉终点），
  不绕障碍走 —— 绕行需要 A* 或导航网格，等场景复杂到直路经常被挡再做
- **移动动画**：人物没有走路摆动，是匀速平移；造型深化时一起做
- **遮挡与精度**：碰撞用的是矩形包络，斗拱、台阶侧面都不参与
- **小地图交互**：不能拖动、缩放、点图定位；只读
- **移动端**：虚拟摇杆与触屏没做，当前只支持键鼠

滚轮断言相机距离变化、右键断言设点与自动收敛、
小地图断言指北标记与人物箭头像素、切场景断言小地图隐藏、浏览器侧零报错。
