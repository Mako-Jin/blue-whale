# 0040. 契约清单的一致性守卫

- **状态**：已采纳
- **日期**：2026-10-13
- **决策者**：舰长

## 背景

`0039` 立了"**活文档不写会变的计数**"，判据是**它会不会因为一次普通提交而变**。
同一篇的「未覆盖」第 1 条把唯一的例外指明了：

> `docs/api/README.md` 写 43 / 67 / 100 —— **并不豁免于决策 1**（新增一个接口就是一次普通提交），
> 它与用例数的**唯一**区别是**有权威源**（`docs/api/openapi.json`）⇒ 正解是加一个零前置守卫；
> **在守卫存在之前，它们与那 5 处漂移没有本质区别。** 加守卫是独立一轮。

本轮就是那一轮。

### 要守的不只是那三个数

三个总数是**最容易发现**的部分：它旁边就有对照（汇总表的接口数之和、后端模块数），
而且写在一句话里、改动时绕不过去。真正危险的是**逐条清单**：

- `docs/api/README.md` §一 逐域列出了**每一条** `方法 + 路径`，共 67 行；
- 后端加一个接口、文档**同时**少一行时，总分表与清单**自洽地错** —— 两边都"看起来对"；
- 而少一行在满屏表格里，与"这个域本来就这么几个接口"**长得一模一样**。

所以这个检查和 `0039` 处置的那张 `web/README.md` §七 表要防的**不是同一类错**：
那张表至少有两个数字互相打脸（485 vs 549），而这里必须拿**契约**去比对 ——
自己跟自己比是比不出东西的。

### 权威源的性质（决定了守卫能做什么、不能做什么）

`docs/api/openapi.json` 是从**运行中的应用**导出的（`0006`），它入库、和代码同一次提交。
于是它可以被一个**零前置**的脚本读取（不连网、不起服务、不构建）——
这一点很关键：它决定了守卫能挂进 CI 的 `guards` job，而不是必须挂在 `server` job 之后。

反过来也划出了它的边界：**它只能证明"文档与契约一致"，不能证明"契约与代码一致"**。
契约落后于代码时，两边读到的都是同一份旧文件。

## 决策

1. **新增 `scripts/verify-api-contract.mjs`**，以 `docs/api/openapi.json` 为权威源，
   逐条核对 `docs/api/README.md` §一。零前置条件，失败非零退出 ——
   挂进 `.github/workflows/ci.yml` 的 `guards` job（与 `verify-nginx-config.mjs` /
   `verify-docs-index.mjs` 同层；`0036` 决策 1 的"能自动判定的一律自动判定"）。

2. **查八个方面**（最后输出是 11 条断言行 —— 总览句那三个数各自单独报出，便于一眼定位），
   覆盖这一节的每一处"会变的数"：

   | 查什么 | 这一项防的错 |
   | --- | --- |
   | 总览句的 路径 / 接口 / 模型 三个数 | 加删接口后只改了正文、没改总览 |
   | 每条明细行都归属到某个 `### 域名（模块名）` 小节 | 改了小节的标题写法 ⇒ 该节的行会从**清单比对与按模块汇总里同时消失**（一处静默通过的孔，实现时抓出来的） |
   | 明细表的 `方法 + 路径` 与契约**双向**相等 | 新增接口未登记；删了接口文档没跟；路径或方法改了 |
   | 明细表内无重复行 | 复制粘贴多一行，所有计数同时偏 |
   | 汇总表接口数之和 = 契约接口数 | 只改明细、忘改汇总（`0039` 里那张 §七 表正是这一类） |
   | 每个模块的汇总数 = 该模块的明细行数 | 同上，而且要按模块定位到"是谁漏了" |
   | 汇总行写了分项时，分项之和 = 该行自己写的数 | 汇总行内部自相矛盾 |
   | 汇总表的模块名在 `server/` 下真有 `pom.xml` | 模块改名 / 名字写错 |

   注：`sts-server-auth` 在文档里跨两节（权限域 + 组织域），按**模块名**归拢后相加 ——
   这正是它必须是 43 + 11 = 54 而不是两行各写一个数的原因。

3. **解析不出来 = 失败**（硬规则）。这个脚本靠正则读 Markdown，标题措辞、表格列顺序一变就匹配不到；
   那时若"匹配不到就跳过"，它会**在什么都没查的情况下报通过**。
   那是**又一个空转的检查，比没有检查更坏**（它让人以为有东西在守）。
   所以取不到总览句 / 汇总表 / 明细表任一处，都直接非零退出并指出**期望的形态**。
   宁可假红，不可假绿。

4. **只核清单，不核文案。** `@Operation` 的描述、字段说明是给人读的散文，判不了对错；
   契约里改了描述而文档没跟，**不在本脚本射程内**（那是 `0006` 那条流程与 review 的事）。

5. **模型只核总数，不核名字。** `docs/api/README.md` 的「关键数据模型」表是**精选**
   （62 个名字 vs 契约 100 个 schema），而且里面混着 `AuditLogQuery` / `OrganizationQuery` /
   `OrgMemberQuery` / `UserGroupQuery` / `UserGroupMemberQuery` / `AuditResult` 这六个
   **被 Springdoc 摊平成查询参数、压根不是 schema** 的名字。要逐个判就得维护一张白名单，
   而**会误报的检查终将被关掉**（`0036` 决策 5 的理由）。⇒ 只核 `100 = components.schemas 条目数`。

6. **§一 的计数保留**（不删）。这是 `0039` 决策 1 的**有据例外**：
   按决策 5 的判据"有没有权威源"，有 ⇒ **钉住它，而不是删掉它**。
   这一步正是 `0039` 的「后续约束」末条写的"有权威源 → 加一个零前置守卫去核对"。

## 后果

**正面**

- 这一类错第一次有了机器兜底：**后端加接口 → 清单没跟 → 推送就红**。
  此前它只能靠"改接口的人顺手想起来"，而那正是 `0039` 已经证伪过的办法
  （"最近一次改动顺手核过的地方就对、没人再看第二眼的地方就漂"）。
- 它零前置，因此跑在最便宜的 job 里、每次都跑、不需要任何服务。
- **它不是空转**：写完之后用 11 个扰动逐个验过 ——
  删一条明细行 / 把某个模块的汇总数改错 / 改总览句的三个数 / 把总览句整句删掉 /
  把模块名写错 / 往明细表塞一条契约里没有的接口 / 把一条接口的方法从 `GET` 改成 `POST` /
  重复列一行 / 改汇总行的分项之和 / 把 `### 域名（模块名）` 的模块名去掉。
  **11 个全部非零退出，且各自报出的正是对应的那一项。**
  最后一个（去掉小节标题里的模块名）是**实现过程中抓出来的一个真孔**：
  当时明细行只在"已知归属模块"时才被收集，于是归属不明的行会**从清单比对与按模块汇总里同时消失** ——
  两头都看不见它。修法是把这类行也收进来、再单独判一次"每条明细行都归属到某个小节"。

**代价 / 负面**

- **它读的是入库的契约，所以"后端接口改了、忘了重新导出契约"它抓不到** ——
  那种情况下契约与清单一起旧，两边一致。那是 `docs/api/README.md` §二
  那三步流程的责任；要把它也自动化，得在流水线里构建并启动一次应用（独立一轮，见"未覆盖"）。
- **改版式会假红。** 改 `§一` 的小节标题措辞或表格列顺序，脚本会报"解析不出来"。
  这是决策 3 换来的：代价是改版式的人要先看一眼这个脚本，收益是不会出现空转。
- 又多了一处"必须保持绿"的东西；它与 `docs/api/README.md` §一的**结构**之间存在一处
  人为维护的耦合（脚本文档里已写明该改哪里）。

**后续约束**

- 改 `docs/api/README.md` §一的**结构**（`## 一、` 标题措辞、`### 域名（模块名）` 的写法、
  表格列顺序、汇总表第二列是模块名）时，**同一次提交**改 `scripts/verify-api-contract.mjs`。
- 新增 / 删除 / 改名后端接口时，按 §二的流程走完"导出契约 → 生成类型 → 改清单"，一次提交。
- **不要**把它当作"契约是对的"的证明：它守的是文档与契约一致，契约本身对不对只能看后端。

## 本决策未覆盖

1. **契约本身是否跟上了代码**没有守卫。`openapi.json` 落后时本脚本两边都读到旧值、报通过。
   可查的做法是在 CI 里构建并启动一次应用重新导出、与入库的做 diff ——
   那是"加一条更贵的检查"，与 `0036` 决策 2 划的边界相邻，**不在本轮**。
2. `web/packages/common-api/src/generated/schema.d.ts` 与 `openapi.json` 是否同步
   （生成物有没有跟上契约）没有守卫。`0006` 把生成物入库就是为了让它在 review 里显形，
   机器兜底尚无。
3. `docs/api/README.md` §五「待补充」里那些**历史进度句**（"已补齐到 20 条路径"这类）
   刻意不在射程内 —— 它们与 ADR 同性质，记的是**当次进度**而非"当前清单"。
   若日后发现它会误导，处置是**把它改写成不带计数的叙述**，不是给守卫加白名单。
4. `web/pnpm-workspace.yaml` 的 `elemental/*` 悬空 glob 仍待定（`0037` / `0039` 均未表态）。
