# 0047 · 登出的两条语义，与「退出所有设备」

- 状态：已采纳
- 日期：2026-10-14
- 相关：`0043`（自助改密的入口与审计）、`0044`（前端改密入口）、`0045`（口令有效期）、`0046`（凭据变更即撤销会话）、`0018`（权限在微前端中的归属）、`0006`（契约由代码导出）

## 背景

`0046`「未覆盖」里记着一条：

> **「退出所有设备」没有独立入口**（只有登出不传刷新令牌时才是全部撤销）。有了它，`SessionRevoker` 就是它的实现 —— 但那条接口还需要一个权限码与一句文案，且要回答"撤销别人所有会话"的授权边界，不该顺手塞进这里。

那句话里有**一个前提先被推翻**：「需要一个权限码」。它不该有 —— 判据与 `/api/auth/password` 完全相同（能登录就该能踢掉自己的会话），理由写在决策 3。

而真正的问题不是"缺一条接口"：**能力早就在了，它只是没有名字。** 这一篇要说清"没有名字"为什么会出事，以及为什么修法不是"加一条新接口"而是"把那一条拆开"。

### 一、现状：两条语义共用一条路径，靠"请求体在不在"区分

`AuthService#logout` 的原文是这样的：

```java
if (request != null && request.getRefreshToken() != null && !request.getRefreshToken().isBlank()) {
    ...撤销那一个...
    return;
}
Long userId = AuthContextHolder.currentUserId();
if (userId != null) {
    sessionRevoker.revokeAll(userId, now);
}
```

写下那个 `if` 的人是在**防**"不传"。而"不传"恰好是另一件事：撤销该用户的**全部**刷新令牌。于是同一段代码里躺着两个动作，区分它们的不是任何写着意图的东西，而是**一个字段在不在**。

拆开看，这件事有四个后果，最后一个才是这一篇的起点。

**1.「退出所有设备」是个没有名字的能力。** 能表达它的唯一方式是"少传一个字段"。而**正当场景恰恰表达不了**：一个手上正握着刷新令牌、又想把别的设备一起踢掉的客户端，传令牌就是单会话撤销、不传就是全部 —— 它没有第三种写法。一个能力没有名字，就没办法被界面引用、被审计谈论、被测试点名 —— 本轮的 `LogoutApiTest` 之前，这条路径**一条用例都没有**（`grep -rn "logout" --include=*.java server/` 只命中 main 代码）。

**2. 危险的那个是省略的默认值。** 发一个 `{}`、或者干脆忘了带请求体，得到的不是"参数缺失"，而是该账号**所有设备被踢下线**。默认值会被任何一次疏忽取到 —— 而这里默认值取的恰好是更重的那个后果。

**3. 未认证时它"什么也没做，却返回成功"。** 拿不到 `currentUserId` 就跳过撤销，然后照样 `R.ok()`。一句"说做了、其实没做"的回复。它在最需要它的时候最坏：用户怀疑账号被人登着，点了「退出所有设备」，看到成功，而别人的会话还开着 —— 与 `0045` 那条"文案指向一个用户做不到的动作"是同一类问题的两个方向。

**4. 被接口逼出来的防御性代码，是最诚实的证据。** 前端 `channel.ts` 的登出写着：

```ts
if (refreshToken) await authApi.logout({ refreshToken });
```

这不是"顺手加个判断"。它是**一个工程师遇到"省略有语义"时的处置** —— 因为不这么写，"本地没有令牌"这条兜底路径就会变成一次全设备踢出。一条接口能把调用方逼到先自查参数，说明它自己没把两种意图分开。本轮的改动之一就是让这个 `if` 回到它本来的含义（"没有东西要撤就别撤"），而不是兼职防一个危险默认值。

### 二、判据：省略一旦有语义，它就该被拿掉

`0046` 的判据讲的是"两个调用方的取值不同才是调用方的语义"。这一篇是它更前面的一层，问的是**参数本身**：

> **一个动作，如果"省略它"会得到更重的后果，那它不是可省略的 —— 它该有名字。**

对照着看，`logout` 的请求体从来就不是"可选项"，它是那次动作的**主语**："撤哪一个会话"。省掉主语之后剩下的不是"随便撤一个"，而是另一个动作（"撤全部"）—— 那就说明有两条路被叠成了一条。

还有一条更朴素的依据：**撤销一个会话与撤销全部会话，是两个不同的动作。** 它们的后果、可逆性、需要的确认步数都不一样（一个点一下就走，一个必须问一句）。两个不同动作共用一条路径，与同一个动作被复制成两处实现（`0046`）是并列的两种错。

## 决策

### 1. `POST /api/auth/logout` 的请求体改为**必填**，语义收窄为"撤请求体里指明的**那一个**会话"

`@RequestBody(required = false)` 改成 `@Valid @RequestBody`，`RefreshRequest` 上那个 `@NotBlank` 从此刻起**真的开始拦东西**（此前它形同虚设：不带请求体走的是另一条分支，绕过校验）。

顺带一个结论：它**不再需要任何身份**。要撤的那一个会话由请求体自己指明了，因此不再读 `AuthContextHolder`。

### 2. 新增 `POST /api/auth/logout-all`：撤**当前用户**的全部刷新令牌（含本次会话）

无请求体；`AuthService#logoutAll` 用 `AuthContextHolder.require()` 取当前用户。实现只有一句 `sessionRevoker.revokeAll(...)` —— `SessionRevoker` 在 `0046` 就已经是"作废令牌的唯一实现"，本轮它是被接上，不是被新建。

### 3. 它**不需要权限码**（推翻 `0046` 那句预设）

判据与 `/api/auth/password` 是同一条：**能登录就该能踢掉自己的会话**。挂上权限码的后果很具体 —— 一个没被授权的用户**永远清不掉自己名下那些会话**，而这恰恰是他在怀疑"账号正被别人登着"时唯一能自救的动作（此刻管理员未必在，也可能正是他要防的人）。

作用域由上下文定死，且**不接受任何传入参数** —— 因此不存在"拿它去撤别人"的写法（"撤销他人会话"是另一件事，见决策 6）。

### 4. 未认证时**明确拒绝**（`40104`），而不是静默成功

"我不知道你是谁"没法被理解成"已经帮你退出了"。这一条是决策 1 的必要补集：拆开之后那条"什么都不做却返回 ok"的兜底分支也随之消失 —— 拒绝比静默准确。

### 5. **不记审计**，判据沿用 `AuthAuditActions` 那句"事后要不要问"

登录 / 登出**不记**是因为高频（逐条记会把审计表灌满，那是应用日志与风控的活）；凭据变更**记**是因为"这个口令是什么时候换掉的"一条记录就能定住整条时间线。

会话撤销两者都不是：它不改变任何凭据，且**对象只有操作者自己**。对照 `/api/auth/password`（同为"自己对自己"，但它记）—— 差别正在于后者是凭据变更。

同时它记一条 `log.info`（低频、且用户本人无法"撤回"这次踢出，排查"我为什么被登出了"时它是唯一线索）。

### 6. 「撤销**别人**的所有会话」不是这条接口的扩展，是**另一条**接口

它是管理动作，要三样这条接口都不需要的东西：权限码、数据范围、以及它自己的审计动作。当前"踢别人"已经由两个动作覆盖：

- **停用账号** —— 续期时读得到 `status`（`AuthService#refresh` 已经在拦），且它是**持续状态**不是一次性动作；
- **重置口令** —— 从 `0046` 起撤销该账号全部刷新令牌。

要不要再加第三条"不换口令、只踢人"，得连同"管理员能不能踢到别的租户 / 别的部门的人"一起回答（数据范围）。本轮不做，判据留在这里。

### 7. 前端的失败处理与登出**刻意相反**

`AuthChannel.logoutAll` 失败时**抛出**、且**不清本地会话**；`logout` 失败时吞掉、照样清本地。判据是"本地清理能不能达成这次动作的意图"：

- 登出的意图是"**我这一台**下线" —— 清掉本地就达成了，服务端那次撤销失败只意味着"那个令牌还留在库里"，用户感知不到差别；
- 退出所有设备的意图是"**别处也要**下线" —— 清本地恰恰达不成它。吞掉失败再清本地，用户会带着"我已经把别人踢了"的错觉回到登录页，而别的设备还好端端地开着。**一次静默的安全失败，且恰好发生在他最需要它成功的时候。**

两个方法在 `try/catch/finally` 上长得完全不一样，那不是不一致。

### 8. 界面入口：基座顶栏、与改密同处、**不自动弹**、点开**先确认**

落点与 `0044` 的判据相同（会话级动作、不依赖任何菜单码、必须在基座）。

步数不同，因为**后果落在谁身上不同**：改密踢的是自己，用户当场感知；退出所有设备踢的是**别的设备上那些会话**，用户看不见，而那边的人可能正在填一张表单。所以它必须先问一句，且要把后果写在动作之前 —— 包括"别的设备正在打开的页面不会立刻掉线，会在下一次请求时被送回登录页"（不说这句，用户会以为没生效而重复点）。

与改密另一处不同：它**不自动弹**。改密有"该做还没做"这个状态（`mustChangePassword`），而它只是一次用户主动发起的动作 —— 自动弹它等于替用户做一个影响到别的设备的决定。

## 顺带回答 `0046` 留的两个问题

`0046`「未覆盖」还写着：改用户名、改绑邮箱 / 手机"两条都该各自回答一次'要不要清会话'，而不是照着这里套"。核过之后，两条的答案**都不是"照着清一遍"**：

### 改用户名：不该清会话，但它有另一个后果

用户名是**登录标识**，不是会话有效性的依据：会话的有效性由 `userId` + `jti` 决定（`AuthTokenFilter` 只做密码学校验、不查库），改名不会让任何令牌失效。

真正的后果在别处：**访问令牌里的 `username` 会变成旧的**（`JwtCodec` 把用户名签进载荷，`AuthTokenFilter` 直接把它放进上下文，界面用它显示"当前身份"）。它最长在一个令牌有效期（默认 2 小时）后自然消解。

所以这一问的正确落点不是"要不要清会话"，而是那个功能自己回答"要不要让旧令牌立刻失效" —— 而它**当前连改名都不允许**（`UserService#update` 刻意排除 username 与 tenantId，理由是"两者变更都应是独立操作"）。

### 改绑邮箱 / 手机：要撤的对象不是会话

`0046` 把它们称作"同样是身份凭据"，这一点对；但**它们不是登录凭据** —— 邮箱 / 手机当前只参与唯一性校验与展示，`login` 只按 username + 口令。因此换绑**不改变任何现有会话的有效性**，按判据（撤销用在"无法从当前状态推出来"的变化上）它不该清会话。

真正该撤的是**另一个对象**：换绑邮箱之后，"旧邮箱上那些还没被用掉的找回凭证"必须失效 —— 这跟"口令泄露要撤会话"是同一动机、不同对象。这正是 `0046` 说的"不照着这里套"：

> 口令泄露要撤的是**攻击者手上的令牌**；邮箱被换掉要撤的是**发往旧地址的那些链接 / 验证码**。

而当前仓里没有找回通道（`0045` 记着「忘记口令」未做），所以这条**现在无从落地**，但它是那条通道的设计前提之一：**它必须让待处理的凭证可以被撤销**，否则"换绑"只是一个界面上的动作。

顺带核出一条真问题：**换绑邮箱这件事在审计里与"改了个昵称"长得一样。** `UserService#update` 只挂 `auth.user.update`，而审计表（`AuditLogEntity`）**没有任何记录"改了哪个字段"的列** —— 查得到"某人在某时改过这个用户"，查不出改的是邮箱。这不是本轮的范围（它要回答"哪些字段的变更值得一个独立动作标识"），但它是 `0043` 那条"`auth.user.reset_password` 与 `auth.user.update` 必须分开"的同一个问题，只是还没被问到。

## 后果

- **`POST /api/auth/logout` 的行为变化是破坏性的**：不带请求体从"撤全部 + 200"变成"`40000` 请求参数错误"。这个代价必须付，而且很小 —— 唯一在用的客户端（`channel.ts`）本来就不走那条路，而它不走的原因正是那条路危险。
- 契约与生成物跟着变：`docs/api/openapi.json` 里 `logout` 的 `requestBody.required` 变成 `true`、新增 `/api/auth/logout-all`；`web` 的生成物随之重出。`AuthLogoutRequest` 因此回到最普通的 `BodyOf<LogoutOp>` —— 它此前要"从 `requestBody` 上手工取模型"，**正是被那个可选性逼出来的形状**（一个类型定义被业务语义逼变形，是可读的信号）。
- 访问令牌的残留（最长 2 小时）没有变，也没有掩饰：**别的设备上正在打开的页面不会立刻掉线**。这句写进了确认对话框。
- 四个真机脚本的登出选择器从 `.basic-layout__action:last-of-type` 换成 `[data-testid="sign-out"]`。前者是一条**位置假设**（"登出恰好是顶栏最后一个按钮"），而本轮正好往顶栏加了按钮 —— 位置选择器会在加按钮时点到别的元素，再报一个与真正原因无关的错。
- 那条"未认证则静默成功"的分支连同它的 `if` 一起消失：`logout` 只剩一段 try/catch，`logoutAll` 只剩一句 `require()` + 一次撤销。

## 未覆盖

- **管理侧的"踢掉某个人的会话"**（决策 6）。要做就得连着数据范围一起定，本轮故意不做。
- **`SessionRevoker.revokeAll` 的返回值仍无人消费**（`0046` 已记）。加一句"已退出 N 台设备"的提示需要 API 返回那个数字，而那个数字既不影响任何分支、也无法在客户端被验证 —— 为一句提示扩契约不划算。
- **多标签页不同步**：在标签页 A 点「退出所有设备」，标签页 B **不会**立刻掉线，要等它下一次请求。`0018` 已把多标签页同步列为未做，本轮没有改变它 —— 但用户对"退出所有设备"的期待会更高一格（他会以为所有窗口都该立刻变），这条比在登出场景下更值得做。
- **子应用独立运行时的入口**：与 `0044` / `0045` 同样的理由 —— 那些形态连登出都没有。
- **会话列表**（"我在哪些设备上登着"）：本轮的对话框只能说"所有设备"，因为接口只能撤、不能列。要列就得让前端展示 IP / UA，那是一次独立的决定（以及一次隐私上的取舍）。
- **审计里"改了哪个字段"**（见上文「改绑邮箱 / 手机」那一节末尾）。它需要先回答"哪些字段的变更值得一个独立动作标识"，本轮只记下问题。
