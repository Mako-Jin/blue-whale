# 0037. 全树格式检查进流水线

- **状态**：已采纳
- **日期**：2026-10-13
- **决策者**：舰长

## 背景

`0036` 立 CI 骨架时，"格式"这一层没进去 —— 当时的理由是"提交钩子里已经有 Prettier 了"。
**本轮把这句话验伪了。**

`pre-commit` → `lint-staged` 的检查有两处**结构性**盲区。它们不是"配置写错了"，
而是"机制本身就看不到"：

| 盲区 | 表现 |
| --- | --- |
| ① 只处理**本次 `git add` 的文件** | 一个文件从建立起就没被单独碰过，它就永远不会被格式化。`0034` / `0035` 那轮已经在 `platform-environment` 上撞过一次（494 行 diff 里 450 行是格式漂移），当时的处置是"定期全仓还债" —— **"定期"意味着靠人记得** |
| ② glob 列表里**没有 `*.html`** | 前端有 3 个 `index.html`（`common-tools/playground`、`platform-admin`、`platform-event-console`）从建立起**从未被格式化过**，而且**永远不会有** —— 钩子根本不会看它们 |

两处叠加的结果是一件很本仓的事：**没有任何人做错什么，格式欠账就自己长出来了**，
并且只在"有人恰好全仓跑一次 Prettier"时才现形。

`pnpm format:check`（= 在 `web/` 下 `prettier --check .`）正是那个"全仓跑一次"。
本轮实测它是**红的**，红的正是那 3 个 html —— 规模很小（**3 文件 / 9 insertions / 7 deletions**，
纯换行与属性折行，无内容变化），但**只要不进流水线，它就会再次长回来**。

## 决策

**把 `pnpm format:check` 加进 `web` job 的静态层**（排在 Stylelint 之后、类型检查之前），
并且**先把欠账还清再开闸**：

1. `lint-staged` 补 `"*.html": ["prettier --write"]` —— 不补的话，开闸等于永久红。
2. `prettier --write` 那 3 个 html。
3. CI 加一步 `pnpm format:check`。

**覆盖范围是前端工作区整棵树**（`format:check` 在 `web/` 下执行）。仓库根的
`docs/` / `server/` / `scripts/` 不在其中 —— 那边的东西压根不被 `lint-staged` 碰，
欠账"改了也不炸"，属于 `0036` 已写明的边界，本决策不改变它。

**为什么放在构建之前**：格式问题不该伪装成构建失败。静态层内部按
"越便宜越靠前"排：ESLint → Stylelint → 格式 → 类型 → 单测 → 构建。

## 后果

**正面**

- 格式从"靠人记得"变成"机器必过"，且 `lint-staged` 的两个盲区**在同一棵树上同时**被覆盖：
  钩子管"这次改的"，流水线管"整棵树"。
- 那 3 个 html 的漂移是这条检查**第一次**就抓到的东西 —— 它不是空开关。
- 本地能精确复现（同一条命令、同一个 cwd），不存在"本地绿、CI 红"的落差。

**负面 / 代价**

- **任何未格式化的文件会直接挡住合并**。这是有意的代价：一次 `pnpm format` 就解决，
  但要接受"开发者得记得跑"。
- 它与 `lint-staged` 的 glob 列表**必须同步**：以后往钩子加新的文件类型时，两边都要看一遍。
  这是一处**人为维护的一致性**，本决策**没有**为它加守卫 —— 判不出"该不该有某类文件"，
  加了只会误报（**会误报的检查终将被关掉**，同 `0036` 决策 5 的理由）。
- 又多了一处"必须保持绿"的东西；它不解决 `web/` 之外（根 `docs/` 等）的欠账。

**后续约束**

- **改了 `lint-staged` 的 glob，就要想一遍 `format:check` 会不会因此红**（反向也成立）。
- 新增前端文件类型（例如 `*.vue`）时，`lint-staged` 与 `.prettierignore` 两处都要过一遍。
- **真机层仍然不在必过项里** —— 本决策不改变 `0036` 决策 2。

## 顺带订正的两处

本决策的起因是"核查还有哪些校验本该进流水线却没进"（结论：**没有漏的** ——
12 个 `verify-*.mjs` 里 3 个零前置的都在 CI、9 个真机脚本都确实要真实浏览器）。
核查过程中顺带抓到两处**名不副实**，一并订正：

1. **`0036` 正文写的"八个浏览器脚本"是错的，实为九个。** 数法是"脚本里有没有
   Chrome / CDP / headless 痕迹"，逐个核过：`verify-admin-permissions` · `verify-atmosphere` ·
   `verify-audit-pipeline` · `verify-menu-permissions` · `verify-micro-frontend` ·
   `verify-player-controls` · `verify-portal-auth` · `verify-scene-switching` ·
   `verify-standalone-dev-login`；零痕迹的三个是 `verify-bundle-secrets`（要产物）、
   `verify-docs-index`、`verify-nginx-config`。**这类计数是会变的值**（加一个脚本就过期），
   故活文档（`AGENTS.md` / `CONTRIBUTING.md` / `scripts/README.md`）里以
   `scripts/README.md` 的**「前置条件」列**为唯一权威清单。
   顺带：`0036` 曾把后端用例数记成 174，同轮已订正为 **180**。

2. **`turbo.json` 给 `build` 声明 `outputs: ["dist/**"]`，而 `common-api` 的 `build` 是
   `tsc --noEmit`** —— 它**不产出任何文件**（该包在工作区内被**源码引用**：`exports`
   指向 `src/*.ts`）。于是每次真正执行构建都打一行
   `WARNING no output files found for task common-api#build`。
   实测确认**只有这一个任务**告警（`turbo run build --force`：8 successful / 0 cached / 1 warning）。
   处置是给该任务单独声明 `"outputs": []`（**承认它没有产物**），
   **不是删掉那个脚本** —— 删掉会让 `pnpm build` 不再覆盖 `common-api` 的类型检查，
   那是一次**静默的覆盖缩减**，与本仓反复记过的那类缺陷同形。

## 本决策未覆盖

- `lint-staged` glob 与 `format:check` 的一致性**没有守卫**（理由见"代价"）。
- 仓库根 `docs/` / `server/` / `scripts/` 的格式**不在任何检查里**（`0036` 的边界）。
- `web/pnpm-workspace.yaml` 里的 `elemental/*` 是**指向不存在目录**的 workspace glob
  （`web/elemental/` 从未建立，`README.md` 的结构图把它标成"通用元素（预留）"）。
  它是"声明了但还没有"，与 `0036` 决策 6 里那个**永远装不进内容**的 `infra/ci/` 不同类：
  留着没有害处、也自洽。**是否保留待定**，不在此处单方面决定。
