# M1 压测基线（P0 验收口径）

> 立项：2026-11-19 ｜ 依据：[M1 制造链闭环执行计划](../plans/2026-11-19-m1-manufacturing-chain-closure.md) M-D
> 状态：脚本与口径已落地；**基线数据待完整环境执行后回填**（本机未同时起服 gateway/auth/erp/mes）。

## 一、口径

| 项 | 说明 |
|---|---|
| 延迟定义 | 单次 HTTP 往返（脚本 Stopwatch 包裹 API 调用），不含脚本启动、登录与预热；百分位取 nearest-rank（P95 = 第 ceil(0.95×N) 个成功样本） |
| 失败样本 | 业务码非 0 或 HTTP 异常计入 `失败`，不进入延迟样本 |
| 账号 | 管理员口令由 `SMOKE_PASSWORD` 提供，与链路冒烟一致 |
| 环境 | 建议单机同规格（网关 8080、auth 8081、ERP 9001、MES 9002），MySQL/Redis 与生产同配置档位；执行前清空无关压测流量 |

## 三、执行步骤

1. 起服 gateway / auth / ERP / MES，准备一名管理员（`SMOKE_PASSWORD`）。
2. 执行权限判定与分页两组读压测（互不影响，可连续执行）。
3. 用 `scripts/smoke/bw-chain-2-erp-mes-erp.ps1` 生成一张已派工任务，取任务 ID 后执行并发报工。
4. 把脚本输出的 Markdown 行替换上表「待回填」行，并在提交信息中注明机器规格与中间件版本。
5. 任一组出现失败样本或 P95 明显高于历史基线时，先排查环境（连接池、GC、锁等待），不要直接改基线数字。

## 四、约束

- 压测对生产库有写入（并发报工会消耗任务可报数量），必须使用独立测试租户/环境。
- 三组脚本均为手动执行，不接入日常 CI；结果以本文档为唯一基线记录。
- 阈值暂不设硬门槛（P95 目标随部署规格差异较大），先积累 2~3 次同规格数据后再定 SLO。
