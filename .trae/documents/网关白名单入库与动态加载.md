# 网关白名单入库与动态加载实施方案

## Context

当前 whale-gateway 的 JWT 白名单硬编码在 `application.yml` 的 `whale.gateway.white-list`（15 条），新增/调整免鉴权路径需要改配置并重启网关，且与权限中心（whale-service-auth）的权限数据割裂。目标是把白名单作为「权限中心控制平面」的数据资产落到 auth 库，由网关动态拉取、无需重启生效，本地配置保留为兜底，避免拉取失败导致登录链路不可用。

关于「然后添加动态路由」：本方案理解为「白名单动态下发/生效」。现有 `/auth/v1/**` 路由已覆盖新增的只读内部接口，**无需新增路由**；若原意是「把网关路由定义也迁到权限中心 DB」，属于独立阶段（涉及 `NacosRouteDefinitionRepository`、`RouteDefinitionValidator`、回滚快照），本轮不做，见文末待确认项。

## 总体方案

```
auth DB(sys_gateway_whitelist) ──> auth 只读内部接口
        GET /auth/v1/internal/gateway/whitelist (X-Internal-Token)
                ▲ lb:// 拉取 + 800ms 超时 + 60s 定时刷新
                │
gateway GatewayWhitelistProvider(AtomicReference 快照)
                │  ∪ 本地 whale.gateway.white-list（兜底）
        JwtAuthGlobalFilter.isWhiteListed(path, method)
```

- 远程成功且非空：快照替换为远程列表；
- 远程失败或为空：清空远程快照，仅用本地配置（保证 login/refresh 始终可放行，不会全量 401，也不会全放行）；
- 远程条目支持 `http_method`（`*` 表示不限方法），本地条目按任意方法匹配。

## 一、数据模型与迁移（auth）

新增 `whale-service-auth-starter/src/main/resources/db/migration/V13__gateway_whitelist.sql`（幂等，沿用 V11 风格）：

- 表 `sys_gateway_whitelist`：`id BIGINT PK`、`path_pattern VARCHAR(255)`、`http_method VARCHAR(16) DEFAULT '*'`、`scope VARCHAR(16) DEFAULT 'PLATFORM'`、`source VARCHAR(16) DEFAULT 'MIGRATION'`、`remark VARCHAR(255)`、`status TINYINT DEFAULT 1`、`sort_no INT DEFAULT 0`、`create_time/update_time/deleted`；
  唯一键 `(path_pattern, http_method, scope)`；索引 `(status, sort_no)`。
- 种子 15 条，按 `WHERE NOT EXISTS` 幂等插入，`source='MIGRATION'`、`status=1`，与当前 yml 逐字一致：`/auth/v1/login`、`/auth/v1/refresh`、`/brand/v1/resolve`、`/actuator/**`、`/v3/api-docs/**`、`/doc.html`、`/webjars/**`、`/favicon.ico`、`/audit/log/frontend/batch`、`/audit/log/behavior/batch`、`/im/ws`、`/doc/ws`、`/music/stream/**`、`/video/stream/**`、`/contract/sign/callback/**`。
- 权限码 `sys:gateway:whitelist:list/add/edit/delete`（号段 2360-2363，按 `perm_code` 判重），为后续管理端预留；本轮不建菜单、不授租户管理员。

## 二、auth 侧分层实现（DDD）

前缀 `AUTH=whale-backend/whale-services/whale-service-auth`：

| 层 | 新增文件 |
|---|---|
| domain | `.../domain/aggregate/GatewayWhitelistAggregate.java`（`reconstitute`、`isEnabled`、常量 `SCOPE_PLATFORM/STATUS_ENABLED/HTTP_METHOD_ANY`） |
| domain | `.../domain/repository/GatewayWhitelistRepository.java`：`List<GatewayWhitelistAggregate> findAllEnabled()` |
| application | `.../application/service/GatewayWhitelistAppService.java` + `impl/GatewayWhitelistAppServiceImpl.java`；`.../application/model/vo/GatewayWhitelistVO.java`（`record(pathPattern, httpMethod)`） |
| infrastructure | `persistence/po/SysGatewayWhitelistPo.java`、`persistence/mapper/SysGatewayWhitelistMapper.java`、`persistence/assembler/GatewayWhitelistPersistenceAssembler.java`、`persistence/repository/GatewayWhitelistRepositoryImpl.java` |
| interfaces | `interfaces/api/GatewayWhitelistInternalApi.java`、`interfaces/dto/response/GatewayWhitelistItemResponse.java` |
| starter | `starter/controller/GatewayWhitelistInternalController.java`、`starter/assemble/GatewayWhitelistAssembler.java` |

接口契约：

```
GET /auth/v1/internal/gateway/whitelist
Header: X-Internal-Token: ${WHALE_INTERNAL_TOKEN}
200 {"code":0,"message":"ok","data":[{"pathPattern":"/auth/v1/login","httpMethod":"*"}]}
```

- 查询条件：`status=1 AND scope='PLATFORM' ORDER BY sort_no, id`，逻辑删除走全局配置。
- 修改 `SecurityConfig`：permitAll 增加 `/auth/v1/internal/**`（`InternalTokenFilter` 的 `/**/internal/**` 已覆盖令牌校验）。
- 不引入 Redis/Caffeine 缓存：每实例每分钟一次查询，直接读库。
- 网关侧 external 访问由 `internal-deny` 的 `/*/*/internal/**` 统一 403（已存在，无需改）。

## 三、网关侧动态加载

`application.yml` 新增（与 `white-list` 平级，避免 List 嵌套绑定冲突）：

```yaml
whale.gateway.whitelist-dynamic:
  enabled: ${WHALE_GATEWAY_WHITELIST_DYNAMIC_ENABLED:true}
  uri: lb://whale-service-auth/auth/v1/internal/gateway/whitelist
  refresh-interval-ms: 60000
  initial-delay-ms: 5000
  timeout-millis: 800
  internal-token: ${WHALE_INTERNAL_TOKEN:}
  internal-token-header: X-Internal-Token
```

新增文件（`whale-gateway/src/main/java/com/bluewhale/gateway/whitelist/`）：

- `GatewayWhitelistDynamicProperties.java`：`@ConfigurationProperties("whale.gateway.whitelist-dynamic")`。
- `GatewayWhitelistRule.java`：`record(String pathPattern, String httpMethod)`，`matchesMethod` 判定。
- `AuthGatewayWhitelistClient.java`：复用 `@Qualifier("loadBalancedWebClientBuilder") WebClient.Builder`（同 `PermissionHeaderGlobalFilter`），带内部令牌头、`.timeout(...)`，解析 `data[]` 并校验 `code==0`，异常返回空列表。
- `GatewayWhitelistProvider.java`：`AtomicReference<List<GatewayWhitelistRule>>` 快照 + `AtomicBoolean` 防重入；`ApplicationReadyEvent` 首拉，`@Scheduled(fixedDelayString=...)` 定时刷新；`matches(path, method)` 只读快照，O(n) 遍历（n≈15，无需预编译 Pattern 缓存；如后续条目增长可加 `AntPathMatcher` 缓存）。
- `WhaleGatewayApplication`（或配置类）增加 `@EnableScheduling`。

修改 `JwtAuthGlobalFilter`：

- 构造器追加 `GatewayWhitelistProvider`；
- `isWhiteListed(path, method)`：本地配置命中 **或** 远程快照命中即放行；
- 命中后仍执行既有的「清除身份/租户头」逻辑，行为不变。

## 四、测试与验证

auth：

- `GatewayWhitelistAppServiceImplTest`：仅返回 `status=1`、排序正确；
- `GatewayWhitelistInternalControllerTest`：200 结构与字段；
- `AuthArchitectureTest`：domain 不依赖 Spring/MyBatis（现有 ArchUnit 覆盖，新增类自动纳入）；
- 迁移幂等：连续启动两次，`sys_gateway_whitelist` 计数仍为 15，`flyway_schema_history` 仅一条 V13。

gateway：

- `GatewayWhitelistProviderTest`：成功替换、空结果回退、异常回退、并发防重入；
- `JwtAuthGlobalFilterTest`：远程命中放行、远程未命中 401、远程失败+本地命中放行、远程失败+本地未命中 401、method 不匹配 401。

端到端：

1. `curl -H "X-Internal-Token: $TOKEN" http://127.0.0.1:8081/auth/v1/internal/gateway/whitelist` → `code=0`；无 token → 403。
2. `curl http://127.0.0.1:8080/auth/v1/internal/gateway/whitelist` → 403（internal-deny）。
3. 停 auth：`POST /auth/v1/login` 仍非 401，`GET /user/v1/page` 无 token → 401（本地兜底生效）。
4. DB 插入 `/demo/open/**`（status=1），≤60s 后该路径免 JWT；置 status=0 后恢复 401，网关不重启。

构建命令：`.\mvnw.cmd -s D:\maven\conf\settings.xml -f whale-backend\pom.xml -pl :whale-service-auth-starter,:whale-gateway -am -DskipITs test`。

## 六、待确认项

1. **「动态路由」原意**：
   - 推荐解释（本方案）：白名单动态下发/刷新，现有 `/auth/v1/**` 路由已覆盖，不新增路由；
   - 若指「路由定义从 Nacos 迁到权限中心 DB」，需独立第二阶段（DB 表 + 合并/优先级 + 回滚快照改造 + 治理端点调整），本轮不做。
2. **是否需要管理端 CRUD**：本轮只做只读内部接口 + DB 种子；如需页面级维护，追加 `GET/POST/PUT/DELETE /auth/v1/gateway/whitelist` 与 `sys:gateway:whitelist:*` 鉴权（文件量约 +6）。

## 七、风险与处理

- auth 不可用：远程快照清空，本地 15 条兜底；登录链路不受影响。
- 误配空结果：远程空列表不覆盖本地，等价于「仅本地生效」。
- 内部令牌未配置：dev 放行；非 dev `WHALE_INTERNAL_TOKEN` 未配置时 auth 启动即失败（既有机制），网关拉取失败自动兜底。
- 配置绑定：新配置项置于 `whale.gateway.whitelist-dynamic`，避开 `white-list` 的 List 绑定。
